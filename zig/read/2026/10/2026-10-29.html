rebuild.zig

const std = @import("std");

fn rebuild(a: i32, b: i32) i32 {
    return @divTrunc(a, b) * b + @mod(a, b);
}

pub fn main(init: std.process.Init) !void {
    var buf: [256]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try stdout.print("{d} {d} {d}\n", .{ rebuild(7, 3), rebuild(-7, 3), rebuild(-6, 3) });
    try stdout.flush();
}

これは何を出力するでしょうか?

Answer

7 -4 -6 です。

@divTrunc は商の小数部を0の側へ切り捨てるので、@divTrunc(-7, 3) は -2.33… から -2 になります。@mod の余りは割る数が正なら0以上で、-7 = 3 * (-3) + 2 と見て @mod(-7, 3) は2です。rebuild(-7, 3) は -2 * 3 + 2 で -4 になり、-7 には戻りません。

q * b + r で元の数に戻るのは、商と余りを同じ向きの切り捨てで作った組だけです。@mod と組になるのは、@divTrunc ではなく負の側へ切り捨てる @divFloor です。2つの切り捨ての向きが違う結果を出すのは、割られる数が負で、しかも割り切れないときだけで、そのとき @divTrunc の商は @divFloor より1大きくなります。@divFloor と @mod の組なら元の数に戻るので、商だけを1大きい @divTrunc に替えた rebuild は、元の数より b だけ大きくなります。7は正なので7に戻り、-6は割り切れるので商はどちらも -2、余りは0で、-6に戻ります。

@divTrunc も負の側へ切り捨てると読むと -3 * 3 + 2、@mod も割られる数の符号に合わせると読むと -2 * 3 + (-1) になり、どちらも -7 に戻って 7 -7 -6 と答えてしまいます。2つの読み違いのどちらか1つだけでも、組がそろったことになって元の数に戻る答えに着きます。
