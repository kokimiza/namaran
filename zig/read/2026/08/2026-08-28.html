fields.zig

const std = @import("std");

fn show(stdout: *std.Io.Writer, v: anytype) !void {
    inline for (@typeInfo(@TypeOf(v)).@"struct".field_names) |name| {
        try stdout.print("{s}={d};", .{ name, @field(v, name) });
    }
    try stdout.print("\n", .{});
}

pub fn main(init: std.process.Init) !void {
    var buf: [256]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try show(stdout, .{ .x = 3, .y = 4 });
    try show(stdout, .{ 3, 4 } ++ .{5});
    try stdout.flush();
}

これは何を出力するでしょうか?

Answer

1行目に x=3;y=4;、2行目に 0=3;1=4;2=5; を出力します。

show は、引数の型のフィールド名を @typeInfo で並べ、名前ごとに @field でその値を読みます。.{ .x = 3, .y = 4 } は型名を省いた構造体リテラル（anonymous struct literal）で、渡す先の型が anytype なので、x と y の2つのフィールドを持つ構造体の型がその場で作られます。

.{ 3, 4 } のようにフィールド名を書かないリテラルはタプル（tuple）で、フィールドには0から順に "0"、"1" という番号の名前が付きます。++ はタプルどうしをつなぎ、右の .{5} の5は3つ目のフィールド "2" になります。@field は名前の文字列でフィールドを引くので、番号の名前でも同じように値が読め、0=3;1=4;2=5; が並びます1。

  1. タプルのフィールド名は数字なので、t.1 とは書けず、t.@"1" と書きます。配列と同じように t[1] とも書けますが、添字はコンパイル時に決まっている必要があります。
