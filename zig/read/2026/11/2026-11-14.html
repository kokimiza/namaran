ruler.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const w = &stdout_writer.interface;
    try w.writeByte('a');
    for (1..7) |i| {
        try w.print("{d}{s}", .{ i, w.buffered() });
        if (i % 3 == 0) try w.flush();
    }
    try w.writeByte('\n');
    try w.flush();
}

これは何を出力するでしょうか?

Answer

Output

a1a2a1a3a1a2a1a4546454

w.buffered() が返すのは、buf にたまっていて、まだ標準出力へ送っていないバイト列です。flush はそれをすべて送り出し、たまった分を空にします。buf は64バイトあり、このプログラムが一度にためるのは最大15バイトなので、flush を呼ぶまでバイトが勝手に送られることはありません。

print の引数は、print が書き始める前に評価されます。w.buffered() はその時点でたまっている分を指すスライスで、長さもそこで決まります。print はまず i を書き、続けてこのスライスを書くので、たまっている文字列を S とすると、1回の print で S は「S、i、S」になります。S の長さは1回ごとに2倍に1を足した長さになり、中身もこの形のまま決まるので、1文字ずつ追う必要はありません。

'a' から始めると、i が1で a1a、2で a1a2a1a、3で a1a2a1a3a1a2a1a になり、ここで flush がこの15文字を出して S を空にします。i が4のときの S は空なので、書かれるのは 4 だけです。そこから5で 454、6で 4546454 になって、また flush されます。最後に改行を書いて flush するので、出力は2つのかたまりをつないだ1行です。

buffered() がそれまでに書いたすべてを返すと考えると、i が4以降も S が伸び続け、a1a2a1a3a1a2a1a4a1a2a1a3a1a2a1a のような行を答えることになります。flush の後に残っているのは、まだ送っていない分だけです。
