same_slice.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    const stdout = std.Io.File.stdout();
    var w = stdout.writer(init.io, &buf);
    const out = &w.interface;
    const a = "abc";
    var b = "abc".*;
    for ([_][]const u8{ a, &b }) |s| {
        std.testing.expectEqual(a, s) catch {
            try out.print("ng\n", .{});
            continue;
        };
        try out.print("ok\n", .{});
    }
    try out.flush();
}

これは何を出力するでしょうか?

Answer

Output

ok
ng

expectEqual は、2つの引数を peer type resolution（langref の用語で、2つの値が共通に変換できる型を選ぶ規則）で同じ型にそろえてから比べます。a は文字列リテラルへのポインタで、s は []const u8 なので、比べる型はスライスです。expectEqual はスライスを、中身ではなく先頭のアドレス（ptr）と長さ（len）で比べます。

1つ目の s は a そのものなので、アドレスも長さ 3 も一致して ok です。2つ目の &b は、a の中身を写した配列 b を指しています。中身は同じ abc で長さも 3 ですが、アドレスが違うので expectEqual は失敗を返し、catch の側で ng が出ます。失敗の詳しい理由は標準エラーに出るので、標準出力には ok と ng の2行だけが並びます。

スライスを中身で比べると読むと、2つ目も ok と答えます。中身を比べたいときは、要素の型を渡す std.testing.expectEqualSlices(u8, a, s) か、文字列専用の expectEqualStrings を使います。expectEqual が中身を比べるのは配列の場合で、a.* と b のように配列どうしを渡せば、要素ごとに比べて一致します。
