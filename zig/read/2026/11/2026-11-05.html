next_id.zig

const std = @import("std");

fn nextId(comptime T: type) T {
    const S = struct {
        var last: T = 0;
    };
    S.last += 1;
    return S.last;
}

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try stdout.print("{d} {d} {d} {d}\n", .{ nextId(u8), nextId(u8), nextId(u16), nextId(u8) });
    try stdout.flush();
}

これは何を出力するでしょうか?

Answer

Output

1 2 1 3

comptime T: type を受け取る関数は、呼び出しで渡された型ごとに、別の関数として作られます。nextId(u8) と nextId(u16) は名前が同じでも中身は別々の関数で、同じ u8 でもう一度呼ぶと、前に作った u8 用の関数がそのまま使われます。関数の中で宣言した struct も、この関数ごとに1つずつ別の型になります。その中の var last は関数の局所変数ではなく、struct に属するコンテナの変数(container-level variable)なので、プログラムの開始から終わりまで1つだけ存在し、呼び出しをまたいで値が残ります。

タプルの要素は左から順に評価されます。1つ目の nextId(u8) は u8 用の last を 0 から 1 にして 1 を返し、2つ目は同じ last を 2 にします。3つ目の nextId(u16) が使うのは u16 用の関数の last で、u8 用とは別の変数なので、0 から数えて 1 です。4つ目でまた u8 用に戻り、2 の続きの 3 を返します。

last がプログラム全体で1つだと読むと、1 2 3 4 になります。struct が呼ぶたびに作り直されると読むと、1 1 1 1 です。型は実行時ではなくコンパイル時に作られ、同じ引数で作った型は同じものになります。標準ライブラリの std.ArrayList(u8) を2か所で書いても同じ型として扱えるのは、この規則があるからです。
