fork.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var out: [64]u8 = undefined;
    var w = std.Io.File.stdout().writer(init.io, &out);
    var buf: [8]u8 = undefined;
    var fba = std.heap.FixedBufferAllocator.init(&buf);
    var spare = fba;
    const x = try fba.allocator().alloc(u8, 3);
    @memset(x, 1);
    const y = try spare.allocator().alloc(u8, 4);
    @memset(y, 2);
    const z = try fba.allocator().alloc(u8, 2);
    @memset(z, 3);
    try w.interface.print("{any} {any}\n", .{ x, y });
    try w.interface.flush();
}

これは何を出力するでしょうか?

Answer

Output

{ 2, 2, 2 } { 2, 2, 2, 3 }

FixedBufferAllocator は、渡された配列を指すスライス buffer と、次に切り出す位置 end_index の2つのフィールドだけを持つ構造体です。確保のたびに buffer の end_index から必要なバイト数を切り出し、end_index をその分進めます。allocator() は *FixedBufferAllocator を受け取り、そのポインタを中に持った std.mem.Allocator を返します。どの構造体の end_index を進めるかは、allocator() を呼んだ変数で決まります。

var spare = fba; は構造体の値のコピーなので、spare は自分の end_index を持ち、その値は0です。一方、コピーされた buffer は先頭のポインタと長さの組であるスライスなので、spare の buffer も同じ buf を指します。1つの配列に、互いを知らない2つの切り出し位置ができたことになり、出力はここから決まります。

x は fba から buf[0..3] を受け取り、fba の位置は3に進みます。y は spare の位置0から切り出されるので buf[0..4] で、2 を書くと x の3バイトも上書きされます。z は fba の位置3から buf[3..5] を受け取り、3 を書くと y の最後の1バイト buf[3] が変わります。x は { 2, 2, 2 }、y は { 2, 2, 2, 3 } になります。

spare を独立した割り当て器だと読むと、x と y は重ならず { 1, 1, 1 } { 2, 2, 2, 2 } と答えます。逆に spare が fba と状態を共有すると読むと、3回の確保で合計9バイトが要り、8バイトの buf から z を切り出せずに error.OutOfMemory で終わると答えます。実際には、配列はスライスを通して共有され、切り出し位置は値として分かれています。割り当て器を使う側に渡すのは fba.allocator() の戻り値で、構造体そのものはコピーせず1か所に置いておきます。
