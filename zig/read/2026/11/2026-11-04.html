fields.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    var r: std.Io.Reader = .fixed("ab,,c,");
    while (try r.takeDelimiter(',')) |field| {
        try stdout.print("[{s}]", .{field});
    }
    try stdout.print("\n", .{});
    try stdout.flush();
}

これは何を出力するでしょうか?

Answer

[ab][][c] です。

std.Io.Reader.fixed は、渡した文字列そのものを読み出し元にする Reader を作ります。takeDelimiter(',') は、次のコンマの手前までをスライスで返し、読む位置をそのコンマの後ろへ進めます。返すスライスにコンマは含まれません。読むものが残っていなければ null を返すので、while はそこで終わります。

"ab,,c," では、1回目が ab を返して1つ目のコンマの後ろへ進みます。2回目はすぐ次がコンマなので、長さ0のスライスを返して2つ目のコンマを越えます。続いたコンマの間には空の欄が1つあり、[] と表示されます。3回目は c を返して最後のコンマを越えます。4回目は読むものが残っていないので null です。末尾のコンマの後ろに空の欄があるとは扱わず、[] はもう出ません。

takeDelimiter は、区切り文字が見つからないまま読み出し元の終わりに来たときも、そこまでの残りを最後の欄として返します。"ab,,c" のように末尾のコンマが無くても、同じ [ab][][c] になります。1

  1. 似た名前の takeDelimiterExclusive は、区切り文字の手前で止まり、区切り文字を読み飛ばしません。続けて呼ぶと、同じ区切り文字の手前で空のスライスを返し続けます。
