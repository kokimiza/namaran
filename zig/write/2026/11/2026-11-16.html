sum_fields.zig

fn sumFields(s: anytype) u32 {
}

構造体の値 s を受け取り、すべてのフィールドの値を足した合計を u32 で返す sumFields を書いてください。s のフィールドはどれも u32 以下の幅の符号なし整数で、合計は u32 に収まるものとします。フィールドが1つも無ければ 0 を返します。例の Rgb は struct { r: u8, g: u8, b: u8 } です。

入力例 1

sumFields(Rgb{ .r = 255, .g = 255, .b = 255 })

出力例 1

765

入力例 2

sumFields(.{ .x = @as(u8, 1), .y = @as(u16, 1000) })

出力例 2

1001

入力例 3

sumFields(.{})

出力例 3

0

fn sumFields(s: anytype) u32 {
    var total: u32 = 0;
    inline for (@typeInfo(@TypeOf(s)).@"struct".field_names) |name| {
        total += @field(s, name);
    }
    return total;
}

@typeInfo(@TypeOf(s)) は s の型の情報を返し、構造体なら .@"struct" の field_names にフィールド名が宣言の順に並びます。この一覧はコンパイル時にしか存在しないので、inline for でループを展開します。展開した各回の name はコンパイル時に決まった文字列になり、コンパイル時の名前を要求する @field(s, name) に渡せます。Rgb なら、ループは total += s.r;、total += s.g;、total += s.b; の3文に展開されたのと同じです。掲載したのは参考実装で、唯一の正解ではありません。

total を u32 にしておけば、u8 や u16 のフィールドは足すときに u32 へ広げられます。入力例 1 の 255 + 255 + 255 = 765 は u8 には収まりませんが、u32 の total には収まります。入力例 3 の .{} はフィールドの無い構造体で、field_names が空なのでループは1回も展開されず、初期値の 0 が返ります。Zig 0.17 では、以前の版で使われた std.meta.fields は使えなくなっていて、@typeInfo を直接読みます。
