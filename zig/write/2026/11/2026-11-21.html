mean.zig

fn mean(xs: []const i32) f64 {
}

i32 のスライス xs の要素の平均を f64 で返す mean を書いてください。要素が1つも無いときは 0 を返します。

入力例 1

mean(&.{ 1, 2, 4 })

出力例 1

2.3333333333333335

入力例 2

mean(&.{ -3, 4 })

出力例 2

0.5

入力例 3

mean(&.{})

出力例 3

0

fn mean(xs: []const i32) f64 {
    if (xs.len == 0) return 0;
    var sum: i64 = 0;
    for (xs) |x| sum += x;
    const s: f64 = @floatFromInt(sum);
    const n: f64 = @floatFromInt(xs.len);
    return s / n;
}

Zig は、整数と浮動小数点数を1つの演算の中で混ぜることも、暗黙に変換することもしません。sum / xs.len は i64 と usize の割り算で、型が揃わずにコンパイルできず、揃えたとしても整数の割り算で小数部が消えます。そこで、和と個数をそれぞれ @floatFromInt で f64 にしてから割ります。@floatFromInt は変換先の型を引数に取らず、受け取る側の型（langref の result type）から決めるので、const s: f64 のように型を書いた定数で受けます。掲載したのは参考実装で、唯一の正解ではありません。@as(f64, @floatFromInt(sum)) と書けば、式の途中でも変換できます。

和を i64 で数えるのは、i32 の要素を足すと i32 の範囲を超えることがあり、Zig では整数のオーバーフローが安全検査で止まる illegal behavior だからです。sum += x では x が i64 に広げられます。広げる変換は値が変わらないので、暗黙に行われます。入力例1は 7 / 3 で、f64 で表せる最も近い値が 2.3333333333333335 と表示されます。入力例3の空のスライスで割り算まで進むと 0 / 0 になり、結果は数でない値（NaN）になります。最初の if で、その前に 0 を返します。
