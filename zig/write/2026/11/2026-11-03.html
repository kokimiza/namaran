repeat_text.zig

fn repeat(comptime s: []const u8, comptime n: usize) []const u8 {
}

文字列 s を n 回続けてつないだ文字列を返す repeat を書いてください。s と n はどちらもコンパイル時に分かる値で、n が 0 のときは空の文字列を返します。アロケータは使わず、main などの実行時のコードから、comptime を付けずに repeat("ab", 3) と呼べるようにしてください。

入力例 1

repeat("ab", 3)

出力例 1

"ababab"

入力例 2

repeat("-", 5)

出力例 2

"-----"

入力例 3

repeat("ab", 0)

出力例 3

""
Reference 
fn repeat(comptime s: []const u8, comptime n: usize) []const u8 {
    comptime var out: []const u8 = "";
    inline for (0..n) |_| {
        out = out ++ s;
    }
    return out;
}

++ は、両辺の長さがコンパイル時に分かるときにだけ使えます。そこで、つないでいく途中の文字列を comptime var の out に置き、空の文字列から n 回 out ++ s を代入し直します。out の長さは代入のたびに s.len ずつ伸びますが、どの時点の長さもコンパイル時に決まっているので、次の ++ も書けます。

ループは inline for にします。ふつうの for は実行時に回るループなので、その中で comptime var に代入すると「store to comptime variable depends on runtime condition」というコンパイルエラーになります。comptime の付かない var out にすると、今度は out の長さが実行時の値になり、out ++ s が「unable to resolve comptime value」で止まります。inline for はループをコンパイル時に n 回分に展開するので、out への代入もすべてコンパイル時に済み、関数が返すのはでき上がった文字列を指すスライスだけです。

n が 0 なら inline for は1回も展開されず、最初の "" がそのまま返ります。掲載したのは参考実装で、唯一の正解ではありません。1

  1. 以前の Zig には配列を繰り返す ** 演算子があり、s ** n の1つの式で書けました。0.17 の言語リファレンスの演算子の表に ** は無く、s ** n と書くとコンパイルエラーになります。
