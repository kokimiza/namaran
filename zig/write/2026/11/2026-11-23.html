aligned_words.zig

fn alignedWords(buf: []u8) []u32 {
}

buf の中で、アドレスが4の倍数になる最初の位置から始まり、u32 が丸ごと収まるだけ並ぶ部分を、buf と同じメモリを指す []u32 として返す alignedWords を書いてください。後ろに残る4バイト未満の端は含めません。u32 が1つも収まらないときは空のスライスを返します。例では buf を var buf: [12]u8 align(4) で宣言した配列とし、返り値を、先頭の要素が buf の先頭から何バイト先にあるかと要素数の組 {開始, 要素数} で書きます。

入力例 1

alignedWords(buf[0..])

出力例 1

{0, 3}

入力例 2

alignedWords(buf[1..])

出力例 2

{4, 2}

入力例 3

alignedWords(buf[1..3]).len

出力例 3

0

fn alignedWords(buf: []u8) []u32 {
    const addr = @intFromPtr(buf.ptr);
    const skip = (4 - addr % 4) % 4;
    if (skip > buf.len) return &.{};
    const n = (buf.len - skip) / 4;
    const bytes = buf[skip..][0 .. n * 4];
    return @ptrCast(@alignCast(bytes));
}

値を置けるアドレスが何の倍数でなければならないかを、アラインメント(alignment)と呼びます。[]u8 のアラインメントは1で、要素のアドレスについて何も約束していません。u32 のアラインメントは4なので1、[]u32 は4の倍数のアドレスを要求します。@ptrCast はアラインメントを上げられないので、それだけでは []u8 を []u32 にできず、コンパイルエラーになります。アラインメントを上げるのは @alignCast の役目です。ただし @alignCast はアドレスを動かしません。4の倍数だと型に書き込むだけで、実行時に本当にそうかを確かめ、違えば illegal behavior として止まります。そこで、先に揃った位置まで進めてから渡します。掲載したのは参考実装で、唯一の正解ではありません。

参考実装は、buf.ptr のアドレスを @intFromPtr で整数にし、次の4の倍数までのバイト数 skip を (4 - addr % 4) % 4 で求めます。skip が長さを超える短いスライスは、揃った位置にすら届かないので空のスライスを返します。残りから4バイト単位で取れる n * 4 バイトだけを切り出せば、長さも4の倍数になります。@alignCast でアラインメントを4に上げたスライスを @ptrCast に渡すと、スライスの長さはバイト数から u32 の個数に換算され、n になります。入力例2の buf[1..] は11バイトで、アドレスは4の倍数より1大きいので skip は 3 です。buf の先頭から4バイト先に残る8バイトが u32 2つになり、{4, 2} です。入力例3の buf[1..3] は2バイトしかなく、skip の 3 に届かないので空になります。

  1. u32 のアラインメントは、x86-64 や AArch64 など広く使われるターゲットで4です。どのターゲットでも、@alignOf(u32) で確かめられます。
