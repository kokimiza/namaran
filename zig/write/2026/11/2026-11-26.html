cap_all.zig

fn capAll(xs: []i32, limit: i32) void {
}

xs の要素のうち limit より大きいものを limit に書き換える capAll を書いてください。limit 以下の要素はそのまま残し、新しい配列は作らずに xs の要素を直接書き換えます。xs が空なら何もしません。例では、呼ぶ前の配列 xs の宣言と呼び出しを入力に、呼んだあとの xs の中身を出力に書きます。

入力例 1

var xs = [_]i32{ 3, 9, 5 };
capAll(&xs, 5);

出力例 1

{ 3, 5, 5 }

入力例 2

var xs = [_]i32{ -2, 8 };
capAll(&xs, -1);

出力例 2

{ -2, -1 }

入力例 3

var xs = [_]i32{};
capAll(&xs, 0);

出力例 3

{  }

fn capAll(xs: []i32, limit: i32) void {
    for (xs) |*x| {
        if (x.* > limit) x.* = limit;
    }
}

for (xs) |x| と書くと、x は要素の値の写しで、しかも const なので代入できません。要素そのものを書き換えるには、|*x| と書いて要素へのポインタを受け取ります。xs は []i32 で要素を書き換えられるスライスなので、x の型は *i32 になり、x.* で読み書きできます。limit を超えた要素だけに limit を書き込めば、ほかの要素はそのまま残ります。掲載したのは参考実装で、唯一の正解ではありません。

入力例1では 9 だけが 5 を超えるので、{ 3, 5, 5 } になります。入力例2の上限は -1 で、-2 は残り、8 が -1 になります。空のスライスではループの本体が一度も実行されず、何も書き換えません。&xs の型は配列へのポインタ *[3]i32 で、要素の数を持っているので、そのまま []i32 の引数に渡せます。仮引数を []const i32 にすると、要素へのポインタも *const i32 になり、x.* = limit がコンパイルエラーになります。
