}

鍵=値 の形の1行 line を最初の = で分け、鍵と値をそれぞれ gpa で確保した新しい領域に写して Pair で返す parsePair を書いてください。返した Pair は呼び出し側が持ち、line を書き換えたり解放したりしたあとも使えて、最後に deinit(gpa) で解放します。= が無ければ何も確保せずに error.MissingEquals を返し、確保に失敗してエラーを返すときは、それまでに確保した領域をすべて解放してから返します。値は空でもかまいません。

入力例 1

parsePair(gpa, "host=example")

出力例 1

.{ .key = "host", .value = "example" }

入力例 2

parsePair(gpa, "token=")

出力例 2

.{ .key = "token", .value = "" }

入力例 3

parsePair(gpa, "verbose")

出力例 3

error.MissingEquals

const std = @import("std");

const Pair = struct {
    key: []u8,
    value: []u8,

    fn deinit(self: Pair, gpa: std.mem.Allocator) void {
        gpa.free(self.key);
        gpa.free(self.value);
    }
};

fn parsePair(gpa: std.mem.Allocator, line: []const u8) !Pair {
    const eq = std.mem.indexOfScalar(u8, line, '=') orelse return error.MissingEquals;
    const key = try gpa.dupe(u8, line[0..eq]);
    errdefer gpa.free(key);
    const value = try gpa.dupe(u8, line[eq + 1 ..]);
    return .{ .key = key, .value = value };
}

まず = の位置を探し、見つからなければその場でエラーを返します。確保より前に調べるので、この道では解放するものがありません。鍵と値は line の一部を指すスライスのままにせず、gpa.dupe で新しい領域に写します。そうすれば Pair が持つのは自分の領域だけになり、line の持ち主が先に書き換えても解放しても影響を受けません。これは参考実装で、唯一の正解ではありません。

確保は2回あり、2回目の dupe だけが失敗することがあります。そのとき key はすでに確保されていて、まだ誰にも渡していないので、parsePair が解放しなければ漏れます。errdefer gpa.free(key); は、この行より後で関数がエラーを返したときだけ実行されます。defer と書くと成功したときにも key が解放され、呼び出し側は解放済みの領域を受け取ったうえ、deinit で二重に解放します。成功して return した時点で、2つの領域を解放する責任は Pair と一緒に呼び出し側へ移ります。2回目の確保の後には失敗する処理が無いので、value に errdefer は要りません。

どの確保が失敗しても漏れないことは、std.testing.checkAllAllocationFailures で確かめられます。この関数は、渡したテスト用の関数を、1回目、2回目と確保を1つずつ失敗させながら繰り返し実行し、確保した量と解放した量が合わなければテストを失敗させます。入力例2の空の値は長さ0の領域になり、deinit の free もそのまま通ります。
