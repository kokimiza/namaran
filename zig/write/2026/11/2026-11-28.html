window.zig

fn Window(
    comptime T: type,
    comptime n: usize,
) type {
}

要素の型 T と個数 n を受け取り、値を1つずつ受け取って最後の n 個の和を答える struct 型を返す Window を書いてください。返す型の値は .{} で作れて、値を足すメソッド push(self: *@This(), x: T) void と、最後に push した n 個の和を返すメソッド sum(self: @This()) T を持ちます。push した値が n 個に満たなければ、それまでに push した値すべての和を返し、1つも無ければ 0 です。T は符号なし整数型、n は 1 以上で、sum の答えは T に収まるものとし、メモリを動的に確保しないでください。例では、作る型と、push した値を順に並べた配列を書き、出力例に sum の結果を書きます。

入力例 1

Window(u32, 3), [1, 2, 3, 4]

出力例 1

9

入力例 2

Window(u16, 4), [5, 2]

出力例 2

7

入力例 3

Window(u8, 2), []

出力例 3

0
Reference 時間計算量 𝒪(n) 空間計算量 𝒪(n) n は Window に渡した個数。時間は sum 1回あたりで、push は 𝒪(1)

Reference

fn Window(
    comptime T: type,
    comptime n: usize,
) type {
    return struct {
        buf: [n]T = @splat(0),
        next: usize = 0,

        fn push(self: *@This(), x: T) void {
            self.buf[self.next] = x;
            self.next = (self.next + 1) % n;
        }

        fn sum(self: @This()) T {
            var s: T = 0;
            for (self.buf) |x| s += x;
            return s;
        }
    };
}

n は comptime の引数なので、返す struct の中でフィールドの型 [n]T の長さに使えます。Window(u32, 3) は長さ3の配列を中に持つ型になり、値を作るときに動的な確保は要りません。配列は輪のように使い、next が次に書き込む位置を指します。push は next の位置に値を書いて next を1つ進め、n に着いたら % n で 0 に戻します。書き込む位置がいちばん古い値の位置なので、配列にはいつも最後の n 個が残ります。これは参考実装で、唯一の正解ではありません。push のたびに和を更新しておき、sum を 𝒪(1) にする書き方もあります。

n 個に満たないときの答えは、配列を @splat(0) ですべて 0 で埋めておくことで出しています。まだ書き込んでいない場所は 0 なので、配列全体を足せば push した値だけの和になり、入力例 3 は 0 を返します。入力例 1 では 4 が最初の 1 の場所に書かれて配列が {4, 2, 3} になり、和は 9 です。T が符号なしなら途中までの和は最後の和を超えないので、答えが T に収まれば s += x もあふれません。next は n 未満を回り続けるだけなので、何回 push してもあふれません。
