half.zig

const std = @import("std");
const testing = std.testing;

fn half(n: u32) !u32 {
    if (n % 2 != 0) return error.Odd;
    return n / 2;
}

test "half" {
}

half が下の入出力例のとおりに振る舞うことを確かめる test ブロックの中身を書いてください。3つの例をすべて確かめ、どれか1つでも違えば zig test が失敗するようにします。

入力例 1

half(8)

出力例 1

4

入力例 2

half(0)

出力例 2

0

入力例 3

half(7)

出力例 3

error.Odd

test "half" {
    try testing.expectEqual(4, try half(8));
    try testing.expectEqual(0, try half(0));
    try testing.expectError(
        error.Odd,
        half(7),
    );
}

half の戻り値は u32 かエラーのどちらかを持つ error union（langref の用語）です。値を確かめる2行では、try half(8) で中の u32 を取り出してから、expectEqual に期待する値、実際の値の順に渡します。half がエラーを返した場合は、その try がエラーをテストの外へ返すので、テストはそこで失敗します。expectEqual 自身も、値が違えばエラーを返す関数です。先頭の try を付けないと、エラーを捨てることになってコンパイルが通りません。

エラーを確かめる expectError には、try を付けずに error union のまま half(7) を渡します。try half(7) と書くと、expectError が呼ばれる前に error.Odd がテストの外へ返り、期待どおりのエラーなのにテストが失敗します。expectError は、渡された値が error.Odd ならそれで成功とし、値だったり別のエラーだったりすれば失敗を返します。掲載したのは参考実装で、唯一の正解ではありません。例ごとに test ブロックを分ければ、失敗したときにどの例かがテストの名前で分かります。
