number_lines.zig

const std = @import("std");

fn numberLines(r: *std.Io.Reader, w: *std.Io.Writer) !void {
}

r から読んだバイト列を w へそのまま写しながら、空でない行の先頭にだけ、1から数えた番号と : を付ける numberLines を書いてください。番号は空でない行だけを数えます。入力のバイトは1つも変えず、改行を足したり減らしたりもしません。最後の行が改行で終わらなくてもかまいません。w の flush は呼び出し側が行います。例では、r から読める内容と w に書かれた内容を Zig の文字列リテラルで書きます。

入力例 1

"a\n\nb\n"

出力例 1

"1: a\n\n2: b\n"

入力例 2

"x\ny"

出力例 2

"1: x\n2: y"

入力例 3

""

出力例 3

""

const std = @import("std");

fn numberLines(r: *std.Io.Reader, w: *std.Io.Writer) !void {
    var line: usize = 0;
    var at_start = true;
    while (r.takeByte()) |c| {
        if (at_start and c != '\n') {
            line += 1;
            try w.print("{d}: ", .{line});
        }
        try w.writeByte(c);
        at_start = c == '\n';
    } else |err| switch (err) {
        error.EndOfStream => {},
        else => |e| return e,
    }
}

行の番号は、改行を読んだときではなく、その行の最初のバイトを書く直前に付けます。参考実装は、直前に書いたのが改行か、まだ何も書いていないことを at_start で覚えておき、at_start のときに読んだバイトが改行でなければ番号を書きます。読んだバイトは writeByte でそのまま写します。takeByte は入力が尽きると error.EndOfStream を返すので、それはループの終わりとして受け、ほかのエラーは呼び出し元へ返します。掲載したのは参考実装で、唯一の正解ではありません。

この1つの条件で、行の境目の扱いがすべて決まります。入力例1の2つ目の改行は、at_start のときに読んだ改行なので、番号を付けずに写され、空の行は数えられません。入力の最後の改行の後には読むバイトが無いので、余計な番号は付きません。入力例2の y のように改行で終わらない最後の行にも、最初のバイトで番号が付きます。空の入力では一度もバイトを読まないので、何も書きません。

改行を読んだ直後に次の行の番号を書く作りにすると、入力例1の最後の改行の後に 3: が付いてしまいます。行ごとに区切って読む関数を使うと、最後の行が改行で終わっていたかどうかが分からなくなり、入力例2で改行を足してしまいがちです。
