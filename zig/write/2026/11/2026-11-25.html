range.zig

const Range = struct {
    lo: i32,
    hi: i32,

    fn include(self: *Range, x: i32) void {
    }
};

Range は lo 以上 hi 以下の整数の範囲を表す構造体で、lo は hi 以下です。x が範囲に入るように、範囲を必要な分だけ広げるメソッド include を書いてください。x がすでに範囲に入っているときは何も変えません。例では、var r: Range = .{ .lo = 2, .hi = 5 }; に対して入力例の呼び出しをしたあとの r を、{any} で表示した形で書きます。

入力例 1

r.include(9)

出力例 1

.{ .lo = 2, .hi = 9 }

入力例 2

r.include(-1)

出力例 2

.{ .lo = -1, .hi = 5 }

入力例 3

r.include(5)

出力例 3

.{ .lo = 2, .hi = 5 }

const Range = struct {
    lo: i32,
    hi: i32,

    fn include(self: *Range, x: i32) void {
        self.lo = @min(self.lo, x);
        self.hi = @max(self.hi, x);
    }
};

include は最初の引数 self を 呼び出し元の Range を指すポインタ *Range で受け取ります。r.include(9) と書くと r のアドレスが self に渡るので、self.lo と self.hi への代入は r のフィールドを書き換えます。ポインタでもフィールドは self.lo と書け、self.*.lo と参照を外す必要はありません。新しい lo は元の lo と x の小さいほう、新しい hi は大きいほうで、組み込み関数 @min と @max がそれを返します。掲載したのは参考実装で、唯一の正解ではありません。

入力例1では 9 が hi の 5 より大きいので hi だけが 9 になり、入力例2では -1 が lo の 2 より小さいので lo だけが -1 になります。入力例3の 5 は範囲の端にあり、@max(5, 5) は 5 なので何も変わりません。self を self: Range と値で受け取ると、Zig の引数は書き換えられないので self.lo = ... がコンパイルエラーになります。範囲の外の値を渡しても lo が hi を超えることは無いので、lo は hi 以下という条件も保たれます。
