parse_list.zig

const std = @import("std");

fn parseList(comptime T: type, buf: []T, text: []const u8) ![]T {
}

カンマで区切った10進数の並び text を型 T の整数として読み、先頭から順に buf へ入れて、入れた部分のスライスを返す parseList を書いてください。T の範囲に収まらない数があれば error.Overflow を、数として読めない欄(空の欄を含む)があれば error.InvalidCharacter を返します。buf の長さは、text の欄の数より短くないものとします。例の出力は、返したスライスを {any} で書式化したものか、返したエラーです。

入力例 1

parseList(u8, &buf, "1,20,255")

出力例 1

{ 1, 20, 255 }

入力例 2

parseList(u8, &buf, "1,256")

出力例 2

error.Overflow

入力例 3

parseList(i8, &buf, "-128,7")

出力例 3

{ -128, 7 }

fn parseList(comptime T: type, buf: []T, text: []const u8) ![]T {
    var it = std.mem.splitScalar(u8, text, ',');
    var n: usize = 0;
    while (it.next()) |field| : (n += 1) {
        buf[n] = try std.fmt.parseInt(T, field, 10);
    }
    return buf[0..n];
}

受け取った T は、そのまま std.fmt.parseInt(T, field, 10) に渡します。parseInt も comptime T: type を受け取る関数で、T の範囲で桁を積み上げ、収まらなくなった時点で error.Overflow を返します。範囲の検査を自分で書かなくても、u8 なら 256 が、i8 なら -129 が範囲外になり、入力例 3 の -128 は i8 に収まります。空の欄や数字以外の文字には error.InvalidCharacter が返り、どちらのエラーも try がそのまま呼び出し元へ返します。戻り値の型 ![]T は、エラーの集合をコンパイラが関数の本体から推論する error union です。

欄を切り出すのは std.mem.splitScalar(u8, text, ',') です。区切りの間が空でも長さ0の欄として返すので、"1,,2" の2つ目の欄は parseInt に渡って error.InvalidCharacter になります。入れた個数は while の継続式 n += 1 で数え、最後に buf[0..n] を返します。buf をまるごと返すと、入力例 1 のように欄が3つでも、何も入れていない残りの要素まで呼び出し元に見えてしまいます。

いったん i64 で読み、@intCast で T に縮める書き方では、入力例 2 は error.Overflow になりません。@intCast は値が収まらないとき illegal behavior になり、Debug ビルドではエラーを返さずに panic で止まるからです。範囲外をエラーとして返すには、読む段階から T を使います。掲載したのは参考実装で、唯一の正解ではありません。
