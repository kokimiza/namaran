insert.zig

fn insertAt(buf: []u8, len: usize, i: usize, x: u8) void {
}

buf の先頭 len バイトに値が入っていて、その後ろに少なくとも1バイトの空きがあります。位置 i に x を挿入し、もとの buf[i] から buf[len - 1] までを1つずつ後ろへずらす insertAt を書いてください。i は 0 以上 len 以下で、i が len なら末尾に足すだけです。len が 0 のときも同じ規則で buf[0] に入れます。例では、buf の中身を文字列で書き、空きのバイトを _ で表します。出力例は呼び出したあとの buf の中身です。

入力例 1

insertAt("abcd_", 4, 1, 'X')

出力例 1

aXbcd

入力例 2

insertAt("abcd_", 4, 4, 'X')

出力例 2

abcdX

入力例 3

insertAt("_", 0, 0, 'X')

出力例 3

X

fn insertAt(buf: []u8, len: usize, i: usize, x: u8) void {
    @memmove(buf[i + 1 .. len + 1], buf[i..len]);
    buf[i] = x;
}

ずらす元は buf[i..len]、ずらす先は1つ後ろの buf[i + 1 .. len + 1] で、どちらも長さ len - i のスライスです。2つは同じ buf の中を指していて、要素が2つ以上あれば範囲が重なります。@memcpy は写す元と先が重ならないことを前提にした組み込み関数で、重なる範囲を渡すのは illegal behavior です。Debug ビルドでは安全検査がこれを見つけて止めます。重なってもよい @memmove なら、どの要素も上書きされる前に読まれるように写してくれます。写し終えたら、空いた buf[i] に x を入れます。

自分でループを書くなら、後ろから写します。j を i から上へ進めて buf[j + 1] = buf[j] とすると、"abcd_" に i = 1 で挿入したとき、buf[2] に入れた b を次の回でまた buf[3] に写すので、同じ文字が後ろへ広がり、最後に X を入れても aXbbb になってしまいます。i が len のときは2つのスライスの長さが 0 なので何も写さず、buf[len] に x が入るだけです。len が 0 の入力例 3 も同じです。掲載したのは参考実装で、唯一の正解ではありません。var j = len; while (j > i) : (j -= 1) buf[j] = buf[j - 1]; のように後ろから1つずつ写してもかまいません。
