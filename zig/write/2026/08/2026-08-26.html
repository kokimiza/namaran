clamp_i8.zig

const std = @import("std");

fn clampI8(s: []const u8) !i8 {
}

10進数の文字列 s を i8 として読み、その値を返す clampI8 を書いてください。値が i8 の範囲を正の側に超えるときは127を、負の側に超えるときは-128を返します。数として読めない文字列（空文字列を含む）なら、エラー error.InvalidCharacter を返します。std.fmt.parseInt(i8, s, 10) は、値が範囲を超えると error.Overflow を、読めない文字列には error.InvalidCharacter を返します。

入力例 1

clampI8("300")

出力例 1

127

入力例 2

clampI8("-300")

出力例 2

-128

入力例 3

clampI8("12a")

出力例 3

error.InvalidCharacter

const std = @import("std");

fn clampI8(s: []const u8) !i8 {
    const r = std.fmt.parseInt(i8, s, 10);
    return r catch |err| switch (err) {
        error.Overflow => if (s[0] == '-')
            std.math.minInt(i8)
        else
            std.math.maxInt(i8),
        error.InvalidCharacter => return err,
    };
}

parseInt の結果 r は、i8 かエラーのどちらかを持つエラー共用体（error union）です。2種類のエラーで扱いが分かれるので、try も catch 127 のような1つの既定値も使えません。try は error.Overflow まで呼び出し元へ返してしまい、既定値は error.InvalidCharacter まで値に変えてしまいます。catch |err| でエラーを受け取り、switch で種類ごとに振り分けます。掲載したのは参考実装で、唯一の正解ではありません。

catch の右側は、エラーのときに r の代わりになる i8 の値です。error.Overflow の腕では、s が - で始まるかで、負の側か正の側かを決めます。error.Overflow が返るのは数字を読めたときだけなので、s は空ではなく、s[0] は範囲外になりません。std.math.minInt(i8) と std.math.maxInt(i8) はコンパイル時に決まる整数で、そのまま i8 になります。

error.InvalidCharacter の腕は値を作らず、return err で clampI8 そのものからエラーを返します。switch は parseInt が返しうるエラーをすべて扱う必要があり、この腕を書き忘れると「switch must handle all possibilities」でコンパイルが止まります。else => return err とまとめても動きますが、腕を1つずつ書いておけば、parseInt が返すエラーが増えたときにコンパイラが知らせてくれます。入力例 3 の "12a" はこの腕を通り、error.InvalidCharacter が呼び出し元へ返ります。
