digit.zig

fn digit(c: u8) u4 {
}

数字の文字 '0' から '9' を受け取り、その値を返す digit を書いてください。数字でない文字を受け取ったときは、呼び出しがコンパイル時に評価されているならコンパイルエラーに、実行時なら panic にします。どちらのメッセージも、文字が x なら not a digit: 'x' とします。

入力例 1

comptime digit('7')

出力例 1

7

入力例 2

comptime digit('x')

出力例 2

error: not a digit: 'x'

入力例 3

digit("4x"[1])

出力例 3

panic: not a digit: 'x'
Reference 
fn digit(c: u8) u4 {
    if (c < '0' or c > '9') {
        if (@inComptime()) @compileError(std.fmt.comptimePrint("not a digit: '{c}'", .{c}));
        std.debug.panic("not a digit: '{c}'", .{c});
    }
    return @intCast(c - '0');
}

@compileError は、コンパイラがその式を解析した時点でコンパイルを失敗させます。範囲の判定の中にそのまま置くと、実行時に呼ばれる digit を解析するときにも @compileError にたどり着き、c の値と関係なく、プログラム全体がコンパイルできなくなります。if (@inComptime()) の条件はコンパイル時に決まる定数なので、実行時用の本体を解析するときは false で、この枝は解析されません。コンパイル時に評価される呼び出しでだけ枝に入り、そのときは c もコンパイル時にわかっているので、std.fmt.comptimePrint で文字を埋め込んだメッセージを作れます。

std.debug.panic はコンパイル時には呼べないので、@inComptime の枝が無いと、入力例 2 はメッセージの代わりに、標準ライブラリの奥で「コンパイル時に値を決められない」というエラーで止まります。入力例 3 の "4x"[1] は値がコンパイル時にわかる式ですが、comptime を付けない呼び出しは実行時に評価されるので、@inComptime() は false になり、panic で知らせます。範囲内の文字なら、c - '0' は0から9の u8 で、@intCast で戻り値の u4 に収めます。

掲載したのは参考実装で、唯一の正解ではありません。実行時の側は panic ではなく error.InvalidCharacter を返す設計もあり、その場合は戻り値の型を !u4 にします1。

  1. 標準ライブラリの std.testing にも同じ形があり、テストの失敗を報告する関数は、コンパイル時なら @compileError に、実行時なら標準エラーへの出力に切り替えています。
