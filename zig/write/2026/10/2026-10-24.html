stats.zig

const Stats = struct {
    hp: u32,
    mp: u32,
    sp: u32,
};

const Stat = enum { hp, mp, sp };

fn add(s: *Stats, which: Stat, amount: u32) void {
}

Stat の各列挙子は、Stats の同じ名前のフィールドを表します。s が指す Stats のうち、which が表すフィールドに amount を足す add を書いてください。ほかのフィールドは変えず、amount が 0 なら何も変わりません。足した結果は u32 に収まるものとします。

入力例 1

var s: Stats = .{ .hp = 10, .mp = 5, .sp = 0 };
add(&s, .mp, 3);

出力例 1

s == .{ .hp = 10, .mp = 8, .sp = 0 }

入力例 2

var s: Stats = .{ .hp = 10, .mp = 8, .sp = 0 };
add(&s, .hp, 0);

出力例 2

s == .{ .hp = 10, .mp = 8, .sp = 0 }

fn add(s: *Stats, which: Stat, amount: u32) void {
    switch (which) {
        inline else => |f| @field(s, @tagName(f)) += amount,
    }
}

@field(s, name) は s.name と書いたのと同じフィールドを指しますが、name はコンパイル時に分かっている文字列でなければなりません。which は実行時の値なので、@field(s, @tagName(which)) と直接書くとコンパイルエラーになります。inline else は列挙子1つごとに腕(prong)を展開し、展開された腕の中では捕まえた f がコンパイル時に分かっている値になります。腕ごとに @tagName(f) が "hp"、"mp"、"sp" という定数になるので、@field に渡せます。s はポインタですが、s.mp と書けるのと同じく、@field もポインタを通して Stats のフィールドを指します。

掲載したのは参考実装で、唯一の正解ではありません。.hp => s.hp += amount, のように腕を3本書いても同じ動きになります。inline else の形なら、Stats と Stat にフィールドと列挙子を同じ名前で足すだけで、add は書き換えずに済みます。Stats に無い名前の列挙子を Stat に足すと、その腕の @field がコンパイルエラーになるので、対応の取り違えが実行時まで残ることもありません。
