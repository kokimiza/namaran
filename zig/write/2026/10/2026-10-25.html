count_fields.zig

fn countOf(comptime T: type, comptime F: type) comptime_int {
}

構造体の型 T のフィールドのうち、型がちょうど F であるものの数を返す countOf を書いてください。結果は配列の長さにも使えるよう、コンパイル時に決まる値として返します。F 型のフィールドが1つも無ければ、フィールドの無い構造体も含めて 0 を返します。T には構造体だけが渡されるものとします。

入力例 1

const Point = struct { x: f32, y: f32, id: u32 };
countOf(Point, f32)

出力例 1

2

入力例 2

countOf(Point, bool)

出力例 2

0

入力例 3

var coords: [countOf(Point, f32)]f32 = undefined;
coords.len

出力例 3

2
Reference 
fn countOf(comptime T: type, comptime F: type) comptime_int {
    comptime var n = 0;
    inline for (@typeInfo(T).@"struct".field_types) |t| {
        if (t == F) n += 1;
    }
    return n;
}

Zig 0.17 の @typeInfo(T).@"struct" は、フィールドの名前と型を field_names と field_types という別々のスライスで持ちます。型の値はコンパイル時にしか存在しないので、field_types を回すループは inline for にし、要素ごとに本体を展開させます。展開された本体の中では t == F がコンパイル時に決まり、真になる回だけ n += 1 が残ります。

comptime var の n は、この展開を解析する間に増えていく変数で、return n に着いたときには数え終わった値を持っています。返り値の型 comptime_int はコンパイル時にしか扱えない整数型なので、countOf の呼び出しはまるごとコンパイル時に評価され、[countOf(Point, f32)]f32 のように配列の長さに書けます。そのため、この関数の中に限っては comptime を省いて var n = 0; と書いてもコンパイルが通ります。comptime var と書いておくと、n がコンパイル時に数えられる値であることを、返り値の型まで見なくても宣言から読み取れます。

掲載したのは参考実装で、唯一の正解ではありません。inline for の代わりに comptime { ... } のブロックの中で普通の for を回しても、同じ数を求められます。
