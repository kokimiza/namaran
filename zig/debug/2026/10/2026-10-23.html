free_all.zig

const std = @import("std");

const User = struct {
    name: []u8,
    email: []const u8,
    age: u32,
};

fn freeAll(gpa: std.mem.Allocator, value: anytype) void {
    const info = @typeInfo(@TypeOf(value)).@"struct";
    inline for (info.field_names, info.field_types) |name, T| {
        if (T == []u8) gpa.free(@field(value, name));
    }
}

pub fn main(init: std.process.Init) !void {
    const gpa = init.gpa;
    const user: User = .{ .name = try gpa.dupe(u8, "ann"), .email = try gpa.dupe(u8, "ann@example.com"), .age = 30 };
    freeAll(gpa, user);
}

freeAll は構造体の値を受け取り、フィールドのうちアロケータで確保したスライスをすべて解放するつもりの関数で、整数のようなスライスでないフィールドは飛ばします。main は name と email を init.gpa で確保した User を渡します。いまはプログラムの終わりに、標準エラーへ error(SafeAllocator): leaked [addr: ..., len: 15 (0xf) align: 1] という報告が出て、15バイトの領域が解放されずに残ります。本来は何も報告されません。

Answer

Wrong

if (T == []u8) gpa.free(@field(value, name));

15バイトは "ann@example.com" の長さで、残っているのは email です。[]const u8 は []u8 とは別の型で、要素を書き換えられないことも型の一部なので、T == []u8 は email で false になります。inline for はフィールドごとに本体を展開し、展開された本体では T がコンパイル時に決まっているので、この if の条件もコンパイル時に決まります。email と age の分岐は解析されずに捨てられ、コンパイルエラーも出ないまま name だけが解放されます。

value が構造体のコピーであることは原因ではありません。スライスは先頭のポインタと長さの組なので、コピーしたスライスを free に渡しても、main で確保した同じ領域が解放されます。

Right

if (@typeInfo(T) == .pointer) gpa.free(@field(value, name));

特定の型と比べる代わりに、型の種類を @typeInfo で調べます。@typeInfo(T) は型の種類をタグに持つ共用体を返し、.pointer と比べるとタグだけが比べられます。[]u8 も []const u8 もポインタの一種なので両方とも解放され、u32 の age はタグが .int なので飛ばされます。free は const の付いたスライスも受け取ります。*u32 のように1つの値を指すポインタのフィールドが加わった場合は、free の中の comptime assert がコンパイル時に止めるので、型の取り違えがリークのように黙って残ることはありません。
