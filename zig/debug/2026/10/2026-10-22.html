setting.zig

const std = @import("std");

const Setting = union(enum) {
    color: enum { red, green },
    size: enum { small, large },
};

fn key(s: Setting) []const u8 {
    return switch (s) {
        inline else => |tag| @tagName(tag),
    };
}

pub fn main(init: std.process.Init) !void {
    var buf: [256]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try stdout.print("{s}\n", .{key(.{ .size = .large })});
    try stdout.flush();
}

Setting は設定ファイルの1項目で、項目の名前をタグに、値をペイロードに持ちます。key は、設定ファイルに size=large のような行を書くとき、左辺に置く項目の名前を返す関数です。main は .{ .size = .large } の名前を出力します。いまは large と出力されます。本来の出力は size です。

Answer

Wrong

inline else => |tag| @tagName(tag),

タグ付き共用体の switch で、キャプチャの1つ目に入るのはタグではなくペイロードです。ここで tag と名付けた変数には、size の値である .large が入っています。inline else では2つ目のキャプチャにタグを受け取れますが、このコードは1つ目しか書いていません。

それでもコンパイルが通るのは、どの項目の値も列挙型だからです。@tagName は列挙型の値も受け取り、その名前を返します。inline else が展開した size の腕では、tag の型は enum { small, large } で、@tagName(tag) は値の名前の "large" になります。値が u32 のような整数の項目が1つでもあれば、その腕で @tagName がコンパイルエラーになり、取り違えに気付けたはずです1。

Right

inline else => |_, tag| @tagName(tag),

1つ目のキャプチャのペイロードは使わないので _ で捨て、2つ目のキャプチャでタグを受け取ります。展開された size の腕では tag がタグの .size になり、@tagName(tag) は "size" を返します。タグの名前だけが欲しいなら、switch を使わずに return @tagName(s); と書いても同じ結果になります。@tagName はタグ付き共用体の値を受け取ると、いま有効なタグの名前を返すからです。

  1. たとえば Setting に retries: u32 を足すと、@tagName(tag) の行は「expected enum or union; found 'u32'」というエラーでコンパイルできなくなります。
