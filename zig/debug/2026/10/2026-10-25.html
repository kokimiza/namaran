next_id.zig

const std = @import("std");

fn nextId() u32 {
    comptime var id: u32 = 0;
    id += 1;
    return id;
}

pub fn main(init: std.process.Init) !void {
    var buf: [256]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try stdout.print("{d} {d} {d}\n", .{ nextId(), nextId(), nextId() });
    try stdout.flush();
}

nextId は、呼ぶたびに1から始まる連番を1つずつ進めて返し、注文などに重ならないIDを振るつもりの関数です。main は nextId を3回呼んで結果を並べます。いまの出力は 1 1 1 です。本来の出力は 1 2 3 です。

Answer

Wrong

fn nextId() u32 {
    comptime var id: u32 = 0;
    id += 1;
    return id;
}

comptime var の読み書きは、プログラムを実行するときではなく、コンパイラが関数の本体を解析するときに行われます。nextId はコンパイル時の引数を持たないので、本体の解析は1回だけです。その1回で id は 0 から 1 になり、return id は定数の 1 を返す命令としてコンパイルされます。実行時に何度呼んでも、加算の命令はどこにも無く、返るのは毎回 1 です。関数の中の static 変数のように呼び出しをまたいで値が残る、と読むと見落とします。

Right

var last_id: u32 = 0;

fn nextId() u32 {
    last_id += 1;
    return last_id;
}

呼び出しをまたいで値を残すには、実行時に存在する変数が要ります。コンテナレベル(container level。ファイルの最上位など)に置いた var はプログラムの実行中ずっと1つだけあり、last_id += 1 は呼ぶたびに実行されます。3回の呼び出しで 1、2、3 が返ります。関数の中の var にすると、呼ぶたびに 0 から作り直されるので、やはり毎回 1 になります。
