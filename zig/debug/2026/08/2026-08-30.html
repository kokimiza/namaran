pair.zig

const std = @import("std");

fn pair(x: u8) []const u8 {
    const arr = [2]u8{ x, x + 1 };
    return &arr;
}

pub fn main(init: std.process.Init) !void {
    var buf: [256]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    const a = pair(4);
    const b = pair(7);
    try stdout.print("{d} {d} {d} {d}\n", .{ a[0], a[1], b[0], b[1] });
    try stdout.flush();
}

pair(x) は、x と x + 1 の2つを並べた列を返すつもりの関数です。main は pair(4) と pair(7) の結果を続けて表示し、本来は 4 5 7 8 と表示されるはずです。いまは Debug ビルドで 7 8 7 8 が表示され、ReleaseFast でビルドすると、どちらでもない値が表示されました。

Answer

Wrong

fn pair(x: u8) []const u8 {
    const arr = [2]u8{ x, x + 1 };
    return &arr;
}

arr は pair のローカル変数で、その2バイトは pair を呼んでいる間だけ使える場所に置かれます。&arr は配列へのポインタ *const [2]u8 で、戻り値の型 []const u8 へ変換されると、その場所を指す長さ2のスライスになります。スライスが運ぶのは場所と長さだけで、要素の写しは持ちません。pair から戻った時点で arr の寿命は終わり、a はもう使われなくなった場所を指しています。

続く pair(7) は同じ場所を自分の arr に使い、そこへ 7 と 8 を書き込みます。a と b は同じ場所を指しているので、Debug ビルドでは両方から 7 8 が読めます。寿命の終わった場所を読むのは illegal behavior で、安全検査でも見つからないので、ビルドの設定によって読める値が変わります。

Right

fn pair(x: u8) [2]u8 {
    const arr = [2]u8{ x, x + 1 };
    return arr;
}

戻り値の型を配列の [2]u8 にして、arr そのものを返します。Zig の配列は要素を中に持つ値なので、return arr; で2つの要素が呼び出し側の a に写され、pair の中の arr が消えても a の中身は残ります。pair(7) の結果は別の値 b に写されるので、a は 4 5 のままで、4 5 7 8 が表示されます。main は a[0] のように添字で読んでいるだけなので、呼び出し側を直す必要はありません。1

  1. 長さが呼び出すたびに変わる列を返したいときは、配列を値で返せません。呼び出し側が用意したバッファのスライスを引数で受け取って書き込むか、アロケータを受け取って確保した領域を返し、解放を呼び出し側に任せます。
