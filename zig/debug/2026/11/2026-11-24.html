shuffle.zig

const std = @import("std");

fn swap(a: anytype, b: @TypeOf(a)) void {
    a.* ^= b.*;
    b.* ^= a.*;
    a.* ^= b.*;
}

pub fn main(init: std.process.Init) !void {
    var xs = [_]u8{ 1, 2, 3, 4 };
    const js = [_]usize{ 0, 0, 1, 3 };
    for (&xs, js) |*x, j| swap(x, &xs[j]);
    var buf: [64]u8 = undefined;
    const stdout = std.Io.File.stdout();
    var w = stdout.writer(init.io, &buf);
    try w.interface.print("{any}\n", .{xs});
    try w.interface.flush();
}

配列 xs をシャッフルするつもりのコードです。i 番目の要素を、0 以上 i 以下の位置 js[i] の要素と入れ替えることを i = 0, 1, 2, 3 の順に行います。js は乱数の代わりに固定した位置の並びです。swap は、同じ型の値を指す2つのポインタを受け取り、指す先の値を入れ替える汎用の関数です。本来は { 2, 3, 1, 4 } を出力するはずが、いまは { 2, 3, 0, 0 } を出力し、1 と 4 が消えています。

Answer

Wrong

fn swap(a: anytype, b: @TypeOf(a)) void {
    a.* ^= b.*;
    b.* ^= a.*;
    a.* ^= b.*;
}

入れ替えは値を移すだけなので、元の配列に無い 0 が現れることは、正しい入れ替えでは起きません。0 が出てくる演算は、このコードでは ^= だけです。a と b が同じ要素を指していると、1行目の a.* ^= b.* は値を自分自身と XOR することになり、どんな値も 0 になります。残りの2行も 0 どうしの XOR なので、その要素は 0 のまま終わります。js を見ると、i = 0 の js[0] は 0、i = 3 の js[3] は 3 で、この2回は要素を自分自身と入れ替えています。i = 0 で 1 が 0 になり、その 0 が入れ替えで3番目へ移り、i = 3 で 4 が 0 になって、出力は { 2, 3, 0, 0 } です。

自分自身との入れ替えは、シャッフルの側の誤りではありません。i 番目の要素がその場に残る並べ方も起きるべきなので、位置は i を含む 0 以上 i 以下から選ぶ必要があり、j が i に等しい回は必ず出てきます。XOR による入れ替えは2つのポインタが別の場所を指すときだけ正しく、その前提を守れない呼び出し方を、swap の側が受け付けていたことが欠陥です。

Right

fn swap(a: anytype, b: @TypeOf(a)) void {
    const t = a.*;
    a.* = b.*;
    b.* = t;
}

一時変数 t に元の値を写してから入れ替えると、a と b が同じ場所を指していても、a.* = b.* は同じ値の書き直しで、b.* = t も元の値を書き戻すだけになり、値は変わりません。i = 0 と i = 3 の回で何も起きなくなるので、出力は { 2, 3, 1, 4 } です。^= を使わなくなったことで、この swap は整数以外の型、たとえば構造体や浮動小数点数を指すポインタにも使える汎用の関数になります。
