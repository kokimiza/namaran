length.zig

const std = @import("std");

const Len = union(enum) { m: u32, km: u32 };

pub fn main(init: std.process.Init) !void {
    const ls = [_]Len{
        .{ .m = 500 },
        .{ .km = 2 },
    };
    var sum: u32 = 0;
    for (ls) |l| sum += l.m;
    const stdout = std.Io.File.stdout();
    var w = stdout.writer(init.io, &.{});
    try w.interface.print("{d}\n", .{sum});
}

このプログラムは、メートルかキロメートルで記録した長さ ls の合計を、メートルに直して出力するつもりのものです。

いまの出力

（何も出力せずにパニックで止まる）

本来の出力

2500
Answer

Wrong

for (ls) |l| sum += l.m;

union(enum) の値は、どのタグが有効かを覚えていて、読めるのはそのタグのフィールドだけです。2つ目の要素 .{ .km = 2 } では km が有効なのに、ループは l.m を読みます。有効でないフィールドを読むのは illegal behavior で、Debug ビルドの安全検査が access of union field 'm' while field 'km' is active と報告してパニックします。合計を出力する前に止まるので、何も出力されません。

Right 時間計算量 𝒪(n) 空間計算量 𝒪(1) n は ls の要素数 

for (ls) |l| sum += switch (l) {
    .m => |m| m,
    .km => |km| km * 1000,
};

switch (l) は有効なタグで腕を選び、そのタグのフィールドの値を |m| や |km| で受け取ります。.km の腕では 2 を 1000 倍した 2000 が足され、合計は 500 + 2000 = 2500 です。union(enum) の switch は、else を書かない限り、すべてのタグの腕がないとコンパイルが通りません。そのため、あとで cm のようなタグを足したときも、このループを直し忘れることがありません。
