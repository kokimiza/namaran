greet.zig

const std = @import("std");

fn greet(w: *std.Io.Writer, names: []const []const u8) !void {
    for (names) |name| try w.print("hello, {s}\n", .{name});
}

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    const stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    var stdout = stdout_writer.interface;
    try greet(&stdout, &.{ "ann", "bob" });
    try stdout.flush();
}

greet で名前ごとに挨拶を1行ずつ標準出力へ書き、最後に flush するつもりのプログラムです。本来は hello, ann と hello, bob の2行を出力するはずが、いまは何も出力されず、手元の実行では flush の中で Segmentation fault になって止まります。

Answer

Wrong

    const stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    var stdout = stdout_writer.interface;
    try greet(&stdout, &.{ "ann", "bob" });

std.Io.Writer は、ファイルへの書き方を知っている std.Io.File.Writer の中に、interface というフィールドとして埋め込まれています。バッファが足りなくなったときや flush で実際に書き出す処理は、受け取った *std.Io.Writer から @fieldParentPtr でそれを含む File.Writer の位置を逆算し、そこにあるファイルや io を使います。

var stdout = stdout_writer.interface; は、そのフィールドを別の変数へ値としてコピーします。コピーはどの File.Writer の中にもないので、flush が逆算した位置にあるのは、スタック上の関係のないバイトです。それをファイルや io として使った時点で illegal behavior になり、手元では不正なアドレスを読んで落ちました。print はバッファに書くだけで済んでいたので、ここまでは何事もなく進みます。stdout_writer を const にしているのは、var のままだと、一度も書き換えない変数としてコンパイルエラーになるからです。

Right

    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    try greet(stdout, &.{ "ann", "bob" });

&stdout_writer.interface で、File.Writer の中にあるフィールドそのものを指すポインタを取ります。flush の逆算はこのポインタから正しい File.Writer にたどり着き、たまった2行を標準出力へ書き出します。interface を通して書き込むとバッファの位置などが書き換わるので、stdout_writer は var になります。
