fps.zig

fn fps(dt: f64) u32 {
    const rate: u32 = @round(1 / dt);
    if (dt == 0) return 0;
    return rate;
}

1フレームにかかった秒数 dt から、1秒あたりのフレーム数を最も近い整数で返す fps です。まだ時間を測れていない最初のフレームでは dt が 0 で、そのときは 0 を返すつもりです。fps(0.25) は 4 を返しますが、fps(0) は 0 を返すはずが、いまは integer part of floating point value out of bounds というメッセージで panic します。

Answer

Wrong

    const rate: u32 = @round(1 / dt);
    if (dt == 0) return 0;

dt は f64 なので、1 / dt は浮動小数点数の割り算です。浮動小数点数を 0 で割ってもエラーにはならず、1 / 0 は正の無限大になります。ここまでは何も起きませんが、rate の型が u32 なので、@round はその結果を整数に変換します。無限大は u32 のどの値にも収まりません。範囲外の値を整数にすると、langref が illegal behavior と呼ぶものになり、Debug ビルドでは安全検査がそこで panic します。

0 を確かめる if はその次の行にあり、変換が済んでからでは間に合いません。fps(0.25) では 1 / 0.25 が 4.0 で、u32 に収まるので問題が見えません。

Right

    if (dt == 0) return 0;
    const rate: u32 = @round(1 / dt);

dt が 0 かどうかを、割り算と変換より前に確かめます。dt が 0 なら無限大を作る前に 0 を返すので、範囲外の値を整数にすることはなくなります。fps(0.25) は今までどおり 4 を返します。止まるのは割り算ではなく整数への変換なので、確かめる if は変換より前にあることが条件です。
