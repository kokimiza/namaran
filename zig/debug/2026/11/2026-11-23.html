byte_sum.zig

const std = @import("std");

fn byteSum(xs: []const u16) u32 {
    const p: [*]const u8 = @ptrCast(xs.ptr);
    var sum: u32 = 0;
    for (p[0..xs.len]) |b| sum += b;
    return sum;
}

pub fn main(init: std.process.Init) !void {
    const xs = [_]u16{ 0x0102, 0x0304 };
    var buf: [64]u8 = undefined;
    const stdout = std.Io.File.stdout();
    var w = stdout.writer(init.io, &buf);
    const out = &w.interface;
    try out.print("{d}\n", .{byteSum(&xs)});
    try out.flush();
}

byteSum(xs) は、u16 の並び xs が占めるメモリの全バイトを、1バイトずつ符号なしの整数として足した和を返すつもりの関数です。main は 0x0102 と 0x0304 の2つを渡します。本来はバイト 1、2、3、4 をすべて足した 10 を出すはずが、いまは 3 を出します。

Answer

Wrong

    const p: [*]const u8 = @ptrCast(xs.ptr);
    var sum: u32 = 0;
    for (p[0..xs.len]) |b| sum += b;

@ptrCast(xs.ptr) は、xs の先頭を指すポインタを、バイトを指す多要素ポインタ [*]const u8 に変えます。多要素ポインタ(many-item pointer)は長さを持たないので、どこまで読むかは p[0..xs.len] の終わりの値が決めます。ところが xs.len は u16 の個数の 2 で、メモリの大きさは 2 × 2 = 4 バイトです。ループは先頭の2バイトにある 0x0102 だけを読み、そのバイト 1 と 2 を足した 3 を返します。0x0304 の2バイトは一度も足されません。

Right

    const p: [*]const u8 = @ptrCast(xs.ptr);
    var sum: u32 = 0;
    for (p[0 .. xs.len * 2]) |b| sum += b;

スライスの長さは要素の個数なので、要素の型を u8 に変えたら、長さも u16 1個あたり2バイトとしてバイト数に換算し直す必要があります。p[0 .. xs.len * 2] なら4バイトすべてを読み、1 + 2 + 3 + 4 で 10 になります。和は足す順に依らないので、u16 の2バイトがメモリにどちらの順で並んでいても結果は同じです1。

  1. 標準ライブラリの std.mem.sliceAsBytes(xs) は、要素の大きさから長さを換算した []const u8 を返します。.ptr を経由せずにスライスのまま @ptrCast した場合も、長さはバイト数に換算されます。
