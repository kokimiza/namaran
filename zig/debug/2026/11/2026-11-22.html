palindrome.zig

const std = @import("std");
const testing = std.testing;

fn isPalindrome(
    gpa: std.mem.Allocator,
    s: []const u8,
) !bool {
    const rev = try gpa.dupe(u8, s);
    std.mem.reverse(u8, rev);
    return std.mem.eql(u8, rev, s);
}

test "isPalindrome" {
    const gpa = testing.allocator;
    const r = try isPalindrome(gpa, "noon");
    try testing.expect(r);
}

s を前から読んでも後ろから読んでも同じかを返すつもりの isPalindrome と、そのテストです。zig test palindrome.zig は All 1 tests passed. だけを出して成功するはずが、いまは同じ行のあとに 1 tests leaked memory. を出し、終了コード 1 で失敗します。

Answer

Wrong

    const rev = try gpa.dupe(u8, s);
    std.mem.reverse(u8, rev);
    return std.mem.eql(u8, rev, s);

gpa.dupe は、s と同じ長さのメモリを gpa から確保して中身を写し、そのスライスを返します。rev は裏返して比べるための作業用で、関数を抜けたらもう使いませんが、gpa.free を呼ぶ行がありません。"noon" の4バイトは、確保されたまま誰も指さなくなります。

判定の結果は正しいので、expect は通ります。テストに渡した std.testing.allocator は、テストが終わった時点で解放されていない確保を数え、残っていればリークとして報告し、テストを失敗にします。表示が成功と失敗の両方に見えるのはこのためです。

Right

    const rev = try gpa.dupe(u8, s);
    defer gpa.free(rev);
    std.mem.reverse(u8, rev);
    return std.mem.eql(u8, rev, s);

確保した直後に defer gpa.free(rev); を置きます。defer の式は、関数がどの return から抜けるときにも、戻り値を計算したあとで実行されます。std.mem.eql が rev を読み終えてから解放されるので、比べている最中にメモリがなくなることもありません。テストの終わりに残る確保がなくなり、std.testing.allocator はリークを報告しなくなります。
