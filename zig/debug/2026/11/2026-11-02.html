greet.zig

const std = @import("std");

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    const stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    var stdout = stdout_writer.interface;
    for ([_][]const u8{ "ann", "bob" }) |name| {
        try stdout.print("hello, {s}\n", .{name});
    }
    try stdout.flush();
}

名前ごとに挨拶の行を標準出力へ書くつもりのプログラムです。本来は hello, ann と hello, bob の2行を表示するはずが、いまは Debug ビルドで実行すると何も表示せず、最後の flush の中で異常終了します。

Answer

Wrong

const stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
var stdout = stdout_writer.interface;

stdout_writer は std.Io.File.Writer で、汎用の std.Io.Writer をフィールド interface として中に持っています。var stdout = stdout_writer.interface; はそのフィールドを別の変数へコピーします。コピーも同じ buf をバッファとして指していて、print はそこに書くだけなので、ここまでは動きます。

flush がファイルへ書くときに呼ぶ File.Writer の関数は、渡された interface のアドレスから、それを埋め込んでいる File.Writer のアドレスを @fieldParentPtr で逆算します。コピーした stdout は File.Writer の中にないので、逆算した先にあるのは File.Writer ではない無関係なメモリです。そこをファイルの情報として読むので、何も書けないまま落ちます。langref はこれを検査されない illegal behavior（unchecked illegal behavior）としていて、どう落ちるかは決まっていません。

Right

var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
const stdout = &stdout_writer.interface;

&stdout_writer.interface で、File.Writer の中にある interface そのものを指すポインタを取ります。@fieldParentPtr の逆算は本物の stdout_writer に戻るので、flush は2行を書き出します。ポインタを通して stdout_writer を書き換えるので、stdout_writer は var に戻します。1

  1. Zig では書き換えない var がコンパイルエラーになるので、問題のコードでは stdout_writer を const にしないとコンパイルが通りません。const に変えたくなったら、そこから値をコピーしていないかを疑う手がかりになります。
