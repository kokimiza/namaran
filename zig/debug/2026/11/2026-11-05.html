total.zig

const std = @import("std");

fn sum(xs: anytype) @TypeOf(xs[0]) {
    var total: @TypeOf(xs[0]) = 0;
    for (xs) |x| total += x;
    return total;
}

pub fn main(init: std.process.Init) !void {
    var buf: [64]u8 = undefined;
    var stdout_writer = std.Io.File.stdout().writer(init.io, &buf);
    const stdout = &stdout_writer.interface;
    const data = [_]u8{ 200, 100 };
    try stdout.print("{d}\n", .{sum(data)});
    try stdout.flush();
}

整数の配列やスライスを受け取り、要素の和を返す汎用の sum です。[_]u8{ 200, 100 } を渡すと、いまは何も表示されずに panic: integer overflow で止まります。本来は 300 と表示されるはずです。

Answer

Wrong

fn sum(xs: anytype) @TypeOf(xs[0]) {
    var total: @TypeOf(xs[0]) = 0;
    for (xs) |x| total += x;
    return total;
}

anytype の引数は、渡された値の型をそのまま受け取ります。data は [2]u8 なので xs[0] は u8 で、戻り値の型も和を入れる total の型も、@TypeOf(xs[0]) と書いたとおり u8 に決まります。u8 に入るのは 255 までで、1回目の足し算で total が 200 になったあと、2回目の 200 + 100 は 300 になって収まりません。

Zig の整数の + は、C の符号なし整数のように 256 で割った余りへ折り返しません。結果が型に収まらないことは illegal behavior で、安全検査のある Debug ビルドでは、その場で integer overflow の panic になります。そのため print まで進まず、何も表示されません。

Right

fn sum(comptime T: type, xs: anytype) T {
    var total: T = 0;
    for (xs) |x| total += x;
    return total;
}

    try stdout.print("{d}\n", .{sum(u32, data)});

和の型を comptime T: type で受け取り、total と戻り値をその型にします。u8 の要素 x は、より広い u32 の total へ足すときに暗黙に u32 へ変換されるので、2回目の足し算は u32 で行われて 300 が収まります。要素の側は anytype のままなので、配列でもスライスでも、for で回せるものなら渡せます。

total の型を u64 のような1つの型に固定しても、この呼び出しは直ります。ただし [_]i32{ -5, 3 } のような符号付きの配列では、i32 の要素を u64 に暗黙には変換できず、コンパイルが通らなくなります。どの型で足せばあふれないかは、要素の型からは決まらず、値の範囲を知っている呼び出し側にしか分かりません。そこで和の型だけは、呼び出し側が引数で指定します。
