field_end.zig

const std = @import("std");

fn fieldEnd(s: []const u8) ?usize {
    var i: usize = 0;
    while (i < s.len) : (i += 1) {
        if (s[i] == '\\') {
            i += 2;
            continue;
        }
        if (s[i] == ',') return i;
    }
    return null;
}

pub fn main() void {
    const end = fieldEnd("x\\\\,y");
    std.debug.print("{?d}\n", .{end});
}

文字列 s の中で、エスケープされていない最初のカンマの位置を返す fieldEnd です。バックスラッシュは直後の1文字をエスケープし、そのようなカンマが無ければ null を返します。"x\\\\,y" は x、\、\、,、y の5文字で、1つ目の \ が2つ目の \ をエスケープするので、標準エラー出力に 3 と出るはずが、いまは null と出ます。

Answer

Wrong

while (i < s.len) : (i += 1) {
    if (s[i] == '\\') {
        i += 2;
        continue;
    }

while の : (i += 1) は継続式（continue expression）で、本体の終わりに届いたときだけでなく、continue で次の繰り返しへ進むときにも、条件を調べる前に実行されます。エスケープを見つけた枝は i += 2 で2つ進み、continue の継続式でさらに1つ進むので、バックスラッシュから数えて3文字先へ飛びます。飛ばしたいのは、バックスラッシュとエスケープされる1文字の2文字だけです。

"x\\\\,y" では、i = 1 のバックスラッシュで i が 3 になり、継続式で 4 になります。位置 3 のカンマは調べられずに飛ばされ、位置 4 の y を調べたあと i は 5 になって条件 i < s.len が偽になり、ループが終わって null が返ります。範囲外の添字を使う前に条件で止まるので、panic もしません。"a\\,b,c" のように、エスケープの直後のカンマを飛ばしてもまだ後ろにカンマがある入力では正しい値が返るので、この欠陥はエスケープの直後に区切りが来たときにしか表に出ません。

Right

while (i < s.len) : (i += 1) {
    if (s[i] == '\\') {
        i += 1;
        continue;
    }

枝の中ではエスケープされる1文字の分だけ進め、バックスラッシュの分は継続式に任せます。合わせて2文字進むので、"x\\\\,y" では i が 1 から 3 へ進み、位置 3 のカンマで 3 が返ります。文字列の最後がバックスラッシュのときは i が長さを1つ超えますが、条件 i < s.len が偽になってループを抜けるので、範囲外を読むことはありません。
