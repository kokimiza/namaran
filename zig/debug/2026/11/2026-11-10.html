greeting.zig

const std = @import("std");

fn greeting(gpa: std.mem.Allocator, name: []const u8) ![]u8 {
    var arena: std.heap.ArenaAllocator = .init(gpa);
    defer arena.deinit();
    const upper = try std.ascii.allocUpperString(arena.allocator(), name);
    return arena.allocator().print("HELLO, {s}!", .{upper});
}

pub fn main(init: std.process.Init) !void {
    var out: [64]u8 = undefined;
    var w = std.Io.File.stdout().writer(init.io, &out);
    const msg = try greeting(init.gpa, "zig");
    defer init.gpa.free(msg);
    try w.interface.print("{s}\n", .{msg});
    try w.interface.flush();
}

greeting は、名前を大文字にした挨拶の文字列を作り、gpa で確保した領域として返すつもりの関数です。途中の大文字の名前は関数の中でしか使わないので、作業用のアリーナに置いて関数の終わりでまとめて捨てます。このプログラムは本来 HELLO, ZIG! を出力するはずが、いまは手元の実行で U が11個並んだ行を出したあと、free of invalid memory という panic で止まります。

Answer

Wrong

    var arena: std.heap.ArenaAllocator = .init(gpa);
    defer arena.deinit();
    const upper = try std.ascii.allocUpperString(arena.allocator(), name);
    return arena.allocator().print("HELLO, {s}!", .{upper});

返す文字列までアリーナから確保しています。ArenaAllocator は、確保した領域を個別には解放せず、deinit でまとめて gpa に返します。defer arena.deinit() は return の式を評価して文字列を作ったあと、関数を抜ける直前に実行されるので、msg が main に届いた時点で、その中身はもう解放されています。print が読むのは解放済みの領域で、Debug ビルドでは解放済みの領域がゴミで埋められるため、11文字分の意味のない文字が出ます。

続く defer init.gpa.free(msg) も壊れています。msg は gpa から直接確保した領域ではなく、アリーナが gpa から借りた大きな領域の一部でした。その領域はもう返却済みで、gpa は自分が渡した覚えのない領域の解放を求められ、panic で止めます。

Right

    var arena: std.heap.ArenaAllocator = .init(gpa);
    defer arena.deinit();
    const upper = try std.ascii.allocUpperString(arena.allocator(), name);
    return gpa.print("HELLO, {s}!", .{upper});

呼び出し側へ返す文字列は、呼び出し側から受け取った gpa で確保します。gpa.print が文字列を作るときに upper の中身は写されるので、そのあとでアリーナが upper を捨てても結果は残ります。関数の中でだけ使う領域はアリーナ、関数の外へ出す領域は gpa と分けると、deinit が捨てるものと呼び出し側が gpa.free で解放するものが重なりません。
