team.zig

const std = @import("std");

const Player = struct {
    score: u32 = 0,
    fn addPoint(self: *Player) void {
        self.score += 1;
    }
};

pub fn main(init: std.process.Init) !void {
    const team = [_]Player{ .{}, .{} };
    var p = team[1];
    p.addPoint();
    const stdout = std.Io.File.stdout();
    var w = stdout.writer(init.io, &.{});
    const out = &w.interface;
    try out.print("{any}\n", .{team});
}

チームの2人目の選手に1点を足してから、チーム全員の得点を表示するつもりのコードです。本来は { .{ .score = 0 }, .{ .score = 1 } } を出力するはずが、いまは { .{ .score = 0 }, .{ .score = 0 } } を出力し、点が増えていません。

Answer

Wrong

const team = [_]Player{ .{}, .{} };
var p = team[1];
p.addPoint();

Zig の配列は要素の値そのものを並べて持つので、var p = team[1]; は2人目の Player を新しい変数 p にコピーします。addPoint は self を *Player で受け取るので、p.addPoint() は p のアドレスを自動で取り、Player.addPoint(&p) として呼ばれます。1 が足されるのはコピーの p の score で、team の中は 0 のまま表示されます。

const と var の付け方も、この欠陥と結び付いています。var p を const p にすると、取れるアドレスは *const Player なので addPoint に渡せず、コンパイルエラーになります。逆に const team を var team にすると、team にはどこからも書き込まないので、「local variable is never mutated」というコンパイルエラーになります。コンパイラは team が変わらないことを知っていて、その指摘に従って const にした結果、書き換えの行き先がコピーだけになりました。

Right

var team = [_]Player{ .{}, .{} };
const p = &team[1];
p.addPoint();

&team[1] は配列の中の2人目を指す *Player です。メソッドを呼ぶ値がすでに *Player なら、p.addPoint() はそのポインタをそのまま self に渡すので、1 は team の中の score に足されます。team はこのポインタを通して書き換えられるので var にする必要があり、今度は「never mutated」とも言われません。p 自身は別の要素を指し直さないので const です。team[1].addPoint(); と直接書いても同じく配列の中の要素が変わります。
