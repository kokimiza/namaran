in_list.rs

fn in_list(column: &str, n: usize) -> String {
}

列名 column と値の個数 n を受け取り、? を n 個 , で区切って並べた IN の条件を返す in_list を書いてください。n が 0 のときは、標準 SQL の構文にない IN () を作らず、どの行にも当てはまらない条件 1 = 0 を返します。

入力例 1

in_list("id", 3)

出力例 1

"id IN (?, ?, ?)"

入力例 2

in_list("tag", 1)

出力例 2

"tag IN (?)"

入力例 3

in_list("id", 0)

出力例 3

"1 = 0"
Reference 
fn in_list(column: &str, n: usize) -> String {
    if n == 0 {
        return "1 = 0".to_string();
    }
    format!("{column} IN ({})", vec!["?"; n].join(", "))
}

vec!["?"; n] で "?" を n 個並べ、join(", ") でつなぎます。join は要素と要素の間にだけ区切りを置くので、末尾に余った , を後から削る処理は要りません。

この関数が受け取るのは値の個数だけで、値そのものは受け取りません。値は呼び出し側が SQL とは別にデータベースのライブラリへ渡し、ライブラリが ? と順に対応づけます。値に ' や ) が入っていても SQL の文字列には現れないので、文の形は変わりません。

n が 0 のときを先に分けるのは、IN () がそのまま SQL に入ると構文エラーになるからです。1 = 0 は常に偽になる比較なので、WHERE や AND の後ろに置けば、該当する行がない条件として働きます。真偽値のリテラル false を持たないデータベースでも、そのまま使えます。

掲載したのは参考実装で、唯一の正解ではありません。(0..n).map(|_| "?").collect::<Vec<_>>().join(", ") と書いても同じ文字列になります。
