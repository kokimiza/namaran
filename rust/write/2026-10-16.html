last_n.rs

fn last_n(v: &[i32], n: usize) -> &[i32] {
}

スライス v の末尾 n 要素を、v の一部を指すスライスとして返す last_n を書いてください。要素はコピーしません。n が v の長さ以上なら v 全体を返し、n が 0 なら空のスライスを返します。

入力例 1

last_n(&[1, 2, 3, 4, 5], 2)

出力例 1

[4, 5]

入力例 2

last_n(&[1, 2], 5)

出力例 2

[1, 2]

入力例 3

last_n(&[], 0)

出力例 3

[]
Reference 
fn last_n(v: &[i32], n: usize) -> &[i32] {
    &v[v.len().saturating_sub(n)..]
}

スライスは自分の長さを持っているので、v.len() から n を引けば、返す部分が始まる添字 start が分かります。&v[start..] は v と同じ要素を指す新しいスライスで、アドレスは start だけ進み、長さは start だけ短くなります。C で同じ関数を書くなら、ポインタと要素数を受け取り、返す側の要素数も別に返すことになりますが、スライスは両方を1つの値で運びます。

n が長さを超えるときに v.len() - n と書くと、usize は負の値を表せないので、デバッグビルドではオーバーフローで panic します。saturating_sub は結果が 0 を下回るときに 0 で止まるので、入力例 2 では &v[0..] となって v 全体を返します。返り値の寿命は、引数の参照が1つなので省略規則によって v と同じになり、注釈を書く必要はありません。

掲載したのは参考実装で、唯一の正解ではありません。&v[v.len() - n.min(v.len())..] と書いても同じで、n.min(v.len()) が先に n を長さ以下に抑えます。
