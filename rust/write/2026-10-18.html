use std::marker::PhantomData;

pub struct Draft;
pub struct Published;

pub struct Post<S> {
    body: String,
    state: PhantomData<S>,
}

impl Post<Draft> {
    pub fn new(body: &str) -> Self {
    }

    pub fn publish(self) -> Post<Published> {
    }
}

impl Post<Published> {
    pub fn body(&self) -> &str {
    }
}

下書きの投稿 Post<Draft> と公開済みの投稿 Post<Published> を型で区別するために、3つのメソッドの本体を書いてください。new は本文が body の下書きを作り、publish は下書きを受け取って同じ本文の公開済みの投稿を返し、body は公開済みの投稿の本文を返します。body は公開済みの投稿にしか無いので、Post::new("hi").body() はコンパイルエラーになります。本文は空文字列でもかまいません。

入力例 1

Post::new("hello").publish().body()

出力例 1

"hello"

入力例 2

Post::new("").publish().body()

出力例 2

""

impl Post<Draft> {
    pub fn new(body: &str) -> Self {
        Post { body: body.to_string(), state: PhantomData }
    }

    pub fn publish(self) -> Post<Published> {
        Post { body: self.body, state: PhantomData }
    }
}

impl Post<Published> {
    pub fn body(&self) -> &str {
        &self.body
    }
}

Draft と Published はフィールドを持たない構造体で、値が1つしかないので大きさは 0 です。この2つは値として使うためではなく、Post<S> の S に入れて状態を表す目印として使います。ただ、型引数 S をどのフィールドにも使わないとコンパイルエラーになるので、PhantomData<S> を置いて S を持っているものとして扱わせます。PhantomData<S> も大きさ0の型なので、状態を型に持たせても、実行時に状態を表すための値は増えません。

publish は self を値で受け取るので、呼んだあとの下書きは使えなくなります。返す Post<Published> は Post<Draft> とは別の型なので、Post { body: self.body, state: PhantomData } と作り直します。Post { state: PhantomData, ..self } と書きたくなりますが、構造体更新構文の ..self は作る値と同じ型の値しか受け付けず、型が合わないというエラーになります。

body は impl Post<Published> の中にしか無いので、Post<Draft> の値に対して呼ぶと、そのメソッドが見つからないというコンパイルエラーになります。公開前の本文を読む誤りは、実行する前に止まります。

掲載したのは参考実装で、唯一の正解ではありません。PhantomData<S> の代わりに state: S を持たせ、state: Published のように目印の値そのものを入れても同じように書けます。
