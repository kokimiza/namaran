repeat.rs

use std::hint::black_box;

fn repeat(n: u32, f: impl Fn(u32) -> u64) -> u64 {
}

ベンチマークで関数 f を n 回呼ぶための repeat を書いてください。f(0)、f(1)、…、f(n - 1) を順に呼び、戻り値をすべて足した和を返します。和が u64 に収まらないときは、2の64乗で割った余りにします。n が 0 なら 0 を返します。コンパイラが呼び出しを省いたり、結果を前もって計算したりしないように、f に渡す引数と f の戻り値は、どちらも black_box に通します。

入力例 1

repeat(3, |i| u64::from(i) * 10)

出力例 1

30

入力例 2

repeat(0, u64::from)

出力例 2

0

入力例 3

repeat(2, |_| u64::MAX)

出力例 3

18446744073709551614
Reference 
fn repeat(n: u32, f: impl Fn(u32) -> u64) -> u64 {
    (0..n).fold(0, |acc, i| acc.wrapping_add(black_box(f(black_box(i)))))
}

black_box は受け取った値をそのまま返す関数ですが、コンパイラには、渡した値がその中でどう使われるか分からないものとして扱わせます1。戻り値を通しておけば、repeat の呼び出し元が和を捨てても f の結果は使われたものとして残り、使われない計算を呼び出しごと消す不要コード除去（dead code elimination）が働きません。引数も通すのは、f の中身と n がコンパイル時に分かると、ループ全体が前もって計算した定数に置き換えられることがあるからです。

和は fold で積み上げ、足し算には wrapping_add を使います。+ で足すと、デバッグビルドでは u64 の範囲を超えたところで panic します。入力例 3 は u64::MAX を2回足すので、和を2の64乗で割った余りの 18446744073709551614 になります。

掲載したのは参考実装で、唯一の正解ではありません。for 文で可変の変数に足していく書き方でも同じ結果になります。

  1. black_box は最善の努力（best effort）で働くもので、どんな最適化も止めるとは保証されていません。標準ライブラリの文書も、暗号やセキュリティのように正しさがかかわる用途には頼らないよう書いています。
