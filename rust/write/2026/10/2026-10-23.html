over_budget.rs

fn over_budget(lines: &[&str], budget: i64) -> Option<usize> {
}

lines は家計簿の行で、1行に支出の金額が1つ書いてあります。上の行から金額を足していき、合計が budget を初めて超えた行の番号(先頭の行を1とする)を Some で返す over_budget を書いてください。空の行と # で始まる行は金額として読まずに飛ばしますが、行の番号には数えます。"__END__" の行があればそこで読むのをやめ、それより後ろの行は見ません。最後まで(または "__END__" まで)読んでも予算を超えなかったとき、数として読めない行に出会ったときは None を返します。

入力例 1

over_budget(&["# lunch", "800", "", "1200", "300"], 1500)

出力例 1

Some(4)

入力例 2

over_budget(&["800", "__END__", "1200"], 1500)

出力例 2

None

入力例 3

over_budget(&["800", "1,200", "300"], 1500)

出力例 3

None

fn over_budget(lines: &[&str], budget: i64) -> Option<usize> {
    let mut total = 0;
    for (i, line) in lines.iter().enumerate() {
        if *line == "__END__" {
            break;
        }
        if line.is_empty() || line.starts_with('#') {
            continue;
        }
        total += line.parse::<i64>().ok()?;
        if total > budget {
            return Some(i + 1);
        }
    }
    None
}

このループには、行の途中で処理を切り上げる書き方が4つあり、行き先がそれぞれ違います。continue はその行の残りを飛ばして次の行へ、break はループを抜けて後ろの None へ進みます。return Some(i + 1) と、読めない行での ? は、ループだけでなく関数そのものから抜けます。? は Option が None ならその場で None を返すので、"1,200" の行では足し算に進まずに None が返ります。"__END__" での break と行き先が同じ None になるので、break を return None と書いても結果は変わりません。

行の番号を飛ばした行も含めて数えるには、enumerate を飛ばす判定より前に置きます。continue で飛ばしても enumerate はすでにその行の番号を払い出しているので、入力例 1 の "1200" は4行目のままです。イテレータで .filter(...) してから .enumerate() すると、コメントと空行が数から抜けて Some(2) を返してしまいます。

掲載したのは参考実装で、唯一の正解ではありません。take_while で "__END__" の手前まで切り、enumerate、filter、scan と組み合わせても書けますが、読めない行で止める処理まで入れると、for と break・continue で書いたほうが行き先を追いやすくなります。
