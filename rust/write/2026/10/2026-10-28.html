urgent_job.rs

#[derive(Clone, Debug, PartialEq)]
struct Job {
    name: String,
    priority: u8,
    retries: u8,
}

fn urgent(job: &Job) -> Job {
}

借用で受け取った job と同じ内容で、priority だけを9にした新しい Job を返す urgent を書いてください。job は呼び出し側にそのまま残ります。priority がもとから9なら、job と同じ内容の Job を返します。出力例は {:?} で表示した返り値です。

入力例 1

urgent(&Job { name: "backup".into(), priority: 1, retries: 3 })

出力例 1

Job { name: "backup", priority: 9, retries: 3 }

入力例 2

urgent(&Job { name: "sync".into(), priority: 9, retries: 0 })

出力例 2

Job { name: "sync", priority: 9, retries: 0 }

入力例 3

urgent(&Job { name: String::new(), priority: 0, retries: 0 })

出力例 3

Job { name: "", priority: 9, retries: 0 }
Reference 
fn urgent(job: &Job) -> Job {
    Job { priority: 9, ..job.clone() }
}

構造体更新記法の .. の後ろには、Default::default() に限らず、同じ構造体型の値になる式を何でも書けます。priority だけを指定し、残りの name と retries を job から持ってくれば、1つのフィールドだけを変えた値になります。

ただし ..*job と書くと、コンパイルエラーになります。.. の後ろの値から残りのフィールドを取り出すのはムーブで、name の String は Copy ではないため、借用している *job の中から持ち出せないからです。そこで job.clone() で所有権を持つ複製を作り、それを土台にします。複製の priority は使われずに捨てられ、呼び出し側の job は変わりません。

掲載したのは参考実装で、唯一の正解ではありません。let mut copy = job.clone(); で複製してから copy.priority = 9; と書き換えて返しても、同じ値になります。残りのフィールドがすべて Copy の型なら、..*job もそのまま通ります。
