take_frame.rs

fn take_frame(buf: &mut Vec<u8>) -> Option<Vec<u8>> {
}

TCPで受け取ったバイトは buf に溜めてあります。メッセージは、本体の長さを2バイトのビッグエンディアン(上位のバイトが先)で書いた見出しと、それに続く本体からできています。buf の先頭に見出しと本体がそろっていれば、その1つ分を buf から取り除き、本体を Some で返す take_frame を書いてください。そろっていなければ buf を変えずに None を返します。長さが 0 のメッセージもあり、そのときは空の本体を返します。

入力例 1

take_frame(&mut vec![0, 2, 104, 105, 9])

出力例 1

Some([104, 105])

入力例 2

take_frame(&mut vec![0, 3, 97, 98])

出力例 2

None

入力例 3

take_frame(&mut vec![0])

出力例 3

None
Reference 
fn take_frame(buf: &mut Vec<u8>) -> Option<Vec<u8>> {
    let [hi, lo, ..] = buf[..] else {
        return None;
    };
    let end = 2 + u16::from_be_bytes([hi, lo]) as usize;
    if buf.len() < end {
        return None;
    }
    Some(buf.drain(..end).skip(2).collect())
}

let [hi, lo, ..] = buf[..] else は、buf が2バイト以上あるときだけ先頭の2バイトを取り出し、足りなければ None を返します。この時点では buf から何も取り除いていません。見出しが読めたら、u16::from_be_bytes で長さにし、見出しを含めたメッセージの終わり end を求めます。

取り除くのは、buf の長さが end に届いているのを確かめてからです。見出しを先に読み捨ててしまうと、入力例2のように本体が届ききっていないとき、次に呼ばれた時点で buf の先頭は本体の途中になり、そこを見出しとして読んでしまいます。そろっていれば drain(..end) で見出しと本体を一度に取り除き、skip(2) で見出しを飛ばして本体だけを集めます。drain は返した反復子を最後まで読まなくても、範囲全体を buf から取り除きます。

掲載したのは参考実装で、唯一の正解ではありません。buf[2..end].to_vec() で本体を写してから buf.drain(..end); で取り除く書き方もあります。
