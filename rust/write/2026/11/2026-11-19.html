records.rs

fn records(log: &[u8]) -> Vec<&[u8]> {
}

ログ log は記録を順に並べたバイト列で、1つの記録は長さ n を表す1バイトと、それに続く n バイトの中身からなります。記録の中身を先頭から順に並べて返す records を書いてください。ログは追記の途中で障害が起きたものかもしれず、最後の記録は中身が n バイトに足りないことがあります。そのときは、それより前の完全な記録だけを返します。log が空なら空の Vec を返します。

入力例 1

records(&[2, 7, 7, 1, 9])

出力例 1

[[7, 7], [9]]

入力例 2

records(&[1, 5, 3, 8])

出力例 2

[[5]]

入力例 3

records(&[])

出力例 3

[]

fn records(log: &[u8]) -> Vec<&[u8]> {
    let mut out = Vec::new();
    let mut rest = log;
    while let Some((&n, tail)) =
        rest.split_first()
    {
        let Some((rec, next)) = tail
            .split_at_checked(n as usize)
        else {
            break;
        };
        out.push(rec);
        rest = next;
    }
    out
}

参考実装は、まだ読んでいない部分 rest の先頭から長さの1バイトを split_first で取り出し、残り tail を split_at_checked で中身とその後ろに分けます。split_at_checked は、tail が n バイトに足りなければ panic せずに None を返すので、let ... else でそこを途中で切れた記録とみなし、ループを抜けます。tail.split_at(n as usize) や &tail[..n as usize] と書くと、障害のあとに残った正常な記録を読み出す前に、復元そのものが panic で止まります。掲載したのは参考実装で、唯一の正解ではありません。

入力例 1 では、長さ 2 の記録 [7, 7] と長さ 1 の記録 [9] を取り出したところで rest が空になり、split_first が None を返してループが終わります。入力例 2 では2つ目の記録が長さ 3 を名乗っているのに、残りは [8] の1バイトしかないので、[[5]] を返します。空のログでは最初の split_first が None です。取り出した中身は log を指すスライスのままで、コピーはしません。戻り値の Vec<&[u8]> の寿命は、ライフタイム省略の規則で引数 log と結び付いています。
