first_true.rs

fn first_true(
    f: impl Fn(u32) -> bool,
) -> Option<u32> {
}

f は、ある値より小さい u32 にはすべて false を、それ以上の u32 にはすべて true を返す関数です。u32 のすべての値（0 から u32::MAX まで）のうち、f が true を返す最小の値を Some で返す first_true を二分探索で書いてください。どの値でも false なら None を返します。出力例は {:?} で表示したものです。

入力例 1

first_true(|x| x >= 10)

出力例 1

Some(10)

入力例 2

first_true(|x| x == u32::MAX)

出力例 2

Some(4294967295)

入力例 3

first_true(|_| false)

出力例 3

None

fn first_true(
    f: impl Fn(u32) -> bool,
) -> Option<u32> {
    let mut lo: u64 = 0;
    let mut hi: u64 = 1 << 32;
    while lo < hi {
        let mid = (lo + hi) / 2;
        if f(mid as u32) {
            hi = mid;
        } else {
            lo = mid + 1;
        }
    }
    u32::try_from(lo).ok()
}

探す区間を lo 以上 hi 未満で持つと、lo と hi が等しくなったところが答えの位置です。この位置は 0 から u32::MAX までの 232 通りに、「どの値も false」を表す 232 を加えた 232 + 1 通りあり、u32 には収まりません。そこで lo と hi を u64 にし、hi を 232 から始めます。ループを抜けた lo が 232 なら u32::try_from が失敗して None になり、それ以外は Some に入ります。mid は hi より小さいので、mid as u32 で値が変わることはありません。

u32 のまま書こうとすると、規則どうしがぶつかります。hi を u32::MAX から始めると、u32::MAX だけが調べられずに、入力例2が None になります。区間を lo 以上 hi 以下の閉区間にして hi = mid - 1 と縮めると、mid が 0 のときに u32 の引き算がオーバーフローします。中点を (lo + hi) / 2 で求めると、lo と hi が大きいときに足し算がオーバーフローします。u64 にすれば、lo + hi も 233 未満に収まります。

掲載したのは参考実装で、唯一の正解ではありません。u32 のまま、先に f(u32::MAX) を調べて false なら None を返し、そのあとは答えが必ずある閉区間で探す書き方もあります。入力例3では、lo が mid + 1 で進み続けて 232 で止まり、None が返ります。
