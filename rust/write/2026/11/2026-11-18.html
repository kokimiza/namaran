seq_len.rs

fn seq_len(lead: u8) -> Option<usize> {
}

UTF-8 では、1文字を表すバイト列の長さが先頭バイトの上位ビットで決まります。先頭バイトが 0xxxxxxx なら1バイト、110xxxxx なら2バイト、1110xxxx なら3バイト、11110xxx なら4バイトです。10xxxxxx は2バイト目以降に置く続きのバイトで、先頭には来ません。先頭バイト lead から、その文字のバイト数を返す seq_len を書いてください。lead が続きのバイトのときと、11111xxx のようにどの形にも当たらないときは None を返します。

入力例 1

seq_len(b'A')

出力例 1

Some(1)

入力例 2

seq_len(0xE3)

出力例 2

Some(3)

入力例 3

seq_len(0x81)

出力例 3

None

fn seq_len(lead: u8) -> Option<usize> {
    match lead.leading_ones() {
        0 => Some(1),
        n @ 2..=4 => Some(n as usize),
        _ => None,
    }
}

4つの形を並べると、上位に続く1の個数がそのままバイト数になっていることが分かります。110xxxxx は1が2個で2バイト、11110xxx は1が4個で4バイトです。参考実装は、上位から続く1の個数を返す u8::leading_ones でこの個数を数え、match で振り分けます。掲載したのは参考実装で、唯一の正解ではありません。0x00..=0x7F のようなバイトの範囲を腕に並べても書けます。

この規則には例外が2つあります。1が0個の 0xxxxxxx は ASCII の1バイト文字なので、0 を Some(1) に読み替えます。1がちょうど1個の 10xxxxxx は続きのバイトなので、個数をそのまま返して Some(1) にしてはいけません。n @ 2..=4 は2から4の個数だけを受け、残りの1個と5個以上は最後の腕で None になります。入力例 2 の 0xE3 は 11100011 で1が3個なので Some(3)、入力例 3 の 0x81 は 10000001 で1が1個なので None です。leading_ones は u32 を返すので、Some に入れる前に usize に変換します。
