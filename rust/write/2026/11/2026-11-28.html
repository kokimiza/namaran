index_of.rs

fn index_of(
    items: &[i32],
    target: &i32,
) -> Option<usize> {
}

target が items の要素のどれかを指しているとき、その要素の位置を返す index_of を書いてください。items の中に同じ値の要素がいくつあっても、返すのは target が指しているその要素の位置です。target が items のどの要素も指していなければ、値の等しい要素があっても None を返します。

入力例 1

let v = [7, 3, 7]; index_of(&v, &v[2])

出力例 1

Some(2)

入力例 2

let v = [7, 3, 7]; index_of(&v, &7)

出力例 2

None

入力例 3

index_of(&[], &1)

出力例 3

None

fn index_of(
    items: &[i32],
    target: &i32,
) -> Option<usize> {
    items.iter().position(|x| {
        std::ptr::eq(x, target)
    })
}

参照どうしを == で比べると、&i32 の PartialEq は参照の先の値を比べます。items.iter().position(|x| x == target) と書くと入力例 1 は値 7 の最初の要素で一致し、Some(0) を返してしまいます。同じ要素かどうかは、その要素がメモリのどこにあるかで決まるので、std::ptr::eq で2つの参照のアドレスを比べます。これは参考実装で、唯一の正解ではありません。enumerate で添字と要素を組にして for で回しても、比べる部分が std::ptr::eq なら同じ結果になります。

入力例 1 の &v[2] は配列 v の3番目の要素のアドレスを持つので、position は添字 2 で一致します。入力例 2 の &7 は v の外にある値 7 を指すので、どの要素ともアドレスが合わず、None です。空のスライスでは position が1度も比べずに None を返します。返す添字はスライスの長さ未満なので、要素がいくつあっても usize に収まります。
