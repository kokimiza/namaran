fn is_valid(
    digits: impl Iterator<Item = u32>,
) -> bool {
}

クレジットカードなどの番号は、次の検査で打ち間違いを見つけます。番号の右端の数字を 1 番目として右から数え、偶数番目の数字は2倍し、2倍した値が2桁なら十の位と一の位を足して1桁にします。奇数番目の数字はそのままにして、これらをすべて足した和が 10 で割り切れれば、番号は正しいとします。番号の数字を左から順に出す digits を受け取り、番号が正しいかを返す is_valid を書いてください。digits は前から1度しか読めず、数字がいくつあるかは読み終えるまで分かりません。使うメモリは数字の個数によらず一定にし、数字を Vec などに溜めないでください。数字は1つ以上あり、個数に上限はありません。

入力例 1

is_valid([1, 8].into_iter())

出力例 1

true

入力例 2

is_valid([8, 1].into_iter())

出力例 2

false

入力例 3

is_valid([0].into_iter())

出力例 3

true

fn is_valid(
    digits: impl Iterator<Item = u32>,
) -> bool {
    let (plain, _) = digits.fold(
        (0, 0),
        |(plain, twice), d| {
            let x = 2 * d;
            let s = x / 10 + x % 10;
            (
                (twice + d) % 10,
                (plain + s) % 10,
            )
        },
    );
    plain == 0
}

どの数字を2倍するかは右端から数えた位置で決まるので、左から読んでいる途中では、いま読んだ数字を2倍すべきかが分かりません。そこで、いま読んだ数字が右端になる場合の和を2通り持ち続けます。plain は、最後に読んだ数字をそのまま足す数え方の和で、番号がここで終われば、これが検査に使う和です。twice は、最後に読んだ数字を2倍する数え方の和で、後ろに続く数字が奇数個のときに正しい和になります。掲載したのは参考実装で、唯一の正解ではありません。

新しい数字 d を読むと、それまでの数字はすべて右へ1つずれ、奇数番目と偶数番目が入れ替わります。d がそのまま足される新しい plain は、直前の数字が2倍される側の和 twice に d を足したもので、d が2倍される新しい twice は、直前の数字がそのまま足される側の和 plain に d を2倍した値の位の和を足したものです。2つの和を入れ替えながら足していくので、読み終えた時点の plain が、最後に読んだ数字を右端とした正しい和になります。

数字の個数には上限が無いので、和をそのまま足し続けると、いずれ u32 に収まらなくなります。たとえば 9 が 477,218,590 個続くと和は 4,294,967,310 になり、u32::MAX を超えて、デバッグビルドではパニックします。検査に要るのは和を 10 で割った余りだけなので、足すたびに % 10 を取り、2つの値を常に 0 から 9 に保ちます。足す前の値が 10 未満で、足す数も 9 以下なので、途中の和も 18 を超えません。持つのは 10 未満の整数2つだけで、メモリも数字の個数によりません。

入力例1では、1 を読んで (plain, twice) が (1, 2) になり、8 を読むと plain は 2 + 8 = 10 の余りで 0、twice は 1 + 7 = 8 です。plain が 0 なので true を返します。入力例2は 8 で (8, 7)、1 で plain が 7 + 1 = 8 になり、false です。数字が1つだけの入力例3は、最初の数字がそのまま足されて plain が 0 になり、true を返します。
