lane_max.rs

fn lane_max(blocks: &[[i32; 4]]) -> Option<i32> {
}

blocks の各要素は4つの値を並べた配列で、SIMD のレジスタのように、同じ位置の値どうしを1本のレーンとして扱います。まずレーンごとに最大値を求め、最後に4本のレーンの最大値をまとめて、すべての値の最大値を返す lane_max を書いてください。blocks が空なら None を返します。

入力例 1

lane_max(&[[3, -1, 4, 1], [-5, 9, 2, -6]])

出力例 1

Some(9)

入力例 2

lane_max(&[[-7, -3, -9, -4], [-8, -6, -5, -2]])

出力例 2

Some(-2)

入力例 3

lane_max(&[])

出力例 3

None

fn lane_max(blocks: &[[i32; 4]]) -> Option<i32> {
    let (first, rest) = blocks.split_first()?;
    let mut acc = *first;
    for block in rest {
        for (a, &x) in acc.iter_mut().zip(block) {
            *a = (*a).max(x);
        }
    }
    acc.into_iter().max()
}

参考実装は、split_first で最初の配列とそれ以外に分け、最初の配列をそのままレーンの初期値 acc にします。残りの配列は zip で acc と同じ位置どうしを組にして、各レーンを大きい方で置き換えます。最後に acc.into_iter().max() で4本のレーンを1つにまとめます。blocks が空なら split_first が None を返し、? でそのまま None が返ります。掲載したのは参考実装で、唯一の正解ではありません。

和を求めるときのつもりでレーンを [0; 4] から始めると、入力例2で間違えます。値がすべて負なので、どのレーンでも 0 の方が大きく、Some(0) が返ってしまいます。和なら足しても変わらない 0 が初期値になりますが、最大値で同じ役を果たすのは、どの値と比べても負ける i32::MIN です。参考実装のように最初の配列から始めれば、初期値もすでに入力の値なので、この心配が要りません。

[i32::MIN; 4] から始める書き方もできます。その場合、空の blocks でもレーンは4本あるので、max() は Some(i32::MIN) を返します。None を返すには、blocks が空かどうかを別に確かめる必要があります。
