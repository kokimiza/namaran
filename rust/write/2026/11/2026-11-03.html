page_count.rs

fn page_count(items: u64, per_page: u64) -> u64 {
}

items 件の項目を、1ページに per_page 件ずつ前から詰めて載せるときに要るページの数を返す page_count を書いてください。最後のページは per_page 件に満たなくてもかまいません。per_page は 1 以上とし、items が 0 のときは 0 ページです。u64 のどの値を渡しても正しい答えを返すようにしてください。

入力例 1

page_count(10, 3)

出力例 1

4

入力例 2

page_count(9, 3)

出力例 2

3

入力例 3

page_count(0, 5)

出力例 3

0

fn page_count(items: u64, per_page: u64) -> u64 {
    items.div_ceil(per_page)
}

items / per_page は商の端数を切り捨てるので、10 件を 3 件ずつ載せると 3 になり、最後の 1 件を載せるページが数えられません。要るのは、余りが 0 でなければ1を足した値、つまり割り算の切り上げです。u64 の div_ceil はこの切り上げをそのまま計算し、割り切れる 9 件なら 3、0 件なら 0 を返します。

切り上げを (items + per_page - 1) / per_page と書く方法もよく見かけますが、items が u64::MAX に近いと足し算があふれます。デバッグビルドでは panic し、リリースビルドでは値が折り返して小さな答えになります。items / per_page + u64::from(items % per_page != 0) のように、商と余りに分けてから足せば、あふれずに書けます。div_ceil も同じようにあふれません。掲載したのは参考実装で、唯一の正解ではありません。
