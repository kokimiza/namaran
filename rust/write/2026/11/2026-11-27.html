picker.rs

fn picker(
    w: &[u32],
) -> impl Fn(u64) -> usize {
}

重みの並び w を受け取り、抽選する関数を返す picker を書いてください。重みの合計を T とすると、返す関数には 0 以上 T 未満の整数 r が渡されます。0 から T 未満までの整数を、先頭の項目から重みの数ずつ順に割り当てたとき、r が割り当てられた項目の添字を返します。重みが 0 の項目には何も割り当てず、選ばれません。w は空でなく、T は 1 以上で u64 に収まるものとします。返す関数は何度も呼ばれるので、1回の呼び出しで w を先頭からなめ直さないでください。

入力例 1

(0..6).map(picker(&[3, 1, 2]))

出力例 1

[0, 0, 0, 1, 2, 2]

入力例 2

(0..3).map(picker(&[2, 0, 1]))

出力例 2

[0, 0, 2]

入力例 3

picker(&[5])(4)

出力例 3

0

fn picker(
    w: &[u32],
) -> impl Fn(u64) -> usize {
    let cum: Vec<u64> = w
        .iter()
        .scan(0, |s, &x| {
            *s += u64::from(x);
            Some(*s)
        })
        .collect();
    move |r| cum.partition_point(|&c| c <= r)
}

項目 i に割り当たるのは、i の手前までの重みの和以上、i までの重みの和未満の整数です。そこで scan で i までの重みの和を並べた表 cum を作ります。入力例1なら [3, 4, 6] です。r を受け持つ項目は、cum の中で r より大きい最初の要素の位置になります。cum は小さい順に並んでいるので、partition_point(|&c| c <= r) が二分探索でその位置を返します。条件を c < r にすると、r = 3 が項目 0 に入ってしまいます。掲載したのは参考実装で、唯一の正解ではありません。

表は picker の中で一度だけ作り、move でクロージャに持たせます。move を書かないと、クロージャは picker の終わりで消えるローカル変数 cum を借用したまま返ることになり、コンパイルが通りません。表を作るのが要素数に比例する手間で、そのあとの1回の抽選は二分探索なので log2 n 回ほどの比較で済みます。重み0の項目は前の項目と同じ値を cum に持ちますが、c <= r の範囲に入るので飛ばされ、入力例2のように選ばれません。cum の和は u64 で取っているので、T が u64 に収まる限りあふれません。
