affordable.rs

fn affordable(prices: &[u32], budget: u32) -> usize {
}

所持金 budget で、値段の並び prices の商品を先頭から順に1つずつ買っていくとき、何個買えるかを返す affordable を書いてください。残りのお金で買えない商品に出会ったら、そこで買い物をやめます。その後ろにもっと安い商品があっても買いません。prices が空なら 0 です。

入力例 1

affordable(&[3, 4, 5, 1], 8)

出力例 1

2

入力例 2

affordable(&[2, 2, 2], 6)

出力例 2

3

入力例 3

affordable(&[9, 1], 8)

出力例 3

0

fn affordable(prices: &[u32], budget: u32) -> usize {
    prices
        .iter()
        .scan(budget, |left, &p| {
            *left = left.checked_sub(p)?;
            Some(())
        })
        .count()
}

scan は、要素をまたいで持ち越す状態を1つ持ったイテレータを作ります。最初の引数 budget が状態の初期値で、クロージャは状態への可変参照 left と要素を受け取り、Option を返します。Some ならその値を次へ流し、None を返すとイテレータはそこで終わり、後ろの要素はもう取り出しません。

クロージャの中では、残金 left から値段を checked_sub で引きます。u32 の引き算が 0 を下回るときは None が返り、? がそれをクロージャの戻り値にするので、買えない商品のところで連鎖が止まります。買えたときは Some(()) を流し、最後の count がその個数を数えます。入力例 1 では 3 と 4 を買って残金が 1 になり、5 で None になるので、後ろの 1 は見ずに 2 を返します。入力例 2 は残金がちょうど 0 になる場合で、0 になる引き算は Some(0) なので3個目まで数えます。

filter で「買える商品だけ」を残すと、5 を飛ばして後ろの 1 も買い、入力例 1 は 3 になります。filter は条件に合わない要素を捨てて次の要素へ進むだけで、イテレータを終わらせることはできません。掲載したのは参考実装で、唯一の正解ではありません。累計を流す scan と、累計が予算以下のあいだだけ続ける take_while をつないでも書けます。
