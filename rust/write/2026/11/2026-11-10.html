redact.rs

fn redact(line: &str, secrets: &[&str]) -> String {
}

ログの1行 line は、項目を空白1つで区切って並べたもので、各項目は 鍵=値 の形か、= を含まない語です。鍵は = を含まず、値は = を含むことがあります。鍵が secrets のどれかと完全に一致する項目だけを、値を *** に置き換えて 鍵=*** にし、それ以外の項目は元のまま、元の順に空白1つで並べた文字列を返す redact を書いてください。line が空なら空の文字列を返します。

入力例 1

redact("user=ann token=abc123 status=200", &["token"])

出力例 1

"user=ann token=*** status=200"

入力例 2

redact("next=/a?token=x pass=a=b", &["pass", "token"])

出力例 2

"next=/a?token=x pass=***"

入力例 3

redact("", &["token"])

出力例 3

""

fn redact(line: &str, secrets: &[&str]) -> String {
    line.split(' ')
        .map(|field| match field.split_once('=') {
            Some((key, _)) if secrets.contains(&key) => format!("{key}=***"),
            _ => field.to_string(),
        })
        .collect::<Vec<_>>()
        .join(" ")
}

項目ごとに伏せるかどうかを決め、決めた項目を空白でつなぎ直します。鍵を取り出すのは split_once('=') で、これは最初の = の前後で文字列を2つに分けます。入力例2の pass=a=b は鍵 pass と値 a=b に分かれ、値の中の = は鍵を決めるのに使われません。= の無い項目では None が返り、2つ目の腕でそのまま残ります。これは参考実装で、唯一の正解ではありません。

伏せる項目は、鍵を secrets と完全一致で比べて選びます。secrets は &[&str] なので、contains には要素の型 &str への参照 &key を渡します。行の中から "token=" という文字列を探して置き換えるやり方では、入力例2の next=/a?token=x の値の途中にある token= にも反応し、伏せる必要のない遷移先の情報が壊れます。逆に split で = をすべて区切りにすると、pass=a=b の値の後半が別の部品として残ります。最初の = で分けることと鍵の完全一致を両方守ると、調べたい項目は残り、秘密の値だけが消えます。

split(' ') は、空の line に対しても空の項目を1つ返します。その項目は = を含まないのでそのまま残り、join の結果は空の文字列になって、入力例3を満たします。split_whitespace を使うと連続した空白が1つにまとまるので、問題文の形の入力なら同じ結果になります。
