サーバーに届く要求を受け付けるかどうかを決める Dedup::accept を、構造体 Dedup のフィールドと合わせて書いてください。各クライアントは自分の要求に 1 から順に番号 seq を振り、番号 n の応答を受け取ってから番号 n+1 を送ります。応答が失われるとクライアントは同じ番号の要求を送り直すので、同じ要求が何度も届くことがあり、遅れた再送が新しい番号の要求より後に届くこともあります。accept(client, seq) は、その (client, seq) が初めて届いたときだけ true を返し、2回目以降は false を返します。1つのクライアントのために使うメモリは、そのクライアントから届いた要求の数に比例して増えてはいけません。例では、空の状態から作った1つの Dedup に順に渡した (client, seq) と、accept が返した値の並びを書きます。

入力例 1

(1, 1) (1, 1) (1, 2)

出力例 1

[true, false, true]

入力例 2

(1, 1) (1, 2) (1, 1)

出力例 2

[true, true, false]

入力例 3

(1, 1) (2, 1) (2, 1)

出力例 3

[true, true, false]

use std::collections::HashMap;

struct Dedup {
    last: HashMap<u32, u64>,
}

impl Dedup {
    fn accept(
        &mut self,
        client: u32,
        seq: u64,
    ) -> bool {
        let last = self
            .last
            .entry(client)
            .or_insert(0);
        if seq > *last {
            *last = seq;
            true
        } else {
            false
        }
    }
}

届いた (client, seq) をすべて集合に入れれば重複は見分けられますが、集合は要求が届くたびに大きくなります。そこで約束の側から、何を覚えておけば足りるかを考えます。クライアントは番号 n の応答を受け取ってから n+1 を送るので、n+1 が初めて届いた時点で、n はすでに一度届いています。この関係をたどると、あるクライアントから届いた最大の番号が m なら、1 から m までの番号はどれも一度は届いています。

そのため、クライアントごとに届いた最大の番号を1つ覚えておけば足ります。seq がそれより大きければ初めての要求なので、最大の番号を更新して true を返します。それ以下なら、その番号はもう届いているので再送で、false を返します。参考実装では、まだ何も届いていないクライアントの最大値を or_insert(0) で 0 とし、番号が 1 から始まることで最初の要求が必ず受け付けられるようにしています。掲載したのは参考実装で、唯一の正解ではありません。

入力例2の3つ目は、番号 1 の遅れた再送が番号 2 より後に届いた場面です。最後に届いた番号だけを覚える実装は、ここで 1 を 2 と比べて「違う番号だから新しい」と誤り、true を返します。比べる相手を最大の番号にすると、1 は 2 以下なので再送と分かります。入力例3のように番号はクライアントごとに独立しているので、表のキーはクライアントです。使うメモリはクライアントの数に比例しますが、1つのクライアントの分は何件届いても整数1つのままです。
