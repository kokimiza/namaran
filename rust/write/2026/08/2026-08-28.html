migrate.rs

struct UserV1 {
    id: u32,
    name: String,
}

struct UserV2 {
    id: u32,
    given: String,
    family: Option<String>,
}

fn migrate(old: UserV1) -> UserV2 {
}

氏名を1つの name に入れていた UserV1 を、名の given と姓の family に分けた UserV2 へ移す migrate を書いてください。name を最初の空白で2つに分け、前を given、後ろを family にします。空白を含まない name は全体を given にし、family は None にします。id はそのまま引き継ぎます。入力例は old.name、出力例は戻り値の given と family を {:?} で並べたものです。

入力例 1

"Ada Lovelace"

出力例 1

"Ada" Some("Lovelace")

入力例 2

"Plato"

出力例 2

"Plato" None

入力例 3

"Mary Ann Evans"

出力例 3

"Mary" Some("Ann Evans")

fn migrate(old: UserV1) -> UserV2 {
    match old.name.split_once(' ') {
        Some((given, family)) => UserV2 {
            id: old.id,
            given: given.to_string(),
            family: Some(family.to_string()),
        },
        None => UserV2 { id: old.id, given: old.name, family: None },
    }
}

split_once(' ') は最初の空白で文字列を分け、空白があれば前後の2つを Some で、なければ None を返します。入力例 3 のように空白が2つあっても、分けるのは最初の1か所だけなので、family には "Ann Evans" が残ります。

Some の側で受け取る given と family は old.name を借用した &str なので、String のフィールドにはそのまま入らず、to_string() で新しい String を作ります。None の側では借用した値が1つも残っていないため、old.name をそのまま given へムーブでき、文字列をコピーせずに済みます。

掲載したのは参考実装で、唯一の正解ではありません。map_or で2つの場合を1つの式にまとめたり、id だけを先に取り出してから組み立てたりする書き方もあります。
