2026-10-15

sort_timer.rs

use std::time::Instant;

struct Timer(&'static str, Instant);

impl Drop for Timer {
    fn drop(&mut self) {
        println!("{} took {:?}", self.0, self.1.elapsed());
    }
}

fn main() {
    let _ = Timer("sort", Instant::now());
    let mut v: Vec<u32> = (0..5).rev().collect();
    v.sort();
    println!("{v:?}");
}

Timer は、作られてから捨てられるまでの時間を、捨てられるときに出力する型です。main はこれでソートにかかる時間を測るつもりです。実行すると、いまは sort took 150ns のような行がソート結果の [0, 1, 2, 3, 4] より先に出ます。本来は [0, 1, 2, 3, 4] が先に出て、そのあとに sort took の行が出ます。

Answer

Wrong

let _ = Timer("sort", Instant::now());

let _ = は、右辺の値をどの変数にも束縛しません。作られた Timer は名前を持たない一時値のままで、一時値はその文の終わりで捨てられます。drop がその場で呼ばれるので、ソートを始める前に sort took の行が出ます。測れたのは Timer を作ってから捨てるまでの一瞬で、ソートは入っていません。

Right

let _timer = Timer("sort", Instant::now());

_timer は先頭に _ が付いていても普通の変数で、値は main の終わりまで生きています。Timer が捨てられるのは main を抜けるときなので、ソートと結果の出力が済んでから sort took の行が出ます。先頭の _ が止めるのは、使っていない変数への警告だけです1。

  1. 同じ誤りは、Mutex のロックを let _ = m.lock(); で受けたときにも起きます。ロックは取った文の終わりで解放されるので、守りたい処理は守られません。こちらはコンパイラの let_underscore_lock という lint が既定でエラーにしますが、自分で書いた Timer のような型には働きません。
