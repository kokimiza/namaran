shared_log.rs

use std::borrow::Borrow;
use std::cell::RefCell;
use std::rc::Rc;

fn total_len<S: Borrow<str>>(words: &[S]) -> usize {
    words.iter().map(|w| w.borrow().len()).sum()
}

fn main() {
    let log = Rc::new(RefCell::new(Vec::new()));
    let writer = Rc::clone(&log);
    writer.borrow_mut().push(String::from("open"));
    writer.borrow_mut().push(String::from("close"));
    println!("{}", total_len(&log.borrow()));
}

このプログラムは、writer経由でlogに書き込んだ文字列の長さの合計を表示するつもりのものです。入力は書き込んだ"open"と"close"で、本来は9を表示するはずですが、いまはコンパイルが通りません。どこを直せばよいでしょうか?

Answer

最後の行のlog.borrow()が、RefCell::borrowではなくBorrow::borrowに解決されています。最小の修正は、この呼び出しをRefCell::borrow(&log)と書くことです。

メソッド呼び出しでは、受け手の型をRc<RefCell<Vec<String>>>からDerefで1段ずつたどり、各段で「そのまま」「&を付けて」「&mutを付けて」の順に名前の合うメソッドを探し、見つかった段で探索を止めます。use std::borrow::Borrow;があると、最初の段の&Rc<…>でBorrow::borrowが見つかります。Rc<T>はBorrow<T>を実装しており、どの型も自分自身へのBorrowを持つからです。RefCellのborrowはDerefで1段たどった先にあるので、そこまで探索が届きません。

このあとtotal_lenが&[S]を求めるので、コンパイラはRc<RefCell<…>>: Borrow<[_]>を満たす実装を探して見つけられず、エラーになります。RefCell::borrow(&log)と関数の形で呼べば、関数の引数という型強制の場所で&Rc<RefCell<…>>が&RefCell<…>になります。返ったRef<Vec<String>>も、&を付けてtotal_lenに渡すとDerefを2段たどって&[String]になります。

use std::borrow::Borrow;を消すと、今度はtotal_lenの中のw.borrow()が書けなくなります。useは残し、呼び出し側を直します。(*log).borrow()と書いても、探索がRefCellの段から始まるのでRefCell::borrowが選ばれます1。

  1. 同じ段に固有メソッドとトレイトのメソッドがあるときは、固有メソッドが優先されます。(*log).borrow()では&RefCell<…>の段にRefCell::borrowと、どの型にもあるBorrow::borrowが並び、RefCell::borrowが選ばれます。
