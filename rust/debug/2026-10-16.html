copy_bytes.rs

use std::io::Read;

fn main() {
    let mut input: &[u8] = b"hello, world";
    let mut buf = [0u8; 5];
    let mut out = Vec::new();
    loop {
        let n = input.read(&mut buf).unwrap();
        if n == 0 {
            break;
        }
        out.extend_from_slice(&buf);
    }
    println!("{}", String::from_utf8_lossy(&out));
}

input のバイト列を5バイトずつ buf に読み、読んだ順に out へ写すつもりのコードです。入力は b"hello, world" の12バイトです。いまの出力は hello, worldwor です。本来の出力は hello, world です。

Answer

Wrong

out.extend_from_slice(&buf);

&[u8] に対する read は、先頭から buf に入るだけのバイトを写し、写した分だけ input 自身を前へ進めて、写したバイト数を返します。12バイトの入力は 5、5、2 バイトの3回で読み終わり、4回目に 0 が返ってループを抜けます。3回目の read が書き換えるのは buf の先頭2バイトだけで、後ろの3バイトには2回目に読んだ , wor の wor が残っています。

&buf は [u8; 5] から作ったスライスで、長さは型が覚えている 5 です。読めたバイト数は戻り値の n しか知らないので、3回目には ld に続けて前回の残りの wor まで out に足され、末尾に余計な3バイトが付きます。

Right

out.extend_from_slice(&buf[..n]);

&buf[..n] は、buf と同じアドレスから始まり、長さが n のスライスです。入れ物の大きさではなく、今回の read が実際に書いた範囲だけを渡すので、前回の残りは out に入りません1。

  1. ファイルやソケットに対する read は、終わりに達していなくても、buf より少ないバイト数を返すことがあります。そのため同じ欠陥は、入力の最後だけでなく途中にも古いバイトを混ぜます。すべてを読むだけなら read_to_end や std::io::copy を使えば、この長さの管理を自分で書かずに済みます。
