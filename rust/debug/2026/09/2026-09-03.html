status_ids.rs

fn query(status: &str, ids: &[i64]) -> (String, Vec<String>) {
    let marks: Vec<String> = (1..=ids.len()).map(|i| format!("?{i}")).collect();
    let sql = format!("SELECT * FROM orders WHERE status = ?1 AND id IN ({})", marks.join(", "));
    let mut params = vec![status.to_string()];
    params.extend(ids.iter().map(|id| id.to_string()));
    (sql, params)
}

fn main() {
    let (sql, params) = query("open", &[7, 9]);
    println!("{sql}");
    println!("{params:?}");
}

query は、状態が status で、id が ids のどれかである注文を探す SQL と、その ?N に順に対応するパラメータの一覧を返すつもりの関数です。引数も標準入力も使わず、main が query("open", &[7, 9]) の結果を出力します。いまは SELECT * FROM orders WHERE status = ?1 AND id IN (?1, ?2) と ["open", "7", "9"] の2行が出力されます。本来は1行目が SELECT * FROM orders WHERE status = ?1 AND id IN (?2, ?3) で、2行目は同じです。

Answer

Wrong

let marks: Vec<String> = (1..=ids.len()).map(|i| format!("?{i}")).collect();

?N はパラメータの一覧の N 番目を指し、一覧の1番目は status の "open" です。IN 句の番号を 1 から振ると ?1 がもう一度現れ、id は "open" と "7" の2つと比べられます。一覧の3番目の "9" を指す番号はどこにもないので、id が 9 の注文は条件から漏れます。

Right

let marks: Vec<String> = (2..=ids.len() + 1).map(|i| format!("?{i}")).collect();

status が ?1 を使っているので、IN 句の番号は 2 から始めます。ids の値は一覧の2番目以降に積まれるので、?2 が "7" を、?3 が "9" を指します1。

  1. 番号を付けない ? なら、値は SQL に現れた順に対応するので、このずれは起きません。その代わり、SQL を組み立てる順と値を積む順をそろえておく必要があります。
