capacity.rs

fn valid_capacity(cap: usize) -> bool {
    cap & (cap - 1) == 0
}

fn main() {
    for cap in [16, 12, 0] {
        println!("{cap}: {}", valid_capacity(cap));
    }
}

valid_capacity は、リングバッファの容量が2のべき乗かどうかを調べるつもりの関数で、容量 0 は不正な値として false を返すべきです。実行すると、本来は 16: true、12: false、0: false の3行を出力するはずですが、いまはデバッグビルドで 16: true、12: false を出力したあと、attempt to subtract with overflow で panic します。リリースビルドでは panic せずに、3行目に 0: true を出力します。

Answer

Wrong

cap & (cap - 1) == 0

cap & (cap - 1) は cap の最下位の1ビットを消す式で、結果が 0 かどうかは「1のビットが1個以下か」を調べています。0 は1のビットが1個もないので、この判定だけでは弾けません。

そのうえ cap が 0 のとき、cap - 1 は usize の範囲を下回ります。Rust の整数演算はデバッグビルドではあふれを検査して panic し、リリースビルドでは既定で回り込みます。回り込んだ usize::MAX はすべてのビットが1なので、0 & usize::MAX は 0 になり、0 が2のべき乗と判定されます1。

Right

cap != 0 && cap & (cap - 1) == 0

&& は左辺が偽なら右辺を評価しないので、cap が 0 のときは引き算そのものが行われません。0 を除いたうえで1のビットが1個以下の数は、1のビットがちょうど1個の数、つまり2のべき乗だけです。標準ライブラリの usize::is_power_of_two を使っても、0 の扱いを含めて同じ判定になります。

  1. Rust の & は == より強く結びつくので、cap & (cap - 1) == 0 は意図どおり (cap & (cap - 1)) == 0 と読まれます。C で同じ式を書くと cap & ((cap - 1) == 0) になります。
