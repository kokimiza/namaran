plan.rs

#[derive(Clone, Copy, Debug)]
enum Plan {
    Free,
    Trial,
    Pro,
}

fn load(code: u8) -> Plan {
    match code {
        0 => Plan::Free,
        1 => Plan::Pro,
        _ => Plan::Trial,
    }
}

fn main() {
    let stored = [0u8, 1];
    let saved: Vec<u8> = stored.iter().map(|&c| load(c) as u8).collect();
    let reloaded: Vec<Plan> = saved.iter().map(|&c| load(c)).collect();
    println!("{reloaded:?}");
}

料金プランの Plan は、v1 では Free と Pro の2つで、保存された数値は Free が0、Pro が1でした。v2 で Trial を足し、load は v1 の数値をそのまま読めるように書いてあります。main は v1 のデータ [0, 1] を読み込み、as u8 で保存し直してから、もう一度読み込みます。いまの出力は [Free, Trial] で、本来の出力は [Free, Pro] です。

Answer

Wrong

enum Plan {
    Free,
    Trial,
    Pro,
}
    let saved: Vec<u8> = stored.iter().map(|&c| load(c) as u8).collect();

判別子（discriminant）を書かない列挙子には、宣言の順に0から番号が付き、as u8 はその番号を返します。Trial を Free と Pro の間に足したので、Pro の番号は1から2に変わりました。load は v1 の約束どおり1を Pro と読むので、最初の読み込みは正しく [Free, Pro] になります。

ずれが表に出るのは保存し直したときです。Pro as u8 は2なので、保存されるのは [0, 2] になり、次の読み込みで2は _ の腕に入って Trial になります。数値から列挙子への対応は load に明示してある一方、列挙子から数値への対応は宣言の順に任せてあり、2つの対応が食い違っています。

Right

enum Plan {
    Free = 0,
    Trial = 2,
    Pro = 1,
}

判別子を明示すると、as u8 が返す数値は宣言の順に左右されなくなり、v1 で保存した数値と同じになります。Pro as u8 は1に戻り、Trial には v1 で使っていない2が割り当てられ、load の対応と一致します。新しい列挙子を必ず末尾に足すという決まりでも同じ番号になりますが、番号を書いておけば、並べ替えたときにも保存済みのデータは変わりません1。

  1. Rust の列挙子の判別子は、明示しなければ直前の列挙子の値に1を足した値になり、先頭は0です。C の enum も同じ規則で、C で保存したデータの読み書きでも同じ欠陥が起きます。
