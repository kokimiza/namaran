hits.rs

use std::sync::atomic::{AtomicU32, Ordering};
use std::thread;

static HITS: AtomicU32 = AtomicU32::new(0);

fn hit() {
    let n = HITS.load(Ordering::Relaxed);
    HITS.store(n + 1, Ordering::Relaxed);
}

fn main() {
    let workers: Vec<_> =
        (0..4).map(|_| thread::spawn(|| (0..100_000).for_each(|_| hit()))).collect();
    workers.into_iter().for_each(|w| w.join().unwrap());
    println!("{}", HITS.load(Ordering::Relaxed));
}

hit を呼ぶたびに、プログラム全体で共有する HITS を1つ増やすつもりのコードです。main は4つのスレッドでそれぞれ10万回 hit を呼ぶので、本来は 400000 が出ます。いまは 151913、107933、148191 のように、40万より小さい値が実行のたびに違って出ます。

Answer

Wrong

fn hit() {
    let n = HITS.load(Ordering::Relaxed);
    HITS.store(n + 1, Ordering::Relaxed);
}

HITS.load と HITS.store は、それぞれ1回ずつなら途中で割り込まれない操作です。しかし hit はこの2つを別々に呼んでおり、読んでから書くまでの間には別のスレッドが入れます。HITS が 7 のときに2つのスレッドがほぼ同時に hit に入ると、両方が n に 7 を読み、両方が 8 を書きます。2回呼んだのに1しか増えず、片方の更新が消えます。4つのスレッドが同時に回っている間はこれが何度も起き、どれだけ消えるかはスレッドの進み方で変わるので、結果は40万より小さく、毎回違う値になります。

Right

fn hit() {
    HITS.fetch_add(1, Ordering::Relaxed);
}

fetch_add(1, ...) は、今の値を読み、1を足し、書き戻すまでを1つの不可分な操作として行います。2つのスレッドが同時に呼んでも、一方が書き戻すまでもう一方は古い値を読めないので、7 から始まれば必ず 9 になります。40万回の呼び出しがそれぞれ1ずつ増やし、400000 が出ます。Ordering::Relaxed のままでよいのは、ここで欲しいのが HITS 1つの数の正しさだけで、ほかの変数との読み書きの順序は問わないからです。1

  1. static mut HITS: u32 に HITS += 1 と書いていたコードを atomic 型へ移すとき、この load と store の2行に書き換えてしまうことがあります。元の HITS += 1 も同じ消え方をするうえ、複数のスレッドから同時に書くのは未定義動作でした。atomic 型にすると未定義動作ではなくなりますが、増やす処理を1つの操作にしなければ数は合いません。
