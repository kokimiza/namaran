mean_check.rs

fn mean(xs: &[f64]) -> f64 {
    xs.iter().sum::<f64>() / xs.len() as f64
}

fn repeat_ok(xs: &[f64]) -> bool {
    let twice = [xs, xs].concat();
    mean(&twice) == 2.0 * mean(xs)
}

fn main() {
    println!("{}", repeat_ok(&[1.0, 2.0, 4.0]));
}

repeat_ok は、xs と、xs を2回つなげた列とで mean の結果を比べ、正しい mean なら必ず成り立つ関係が成り立つかを確かめるつもりの関数です。mean は列の要素の平均を正しく返しています。repeat_ok(&[1.0, 2.0, 4.0]) は本来 true を返すはずが、いまは false が表示され、正しい mean が検査に落ちます。

Answer

Wrong

let twice = [xs, xs].concat();
mean(&twice) == 2.0 * mean(xs)

[xs, xs].concat() は [1.0, 2.0, 4.0, 1.0, 2.0, 4.0] を作ります。列を2回つなげると和は 7.0 から 14.0 の2倍になりますが、要素の個数も 3 から 6 の2倍になるので、平均は 7.0 / 3.0 のまま変わりません。検査は和に成り立つ「2倍になる」という関係を平均に当てはめていて、左辺は 7.0 / 3.0、右辺は 14.0 / 3.0 です。平均が 0 でない列なら、左辺は右辺のおよそ半分にしかならず、xs が何であっても検査は通りません。

この検査は、正しい mean を誤りとして報告します。正しい結果の値を書かずに確かめる検査では、確かめる関係そのものが正しくなければ、検査は何も保証しません。

Right

let twice = [xs, xs].concat();
mean(&twice) == mean(xs)

比べる関係を「2回つなげても平均は変わらない」に直すと、両辺はどちらも 7.0 / 3.0 になり、true が出ます。この入力の要素と和はどれも誤差なく表せる整数なので、左辺の 14.0 / 6.0 と右辺の 7.0 / 3.0 は同じ真の値を丸めた結果になり、浮動小数点数でも == で一致します。1

  1. 正しい出力が分からなくても、入力を変えたときに出力がどう変わるはずかという関係で関数を確かめるこの方法を、メタモルフィックテスト(metamorphic testing)と呼びます。0.1 のように誤差を含む要素では、後半の要素を前半の和に足していく途中で丸めが起き、正しい関係でも == がわずかな差で崩れることがあります。そうした入力も扱う検査では、差の絶対値が小さいかどうかで比べます。
