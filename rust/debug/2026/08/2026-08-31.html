mines.rs

fn around(grid: &[u8], w: usize, i: usize) -> usize {
    [i.wrapping_sub(1), i + 1, i.wrapping_sub(w), i + w]
        .into_iter()
        .filter(|&j| grid.get(j) == Some(&b'#'))
        .count()
}

fn main() {
    let grid = b"..#\
                 #..\
                 ...";
    let counts: Vec<usize> = (0..grid.len()).map(|i| around(grid, 3, i)).collect();
    println!("{counts:?}");
}

around は、幅 w の格子を1行ずつつないだバイト列 grid について、i 番目のマスの上下左右にある # の数を返すつもりの関数です。格子の外は数えません。3×3の格子の全マスについて数えると、いまは [1, 1, 1, 1, 1, 1, 1, 0, 0] が出ます。本来は [1, 1, 0, 0, 1, 1, 1, 0, 0] です。

Answer

Wrong

[i.wrapping_sub(1), i + 1, i.wrapping_sub(w), i + w]
    .into_iter()
    .filter(|&j| grid.get(j) == Some(&b'#'))

間違っているのは添字2と3で、格子では1行目の右端と2行目の左端です。1行目の右端の添字2に1を足した3は、一次元の並びでは隣ですが、格子では2行目の左端にあたります。そこにある # を、i + 1 は右隣として数えてしまいます。添字3から1を引いた2も同じで、1行目の右端の # が左隣として数えられます。

このコードは、格子の外を2つの仕組みで除いているように見えます。上の端では i.wrapping_sub(w) が usize の最大値付近まで回り込み、下の端では i + w が grid.len() 以上になって、どちらも grid.get(j) が None を返します。添字0の左隣も、wrapping_sub(1) が最大値になって除かれます。しかし get が見ているのはバイト列全体の長さだけで、行の境目は知りません。左右の端で隣の行へはみ出した添字は、列の外なのにバイト列の中に収まっていて、どちらの仕組みにも掛かりません。

Right

[i.wrapping_sub(1), i + 1, i.wrapping_sub(w), i + w]
    .into_iter()
    .filter(|&j| j / w == i / w || j % w == i % w)
    .filter(|&j| grid.get(j) == Some(&b'#'))

添字 j の行は j / w、列は j % w です。左右の隣は同じ行に、上下の隣は同じ列にあるはずなので、行か列のどちらかが i と一致するものだけを残します。添字2の右の3は j / w が1、j % w が0で、i が2のときの0と2のどちらとも一致しないので除かれます。上下の候補は w の倍数だけずれているので列が一致し、これまでどおり get が格子の外を除きます。
