parse_id.rs

fn parse_id(s: &str) -> Option<u64> {
    let bytes = s.as_bytes();
    let mut i = 0;
    let mut id = 0;
    while i < bytes.len() {
        let b = bytes[i];
        if b == b'-' {
            continue;
        }
        if !b.is_ascii_digit() {
            return None;
        }
        id = id * 10 + u64::from(b - b'0');
        i += 1;
    }
    Some(id)
}

parse_id は、1234-5678 のようにハイフンで区切って書かれた会員番号から数字だけを読み、1つの数にする関数です。数字とハイフン以外の文字があれば None を返します。parse_id("12345678") はいまも Some(12345678) を返しますが、parse_id("1234-5678") を呼ぶと関数から返ってこなくなります。本来はこちらも Some(12345678) を返します。

Answer

Wrong

if b == b'-' {
    continue;
}

continue は、ループ本体の残りを飛ばして while の条件の判定に戻ります。飛ばされる残りには、最後の i += 1; も入っています。"1234-5678" では i が4のときに b が b'-' になり、i を進めないまま条件に戻るので、次の周も同じ bytes[4] を読み、また continue します。ハイフンを含む入力では、この繰り返しが終わりません。

Right

if b == b'-' {
    i += 1;
    continue;
}

continue の前で添字を進めます。ハイフンを読み飛ばした次の周は bytes[5] の '5' から読むので、ループは文字列の終わりで止まります。while で添字を自分で進めるループでは、continue のたびに更新を書き足す必要があります。for &b in bytes のように書けば、continue しても次の要素へ進むのはイテレータの役目になるので、同じ誤りは起きません。
