pages.rs

fn per_page<T>(page_bytes: usize) -> usize {
    page_bytes / size_of::<T>()
}

fn pages<T>(items: &[T], page_bytes: usize) -> usize {
    items.len().div_ceil(per_page::<T>(page_bytes))
}

fn main() {
    let samples = [0u32; 10];
    let ticks = [(); 10];
    println!("{}", pages(&samples, 16));
    println!("{}", pages(&ticks, 16));
}

pages は、要素の列を1ページ page_bytes バイトずつに分けて保存するとき、何ページ要るかを返すつもりの汎用関数です。大きさ0の型の要素はいくつあっても1ページに収まる、という仕様です。main は u32 の10個と () の10個を、それぞれ16バイトのページで数えます。いまは1行目の 3 を出力したあと、2つ目の呼び出しで attempt to divide by zero の panic が起きて止まります。本来の出力は 3 と 1 の2行です。

Answer

Wrong

fn per_page<T>(page_bytes: usize) -> usize {
    page_bytes / size_of::<T>()
}

() はとりうる値が1つしかないので、値を区別するための情報を持たず、大きさ0の型です。pages(&ticks, 16) では T が () になり、size_of::<T>() は 0 を返します。Rust の整数の割り算は、0で割ると最適化の有無にかかわらず panic するので、per_page の 16 / 0 で止まります。

u32 の呼び出しで問題が出ないのは、4バイトで割って1ページ4個になり、10個を4個ずつ切り上げて3ページになるからです。per_page はどの型も1バイト以上あると決めてかかっていて、その前提を破るのは大きさ0の型だけです。

Right

fn per_page<T>(page_bytes: usize) -> usize {
    page_bytes.checked_div(size_of::<T>()).unwrap_or(usize::MAX)
}

checked_div は割る数が0のとき panic せずに None を返すので、その場合を usize::MAX に置き換えます。大きさ0の要素は1ページに何個でも入る、という仕様をそのまま値にしたものです1。10.div_ceil(usize::MAX) は 1 になり、要素が0個なら 0 ページのままです。

  1. 標準ライブラリの Vec も同じ扱いをしていて、要素が大きさ0の型なら領域を確保せず、capacity() は usize::MAX を返します。
