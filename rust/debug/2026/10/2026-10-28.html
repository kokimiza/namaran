2026-10-28

batcher.rs

#[derive(Default)]
struct Batcher {
    size: usize,
    limit: usize,
}

impl Batcher {
    fn new() -> Self {
        Batcher { size: 2, limit: usize::MAX }
    }

    fn run(&self, items: &[u32]) -> Vec<u32> {
        items.chunks(self.size).take(self.limit).map(|c| c.iter().sum()).collect()
    }
}

fn main() {
    let batcher = Batcher { limit: 2, ..Default::default() };
    println!("{:?}", batcher.run(&[1, 2, 3, 4, 5]));
}

Batcher は、入力を size 個ずつの組に分けて組ごとの和を求め、先頭から limit 組までを返すつもりの型で、既定の設定は new に書いてあります。main は既定の設定から limit だけを2に変え、[1, 2, 3, 4, 5] を渡します。本来は [3, 7] と出力されるはずが、いまは何も出力されず、chunk size must be non-zero というメッセージで panic します。

Answer

Wrong

#[derive(Default)]
struct Batcher {
    size: usize,
    limit: usize,
}

main の ..Default::default() が呼ぶのは Batcher の Default 実装で、new ではありません。Default は #[derive(Default)] で作られていて、各フィールドにその型の既定値を入れるので、size も limit も usize の既定値の0になります。new に書いた2は、どこからも使われません。

main は limit だけを指定するので、size には0が残ります。run の items.chunks(self.size) は、組の大きさが0だと分けようがないので panic します。new を既定値の置き場と考えていると、Default::default() も同じ値を返すと読んでしまい、size が0になる経路に気付けません。

Right

struct Batcher {
    size: usize,
    limit: usize,
}

impl Default for Batcher {
    fn default() -> Self {
        Batcher::new()
    }
}

#[derive(Default)] をやめ、Default を new に任せる実装を書きます。既定値が new の1か所だけになるので、..Default::default() の土台も size が2の値になり、main は2個ずつの組 [1, 2]、[3, 4] の和 [3, 7] を出力します。呼び出し側で ..Batcher::new() と書いても今回は直りますが、Default::default() を呼ぶほかの場所(unwrap_or_default など)には0が残ったままです1。

  1. Clippy の new_without_default は、引数のない公開の new があるのに Default を実装していない型を指摘します。この問題のように Default を derive で済ませていると指摘の対象にならず、new と Default の値が食い違っていても警告は出ません。
