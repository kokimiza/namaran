grid_pi.rs

fn estimate_pi(n: u32) -> f64 {
    let mut inside = 0;
    for i in 0..n {
        for j in 0..n {
            let x = (f64::from(i) + 0.5) / f64::from(n);
            let y = (f64::from(j) + 0.5) / f64::from(n);
            if x * x + y * y <= 1.0 {
                inside += 1;
            }
        }
    }
    4.0 * f64::from(inside / (n * n))
}

fn main() {
    println!("{}", estimate_pi(100));
}

estimate_pi は、1辺が1の正方形に n × n 個の点を格子状に並べ、x² + y² ≤ 1 の内側に入った点の割合を4倍して円周率を推定するつもりの関数です。モンテカルロ法の乱数の代わりに格子点を使っています。estimate_pi(100) を表示すると、いまは 0 が出ます。本来の出力は 3.1428 です。

Answer

Wrong

4.0 * f64::from(inside / (n * n))

inside は n * n と割られるので、n と同じ u32 に推論されます。inside / (n * n) は整数どうしの割り算で、商の小数部は切り捨てられます。内側に入った点は全体より少ないので、7857 / 10000 の商は 0 です。f64::from が変換するのは割り終えたあとの 0 なので、4倍しても 0.0 のままで、{} では 0 と表示されます。

Right

4.0 * f64::from(inside) / f64::from(n * n)

割る前に、割られる数と割る数の両方を f64 に変換します。割り算が浮動小数点数で行われるので、7857 を 10000 で割った 0.7857 がそのまま残り、4倍した 3.1428 が返ります。
