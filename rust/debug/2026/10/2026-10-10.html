weekly.rs

use std::collections::BTreeMap;

fn main() {
    let header = "mon,tue,wed";
    let rows = ["3,,5", "4,1,2"];
    let mut total = BTreeMap::new();
    for row in rows {
        let values = row.split(',').flat_map(str::parse::<u32>);
        for (day, n) in header.split(',').zip(values) {
            *total.entry(day).or_insert(0) += n;
        }
    }
    println!("{total:?}");
}

CSV の行を読み、header の曜日ごとに値を合計するコードです。空の欄は、その曜日に記録がなかったことを表します。rows の2行を集計すると、本来は {"mon": 7, "tue": 1, "wed": 7} が出力されるはずが、いまは {"mon": 7, "tue": 6, "wed": 2} が出力されます。

Answer

Wrong

let values = row.split(',').flat_map(str::parse::<u32>);
for (day, n) in header.split(',').zip(values) {
    *total.entry(day).or_insert(0) += n;
}

1行目の "3,,5" を split(',') で切ると、"3"、""、"5" の3つになり、空の欄は空文字列として残ります。空文字列は数ではないので "".parse::<u32>() は Err を返しますが、パニックも 0 への読み替えも起きません。Result は Ok なら1個、Err なら0個の要素を持つ並びとして IntoIterator を実装しているので、flat_map はこの Err を黙って捨てます。values が返すのは 3 と 5 の2つだけです。

zip は2つの並びを先頭から順に組にし、短いほうが尽きたところで止まります。曜日は3つ、値は2つなので、mon と 3、tue と 5 が組になり、wed は相手のないまま終わります。エラーもパニックもなく、水曜の 5 が火曜に入るわけです。2行目の "4,1,2" には空の欄がないので正しく組になり、合計は tue が 5 + 1 = 6、wed が 2 になります。

Right

let values = row.split(',').map(str::parse::<u32>);
for (day, n) in header.split(',').zip(values) {
    if let Ok(n) = n {
        *total.entry(day).or_insert(0) += n;
    }
}

map にすると、values は空の欄にも Err を1つ返すので、値の並びは曜日の並びと同じ長さを保ちます。zip で曜日と組にしたあとで if let Ok(n) によって空の欄を飛ばせば、捨てるのは火曜の欄だけで、水曜の 5 は水曜に足されます。空の欄を読み飛ばすかどうかは、どの列の値かが決まってから判断します1。

  1. 空の欄を 0 として数えてよいなら、map(|f| f.parse::<u32>().unwrap_or(0)) でも列はずれません。ただしその書き方では、"x" のような壊れた欄も黙って 0 になります。
