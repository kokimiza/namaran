line_reader.rs

fn main() {
    let segments = ["PING\nPI", "NG\n", "QUIT\n"];
    let mut pending = String::new();
    for segment in segments {
        pending.push_str(segment);
        let mut lines: Vec<&str> = pending.lines().collect();
        let rest = lines.pop().unwrap_or("").to_string();
        for line in lines {
            println!("{line}");
        }
        pending = rest;
    }
}

TCPで断片ごとに届く文字列を pending に溜め、改行で終わったコマンドを1行ずつ出力するつもりのプログラムです。改行がまだ来ていない最後の部分は、次の断片が来るまで pending に残します。断片が "PING\nPI"、"NG\n"、"QUIT\n" の順に届くと、本来は PING、PING、QUIT の3行が出力されるはずが、いまは PING の1行しか出力されません。

Answer

Wrong

let mut lines: Vec<&str> = pending.lines().collect();
let rest = lines.pop().unwrap_or("").to_string();

このコードは、分けた最後の1つを改行の来ていない残りとみなして pop で取っておきます。ところが str::lines は、文字列が改行で終わるとき、その後ろの空の行を返しません。2つ目の断片を足した pending は "PING\n" で、lines は ["PING"] だけを返すので、完結した2つ目の PING が残りとして pop され、出力されないまま pending に戻ります。

3つ目の断片はその後ろにつながり、pending は "PINGQUIT\n" になります。ここでも同じことが起き、"PINGQUIT" が残りとして取っておかれるので、2行目以降は何も出力されません。

Right

let mut lines: Vec<&str> = pending.split('\n').collect();
let rest = lines.pop().unwrap_or("").to_string();

split('\n') は、改行で終わる文字列の後ろにも空の部分を1つ返します。"PING\n" は ["PING", ""] に分かれ、pop されるのは空の残りなので、PING は出力されます。改行が来ていなければ最後の部分は書きかけの行なので、どちらの場合も最後の1つを残りにする扱いが正しくなります。1

  1. str::lines は、行末の \r\n の \r も取り除きます。\r\n で区切るプロトコルでは、split('\n') で分けたあとに各行の末尾の \r を自分で取り除きます。
