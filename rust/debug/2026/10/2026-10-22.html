status.rs

fn label(code: u16, retry_code: u16) -> &'static str {
    match code {
        200 => "ok",
        retry_code => "retry",
        _ => "fail",
    }
}

fn main() {
    for code in [200, 503, 404] {
        println!("{code} {}", label(code, 503));
    }
}

label は HTTP のステータスコード code を、200なら ok、引数 retry_code と等しければ retry、それ以外なら fail に分類します。main は retry_code を503にして、200、503、404を分類します。いまの出力は 200 ok、503 retry、404 retry の3行です。本来は3行目が 404 fail になるはずです。

Answer

Wrong

retry_code => "retry",

パターンの中に小文字の名前を書くと、それは外の変数を参照する式ではなく、照合する値を束縛する新しい変数になります。この腕の retry_code はどんな u16 にも当てはまり、その値を同じ名前の新しい変数に入れて、引数の retry_code を隠します。200以外のコードはすべてこの腕に入るので、404も retry になり、下の _ の腕には何も届きません。

Right

c if c == retry_code => "retry",

実行時に決まる値と比べるには、どの値にも当てはまる束縛 c にガードの if c == retry_code を付けます。ガードが偽になった値は次の腕へ進むので、404は _ の腕で fail になります。比べたい値がコンパイル時に決まる定数なら、const RETRY: u16 = 503; と宣言した名前をパターンに書けば、束縛ではなく定数との比較になります1。

  1. 欠陥のある版をコンパイルすると、rustc は _ の腕に unreachable pattern の警告を出し、引数の retry_code が使われていないことも警告します。どちらも、パターンの名前が新しい束縛になっていることの手がかりです。
