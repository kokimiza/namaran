unique_names.rs

fn nfc(s: &str) -> String {
    s.replace("e\u{301}", "\u{e9}")
}

fn unique(mut names: Vec<String>) -> Vec<String> {
    names.sort();
    names.dedup_by(|a, b| nfc(a) == nfc(b));
    names
}

fn main() {
    let names = ["Jos\u{e9}", "Josh", "Jose\u{301}"];
    let names = names.iter().map(|s| s.to_string()).collect();
    println!("{:?}", unique(names));
}

unique は、名前の一覧から、見た目が同じ名前を1つだけ残して返すつもりの関数です。é は、1文字の U+00E9 でも、e のあとに上にアクセントを重ねる U+0301 を続けた2文字でも書けるので、nfc で2文字の形を1文字の形へそろえてから比べています（この問題に出てくる書き分けは é だけです）。main の一覧には José が2通りの書き方で入っているので、["Josh", "José"] が出力されるはずですが、いまは ["Jose\u{301}", "Josh", "José"] が出力されます。

Answer

Wrong

names.sort();
names.dedup_by(|a, b| nfc(a) == nfc(b));

dedup_by は、隣り合う2つの要素だけを比べて後ろの方を消します。sort のあとなら同じものは隣に並ぶ、というのがこの書き方の前提ですが、sort が使う String の順序は、文字を先頭からコードポイントの値で比べる順序です。nfc を通したあとの等しさとは関係なく並びます。

3つの名前は Jos までが同じで、4文字目で順序が決まります。e は U+0065、h は U+0068、é は U+00E9 なので、"Jose\u{301}"、"Josh"、"José" の順になります。U+00E9 はどの ASCII の英字よりも大きいので、1文字で書いた José は e で始まる側から遠く離れ、2つの José の間に "Josh" が入ります。dedup_by が比べるのは "Jose\u{301}" と "Josh"、"Josh" と "José" の組だけで、どちらも等しくないので何も消えません。

Right

names.sort_by_key(|s| nfc(s));
names.dedup_by(|a, b| nfc(a) == nfc(b));

並べ替えも nfc を通した値で行います。sort_by_key のキーが等しい要素は、dedup_by の比較でも等しくなります。キーで並べた列ではキーの等しい要素がひとまとまりに並ぶので、その間に別の名前が入ることはありません。3つのキーは "José"、"Josh"、"José" で、並べると "Josh" のあとに2つの José が並び、dedup_by が後ろの "Jose\u{301}" を消して ["Josh", "José"] になります。

sort_by_key は安定な並べ替えなので、同じキーの要素は元の順を保ち、残るのは一覧で先に出てきた書き方です。
