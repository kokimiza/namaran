turns.rs

type Pt = (usize, usize);

fn cross(o: Pt, a: Pt, b: Pt) -> i64 {
    let dx1 = (a.0 - o.0) as i64;
    let dy1 = (a.1 - o.1) as i64;
    let dx2 = (b.0 - o.0) as i64;
    let dy2 = (b.1 - o.1) as i64;
    dx1 * dy2 - dy1 * dx2
}

fn main() {
    let path = [(0, 0), (4, 0), (4, 3), (1, 5)];
    for w in path.windows(3) {
        println!("{}", cross(w[0], w[1], w[2]));
    }
}

cross は、格子上の点 o から a へ進み、そこから b へ向かうときに左へ曲がるなら正、右へ曲がるなら負、一直線なら0を返す関数です。経路 (0, 0), (4, 0), (4, 3), (1, 5) の連続する3点ごとに値を表示し、本来は 12 と 9 の2行を出力するはずが、いまは手元の実行で 12 を出力したあと、attempt to subtract with overflow という panic で止まります。

Answer

Wrong

    let dx1 = (a.0 - o.0) as i64;
    let dy1 = (a.1 - o.1) as i64;
    let dx2 = (b.0 - o.0) as i64;
    let dy2 = (b.1 - o.1) as i64;

as i64 は付いていますが、括弧の中の引き算は usize のまま行われ、変換はそのあとです。1組目の (0, 0), (4, 0), (4, 3) では差がすべて0以上なので 12 が出ます。2組目の (4, 0), (4, 3), (1, 5) では o が (4, 0)、b が (1, 5) なので、b.0 - o.0 は 1 − 4 です。−3 は usize で表せないので、オーバーフローを検査するデバッグビルドはここで panic します。1

Right

    let dx1 = a.0 as i64 - o.0 as i64;
    let dy1 = a.1 as i64 - o.1 as i64;
    let dx2 = b.0 as i64 - o.0 as i64;
    let dy2 = b.1 as i64 - o.1 as i64;

座標を1つずつ i64 に変換してから引けば、差が負になっても i64 の値として表せます。as は - より強く結び付くので、a.0 as i64 - o.0 as i64 は変換した2つの値の引き算です。2組目は dx1 = 0, dy1 = 3, dx2 = −3, dy2 = 5 で、0 × 5 − 3 × (−3) = 9 になります。座標そのものは負にならないので usize で持てますが、座標の差は負になりうるので、引き算の前に符号付きの型へ移す必要があります。

  1. オーバーフローの検査を外したリリースビルドでは、1 − 4 は 264 − 3 に回り込み、それを as i64 で変換すると −3 に戻ります。そのため、リリースビルドだけで試すと正しい値が出て、欠陥に気付けません。
