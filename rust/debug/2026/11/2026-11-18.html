decode2.rs

fn decode2(b0: u8, b1: u8) -> char {
    let hi = ((b0 & 0x1F) << 6) as u32;
    let lo = (b1 & 0x3F) as u32;
    char::from_u32(hi | lo).unwrap()
}

fn main() {
    for s in ["é", "π"] {
        let b = s.as_bytes();
        print!("{}", decode2(b[0], b[1]));
    }
    println!();
}

UTF-8 で2バイトになる文字を、その2バイトから char に戻す decode2 です。2バイトの文字は、1バイト目の下位5ビットと2バイト目の下位6ビットを、この順につなげた11ビットが符号位置になります。"é" と "π" を戻して並べるので éπ と出るはずが、いまは éÀ と出ます。

Answer

Wrong

let hi = ((b0 & 0x1F) << 6) as u32;

b0 & 0x1F は u8 なので、続く << 6 も u8 の8ビットの中で計算されます。8ビットからはみ出した上位のビットはここで捨てられ、そのあとで as u32 にしても戻りません。シフトする量が型の幅より小さいので、Rust はこれをオーバーフローとして扱わず、デバッグビルドでも panic しません。

"π" は 0xCF 0x80 です。0xCF & 0x1F は 0x0F で、6ビットずらすと本来は 0x3C0 ですが、u8 に残るのは下位8ビットの 0xC0 だけです。2バイト目の下位6ビットは0なので、符号位置は U+00C0 の À になります。"é" の1バイト目 0xC3 は下位5ビットが 0x03 で、ずらしても 0xC0 と8ビットに収まるため、正しく戻ります。

Right

let hi = u32::from(b0 & 0x1F) << 6;

u32::from で先に u32 に広げてからずらせば、シフトは32ビットの中で計算され、11ビットの符号位置のどのビットも落ちません。π では 0x3C0 がそのまま残り、U+03C0 の π に戻ります。as u32 で広げてもよいのですが、(b0 & 0x1F) as u32 << 6 と書くと u32<< がジェネリクスの始まりと読まれてコンパイルエラーになるので、括弧で囲む必要があります。
