2026-11-04

lot_area.rs

fn area(p: &[(i32, i32)]) -> i64 {
    let mut twice: i64 = 0;
    for w in p.windows(2) {
        let ((x0, y0), (x1, y1)) = (w[0], w[1]);
        twice += (x0 * y1 - x1 * y0) as i64;
    }
    twice.abs() / 2
}

fn main() {
    let lot = [(0, 0), (60000, 0), (60000, 50000), (0, 50000), (0, 0)];
    println!("{}", area(&lot));
}

頂点の座標を周に沿って並べ、最後に最初の頂点をもう一度置いたスライスから、土地の面積を求めるつもりの area です。main は横 60000、縦 50000 の長方形を渡します。本来は 3000000000 と表示するはずが、いまは何も表示されず、attempt to multiply with overflow で panic します。

Answer

Wrong

for w in p.windows(2) {
    let ((x0, y0), (x1, y1)) = (w[0], w[1]);
    twice += (x0 * y1 - x1 * y0) as i64;
}

as i64 が変換するのは、括弧の中の計算が終わったあとの値です。x0 も y1 も i32 なので、x0 * y1 は i32 のまま計算されます。2つ目の辺 (60000, 0) から (60000, 50000) では 60000 * 50000 が 3000000000 になり、i32 の最大値 2147483647 を超えます。デバッグビルドの Rust は整数の桁あふれを検査していて、この掛け算で panic します。

結果を受ける twice が i64 でも、掛け算の型は変わりません。リリースビルドでは検査が外れて値が黙って切り詰められ、panic の代わりに誤った面積が出ます。

Right

for w in p.windows(2) {
    let ((x0, y0), (x1, y1)) = (w[0], w[1]);
    twice += i64::from(x0) * i64::from(y1) - i64::from(x1) * i64::from(y0);
}

座標を先に i64::from で i64 にしてから掛けると、掛け算そのものが i64 で行われます。i32 の値どうしの積は、絶対値が 2 の 62 乗以下なので i64 に収まります。i64::from は値を失わない変換にしか使えないので、as と違って、うっかり狭い型へ変換していればコンパイルエラーになります。長方形の和は 6000000000 で、その半分の 3000000000 が表示されます。
