fn pick(w: &[u8], r: u64) -> usize {
    let total: u8 = w.iter().sum();
    let r = r % u64::from(total);
    let mut acc = 0;
    for (i, &x) in w.iter().enumerate() {
        acc += u64::from(x);
        if r < acc {
            return i;
        }
    }
    unreachable!()
}

fn main() {
    println!("{}", pick(&[200, 100], 250));
}

pick は、重み w の合計を T として、r を T で割った余りが、先頭から重みの数ずつ割り当てた整数のどれに当たるかで項目を選び、その添字を返すつもりの関数です。w の重みのうち少なくとも1つは正とします。main は重み 200 と 100 の2項目から、r = 250 で選んだ添字を出力します。

Answer

Wrong

let total: u8 = w.iter().sum();
let r = r % u64::from(total);

sum が返す和の型は、要素と同じ u8 です。200 に 100 を足した 300 は u8 の最大値 255 を超えるので、デバッグビルドでは足した時点で attempt to add with overflow のパニックが起きます。リリースビルドでは検査が外れ、300 を 256 で割った余りの 44 が黙って入ります1。どちらにしても、合計が 255 を超える重みでは正しく抽選できません。

Right 時間計算量 𝒪(n) 空間計算量 𝒪(1) n は w の要素数 

let total: u64 = w
    .iter()
    .map(|&x| u64::from(x))
    .sum();
let r = r % total;

足す前に各重みを u64 へ変換すれば、和も u64 で計算されます。250 を 300 で割った余りは 250 で、acc が 200 では r < acc にならず、300 になったところで添字 1 が返ります。u8 の最大値 255 を u64 であふれるまで足すには 256 個を超える要素が要り、そんな長さのスライスはメモリに置けないので、どの w でも合計はあふれません。

  1. リリースビルドで 44 になった場合、r は 250 を 44 で割った余りの 30 になり、パニックせずに添字 0 を返します。黙って違う項目を選ぶので、デバッグビルドのパニックより見つけにくい誤りです。
