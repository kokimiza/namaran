2026-11-05

powers_below.rs

fn powers_below(limit: i32) -> usize {
    std::iter::successors(Some(1), |&p| Some(p * 2)).filter(|&p| p < limit).count()
}

fn main() {
    println!("{}", powers_below(50));
}

1, 2, 4, 8, … と続く2の累乗のうち、limit 未満のものの個数を返すつもりの powers_below です。powers_below(50) は本来 6 を返して表示するはずが、いまはデバッグビルドで実行すると何も表示されず、2行目で attempt to multiply with overflow の panic が起きて終わります。

Answer

Wrong

std::iter::successors(Some(1), |&p| Some(p * 2)).filter(|&p| p < limit).count()

successors のクロージャは常に Some を返すので、このイテレータは終わりません。filter は条件に合わない値を捨てるだけで、条件が偽になっても止まりません。64を捨てたあとも128、256と次の値を求め続け、count はイテレータが終わるのを待ち続けます。値が大きくなる順に並んでいて、64以降に条件を満たす値がもう無いことは、filter には分かりません。

値は i32 なので、p が 1 << 30 に達すると、次の p * 2 は i32 の最大値を超えます。デバッグビルドでは整数のオーバーフローが検査され、ここで panic します。止まらないはずのループが panic で終わるので、症状は無限ループではなく掛け算の panic として見えます。リリースビルドでは検査が無く値が折り返すので、panic せずに回り続けます。

Right

std::iter::successors(Some(1), |&p| Some(p * 2))
    .take_while(|&p| p < limit)
    .count()

take_while は、条件が初めて偽になった時点でイテレータ全体を終わらせます。1, 2, 4, 8, 16, 32 を通したあと64で条件が偽になり、そこで終わるので count は6を返します。64より先の値は求められないので、掛け算がオーバーフローするところまで進むこともありません。大きくなる一方の列を上限で切るときは、捨てる filter ではなく、打ち切る take_while を使います。1

  1. (1..).filter(…).count() のように終わりの無い範囲を直接書いた場合は、Clippy の infinite_iter が検出します。successors のようにクロージャが次の値を決める形は、終わるかどうかを Clippy が判断できないので、警告が出ません。
