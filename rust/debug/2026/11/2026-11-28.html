status.rs

fn status(
    code: u16,
    expected: u16,
) -> &'static str {
    match code {
        expected => "ok",
        _ => "unexpected",
    }
}

fn main() {
    println!("{}", status(404, 200));
}

status は、HTTP の応答コード code が期待したコード expected と等しければ "ok" を、違えば "unexpected" を返すつもりの関数です。main は、期待したコードが 200 のときに 404 が返ってきた場合の結果を出力します。

いまの出力

ok

本来の出力

unexpected
Answer

Wrong

match code {
    expected => "ok",
    _ => "unexpected",
}

パターンに書いた名前は、外にある同じ名前の変数を参照しません。expected => "ok" の expected は、照合する値をその名前で新しく束縛するパターンで、どんな値にも一致します。引数の expected はこの腕の中では隠れ、200 と比べられることはありません。status(404, 200) では 404 が最初の腕に一致し、"ok" が返ります。2つ目の腕 _ には、どの値も届きません1。

Right 時間計算量 𝒪(1) 空間計算量 𝒪(1) 

match code {
    c if c == expected => "ok",
    _ => "unexpected",
}

値と比べるには、束縛した値をガードの if c == expected で比べます。ガードの == は式なので、この expected は引数を指します。404 は 200 と等しくないので最初の腕は選ばれず、_ の腕が "unexpected" を返します。パターンの中で値そのものと比べられるのは、200 のようなリテラルや const で定めた定数だけです。

  1. コンパイラはこのコードに、2つ目の腕に届かないという unreachable_patterns の警告と、引数の expected を使っていないという警告を出します。どちらも警告なので、コンパイルは通ります。
