stuck_rng.rs

#[derive(Clone, Copy)]
struct Rng(u64);

impl Rng {
    fn draw(mut self) -> u32 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1);
        (self.0 >> 32) as u32
    }
}

fn main() {
    let rng = Rng(9);
    let found = (0..100).map(|_| rng.draw()).find(|&n| n.wrapping_mul(3) / 3 != n);
    println!("{found:?}");
}

掛け算の桁あふれを折り返すと「3倍してから3で割ると元に戻る」が崩れる n を、乱数で作った100個の u32 から探すつもりのプロパティベーステストです。乱数は、内部の64ビットの状態を呼ぶたびに更新し、その上位32ビットを返すつもりの Rng で作ります。いまは反例が見つからず None が表示されます。本来の出力は Some(2708277318) です。

Answer

Wrong

#[derive(Clone, Copy)]
struct Rng(u64);

impl Rng {
    fn draw(mut self) -> u32 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1);
        (self.0 >> 32) as u32
    }
}

draw は self を値で受け取ります。Rng は Copy を導出しているので、rng.draw() は rng をムーブせず、そのコピーを self に渡します。mut self が書き換えるのはこのコピーの状態で、draw から戻るとコピーごと消えます。main の rng は Rng(9) のままなので、クロージャが100回呼ぶ rng.draw() は毎回同じ値450991511を返し、テストは同じ入力を100回試しているだけです。この値は3倍しても u32 に収まり、性質が成り立つので、find は None を返します。

Copy が無ければ、rng.draw() は rng をムーブし、map に渡したクロージャの中から2回目を呼べないのでコンパイルエラーになります。mut self だけ、または Copy だけなら気付けた誤りが、2つ揃ったことでコンパイルを通り、黙って同じ値を返し続けます。rng を let で宣言したまま書き換えているように見えるのに、コンパイラが mut を求めないのも、rng 自身は一度も書き換えられていないからです。

Right

#[derive(Clone, Copy)]
struct Rng(u64);

impl Rng {
    fn draw(&mut self) -> u32 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1);
        (self.0 >> 32) as u32
    }
}

&mut self で受け取れば、draw は呼び出し元の rng そのものの状態を更新します。main では let mut rng = Rng(9); と宣言し直し、クロージャは rng を可変で借用します。呼ぶたびに状態が進むので100個の入力は別々の値になり、4個目の2708277318が 1431655765 を超えるため、3倍が桁あふれして Some(2708277318) が見つかります。
