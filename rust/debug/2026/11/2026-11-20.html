partition.rs

fn partition(v: &mut [i32]) -> usize {
    let hi = v.len() - 1;
    let mut i = 0;
    for j in 0..hi {
        if v[j] <= v[hi] {
            i += 1;
            v.swap(i, j);
        }
    }
    v.swap(i, hi);
    i
}

fn main() {
    let mut v = [3, 1, 2];
    let p = partition(&mut v);
    println!("{v:?} {p}");
}

末尾の値を基準値にして、基準値以下の値をスライスの前へ集め、その直後に基準値を置いて、基準値の位置を返す partition です。[3, 1, 2] を渡すと [1, 2, 3] 1 と表示されるはずが、いまは [3, 2, 1] 1 と表示されます。

Answer

Wrong

    let mut i = 0;
    for j in 0..hi {
        if v[j] <= v[hi] {
            i += 1;
            v.swap(i, j);
        }
    }
    v.swap(i, hi);

i を 0 から始めるなら、i は「次に基準値以下の値を置く場所」で、v[..i] にそこまでの基準値以下の値が並びます。ところがこのコードは交換の前に i を増やすので、見つけた値は v[i] ではなく1つ先の v[i + 1] に置かれ、v[0] には誰も置かれません。

[3, 1, 2] では、基準値 2 以下の 1 が j = 1 で見つかり、i が 1 になってから自分自身と交換されます。ループのあとの v.swap(i, hi) は、その 1 が入っている v[1] と基準値を入れ替えるので、集めた 1 が末尾へ追い出されて [3, 2, 1] になります。返す 1 の位置には基準値がありますが、左に 3 が、右に 1 が残っています。

Right

    let mut i = 0;
    for j in 0..hi {
        if v[j] <= v[hi] {
            v.swap(i, j);
            i += 1;
        }
    }
    v.swap(i, hi);

交換してから i を増やせば、見つけた値は v[i] に入り、v[..i] は常に基準値以下の値だけになります。ループが終わったとき v[i] は基準値より大きい値か基準値自身なので、そこへ基準値を移しても集めた値は動きません。[3, 1, 2] では 1 が v[0] に入って i = 1 になり、v.swap(1, 2) で [1, 2, 3] になります。

増やしてから交換する書き方は、i を「最後に置いた場所」と読み、−1 から始める書き方の名残です1。usize は −1 を持てないので開始を 0 に変えるなら、i の意味も「次に置く場所」に変わり、増やす順と最後の交換の位置をそれに合わせる必要があります。

  1. よく知られた教科書の擬似コードは i = lo − 1 から始め、増やしてから交換し、最後に i + 1 と基準値を入れ替えて i + 1 を返します。そのまま Rust に写すと、lo が 0 のとき 0 - 1 の計算がデバッグビルドでは panic します。
