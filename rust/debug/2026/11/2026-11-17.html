transfer.rs

fn send(
    bal: &mut [i64],
    from: usize,
    to: usize,
) {
    let (f, t) = (bal[from], bal[to]);
    bal[from] = f - 10;
    bal[to] = t + 10;
}

fn main() {
    let mut bal = vec![100; 4];
    for k in 0..4 {
        send(&mut bal, k, k * 3 % 4);
    }
    println!("{}", bal.iter().sum::<i64>());
}

send は、口座 from から口座 to へ 10 を移すつもりの関数です。main は4つの口座に 100 ずつ入れ、口座 k から口座 k * 3 % 4 への送金を k = 0, 1, 2, 3 の順に1回ずつ行ってから、全口座の残高の合計を出力します。送金はお金を移すだけなので 400 が出力されるはずですが、いまは 420 が出力されます。

Answer

Wrong

fn send(
    bal: &mut [i64],
    from: usize,
    to: usize,
) {
    let (f, t) = (bal[from], bal[to]);
    bal[from] = f - 10;
    bal[to] = t + 10;
}

残高を1回ずつ追わなくても、合計だけを見れば原因が絞れます。from と to が別の口座なら、2つの書き込みは別の要素に入り、一方が 10 減ってもう一方が 10 増えるので、合計は変わりません。合計が変わりうるのは、2つの添字が同じ要素を指すときだけです。そのとき f と t はどちらも同じ残高のコピーで、bal[from] = f - 10 の書き込みは次の bal[to] = t + 10 に上書きされ、口座には元の残高より 10 多い値が残ります。

合計の増え方は 20 なので、自分自身への送金が2回あったことになります。k * 3 % 4 は k = 0, 1, 2, 3 に対して 0, 3, 2, 1 で、k = 0 と 2 で送り先が送り元と同じ口座です。ここでコピーを取っているのは、&mut bal[from] と &mut bal[to] を同時に持つと借用規則に反してコンパイルできないからでしょう。借用チェッカーがこれを拒むのは、2つの添字が同じ要素を指しうるからです。i64 は Copy なので値をコピーすればコンパイルは通りますが、同じ要素だったときの扱いは誰も確かめなくなります。

Right

fn send(
    bal: &mut [i64],
    from: usize,
    to: usize,
) {
    bal[from] -= 10;
    bal[to] += 10;
}

要素を読んで書く操作を、1つの文で完結させます。bal[from] -= 10 の可変の借用はその文の終わりで切れるので、次の bal[to] += 10 は書き換えたあとの値から始まります。from と to が同じなら、10 減らしてから 10 増やして元に戻り、別の口座なら一方が減って他方が増えるだけです。どちらの場合も合計は変わらず、400 が出力されます。2つの要素を同時に書き換える必要があるなら、同じ添字を渡すと Err を返す get_disjoint_mut を使うと、重なった場合を見落とさずに済みます1。

  1. bal.get_disjoint_mut([from, to]) は、添字が範囲外か重なっていれば Err を、そうでなければ2つの &mut i64 を返します。重なっているときにどうするか（送金を何もしない、エラーにする）を、呼び出し側で決めることになります。Rust 1.86 で安定化されました。
