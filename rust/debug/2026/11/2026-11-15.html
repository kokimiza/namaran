split_number.rs

fn split_number(name: &str) -> (&str, u32) {
    let i = name.chars().position(|c| c.is_ascii_digit()).unwrap_or(name.len());
    (&name[..i], name[i..].parse().unwrap_or(0))
}

fn main() {
    let mut names = vec!["file10", "file2", "été10", "été2"];
    names.sort_by_key(|s| split_number(s));
    println!("{names:?}");
}

split_number は名前を最初の数字の前と後ろに分け、後ろを数として読みます。それをキーにして、file2 が file10 より前に来るように並べるつもりのプログラムです。本来は ["file2", "file10", "été2", "été10"] と出るはずが、いまは ["file2", "file10", "été10", "été2"] と出ます。file の2つは正しく並ぶのに、été の2つは並びが入れ替わりません。

Answer

Wrong

let i = name.chars().position(|c| c.is_ascii_digit()).unwrap_or(name.len());
(&name[..i], name[i..].parse().unwrap_or(0))

chars().position が返すのは、何文字目かという文字の位置です。一方、&name[..i] のような文字列のスライスはバイトの位置で切ります。UTF-8 では é が2バイトなので、é を含む名前では2つの位置がずれます。ASCII だけの file10 では文字の位置とバイトの位置が同じなので、正しく ("file", 10) に分かれます。

"été10" の最初の数字は4文字目で、0 から数える position は 3 を返します。バイトで数えると é、t、é で5バイトあり、数字は位置 5 から始まります。位置 3 はたまたま2つ目の é の先頭なので panic にはならず、名前は "ét" と "é10" に分かれます。"é10" は数として読めないので unwrap_or(0) で 0 になり、"été2" も同じく ("ét", 0) になります。キーが等しい2つは、安定な sort_by_key によって元の順のまま残ります。

Right

let i = name.find(|c: char| c.is_ascii_digit()).unwrap_or(name.len());
(&name[..i], name[i..].parse().unwrap_or(0))

str::find は、条件に合う最初の文字のバイトの位置を返します。スライスと同じ単位なので、"été10" は位置 5 で "été" と "10" に分かれ、"été2" の 2 と比べて正しく並びます。find が返す位置はいつも文字の先頭なので、どんな名前でもスライスで panic しません。
