2026-11-08

version.rs

#[derive(Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Version {
    minor: u32,
    major: u32,
}

fn main() {
    let vs = [Version { major: 1, minor: 9 }, Version { major: 2, minor: 0 }];
    println!("{:?}", vs.iter().max().unwrap());
}

バージョン番号の一覧から、いちばん新しいものを選ぶつもりのプログラムです。1.9 と 2.0 を比べて、本来は Version { major: 2, minor: 0 } が表示されるはずが、いまは Version { minor: 9, major: 1 } が表示されます。

Answer

Wrong

#[derive(Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Version {
    minor: u32,
    major: u32,
}

derive で導出した PartialOrd と Ord は、フィールドを宣言した順に比べます。最初のフィールドで大小が決まればそれで終わり、等しいときだけ次のフィールドへ進みます(辞書で単語を並べるときと同じ順序です)。この構造体は minor を先に宣言しているので、1.9 と 2.0 はまず minor の9と0で比べられ、major を見る前に 1.9 の方が大きいと決まります。max はこの Ord に従って 1.9 を返し、Debug も宣言順にフィールドを並べるので、Version { minor: 9, major: 1 } と表示されます。構造体リテラルでは major から書いているので、フィールドの順が比較の順と逆だとは見えにくくなっています。

Right

#[derive(Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Version {
    major: u32,
    minor: u32,
}

比べたい順にフィールドを宣言し直すと、導出された Ord はまず major の1と2を比べ、2.0 の方が大きいと決めます。minor を見るのは major が等しいときだけになり、1.2 と 1.10 のような組も minor の数値で正しく並びます。構造体リテラルや Debug の出力はフィールド名で書かれるので、順番を入れ替えても main は変えずに済みます。
