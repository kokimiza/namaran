square_cache.rs

use std::cell::RefCell;
use std::collections::HashMap;

type Cache = RefCell<HashMap<u64, u64>>;

fn square(cache: &Cache, n: u64) -> u64 {
    match cache.borrow().get(&n) {
        Some(&v) => v,
        None => {
            let v = n * n;
            cache.borrow_mut().insert(n, v);
            v
        }
    }
}

n の2乗を返し、一度計算した値は cache に覚えておいて次から使い回す square です。空の cache で square(&cache, 3) を呼ぶと、9 を返すはずが、いまは RefCell already borrowed というメッセージで panic します。

Answer

Wrong

    match cache.borrow().get(&n) {
        Some(&v) => v,
        None => {
            let v = n * n;
            cache.borrow_mut().insert(n, v);

cache.borrow() は、借用が続いているあいだ RefCell を読み取り中にしておく Ref を返します。この Ref は名前の無い一時値で、match の対象の式で作った一時値は、match 全体が終わるまで drop されません1。get(&n) が返す参照もこの Ref から借りているので、match の腕の中まで読み取りの借用が続きます。

空の cache では None の腕に入り、まだ読み取りの借用が残っているところで borrow_mut() を呼びます。RefCell は読み取り中の書き込みの借用を実行時に断るので、ここで panic します。コンパイラはこの重なりを検査しません。RefCell の借用の規則は実行時に確かめられるものだからです。

Right

    let hit =
        cache.borrow().get(&n).copied();
    match hit {
        Some(v) => v,
        None => {
            let v = n * n;
            cache.borrow_mut().insert(n, v);

引いた結果を copied() で Option<u64> の値にして、let の文で変数に入れます。let の文で作った一時値は、その文の終わりで drop されるので、Ref は次の行に進む前に消え、読み取りの借用も終わります。hit は cache から何も借りていない値なので、None の腕で borrow_mut() を呼んでも衝突せず、9 を覚えて返します。2回目の呼び出しでは Some(9) の腕から同じ 9 が返ります。

  1. Rust 2024 エディションでは、if let の対象の式で作った一時値が else の前に drop されるように変わりました。match の対象の一時値は、2024 エディションでも match の終わりまで残ります。
