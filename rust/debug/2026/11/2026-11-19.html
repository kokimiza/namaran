replay.rs

fn main() {
    let log = "begin a=1 begin b=2 commit";
    let mut db = Vec::new();
    let mut tx = Vec::new();
    for rec in log.split(' ') {
        match rec {
            "begin" => {}
            "commit" => db.append(&mut tx),
            set => tx.push(set),
        }
    }
    println!("{db:?}");
}

書き込みのログ log を先頭から読み直し、コミットまで済んだトランザクションの更新だけを db に復元するつもりのプログラムです。ログは begin でトランザクションを始め、キー=値 の更新を並べ、commit で確定します。この log は、a=1 を書いたところでプロセスが落ち、再起動後のトランザクションが b=2 をコミットしたものです。["b=2"] と出るはずが、いまは ["a=1", "b=2"] と出て、コミットされていない a=1 が復元されています。

Answer

Wrong

match rec {
    "begin" => {}
    "commit" => db.append(&mut tx),
    set => tx.push(set),
}

tx は、いま読んでいるトランザクションの更新を commit まで溜めておく場所です。コミット済みのトランザクションなら、commit の腕の append が tx の中身をすべて db へ移し、tx は空に戻ります。ところが障害で途切れたトランザクションには commit が来ないので、a=1 は tx に残ったままです。ログは再起動後も同じファイルに続けて書かれるので、次の begin が来ますが、begin の腕は何もしません。続く b=2 が a=1 の後ろに積まれ、commit で2つまとめて db に移ります。

Right

match rec {
    "begin" => tx.clear(),
    "commit" => db.append(&mut tx),
    set => tx.push(set),
}

begin は新しいトランザクションの始まりなので、その時点で tx に残っている更新は、コミットされずに終わったトランザクションのものです。begin で tx.clear() すれば、それを捨ててから次のトランザクションを読み始められます。コミットされた直後の begin では tx はもう空なので、捨てるものはありません。ログの末尾が書きかけで終わった場合は、最後の更新が tx に残ったままループが終わり、db には入りません。
