2026-10-09

interest.rs

#[derive(Clone, Copy)]
struct Account {
    balance: u64,
}

fn main() {
    let accounts = [Account { balance: 100 }, Account { balance: 250 }];
    let mut total = 0;
    for mut account in accounts {
        account.balance += account.balance / 10;
        total += account.balance;
    }
    println!("{total} {:?}", accounts.map(|a| a.balance));
}

各口座の残高に利息として1割を足し、足したあとの合計と各口座の残高を出力するつもりのコードです。引数も標準入力も使いません。いまは 385 [100, 250] が出ますが、本来は 385 [110, 275] が出るはずです。

Answer

Wrong

    let accounts = [Account { balance: 100 }, Account { balance: 250 }];
    let mut total = 0;
    for mut account in accounts {
        account.balance += account.balance / 10;
        total += account.balance;
    }

for に配列を値のまま渡すと、for は配列を IntoIterator で消費し、要素を1つずつ値で取り出します。Account は Copy を導出しているので、このとき配列はコピーされ、account は元の要素の写しになります。account.balance に足した利息は写しに入るだけで、写しはループの1周ごとに捨てられます。account に mut が要ったのも、書き換えている相手が写しだからです。

写しの残高は110と275になるので、そこから足した total は正しく385になります。元の accounts は一度も書き換わらず、残高は100と250のままです。Account が Copy でなければ、for が配列を移動したあとで accounts を使う最後の行がコンパイルエラーになり、この取り違えに気付けたはずです。Copy を導出していたので、エラーが出ないまま写しを書き換えるコードになりました。

Right

    let mut accounts = [Account { balance: 100 }, Account { balance: 250 }];
    let mut total = 0;
    for account in &mut accounts {
        account.balance += account.balance / 10;
        total += account.balance;
    }

&mut accounts を回すと、account は各要素への可変参照 &mut Account になり、account.balance += … は配列の中の要素そのものを書き換えます。配列を書き換えるので accounts には mut が要り、写しを書き換えるための for mut account の mut は要らなくなります1。

  1. 配列が値の IntoIterator を実装したのは Rust 1.53 からです。それより前は for に配列を値で渡せず、この書き方自体がコンパイルエラーでした。
