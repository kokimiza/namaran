cells.rs

use std::num::ParseIntError;

fn add(body: &mut String, cell: &str) -> Result<(), ParseIntError> {
    *body = std::mem::take(body) + &cell.parse::<i32>()?.to_string() + ",";
    Ok(())
}

fn main() {
    let mut body = String::new();
    for cell in ["1", "2", "x", "4"] {
        if add(&mut body, cell).is_err() {
            eprintln!("skip {cell}");
        }
    }
    println!("{body}");
}

add は、表のセルを1つ数として読み、body の末尾に「数,」を書き足す関数です。数として読めないセルではエラーを返し、呼び出し側はそのセルを飛ばして続けます。main は "1" "2" "x" "4" の4つのセルを渡すので、本来は 1,2,4, と表示されるはずですが、いまは 4, と表示されます。

Answer

Wrong

*body = std::mem::take(body) + &cell.parse::<i32>()?.to_string() + ",";

+ の左辺は String を値で受け取るので、&mut String の先にある中身をそのまま渡すことはできません。そこで std::mem::take で body の中身を取り出し、代わりに空の String を置いています。clone で写すと連結のたびに全体をコピーすることになるので、取り出すこと自体は理にかなっています。

問題は取り出す時機です。二項演算子のオペランドは左から順に評価されるので、"x" のセルでは、まず mem::take が "1,2," を取り出して body を空にし、そのあとで右側の cell.parse::<i32>() が失敗します。? はそこで関数から抜けるので、代入までは進みません。取り出した "1,2," は一時的な値のまま捨てられ、body には空の String が残ります。続く "4" はこの空の body に書き足されるので、表示は 4, になります。

Right

let n: i32 = cell.parse()?;
*body = std::mem::take(body) + &n.to_string() + ",";

失敗しうる読み取りを、body から取り出す前に済ませます。? で抜けるのは body に手を付ける前になるので、"x" のセルでも body は "1,2," のまま残ります。取り出してから戻すまでの間に ? を置かなければ、同じ消え方は起きません1。

  1. body.push_str(&n.to_string()) のように &mut String へ直接書き足せば、そもそも取り出す必要がありません。push_str も + と同じく末尾に書き足すだけなので、かかる時間は足す文字数に比例します。
