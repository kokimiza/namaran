cleanup.rs

use std::time::{Duration, SystemTime};

fn expired(modified: SystemTime, max_age: Duration) -> bool {
    modified.elapsed().unwrap_or(Duration::MAX) > max_age
}

fn main() {
    let now = SystemTime::now();
    let hour = Duration::from_secs(3600);
    let files = [
        ("a.log", now - 2 * hour),
        ("b.log", now),
        ("c.log", now + Duration::from_secs(90)),
    ];
    for (name, modified) in files {
        if expired(modified, hour) {
            println!("delete {name}");
        }
    }
}

expired は、更新時刻 modified から max_age より長く経ったかどうかを返す関数で、main はそれが true になったファイルを消すつもりです。引数も標準入力も使いません。本来は delete a.log の1行だけが出力されるはずが、いまは delete a.log と delete c.log の2行が出力されます。

Answer

Wrong

modified.elapsed().unwrap_or(Duration::MAX) > max_age

c.log の更新時刻は、いまより90秒先です。SystemTime::elapsed は、いまの時刻が modified より前だと Err を返します。経過時間が負になり、Duration では表せないからです。unwrap_or(Duration::MAX) はこの Err を「この上なく古い」と読み替えるので、Duration::MAX > max_age が true になり、書かれたばかりの c.log が消されます。

更新時刻が未来になることは珍しくありません。ファイルの更新時刻は壁時計の値なので、時計が進んでいる別のマシンで書かれたり、書いたあとで NTP が時計を戻したりすると、いまより先の時刻が残ります。消すかどうかを決める場面で、経過時間が分からないものを古い側に倒すと、データを失います。

Right

modified.elapsed().unwrap_or(Duration::ZERO) > max_age

Err のときの既定値を Duration::ZERO にすると、未来の更新時刻は「いま更新された」のと同じ扱いになり、max_age を超えないので消されません。時計が追いつけば elapsed は Ok を返すようになり、そこから経過時間が普通に数えられます1。

  1. 更新時刻はファイルシステムに残る壁時計の値なので、Instant では置き換えられません。Instant は1つのプロセスの中で2つの時点の間隔を測るためのもので、ファイルに保存したり、別のマシンの時刻と比べたりする手段を持たないからです。
