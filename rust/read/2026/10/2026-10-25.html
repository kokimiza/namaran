stale_version.rs

#[derive(Clone, Copy)]
struct Row {
    version: u32,
    stock: i32,
}

fn main() {
    let mut row = Row { version: 1, stock: 10 };
    let read = row;
    let mut other = move |d: i32| {
        row.stock += d;
        row.version += 1;
        (row.version, row.stock)
    };
    print!("{:?} {:?} ", other(-3), other(-2));
    if row.version == read.version {
        row.stock = read.stock - 4;
        row.version += 1;
    }
    println!("{} {}", row.version, row.stock);
}

これは何を出力するでしょうか?

Answer

(2, 7) (3, 5) 2 6 です。

Row は Copy なので、let read = row; は row を移動せず、その時点の写しを作ります。版番号 1、在庫 10 を読んだ記録としての read は、あとで row が変わってもそのままです。

move クロージャも、捕捉した変数を自分の中へ移します。ところが Copy な値の「移動」はコピーなので、other は row の写しを自分のフィールドとして持ち、外の row は使える状態のまま残ります。そのため、move のあとで row を使う行もコンパイルエラーにはなりません。other の中の row.stock += d と row.version += 1 が書き換えるのは、この写しのほうです。

写しはクロージャが持つ状態なので、呼び出しのたびに作り直されることはありません。1回目の other(-3) で写しは版 2、在庫 7 になり、2回目の other(-2) はそこから版 3、在庫 5 に進みます。print! の引数は左から順に評価されるので、(2, 7) (3, 5) の順に出ます。

もう1人の書き手は版を2つ進めたように見えますが、外の row は版 1 のままです。row.version == read.version は真になり、衝突は見つかりません。在庫は読んだときの 10 から 4 を引いた 6、版は 2 になります。other が外の row を書き換えると読めば、版の比較で衝突が見つかって 3 5 と答えることになります。楽観的ロックの版番号は、全員が同じ1つの値を読み書きして初めて衝突を見つけられます。書き手がそれぞれ自分の写しを持っていれば、比べる相手がいません。
