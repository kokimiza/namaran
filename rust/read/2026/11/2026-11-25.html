spring_forward.rs

fn to_utc(local: i32) -> Option<i32> {
    match local {
        ..120 => Some(local - 60),
        120..180 => None,
        _ => Some(local - 120),
    }
}

fn main() {
    let r = [119, 120, 180].map(to_utc);
    println!("{r:?}");
}

これは何を出力するでしょうか?

Answer

Output

[Some(59), None, Some(60)]

match は腕を上から順に試し、最初に合った腕の式を値にします。範囲パターンの ..120 は 120 未満のすべての値に、120..180 は 120 以上 180 未満の値に合い、どちらも右端の値を含みません。119 は最初の腕に合って Some(59)、120 は2番目の腕に合って None になります。180 は 120..180 に含まれないので最後の _ まで進み、Some(60) です。

to_utc は、夏時間が始まる日の現地時刻（0時からの分）を UTC に直す関数として読めます。この地域はふだん UTC より60分進んでおり、現地の 2:00 に時計を 3:00 へ進めて、そこからは120分進んだ時刻になります。2:00 から 2:59 までの現地時刻はこの日には存在しないので、None を返します。現地の 1:59 は UTC の 0:59、3:00 は UTC の 1:00 なので、出力の 59 と 60 は、時計の上では1時間1分離れた2つの時刻が、実際には1分しか離れていないことを表しています。

120..180 を、右端も含む 120..=180 と同じように読むと、180 も2番目の腕に入り、[Some(59), None, None] と答えることになります。a..b は for 文や添字の範囲と同じく右端を含まないので、3:00 ちょうどは存在する側に入ります。
