use std::collections::BTreeMap;

fn main() {
    let log = "a=1\ncommit\na=3\nb=2\ncommit\n";
    let mut txs: Vec<&str> = log.split("commit\n").collect();
    txs.pop();
    let db: BTreeMap<&str, &str> =
        txs.iter().flat_map(|t| t.lines()).filter_map(|l| l.split_once('=')).collect();
    println!("{db:?}");
}

これは何を出力するでしょうか?

Answer

Output

{"a": "3", "b": "2"}

このプログラムは、更新を記録したログ log から、コミットまで書き終えた更新だけを取り出して再生します。log.split("commit\n") は区切りの文字列が現れるたびに切り、区切り自体は捨てて、その前後の部分を返します。区切りが k 回現れれば部分は必ず k + 1 個で、区切りが末尾にあれば、そのあとの空文字列 "" も1つの部分として返ります。このログは commit\n で終わっているので、txs は ["a=1\n", "a=3\nb=2\n", ""] の3つです。最後の部分は最後のコミットより後ろに書かれた、まだコミットされていない更新で、pop はそれを捨てます。ここで捨てられるのは空文字列なので、2つのトランザクションはどちらも残ります。

残った部分を lines で行に分け、split_once('=') でキーと値の組にすると、("a", "1")、("a", "3")、("b", "2") がこの順に並びます。BTreeMap へ collect すると、組は前から順に挿入され、同じキーがもう一度来たときは後の値で上書きされます。"a" の値はログで後に書かれた "3" になり、更新を書いた順に再生した結果と一致します。BTreeMap の Debug 表示はキーの順に並び、&str は引用符付きで表示されます。

split が末尾の空文字列を返さないと考えると、pop が2つ目のトランザクションを捨てることになり、{"a": "1"} と答えます。末尾の空文字列には気付いても、collect では先に入った値が残ると考えると、{"a": "1", "b": "2"} と答えます。正しい答えには、捨てる部分が空であることと、後の値が残ることの両方が要ります。
