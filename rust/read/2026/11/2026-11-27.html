lottery.rs

use std::collections::BTreeMap;

fn main() {
    let w = [('a', 2), ('b', 0), ('c', 3)];
    let mut m = BTreeMap::new();
    let mut acc = 0;
    for (k, x) in w {
        acc += x;
        m.insert(acc, k);
    }
    for r in 0..acc {
        let (_, k) =
            m.range(r + 1..).next().unwrap();
        print!("{k}");
    }
    println!();
}

これは何を出力するでしょうか?

Answer

Output

bbccc

1つ目のループは、重みの累積和をキー、項目の名前を値にして m に入れます。a のあと acc は 2 で、m は {2: 'a'} です。b の重みは 0 なので acc は 2 のままで、m.insert(2, 'b') は既にあるキー 2 に入ります。BTreeMap::insert は、キーが既にあれば値を新しいものに置き換え、古い値を Some('a') として返します。返り値は捨てているので、a は表から黙って消え、m は {2: 'b'} になります。c のあとは {2: 'b', 5: 'c'} です。

2つ目のループの m.range(r + 1..) は、キーが r + 1 以上、つまり r より大きいものを小さい順に並べ、next がその最初を取ります。キー 2 の項目は r が 0 と 1 のとき、キー 5 の項目は r が 2, 3, 4 のときに引かれます。キー 2 の値はもう 'b' なので、出力は bbccc です。

重み0の b は区間を持たないので選ばれない、と考えると、insert の置き換えを見落として aaccc と答えることになります。range(r + 1..) をキーが r 以上のものと読み違えると、キー 2 が r = 2 まで受け持って、c は2回しか出ません。重み0の項目は累積和を変えないのでキーがぶつかり、ぶつかったキーでは後から入れた値が残ります。この2つが同じ箇所で重なって、a の当たりがそっくり b に移ります1。

  1. C++ の std::map::insert は逆に、キーが既にあれば何も変えずに古い値を残します。Rust で古い値を残したいときは m.entry(acc).or_insert(k) と書きます。
