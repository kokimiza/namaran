size.rs

trait Size {
    fn len(&self) -> usize {
        0
    }
}

impl Size for Vec<i32> {}

fn size<T: Size>(x: &T) -> usize {
    x.len()
}

fn main() {
    let v = vec![4, 5, 6];
    println!("{} {}", v.len(), size(&v));
}

これは何を出力するでしょうか?

Answer

Output

3 0

Vec<i32> には、標準ライブラリが impl ブロックで直接定義した len(固有メソッド)があり、さらにこのコードでトレイト Size を実装したので、既定の本体を持つ Size::len も使えます。同じ名前のメソッドが両方にあるとき、v.len() は固有メソッドを先に選びます。そのため1つ目の値は要素数の 3 です。

size の中の x.len() は事情が違います。ジェネリック関数の本体は、T に何が来るかを知らないまま、トレイト境界 T: Size だけを頼りに1度だけ型検査されます。T について分かっているのは Size のメソッドを持つことだけなので、x.len() は Size::len に決まり、T が Vec<i32> になっても変わりません。既定の本体が0を返すので、2つ目の値は 0 です。

C++ のテンプレートのように、実際の型を当てはめてから呼び出しを決めると考えると、size(&v) でも Vec の len が呼ばれて 3 3 と答えます。逆に、トレイトを実装すると同名のメソッドが置き換わると考えると、0 0 と答えることになります。
