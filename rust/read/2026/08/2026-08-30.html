midpoint.rs

fn mid(lo: i32, hi: i32) -> i32 {
    (lo + hi) / 2
}

fn main() {
    let base = mid(1, 2);
    for k in [1, -1, -2, -3] {
        let shifted = mid(1 + k, 2 + k);
        print!("{} ", shifted == base + k);
    }
    println!();
}

これは何を出力するでしょうか?

Answer

Output

true true false false

main は、mid の正しい値を知らないまま、「区間の両端を k だけずらせば、中点も k だけずれるはず」という関係が成り立つかを4つの k で確かめています。基準の base は mid(1, 2) で、3 / 2 の商の 1 です。

Rust の整数の / は、商の小数部分を 0 に向かって切り捨てます。正の数なら切り下げと同じですが、負の数では切り上げになります。k = 1 は mid(2, 3) が 5 / 2 で 2、k = -1 は mid(0, 1) が 1 / 2 で 0 なので、どちらも base + k と一致して true です。k = -2 では mid(-1, 0) が -1 / 2 で、-0.5 を 0 に向かって切り捨てた 0 になり、期待する -1 と食い違います。k = -3 の mid(-2, -1) も -3 / 2 が -1 になって、期待する -2 と食い違います。

割り算を切り下げだと思って読むと、-1 / 2 を -1、-3 / 2 を -2 と計算し、4つとも true と答えてしまいます。和が負の奇数になると、mid の結果は切り下げより1大きくなり、ずらした関係が崩れます。この検査は、正しい中点の値を1つも書かずに、mid が負の範囲で切り下げとは違う値を返すことを見つけています。1

  1. このように、正しい出力が分からない計算を、入力を変えたときに出力がどう変わるはずかという関係で確かめる方法を、メタモルフィックテスト(metamorphic testing)と呼びます。切り下げの割り算が要るなら、i32::div_euclid を使うと (-1).div_euclid(2) は -1 になります。
