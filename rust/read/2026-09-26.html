seat_guard.rs

use std::sync::Mutex;

fn state(m: &Mutex<Vec<u32>>) -> &'static str {
    if m.try_lock().is_ok() { "free" } else { "held" }
}

fn main() {
    let seats = Mutex::new(vec![7]);

    let left = seats.lock().unwrap().len();
    println!("1 {left} {}", state(&seats));

    if let Some(&n) = seats.lock().unwrap().last() {
        println!("2 {n} {}", state(&seats));
    }

    match seats.lock().unwrap().pop() {
        Some(n) => println!("3 {n} {}", state(&seats)),
        None => println!("3 none {}", state(&seats)),
    }

    if let Some(n) = seats.lock().unwrap().pop() {
        println!("4 {n} {}", state(&seats));
    } else {
        println!("4 none {}", state(&seats));
    }
}

これは何を出力するでしょうか?

Answer

1 1 free、2 7 held、3 7 held、4 none free の4行が出力されます。

seats.lock().unwrap() が返す MutexGuard は、どの変数にも束縛されない一時値で、ロックはこのガードが破棄されるまで外れません。各行の free と held は、state を呼んだ時点でその一時値がまだ生きているかを表しています。一時値がいつ破棄されるかは、それを含む構文で決まります。

1行目の let 文では、一時値は文の終わりで破棄されます。left に残るのは len() が返した usize のコピーだけで、表示の時点でロックは外れています。2行目の if let では、条件の式で作った一時値が本体の終わりまで生きるので、本体の中ではロックを握ったままです。3行目の match も同じで、対象の式の一時値は match 全体の終わりまで生き、どの腕に入っても held になります。4行目では pop() が None を返して else に入ります。Rust 2024 からは、if let の一時値は else に入る前に破棄されるので、ここは free です1。

free と held の差は、確認してから使うまでの間にロックが外れているかどうかの差でもあります。1行目の left は表示した瞬間にもう古いかもしれない値で、この数を見て座席を割り当てると、その間に他のスレッドが割り込めます。確認した時点(time of check)と使う時点(time of use)の間に状態が変わる、TOCTOU と呼ばれる競合です。2行目と3行目では、取り出した値を使う間もロックが続いているので、この心配はありません。その代わり、本体の中でもう一度 lock() を呼ぶと戻ってこないので、ここでは待たずに結果を返す try_lock で調べています2。

  1. Rust 2021 までは、if let の一時値は else の終わりまで生きていたので、4行目も held でした。else の中で同じ Mutex をもう一度ロックするコードは、2021 ではデッドロックし、2024 では動きます。
  2. ロックを握っているスレッド自身が std::sync::Mutex をもう一度 lock() したときの動作は規定されておらず、デッドロックかパニックになります。try_lock は、ロックが取れなければ待たずに Err を返します。
