offset_vs_cursor.rs

fn page_offset(ids: &[u32], offset: usize, limit: usize) -> Vec<u32> {
    ids.iter().skip(offset).take(limit).copied().collect()
}

fn page_after(ids: &[u32], after: u32, limit: usize) -> Vec<u32> {
    ids.iter().filter(|&&id| id > after).take(limit).copied().collect()
}

fn main() {
    let mut ids = vec![1, 2, 3, 4, 5, 6];
    let first = page_offset(&ids, 0, 3);
    ids.remove(0);
    let by_offset = page_offset(&ids, 3, 3);
    let by_cursor = page_after(&ids, first[2], 3);
    println!("{first:?} {by_offset:?} {by_cursor:?}");
}

これは何を出力するでしょうか?

Answer

[1, 2, 3] [5, 6] [4, 5, 6] を出力します。

1ページ目は [1, 2, 3] です。そのあと ids.remove(0) で先頭の 1 が消え、ids は [2, 3, 4, 5, 6] に詰まります。page_offset の skip(3) は値ではなく位置で3つ飛ばすので、2, 3, 4 が飛ばされて2ページ目は [5, 6] になり、4 はどちらのページにも出てきません。

page_after は、1ページ目の最後の値 first[2] である 3 より大きいidを探すので、あいだで行が消えても [4, 5, 6] を返します。SQLの LIMIT 3 OFFSET 3 と WHERE id > 3 ORDER BY id LIMIT 3 の違いも同じで、ページの境目を行の数で覚えるか、最後に見た値で覚えるかで分かれます。逆に行が増えた場合、OFFSET方式は同じ行を2回返します。
