replay.rs

struct Lcg(u32);

impl Lcg {
    fn next(&mut self) -> u32 {
        self.0 = (self.0 * 5 + 1) % 16;
        self.0
    }
}

fn main() {
    let saved = [Some(9), None, Some(4)];
    let mut rng = Lcg(3);
    let a: Vec<u32> = saved.iter().map(|s| s.unwrap_or(rng.next())).collect();
    let mut rng = Lcg(3);
    let b: Vec<u32> = saved.iter().map(|s| s.unwrap_or_else(|| rng.next())).collect();
    println!("{a:?} {b:?}");
}

これは何を出力するでしょうか?

Answer

[9, 1, 4] [9, 0, 4] です。

Lcg(3) は、next を呼ぶたびに 0, 1, 6, … を返します。3 × 5 + 1 = 16 を 16 で割った余りが 0、次が 0 × 5 + 1 = 1、その次が 1 × 5 + 1 = 6 です。2つの rng は同じシード 3 から始まるので、返す値の並びも同じです。結果の違いは、それぞれが next を何回呼ぶかから生まれます。

unwrap_or(rng.next()) は普通のメソッド呼び出しなので、s が Some でも None でも、呼ぶ前に引数の rng.next() が評価されます。a を作るときは要素ごとに1回ずつ next が呼ばれ、2番目の None が受け取るのは2回目の値 1 です。Some(9) と Some(4) のときに引いた 0 と 6 は、使われずに捨てられます。

unwrap_or_else に渡したクロージャは、s が None のときにしか呼ばれません。b を作るときに next が呼ばれるのは None の1回だけなので、最初の値 0 がそのまま入ります。同じシードでも、記録した値で済ませた要素の分まで乱数を引くかどうかで、その後に続く値がずれます。
