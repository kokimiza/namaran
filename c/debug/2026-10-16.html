port_slot.c

#include <stdio.h>

static const int *find(const int *first, const int *last, int v) {
    while (first != last && *first != v) {
        first++;
    }
    return first;
}

int main(void) {
    const int ports[] = {22, 80, 443};
    const int want[] = {443, 8080};
    for (int i = 0; i < 2; i++) {
        const int *p = find(ports, ports + 3, want[i]);
        if (p != NULL) {
            printf("%d: slot %td\n", want[i], p - ports);
        } else {
            printf("%d: closed\n", want[i]);
        }
    }
}

main は、want の各ポート番号が ports の何番目にあるかを find で調べ、無いものには closed と出すつもりのコードです。入力は want の 443 と 8080 です。いまは 443: slot 2 と 8080: slot 3 の2行が出ます。本来の出力は 443: slot 2 と 8080: closed です。

Answer

Wrong

if (p != NULL) {

find は、見つからなかったことを NULL ではなく、受け取った範囲の終わり last を返して伝えます。8080 は ports に無いので、while は first が last に追いつくまで回り、戻り値は ports + 3 です。このポインタは配列の末尾の1つ先を指す正しい値で、NULL と等しくなることはありません。p != NULL が真になり、p - ports の 3 が見つかった位置として出力されます。

この分岐の中で *p を読んでいたら、出力が誤るだけでは済まず、配列の外を読む未定義動作になります。末尾の1つ先のポインタは、作ることも比べることも許されていますが、指す先を読むことは許されていません。

Right

if (p != ports + 3) {

見つかったかどうかは、find に渡した終わりの ports + 3 と比べて判定します。同じ配列を指す2つのポインタの比較なので、末尾の1つ先を相手にしても定義された結果になり、8080 では偽になって 8080: closed が出ます。find の側を変えて見つからないときに NULL を返す形にもできますが、そうすると呼び出し側は、範囲の終わりと NULL のどちらと比べるかを関数ごとに覚えることになります1。

  1. C の標準ライブラリでは、strchr や bsearch は見つからないときに NULL を返します。C++ の std::find は、このコードの find と同じく範囲の終わりを返します。C で C++ 流の関数を書くと、この2つの流儀が同じコードベースに混ざります。
