fetch_authors.c

#include <stdbool.h>
#include <stdio.h>

static void fetch_authors(const int *ids, size_t n) {
    printf("SELECT * FROM users WHERE id IN (");
    const char *sep = "";
    for (size_t i = 0; i < n; i++) {
        bool seen[100] = {false};
        if (!seen[ids[i]]) {
            seen[ids[i]] = true;
            printf("%s%d", sep, ids[i]);
            sep = ", ";
        }
    }
    printf(")\n");
}

int main(void) {
    int author_ids[] = {3, 1, 3, 3, 1};
    fetch_authors(author_ids, 5);
}

投稿の著者IDの列から重複を除き、1本の IN 句で著者をまとめて取得する SQL を出力する fetch_authors です。入力は main のとおり、著者ID {3, 1, 3, 3, 1} です。いまの出力は SELECT * FROM users WHERE id IN (3, 1, 3, 3, 1) で、重複が残っています。本来の出力は SELECT * FROM users WHERE id IN (3, 1) です。どこを直せばよいでしょうか?

Answer

bool seen[100] = {false}; を for の前へ移します。

seen はループ本体のブロックの中で宣言されています。ブロックの中で宣言した変数はブロックに入るたびに新しく作られ、初期化子があればそのたびに初期化されます。そのため反復ごとに seen は全要素が false に戻り、前の反復で true にした印は次の反復に残りません。どの ID も初めて見たものと判定されて、5つすべてが出力されます。

ループの前で一度だけ宣言すれば、seen は関数の呼び出し1回のあいだ生き続け、印が反復をまたいで残ります。2つ目の 3 と、2つ目以降の 1 が飛ばされて IN (3, 1) になります。

static bool seen[100]; にしても今回の出力は直ります。ただし今度は、fetch_authors を2回呼ぶと1回目の印が残ったままになり、2回目の IN 句から ID が抜け落ちます。
