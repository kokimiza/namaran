reversed_same.c

#include <stdio.h>

static int last(const int *a) {
    return a[2];
}

static bool reversed_same(int (*f)(const int *)) {
    int a[] = {3, 1, 2};
    int *b = a;
    int t = b[0];
    b[0] = b[2];
    b[2] = t;
    return f(a) == f(b);
}

int main(void) {
    puts(reversed_same(last) ? "same" : "differs");
}

reversed_same は、計算 f が配列 {3, 1, 2} と、それを逆順にした {2, 1, 3} とで同じ値を返すかを調べる関数です。末尾の要素を返す last を渡して呼ぶと、いまは same と出力されます。本来の出力は differs です。

Answer

Wrong

int a[] = {3, 1, 2};
int *b = a;
int t = b[0];
b[0] = b[2];
b[2] = t;
return f(a) == f(b);

int *b = a; で作られるのは配列のコピーではなく、a の先頭を指すポインタです。続く入れ替えは b を通して a そのものを {2, 1, 3} に書き換えるので、f(a) と f(b) は同じ配列を見て、last はどちらにも 3 を返します。比べる2つが同じ配列なので、どんな f を渡しても same になります。

Right

int a[] = {3, 1, 2};
int b[] = {a[0], a[1], a[2]};
int t = b[0];
b[0] = b[2];
b[2] = t;
return f(a) == f(b);

b を a の要素で初期化した別の配列にすれば、入れ替えは b にだけ起きます。a は {3, 1, 2} のまま残り、last(a) は 2、last(b) は 3 なので differs が出ます。

この関数のように、正しい出力の代わりに入力の変え方と出力の変わり方の関係を確かめる検査を、メタモルフィックテスト（metamorphic testing）といいます。比べる2つの入力が同じものを指していると、検査は何も確かめないまま成功し続けます1。

  1. 検査が常に成功してしまう欠陥は、検査が通っているあいだは表に出ません。last のように結果が順序で変わると分かっている関数を渡し、検査がそれを見つけられるかを試しておくと、この種の欠陥に気付けます。コードにわざと誤りを入れてテストが失敗するかを調べる、ミューテーションテスト（mutation testing）と同じ考え方です。
