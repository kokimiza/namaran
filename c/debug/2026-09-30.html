report.c

#include <stdio.h>
#include <stdlib.h>

static const char *label;

static void report(void) {
    printf("%s: done\n", label);
}

int main(void) {
    char name[16] = "job-42";
    label = name;
    atexit(report);
    puts("working");
    return 0;
}

このプログラムは、終了するときに report で仕事の名前を出力するつもりです。引数も標準入力も使いません。実行すると、本来は working の次の行に job-42: done と出るはずですが、いまは2行目の job-42 の部分が読めない文字の並びになり、その中身も実行するたびに変わります。

Answer

Wrong

int main(void) {
    char name[16] = "job-42";
    label = name;
    atexit(report);
    puts("working");
    return 0;
}

main から return 0 で戻ると、exit(0) を呼んだのと同じ終了処理が始まり、その中で report が呼ばれます。ただし終了処理が始まるのは main から戻ったあとで、その時点で main の自動変数 name の寿命はもう終わっています。label が指しているのは、寿命の尽きた配列です。

寿命の尽きた変数を読むのは未定義動作です。name が置かれていたスタックの領域は、終了処理を進める関数の呼び出しで上書きされ、report はそこに残ったバイトを文字列として出力します。上書きされる中身はアドレスの配置によって変わるので、化け方も実行のたびに変わります。

Right

    static char name[16] = "job-42";

static を付けると name は静的記憶域期間を持ち、プログラムの実行中ずっと、終了処理の間も生きています。atexit で登録した関数が読むデータは、main の中で用意するものでも、ファイル有効範囲の変数か static の変数に置きます1。

  1. return 0 を exit(0) に変えても、この例は正しく動きます。main の中から exit を呼ぶと、main はまだ戻っていないので、name が生きたまま終了処理が進むからです。ただし、誰かが最後を return に書き戻せば同じバグが戻ってきます。setvbuf で標準出力のバッファに main の自動変数の配列を渡したときも、同じ順序が問題になります。バッファの吐き出しは終了処理の中で行われるので、そのときには配列の寿命が終わっています。
