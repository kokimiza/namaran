flags.c

#include <stdint.h>
#include <stdio.h>

enum { F_READ = 0x001, F_ADMIN = 0x100 };

uint8_t has_flag(unsigned flags,
                 unsigned f) {
    return flags & f;
}

int main(void) {
    unsigned user = F_READ | F_ADMIN;
    if (has_flag(user, F_ADMIN)) {
        puts("admin");
    } else {
        puts("guest");
    }
}

has_flag は、flags に f のビットが立っているかを判定するつもりの関数です。F_READ と F_ADMIN を両方立てた user について has_flag(user, F_ADMIN) を調べると、本来は admin と出力するはずが、いまは guest と出力します。

Answer

Wrong

uint8_t has_flag(unsigned flags,
                 unsigned f) {
    return flags & f;
}

flags & f の値は 0x101 & 0x100 で 0x100（10進で 256）になり、0 ではありません。ところが関数の戻り値の型は uint8_t なので、return の時点で 256 は uint8_t に変換されます。符号なし整数型への変換は、その型で表せる個数（uint8_t なら 256）で割った余りを残すので、0x100 は 0 になります。if が受け取るのは変換後の 0 なので、guest の側へ進みます。

if (flags & f) と直接書けば正しく動くので、見慣れた式をそのまま関数に包んだだけに見えます。違いは、0 かどうかを調べる前に、戻り値の型への変換が1回挟まることです。下位8ビットに立っているフラグ（F_READ など）は変換しても残るため、この欠陥は 0x100 以上のフラグを調べたときにだけ表に出ます。

Right

bool has_flag(unsigned flags, unsigned f) {
    return flags & f;
}

戻り値の型を bool にすると、return での変換は余りを取るのではなく、0 なら false、それ以外なら true にする変換になります1。256 は 0 ではないので true が返り、admin と出力されます。どのビットのフラグでも、flags & f が 0 でない限り true になるので、フラグの位置によって結果が変わることはありません。C23 では bool が予約語なので、<stdbool.h> を読み込まずに書けます。

  1. _Bool が C99 で入るまでは、typedef unsigned char BOOL; のような自作の真偽値型がよく使われ、ビット演算の結果を代入して同じ欠陥を生みました。
