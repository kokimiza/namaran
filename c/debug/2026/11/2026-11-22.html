range_min.c

#include <stdio.h>

int query(
    int k, int lo, int hi, int l, int r) {
    const int t[] = {0, 1, 3, 1, 4, 3, 9, 1};
    if (r <= lo || hi <= l)
        return 0;
    if (l <= lo && hi <= r)
        return t[k];
    int mid = (lo + hi) / 2;
    int a = query(2 * k, lo, mid, l, r);
    int b = query(2 * k + 1, mid, hi, l, r);
    return a < b ? a : b;
}

int main(void) {
    printf("%d\n", query(1, 0, 4, 0, 3));
}

t は葉に 4, 3, 9, 1 を持つセグメント木で、query(k, lo, hi, l, r) は、節点 k が受け持つ lo 以上 hi 未満の位置のうち、l 以上 r 未満にある値の最小値を返すつもりの関数です。query(1, 0, 4, 0, 3) は先頭3つの 4, 3, 9 の最小値 3 を出力するはずが、いまは 0 を出力します。

Answer

Wrong

    if (r <= lo || hi <= l)
        return 0;

query(1, 0, 4, 0, 3) は、根の範囲 0〜3 が求める範囲 0〜2 に収まらないので、左右の子に分かれます。左の節点 2 は範囲 0〜1 がまるごと入るので t[2] の 3 を返します。右の節点 3 は範囲 2〜3 の半分だけが入るのでさらに分かれ、節点 6 は 9 を返し、範囲の外にある節点 7 は return 0; で 0 を返します。節点 3 の結果は min(9, 0) で 0 になり、根も min(3, 0) で 0 です。

範囲の外の節点が返す値は、本来は答えに何の影響も与えてはいけません。和を求めるセグメント木なら 0 を足しても和は変わりませんが、最小値をとる場合の 0 は、葉のどの値よりも小さい本物の候補として勝ってしまいます。

Right

    if (r <= lo || hi <= l)
        return INT_MAX;

範囲の外では int の最大値 INT_MAX を返します（<limits.h> を取り込みます）。どんな x についても min(x, INT_MAX) は x なので、範囲の外の節点は比べ合いに加わっても結果を変えません。節点 3 は min(9, INT_MAX) で 9 を返し、根は min(3, 9) で 3 になります。最小値をとる演算にとっての INT_MAX は、足し算にとっての 0 にあたる値です。こうした値を単位元1と呼び、和の木を最小値の木に書き換えるときは、範囲の外で返す単位元も一緒に替える必要があります。

  1. 単位元（たんいげん、identity element）は、ある演算で相手をそのまま残す値のことです。足し算では 0、掛け算では 1、2つのうち小さいほうをとる演算では、とりうる値の最大値がそれにあたります。
