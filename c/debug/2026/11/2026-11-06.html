print_radix.c

#include <stdint.h>
#include <stdio.h>

void print_radix(uint32_t x, int k) {
    for (int s = 32 - k; s >= 0; s -= k) {
        putchar("0123456789abcdef"[(x >> s) & ((1u << k) - 1)]);
    }
    putchar('\n');
}

int main(void) {
    print_radix(493, 4);
    print_radix(493, 3);
}

print_radix(x, k) は、32ビットの x を2の k 乗進数で表し、先頭の0も省かずに全桁を1行に表示するつもりの関数です。k には1、3、4のどれかを渡します。main のとおり493を16進数と8進数で表示すると、いまは 000001ed と 0000000173 が出ます。本来の出力は 000001ed と 00000000755 です。

Answer

Wrong

for (int s = 32 - k; s >= 0; s -= k) {
    putchar("0123456789abcdef"[(x >> s) & ((1u << k) - 1)]);
}

2の k 乗進数の1桁は k ビットで、桁の区切りは最下位ビットから k ビットずつ数えて決まります。ループの s は各桁の最下位ビットの位置で、(x >> s) & ((1u << k) - 1) がその桁を取り出します。ところが s は 32 - k から始まるので、区切りは最上位ビットの側から数えられています。k = 4 では 28, 24, …, 0 と進み、32が4で割り切れるので最後にちょうど0に着き、16進数は正しく出ます。k = 3 では 29, 26, …, 2 と進んだあと、次の -1 でループを抜けます。ビット0と1は一度も読まれず、すべての区切りが本来の位置から2ビット上にずれます。

493は2進数で 111101101 です。本来の区切りなら下から 101、101、111 の 5, 5, 7 になります。ずれた区切りではビット2〜4、5〜7、8〜10を読むので、493 >> 2 = 123 の下3ビットが3、493 >> 5 = 15 の下3ビットが7、493 >> 8 = 1 が1になり、上位の0が7桁付いた 0000000173 が表示されます。「32は3で割り切れないので、はみ出した最上位の桁が欠けるだけだ」と考えると、桁が1つ減った 0000000755 を予想します。実際に欠けるのは最下位の2ビットで、その影響は全部の桁に及びます。

Right

for (int s = 31 / k * k; s >= 0; s -= k) {
    putchar("0123456789abcdef"[(x >> s) & ((1u << k) - 1)]);
}

31 / k * k は31以下で最大の k の倍数です。s が k の倍数から始まれば、k ずつ減らしたときに必ず0を通るので、区切りが最下位ビットにそろいます。k = 3 では s が30から始まって11桁を表示し、00000000755 になります。32ビットのうち最上位の桁はビット30と31の2ビットしか持たず、x >> 30 は0〜3にしかなりませんが、マスクは3ビット分のままで困りません。k = 4 では 31 / 4 * 4 が28、k = 1 では31なので、16進数と2進数の出力は前と変わりません。
