count_valid.c

#include <setjmp.h>
#include <stdio.h>

int main(void) {
    jmp_buf env;
    int xs[] = {3, 1, -4, 1};
    int count = 0;
    if (setjmp(env) != 0) {
        printf("%d valid\n", count);
        return 1;
    }
    for (int i = 0; i < 4; i++) {
        if (xs[i] < 0) {
            longjmp(env, 1);
        }
        count++;
    }
}

配列 xs を先頭から調べ、負の値に出会うまでに何個の値が有効だったかを出力するつもりのプログラムです。xs は {3, 1, -4, 1} なので 2 valid が出るはずです。最適化なしでビルドすると 2 valid が出ますが、-O2 を付けてビルドすると 0 valid が出ます。

Answer

Wrong

int count = 0;
if (setjmp(env) != 0) {
    printf("%d valid\n", count);
    return 1;
}

count は setjmp を呼んだあとのループで 0 から 2 まで増え、そのあと longjmp で if の中へ戻ってから読まれます。C の規格では、setjmp を呼んだ関数の局所変数のうち、volatile でなく、setjmp から longjmp までの間に書き換えたものは、longjmp のあとで値が不定になります。printf に渡す count がまさにそれで、何が出ても規格の上では誤りではありません。

-O2 では、コンパイラは count をメモリに置かずレジスタに持ちます。setjmp は呼ばれた時点のレジスタを env に保存し、longjmp はそれを書き戻すので、count のレジスタはループで増やす前の 0 に戻ります。最適化なしでは count がメモリに置かれるので 2 が残りますが、それはたまたまです。

Right

volatile int count = 0;
if (setjmp(env) != 0) {
    printf("%d valid\n", count);
    return 1;
}

volatile を付けると、count を読み書きするたびにメモリへアクセスすることになり、コンパイラは値をレジスタだけに持てなくなります。規格も、volatile の局所変数は longjmp のあとで最後に書いた値を持つと定めています。そのため最適化の有無にかかわらず 2 valid が出ます。
