stock.c

#include <stdio.h>

static void put_int(int v) {
    printf("%d\n", v);
}

static void put_unsigned(unsigned v) {
    printf("%u\n", v);
}

#define PUT(x) _Generic((x), int: put_int, unsigned: put_unsigned)(x)

int main(void) {
    unsigned stock[] = {4, 0, 7};
    for (int i = 0; i < 3; i++) {
        PUT(stock[i] > 0 ? stock[i] : -1);
    }
}

品目ごとの在庫数を1行に1つずつ出し、在庫が0の品目には在庫数の代わりに -1 を出すつもりのプログラムです。stock が {4, 0, 7} のとき、本来は 4、-1、7 を1行ずつ出すはずが、いまは 4、4294967295、7 が出ます。

Answer

Wrong

        PUT(stock[i] > 0 ? stock[i] : -1);

_Generic が関数を選ぶのはコンパイルのときで、手がかりは制御式の型だけです。ループの各回でどちらの枝を通るかは、選択に関係しません。そこで見るべきなのは、条件演算子の式 stock[i] > 0 ? stock[i] : -1 全体が持つ1つの型です。2つ目と3つ目のオペランドが算術型なら、条件演算子は両者に通常の算術変換をかけ、その共通の型を式の型にします。unsigned と int の共通の型は unsigned なので、この式はどの回でも unsigned で、PUT は毎回 put_unsigned を選びます。

在庫が0の回は -1 の枝を通りますが、その値も式の型 unsigned に変換されます。-1 を unsigned に変換すると、unsigned の最大値 UINT_MAX になります。手元の処理系では unsigned が32ビットなので、put_unsigned は 4294967295 を出しました。1回ずつ値を追って「この回は -1 だから put_int」と考えると、この出力は説明できません。

Right

        if (stock[i] > 0) {
            PUT(stock[i]);
        } else {
            PUT(-1);
        }

PUT を枝ごとに呼べば、_Generic はそれぞれの式の型で関数を選びます。stock[i] は unsigned なので put_unsigned が、-1 は int なので put_int が選ばれ、在庫0の品目に -1 が出ます。型で分岐するマクロに渡す式は、実行時の分岐をまたがないようにすれば、各呼び出しで選ばれる関数がその場の型と一致します。
