apply_op.c

int add(int a, int b) {
    return a + b;
}

int sub(int a, int b) {
    return a - b;
}

int (*const ops[])(int, int) = {add, sub};

int apply(unsigned op, int a, int b) {
    if (op >= sizeof ops) {
        return 0;
    }
    return ops[op](a, b);
}

演算の番号 op で ops から関数を選んで呼び、範囲外の番号なら 0 を返すつもりの apply です。printf("%d %d\n", apply(1, 7, 3), apply(2, 7, 3)); で2つの結果を表示すると、いまは何も表示されずに異常終了します。手元のビルドでは毎回 Segmentation fault で終わりましたが、どう壊れるかは決まっていません。本来は 4 0 と表示されるはずです。

Answer

Wrong

int apply(unsigned op, int a, int b) {
    if (op >= sizeof ops) {
        return 0;
    }
    return ops[op](a, b);
}

sizeof ops が返すのは、配列 ops の要素の個数ではなく、配列全体のバイト数です。ops は関数ポインタ2つの配列なので、ポインタ1つが8バイトの環境では 16 になります。apply(2, 7, 3) の op は 2 で、2 >= 16 は偽なので、0 を返す枝を通らずに ops[2] を読みます。

ops[2] は配列の外にあり、そこを関数ポインタとして読んで呼び出すのは未定義動作です。たまたま隣にあるメモリの値を関数の場所として飛ぶので、手元のビルドでは落ちました。2つの apply は printf より先に評価されるので、apply(1, 7, 3) の結果も表示されません。

Right

int apply(unsigned op, int a, int b) {
    if (op >= sizeof ops / sizeof ops[0]) {
        return 0;
    }
    return ops[op](a, b);
}

配列全体のバイト数を要素1つのバイト数で割ると、要素の個数になります。sizeof ops / sizeof ops[0] はポインタの大きさに関係なく 2 なので、2 以上の番号は 0 を返す枝に入り、4 0 と表示されます。この式は初期化子から数えた要素数をそのまま使うので、ops に演算を足しても検査を書き換える必要はありません。
