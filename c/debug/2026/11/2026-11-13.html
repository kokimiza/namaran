country.c

#include <stdio.h>
#include <string.h>

static const char codes[][3] = {"JP", "USA", "UK"};

static int find(const char* code) {
    for (int i = 0; i < 3; i++) {
        if (strcmp(codes[i], code) == 0) {
            return i;
        }
    }
    return -1;
}

int main(void) {
    printf("%d %d %d\n", find("JP"), find("USA"), find("UK"));
}

find は、表 codes から引数と同じ国コードの行を探してその番号を返し、見つからなければ -1 を返す関数です。このプログラムは 0 1 2 を出力するはずが、いまは 0 -1 2 を出力し、表にあるはずの "USA" だけが見つかりません。

Answer

Wrong

static const char codes[][3] = {"JP", "USA", "UK"};

"USA" だけが見つからないのは、3文字のコードが "USA" だけだからです。codes の行は3要素の char 配列で、"USA" の初期化には 'U' 'S' 'A' の3つで行が埋まります。C では、文字列リテラルの文字数が配列の要素数とちょうど同じとき、終端の '\0' は入らず、エラーにもなりません。1 "JP" と "UK" は2文字なので、3つ目に '\0' が入ります。

2次元配列の行はメモリ上に隙間なく並ぶので、codes[1] の USA のすぐ後ろには codes[2] の UK\0 が続きます。strcmp(codes[1], "USA") は '\0' に出会うまで読み進め、"USAUK" と "USA" を比べることになるので、一致しません。行の外まで読むこの比較は未定義動作で、-1 は手元の実行で観測した結果です。表の最後の行が3文字なら、配列の外まで読むことになります。

Right

static const char codes[][4] = {"JP", "USA", "UK"};

行を4要素にすると、3文字のコードにも '\0' の入る場所ができ、どの行もヌル終端の文字列になります。strcmp(codes[1], "USA") は4文字目の '\0' で止まって一致し、0 1 2 が出力されます。行の要素数は、いちばん長いコードの文字数に1を足した数にします。static const char* const codes[] = {...} のようにポインタの配列にしても直ります。各ポインタが指す文字列リテラルには、いつも '\0' が付いているからです。

  1. C++ では、この初期化はコンパイルエラーです。'\0' の分も配列に収まらなければならないからです。GCC 15 には、C でこの形を知らせる -Wunterminated-string-initialization という警告が加わりました。
