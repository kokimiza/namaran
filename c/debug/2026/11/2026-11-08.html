max_gap.c

#include <stdio.h>

int max_gap(const int* t, size_t n) {
    int best = 0;
    for (size_t i = 0; i < n - 1; i++)
        if (t[i + 1] - t[i] > best)
            best = t[i + 1] - t[i];
    return best;
}

int main(void) {
    int times[] = {3, 8, 10};
    printf("%d\n", max_gap(times, 3));
    printf("%d\n", max_gap(times, 0));
}

記録した時刻の列 t から、隣り合う時刻の差の最大値を返すつもりの max_gap です。差を取れる組が無いとき(要素が1個以下のとき)は0を返します。main は3件の記録 {3, 8, 10} と、要素数0の空の記録で呼びます。本来は 5 と 0 が表示されますが、いまは空の記録で呼んだところで 0 が返らず、決まった出力になりません。手元のビルドでは Segmentation fault で落ちました。

Answer

Wrong

int max_gap(const int* t, size_t n) {
    int best = 0;
    for (size_t i = 0; i < n - 1; i++)

n は符号なしの size_t なので、n - 1 の 1 も size_t に変換され、引き算は符号なしで行われます。符号なしの演算は負にならず、0から1を引くと size_t の最大値 SIZE_MAX に回り込みます。空の記録では条件が i < SIZE_MAX になってループが止まらず、t[0] から順に読み進め、3要素の配列の外の t[3] を読んだ時点で未定義動作です。手元では Segmentation fault で落ちましたが、たまたま読めた値で差を計算して何かを返すこともあります。

要素が1個のときは n - 1 が0で、ループは1回も回らずに best の初期値0が返ります。初期値を0にしてあることからも、要素が少ない場合を考えて書いたことが分かります。数学の引き算なら、要素が0個のときの n - 1 は -1 で、ループはやはり回りません。size_t には -1 が無いので、この読み方が成り立たないのです。

Right

int max_gap(const int* t, size_t n) {
    int best = 0;
    for (size_t i = 0; i + 1 < n; i++)

i + 1 < n は i < n - 1 と同じ意味の条件を、引き算を使わずに書いたものです。足し算の i + 1 は n より大きくなる手前で止まるので回り込まず、n が0なら 1 < 0、1なら 1 < 1 が偽になってループは回りません。空の記録でも1件の記録でも best の0が返り、3件の記録では i が0と1の2回だけ回って、差5と2のうち 5 を返します。
