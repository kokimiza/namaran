trim_end.c

#include <ctype.h>
#include <stdio.h>
#include <string.h>

void trim_end(char* s) {
    size_t n = strlen(s);
    while (isspace((unsigned char)s[n - 1])) {
        s[--n] = '\0';
    }
}

int main(void) {
    char s[] = "\r\n";
    trim_end(s);
    printf("[%s]\n", s);
}

読み込んだ行の末尾から、改行コードを含む空白類の文字を取り除く trim_end です。"ab \r\n" なら "ab" になります。CRLF の空行 "\r\n" を渡すと、手元のビルドでは本来の出力どおり [] と表示されましたが、AddressSanitizer を付けてビルドすると stack-buffer-underflow を報告して止まります。どこが原因で、どう直せばよいでしょうか?

Answer

Wrong

    size_t n = strlen(s);
    while (isspace((unsigned char)s[n - 1])) {
        s[--n] = '\0';
    }

"\r\n" は2文字とも空白類なので、ループは '\n' と '\r' を順に '\0' にして、n を 2 から 0 まで減らします。ところが n が 0 になっても条件の s[n - 1] はもう一度評価されます。n は符号なしの size_t なので、0 - 1 は負の数にならず size_t の最大値に折り返し、s[n - 1] は配列 s の範囲の外を指します。

範囲の外を読むのは未定義動作で、手元のビルドでは配列のすぐ前の1バイトを読みました。その値がたまたま空白類でなかったので止まり、[] と正しそうに表示されただけです。空白類だった場合は、配列の外に '\0' を書き込んでさらに前を調べます。AddressSanitizer はこの読み込みを、配列の先頭より前へのアクセスとして報告しました。

Right

    size_t n = strlen(s);
    while (n > 0 && isspace((unsigned char)s[n - 1])) {
        s[--n] = '\0';
    }

&& は左から評価され、左が偽なら右を評価しません。n > 0 を先に置けば、n が 0 になった時点でループを抜け、s[n - 1] は読まれません。n が 1 以上のときだけ n - 1 を計算するので、添字はいつも 0 から n - 1 の範囲に収まります。空文字列を渡したときも、最初の判定で抜けます。
