count_even.c

#include <stdio.h>

int count_even(const int* a, int n) {
    int count;
    for (int i = 0; i < n; i++) {
        if (a[i] % 2 == 0) {
            count++;
        }
    }
    return count;
}

int main(void) {
    int a[] = {4, 7, 10, 3, 8};
    printf("%d\n", count_even(a, 5));
}

配列の中の偶数の個数を返すつもりの count_even です。main は {4, 7, 10, 3, 8} を渡しており、本来は 3 が出ます。いまは、最適化なしでビルドすると 3 が出ることもありますが、-O2 を付けてビルドすると実行のたびに 91680187 や 16080315 のような違う値が出ます。

Answer

Wrong

int count_even(const int* a, int n) {
    int count;

int count; には初期化子がありません。関数の中で static を付けずに宣言した変数は、関数に入るたびに新しく作られ、初期化子を書かなければ 0 から始まる保証もなく、値は決まらないままです。count++ は count = count + 1 と同じ再代入で、右辺で count の今の値を読みます。初めの値が決まっていないので、そこに偶数の個数を足しても答えは決まりません。

この決まらない値を読むと動作は未定義になり、何が出るかはコンパイラ次第です。count がどの値から数え始めるかは、ビルドの仕方と、そのときメモリやレジスタに残っていた中身で変わります。最適化なしで 3 が出るのは、その場所にたまたま 0 が入っていたときで、-O2 で値が毎回変わるのと同じ欠陥です。1

Right

int count_even(const int* a, int n) {
    int count = 0;

宣言に = 0 を付けると、count は作られた時点で 0 になり、ループの count++ はそこから1ずつ増やします。{4, 7, 10, 3, 8} では 4、10、8 で増えて 3 です。n が 0 でループが1回も回らないときも、初期化した 0 がそのまま返ります。足し込んだり数えたりする変数は、+= や ++ で書き換える前に、宣言の初期化子で始まりの値を与えておきます。

  1. 関数の外の変数や static を付けた変数は、初期化子が無くても 0 で初期化されます。初期化子を省いて 0 から始まるのは、こちらだけです。GCC 14 は、-Wall -O2 でビルドするとこの count に -Wmaybe-uninitialized の警告を出しますが、-Wall だけで最適化しないビルドでは何も言いません。
