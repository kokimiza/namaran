sort_pairs.c

#include <stdio.h>
#include <stdlib.h>

static int by_first(const void *a, const void *b) {
    const int *pa = *(const int *const *)a;
    const int *pb = *(const int *const *)b;
    return (pa[0] > pb[0]) - (pa[0] < pb[0]);
}

int main(void) {
    int pairs[][2] = {{3, 30}, {1, 10}, {2, 20}};
    size_t n = sizeof pairs / sizeof pairs[0];
    qsort(pairs, n, sizeof pairs[0], by_first);
    for (size_t i = 0; i < n; i++) {
        printf("%d %d\n", pairs[i][0], pairs[i][1]);
    }
    return 0;
}

pairs の各行 {キー, 値} を qsort でキーの昇順に並べ替え、1行ずつ表示するプログラムです。入力は {{3, 30}, {1, 10}, {2, 20}} です。いまは何も表示されないまま異常終了します(手元では Segmentation fault でしたが、未定義動作なので結果は定まりません)。本来の出力は 1 10、2 20、3 30 の3行です。どこを直せばよいでしょうか?

Answer

by_first の最初の2行が、受け取ったポインタの指す先を取り違えています。

qsort は比較関数に、並べ替える配列の要素を指すポインタを渡します。pairs の要素は int[2] という行なので、a が指しているのは {3, 30} のような2つの int そのものです。ところが *(const int *const *)a は、a の指す先に「行を指すポインタ」が置いてあるものとして読みます。実際にそこにあるのは 3 と 30 なので、そのバイト列がアドレスとして解釈され、pa[0] はでたらめな場所を読みにいきます。

この書き方が正しいのは、要素そのものがポインタである配列、たとえば const int *rows[] や char *names[] を並べ替えるときです。そのときは a が要素のポインタを指しているので、1回たどって行の先頭を取り出す必要があります。2次元配列には行ポインタがどこにも格納されていないので、たどる段数が1つ多すぎます。

直すには、a をそのまま行の先頭として受け取ります: 

    const int *pa = a;
    const int *pb = b;

行の先頭のアドレスは、その行の最初の int のアドレスと同じです。比較関数の引数は const void * なので、キャストが間違っていてもコンパイラは何も言いません。この取り違えは、実行して初めて表に出ます。
