payment.c

#include <stdio.h>

static unsigned last_key;
static int charged, outages = 1;

static bool bank_transfer(int amount) {
    if (outages-- > 0) return false;
    charged += amount;
    return true;
}

static bool pay(unsigned key, int amount) {
    if (key == last_key) return true;
    last_key = key;
    return bank_transfer(amount);
}

int main(void) {
    while (!pay(42, 30)) {}
    printf("%d\n", charged);
}

pay は、冪等性キー key で同じ要求の再送を見分け、二重に処理しないようにしながら bank_transfer で amount を送金するつもりの関数です。bank_transfer は最初の1回だけ通信障害で失敗し、main は pay が成功を返すまで同じキー 42 で再送します。引数も標準入力も使いません。いまは 0 が出ます。本来は 30 が出るはずです。

Answer

Wrong

static bool pay(unsigned key, int amount) {
    if (key == last_key) return true;
    last_key = key;
    return bank_transfer(amount);
}

1回目の pay(42, 30) は、bank_transfer を呼ぶ前に last_key を 42 にします。その送金は通信障害で失敗して pay が false を返すので、main は同じキーで再送します。2回目の呼び出しでは key == last_key が成り立ち、pay は送金しないまま true を返します。ループはそこで終わり、charged は 0 のままです。

キーを記録した時点で処理済みと宣言しているので、失敗した要求も処理済みとして残ります。呼び出し側は成功を受け取っており、一度も送金されていないことに気づけません。

Right

static bool pay(unsigned key, int amount) {
    if (key == last_key) return true;
    if (!bank_transfer(amount)) return false;
    last_key = key;
    return true;
}

送金が成功してからキーを記録すれば、失敗した要求は記録に残りません。2回目の pay(42, 30) は last_key と一致しないので送金をやり直し、今度は成功して charged が 30 になります。そのあと同じキーで届いた再送は記録と一致するので、送金せずに true を返します1。

  1. 実際のサービスでは、送金とキーの記録の間でプロセスが落ちることもあります。そのため、処理の結果とキーを同じトランザクションで記録したり、キーに処理中という状態を持たせて、同時に届いた再送を待たせたりします。
