int_to_str.c

#include <limits.h>
#include <stdio.h>

char* to_str(int n, char* end) {
    unsigned u = n < 0 ? -n : n;
    *--end = '\0';
    do {
        *--end = (char)('0' + u % 10);
        u /= 10;
    } while (u != 0);
    if (n < 0) {
        *--end = '-';
    }
    return end;
}

int main(void) {
    char buf[12];
    puts(to_str(-42, buf + sizeof buf));
    puts(to_str(INT_MIN, buf + sizeof buf));
}

to_str は int を10進の文字列にして、end の手前から後ろ詰めで書き込み、その先頭を返す関数です。main のように -42 と INT_MIN を渡すと、いまも出力は -42 と -2147483648 の2行で、見た目は正しく出ます。ところが UBSan(-fsanitize=undefined)を付けてビルドすると、INT_MIN を渡した呼び出しで実行時エラーが報告されます。本来は、どの int を渡しても未定義動作を起こさずに同じ2行を出力するはずです。

Answer

Wrong

unsigned u = n < 0 ? -n : n;

この行は、INT_MIN の絶対値が int に収まらないことを知ったうえで、unsigned に移して扱おうとしています。ところが unsigned への変換は、条件演算子の値が決まったあとの代入で起きます。-n と n はどちらも int なので、条件演算子の結果も int で、-n はそれより前に int のまま計算されます。32ビットの int の範囲は -2147483648 から 2147483647 までで1、INT_MIN を反転した 2147483648 は表せません。符号付き整数のオーバーフローは未定義動作で、UBSan が報告しているのはこの -n です。

出力が正しく見えるのは、最適化なしの GCC が反転を2の補数のまま計算し、INT_MIN が INT_MIN に戻ったものが unsigned で 2147483648 になったからです。たまたまそうなっただけで、コンパイラは未定義動作が起きないものとして最適化してかまいません。buf の12バイトは "-2147483648" の11文字と終端の '\0' にちょうど足り、'0' + u % 10 も u % 10 が0から9なので数字の文字になります。疑わしく見えるこの2か所に欠陥はありません。

Right

unsigned u = n < 0 ? -(unsigned)n : (unsigned)n;

先に unsigned へ変換してから反転します。int から unsigned への変換は、値を 232 で割った余りに移すと規格が定めているので、(unsigned)INT_MIN は 2147483648 です。unsigned の単項マイナスも 232 を法とする計算でオーバーフローせず、-(unsigned)n は 2147483648 のまま、-42 なら 42 になります。int のまま計算される式がどこにも残らないので、INT_MIN でも未定義動作は起きません。

  1. C23 からは符号付き整数が2の補数で表されることが規格の要件になり、INT_MIN が -INT_MAX - 1 であることも保証されました。C17 までは1の補数や符号と絶対値の表現も許されていました。
