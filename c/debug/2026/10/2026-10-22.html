find_point.c

#include <stdio.h>
#include <string.h>

struct point {
    double x, y;
};

static int find(const struct point* ps, int n, struct point p) {
    for (int i = 0; i < n; i++) {
        if (memcmp(&ps[i], &p, sizeof p) == 0) {
            return i;
        }
    }
    return -1;
}

int main(void) {
    struct point ps[] = {{1.0, 0.0}, {-1.0, 0.0}};
    struct point mirrored = {-ps[0].x, -ps[0].y};
    printf("%d\n", find(ps, 2, mirrored));
}

find は、点の配列 ps の先頭 n 個から座標が p と等しい点を探し、その添字を返します。見つからなければ -1 を返します。main は、ps[0] の点 (1, 0) と原点について対称な点 (-1, 0) を作って探します。いまは -1 と出力されます。本来は、ps[1] が見つかって 1 と出力されるはずです。

Answer

Wrong

if (memcmp(&ps[i], &p, sizeof p) == 0) {

memcmp は2つの構造体を、値ではなくメモリ上のバイト列として比べます。struct point は double が2つ並んでいるだけで、メンバの間や末尾に詰め物(パディング)が入る余地もないので、バイト列が同じなら座標も同じ、と考えてしまいがちです。ところが逆向きは成り立ちません。座標が等しくてもバイト列が違う値があるからです。

mirrored の y 座標は 0.0 の符号を反転した -ps[0].y です。IEEE 754 の浮動小数点数は0にも符号を持ち、単項の - は符号のビットだけを反転するので、結果は -0.0 になります。-0.0 == 0.0 は真ですが、-0.0 は最上位のビットが1で、0.0 のすべてのビットが0のバイト列とは一致しません。そのため ps[1] の {-1.0, 0.0} とは memcmp が0を返さず、探索は -1 で終わります。

Right

if (ps[i].x == p.x && ps[i].y == p.y) {

座標を == で比べれば、-0.0 と 0.0 は等しいと判定され、ps[1] が見つかって 1 が出力されます。使わなくなった <string.h> は消します。== で比べると、NaN(非数)を含む点は自分自身とも等しくなりません。memcmp はこれも逆の答えを出すので、浮動小数点数を持つ構造体はメンバごとに比べます1。

  1. C の規格は memcmp の脚注で、構造体のパディングの中身は不定なので比較に問題を起こしうると注意しています。負の0は、パディングのない構造体でも同じ問題を起こします。
