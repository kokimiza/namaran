bit_count_bench.c

#include <stdio.h>
#include <time.h>

static int bit_count(unsigned n) {
    int count = 0;
    for (int b = 0; b < 32; b++) {
        count += (n >> b) & 1;
    }
    return count;
}

int main(void) {
    clock_t start = clock();
    for (unsigned i = 0; i < 100000000; i++) {
        bit_count(i);
    }
    printf("%.2f s\n", (double)(clock() - start) / CLOCKS_PER_SEC);
}

bit_count を1億回呼び、かかった時間を測るつもりのプログラムです。gcc -O2 でビルドして実行すると、いまは 0.00 s と出力されます。同じプログラムを最適化なしでビルドすると 3.90 s と出る処理なので、-O2 でも1億回の bit_count にかかった、0より大きい時間が出るはずです。

Answer

Wrong

for (unsigned i = 0; i < 100000000; i++) {
    bit_count(i);
}
printf("%.2f s\n", (double)(clock() - start) / CLOCKS_PER_SEC);

bit_count(i) の戻り値はどこにも使われずに捨てられています。bit_count は引数から数を計算して返すだけで、出力もせず、外の変数も書き換えません。C の処理系が守らなければならないのは、出力や volatile な変数への読み書きのように外から観測できる動作だけです1。この呼び出しは観測できる動作に何も影響しないので、-O2 の GCC は呼び出しを取り除き、空になったループも消します。

2回の clock() の間には何も残らないので、測った時間は 0.00 s になります。最適化なしのビルドでは呼び出しが残るので、この欠陥は最適化を有効にしたときにだけ現れます。

Right

long total = 0;
for (unsigned i = 0; i < 100000000; i++) {
    total += bit_count(i);
}
printf("%.2f s (%ld)\n", (double)(clock() - start) / CLOCKS_PER_SEC, total);

戻り値を total に足し、最後に total を出力します。bit_count の結果が出力される値を決めるようになったので、結果を捨てて呼び出しごと消す、ということはできなくなります。手元の -O2 では 1.12 s (1314447104) と出ました。

  1. C規格の「プログラムの実行」の節が定める規則で、as-if ルールと呼ばれます。結果が同じに見える限り、処理系はプログラムを書かれたとおりに実行しなくてかまいません。
