leap_cases.c

#include <stdio.h>

static int is_leap(int y) {
    return y % 4 == 0 && y % 100 != 0;
}

static int run(const int cases[][2]) {
    int failed = 0;
    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; i++) {
        if (is_leap(cases[i][0]) != cases[i][1]) {
            printf("FAIL %d\n", cases[i][0]);
            failed++;
        }
    }
    return failed;
}

int main(void) {
    const int cases[][2] = {{2024, 1}, {1900, 0}, {2000, 1}};
    printf("%d failed\n", run(cases));
}

run は、年と期待値（閏年なら1）の組を並べた表で is_leap を確かめる単体テストです。グレゴリオ暦では、4で割り切れる年を閏年とし、そのうち100で割り切れる年は除き、さらに400で割り切れる年は閏年に戻します。x86-64 の Linux で実行すると、いまは 0 failed と出てテストが通ります。本来は is_leap の誤りを捕まえ、FAIL 2000 と 1 failed の2行を出力するはずです。直すのは is_leap ではなくテストの側です。

Answer

Wrong

static int run(const int cases[][2]) {
    int failed = 0;
    for (size_t i = 0; i < sizeof cases / sizeof cases[0]; i++) {

is_leap は400で割り切れる年を閏年に戻していないので、2000年に0を返し、表の3行目で失敗するはずです。それが報告されないのは、3行目までループが届いていないからです。関数の引数に配列の形で書いた const int cases[][2] は、配列ではなく先頭要素を指すポインタ const int (*)[2] として宣言されます。main では表全体の大きさだった sizeof cases が、run の中ではポインタの大きさになり、x86-64 では8です。

割る側の sizeof cases[0] は int 2つ分の行の大きさで、こちらも8です。8 / 8 は1なので、ループは0回ではなく1回だけ回り、1行目の2024年だけを確かめます。2024年は閏年で is_leap も1を返すので、失敗は0件です。ケースが1つも回らないなら気付けたかもしれませんが、1件は回っているので、テストは正しく動いているように見えます1。

表の行数は、配列の型がまだ残っている main で sizeof を使って求め、run に引数で渡します。main の sizeof cases は int 6つ分の24なので、24 / 8 で3行すべてが回り、2000年の行で FAIL 2000 が出て、最後に 1 failed が出ます。

  1. ポインタが4バイトの32ビット環境では 4 / 8 が0になり、ループは1回も回りません。どちらの環境でも、GCC は既定で有効な -Wsizeof-array-argument で、配列の形の引数に sizeof を使った箇所を警告します。
