runs.c

#include <stdio.h>

static long decoded_size(const unsigned char *in, size_t n, long limit) {
    long total = 0;
    for (size_t i = 0; i + 1 < n; i += 2) {
        if (in[i] > limit) return -1;
        total += in[i];
    }
    return total;
}

int main(void) {
    const unsigned char in[] = {200, 'a', 200, 'b', 200, 'c'};
    printf("%ld\n", decoded_size(in, sizeof in, 500));
}

decoded_size は、(個数, バイト) の組を並べたラン長圧縮のデータが展開後に何バイトになるかを数え、展開する前に上限 limit を超えるデータを見つけて -1 を返すための関数です。main は200個ずつ3つの組からなるデータを、上限500バイトで調べています。いまの出力は 600 で、上限を超えるデータが通ってしまいます。本来の出力は -1 です。

Answer

Wrong

if (in[i] > limit) return -1;
total += in[i];

この検査が上限と比べているのは、いま読んだ1組の個数 in[i] です。個数は unsigned char に入っているので255を超えず、上限が500なら検査は一度も成り立ちません。3つの組はどれも200で通り、合計の600がそのまま返ります。

Right

total += in[i];
if (total > limit) return -1;

上限が守るべきなのは展開後の合計なので、足したあとの total を上限と比べます。3つ目の組を足して total が600になった時点で -1 が返ります。1組の個数が255で頭打ちでも、組の数を増やせば合計はいくらでも大きくなるので、1組ずつの検査では展開量を抑えられません。
