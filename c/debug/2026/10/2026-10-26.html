check_macro.c

#include <stdio.h>

#define CHECK(cond)                              \
    do {                                         \
        if (!(cond))                             \
            printf("check failed: " #cond "\n"); \
    } while (0)

int main(void) {
    int count = 7, divisor = 2;
    CHECK(count > 0);
    CHECK(count % divisor == 0);
}

CHECK は、条件 cond が偽のときに、その条件式を書いたとおりに表示するつもりのマクロです。main は count を 7、divisor を 2 として2つの条件を確かめ、偽になる2つ目について1行出力します。本来の出力は check failed: count % divisor == 0 です。いまは check failed: count -550729560ivisor == 0 のように式の途中に意味のない数が入り、divisor の d が消えます。数は実行するたびに変わります。

Answer

Wrong

            printf("check failed: " #cond "\n"); \

#cond は条件式の字句を文字列リテラル "count % divisor == 0" にします。隣り合う文字列リテラルは1つに連結されるので、printf が受け取る書式は "check failed: count % divisor == 0\n" です。printf は書式の中の % を変換指定の始まりと読み、% d を空白のフラグ付きの %d として扱います。

この %d は int の引数を1つ取り出そうとしますが、引数は渡していないので未定義動作で、手元ではそのときレジスタに残っていた値が数として出ました。divisor の d は変換指定の一部として消費され、残りの ivisor == 0 だけが文字のまま出ます。条件式に % が入らない1つ目の CHECK は、偽になっても正しく表示されるので、剰余を確かめるまで欠陥に気付けません。

Right

            printf("check failed: %s\n", #cond); \

条件式の文字列を書式に混ぜず、%s の引数として渡します。printf は引数の文字列を書式として読まないので、条件式に % が入っていても文字のまま出ます。書式は条件式によらない固定の文字列リテラルになるので、どの CHECK でも変換指定と引数の数が合います。1

  1. GCC は欠陥のあるほうのコードにも、-Wformat で「%d に対応する int の引数がない」と警告します。書式が文字列リテラルの連結だけでできているので、マクロを展開したあとの書式をコンパイル時に検査できるからです。
