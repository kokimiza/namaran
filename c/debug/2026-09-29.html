sum.c

#include <stdio.h>

int sum(const int *a, int n) {
    int s = 0;
    for (int i = 0; i < n; i++) {
        s += *(a + i * sizeof *a);
    }
    return s;
}

int main(void) {
    int a[] = {1, 2, 3, 4};
    printf("%d\n", sum(a, 4));
}

sum は配列 a の先頭 n 個の和を返すつもりの関数です。main のとおり {1, 2, 3, 4} を渡すと、本来は 10 を出力するはずですが、いまは 932784017 や -1505757407 のように、実行するたびに違う値を出力します。

Answer

Wrong

for (int i = 0; i < n; i++) {
    s += *(a + i * sizeof *a);
}

ポインタに整数を足すと、C はその整数を要素の個数として扱い、要素の大きさを掛けた分だけアドレスを進めます。a + 1 はすでに次の int を指しているので、自分で sizeof *a を掛けると大きさを二重に掛けることになります。int が4バイトなら、i が 1 のときに読むのは a[4] で、4要素の配列の外です。

配列の外を読んだ時点で未定義動作になり、足されるのはたまたまそこにあった値です。それが実行のたびに変わるので、出力も毎回違います。

Right

for (int i = 0; i < n; i++) {
    s += a[i];
}

a[i] は *(a + i) と定義されているので、要素の大きさを掛ける計算はポインタの足し算の中に含まれています。添字で書けば、i をバイト数に直す必要はありません1。

  1. バイト単位でずらす必要があるときは、(const char *)a + i * sizeof *a のように char へのポインタに変えてから足します。char の大きさは1なので、足した数がそのままバイト数になります。qsort のように要素の型を知らない汎用コードは、この形で要素の位置を求めます。
