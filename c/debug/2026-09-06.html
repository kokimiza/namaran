trim_newline.c

#include <assert.h>
#include <stdio.h>
#include <string.h>

static void trim_newline(char *s) {
    size_t n = strlen(s);
    assert(n > 0 && s[--n] == '\n');
    s[n] = '\0';
}

int main(void) {
    char line[] = "hello\n";
    trim_newline(line);
    printf("[%s]\n", line);
}

行末の改行を1つ取り除く trim_newline です。改行で終わらない文字列を渡すのは呼び出し側の誤りなので、assert で検査しています。このプログラムを -DNDEBUG を付けたリリースビルドで実行すると、いまは [hello と ] が2行に分かれて出力されます。本来の出力は、NDEBUG なしのビルドと同じ [hello] です。どこを直せばよいでしょうか?

Answer

assert の中の --n をやめ、改行の位置を n - 1 で指します。assert(n > 0 && s[n - 1] == '\n'); と s[n - 1] = '\0'; の2行に直します。

NDEBUG を定義すると、assert(...) は中の式ごと消えます。消えるのは検査だけではなく、条件の中に書いた --n も一緒です。リリースビルドでは n が strlen(s) の 6 のまま残り、s[6] = '\0' は最初からある終端の '\0' に同じ値を書くだけなので、改行は消えません。

NDEBUG なしのビルドで気付けないのは、そちらでは --n が実行されて n が 5 になり、s[5] の改行が消えるからです。直したあとは n を変えずに n - 1 で改行を指すので、assert が消えても s[n - 1] = '\0' はどちらのビルドでも同じ位置に書き込みます1。

  1. リリースビルドで空文字列を渡すと s[n - 1] は配列の外を指します。そうした呼び出しは assert が禁じている使い方で、NDEBUG のビルドでは検査されなくなる、というのが assert で前提を書くことの意味です。
