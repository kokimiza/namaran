join_ids.c

#include <stdio.h>

static void join(char *buf, size_t size, const int *ids, int count) {
    size_t n = 0;
    buf[0] = '\0';
    for (int i = 0; i < count; i++)
        n += snprintf(buf + n, size - n, i ? ",%d" : "%d", ids[i]);
}

int main(void) {
    int ids[] = {100, 200, 300, 400, 500, 600};
    char buf[16];
    join(buf, sizeof buf, ids, 6);
    puts(buf);
}

join は、ids の数をカンマ区切りで buf に書き、入りきらない分は切り捨てるつもりの関数です。書いた長さを n に持っておくのは、strcat のように毎回先頭から終端を探さずに済ませるためです。main のとおり6個の数を16バイトの buf に書くと、いまも表示は 100,200,300,400 になりますが、AddressSanitizer を付けて動かすと stack-buffer-overflow で止まります。本来は同じ 100,200,300,400 を表示し、buf の外には何も書き込まないはずです。

Answer

Wrong

for (int i = 0; i < count; i++)
    n += snprintf(buf + n, size - n, i ? ",%d" : "%d", ids[i]);

snprintf は、書ききれずに切り捨てたときも、切り捨てなければ何文字になったかを返します。400 の回は残りの5バイトに ,400 とヌル文字がちょうど収まり、n は 15 になります。500 の回は残りが1バイトしかなく、ヌル文字だけを書きますが、返り値は ,500 の4なので n は 19 に進み、size を追い越します。

size - n は size_t どうしの引き算なので負にはならず、とても大きな値に回り込みます。600 の回の snprintf はそれを書いてよい大きさとして受け取り、16バイトの buf の外にある buf + 19 から ,600 を書き込みます。表示が正しく見えるのは、puts が buf[15] のヌル文字で読むのをやめるからです1。

Right

for (int i = 0; i < count && n < size; i++)
    n += snprintf(buf + n, size - n, i ? ",%d" : "%d", ids[i]);

n が size に届いたら、もう書く場所はありません。ループの条件に n < size を足すと、500 の回で n が 19 になったところでループを抜けるので、回り込んだ size - n を snprintf に渡すことがなくなります。buf は直前の snprintf がヌル文字で閉じているので、表示は 100,200,300,400 のままです。

  1. はみ出した書き込みはスタック上の別のデータを壊すので、どう表に出るかは決まりません。この例では何も起きないように見えますが、AddressSanitizer はその書き込みの時点で止めます。
