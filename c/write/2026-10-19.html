grant.c

size_t grant(size_t total, size_t len, size_t limit) {
}

圧縮データを展開しながら、出力の合計が上限 limit バイトを超えないように書き出す長さを決める grant を書いてください。これまでに書き出したバイト数が total、次に書き出したいバイト数が len のとき、len と残りの容量 limit - total のうち小さい方を返します。total は常に limit 以下で呼ばれ、len には展開しようとしているデータが申告する長さがそのまま来るので、size_t のどんな値もありえます。残りの容量が0なら0を返します。

入力例 1

grant(90, 30, 100)

出力例 1

10

入力例 2

grant(10, SIZE_MAX, 100)

出力例 2

90

入力例 3

grant(100, 1, 100)

出力例 3

0
Reference 
size_t grant(size_t total, size_t len, size_t limit) {
    size_t left = limit - total;
    return len < left ? len : left;
}

先に残りの容量 limit - total を求め、それと len を比べます。total は limit 以下なので、この引き算は0以上の値になり、回り込みません。

条件を total + len > limit と書くと、入力例 2 で誤ります。size_t の足し算は SIZE_MAX + 1 で割った余りになるので、10 + SIZE_MAX は9に回り込み、9 > 100 は偽です。上限に収まると判断されて SIZE_MAX がそのまま返り、上限の検査が素通りになります。len は外から来る値なので、足し算に使わず、上限から引いた側と比べます。

掲載したのは参考実装で、唯一の正解ではありません。len > limit - total を条件にして分岐しても同じ結果になります。
