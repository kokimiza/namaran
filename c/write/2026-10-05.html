float_bits.c

#include <stdint.h>

uint32_t float_bits(float f) {
}

float の値 f を、同じ32ビットの並びを持つ uint32_t として返す float_bits を書いてください。数値の変換ではなくビット列をそのまま取り出すので、1.0f を渡しても 1 にはなりません。float は IEEE 754 の単精度で uint32_t と同じ大きさとし、出力例は返り値を16進で書いています。

入力例 1

float_bits(1.0f)

出力例 1

0x3f800000

入力例 2

float_bits(-0.0f)

出力例 2

0x80000000

入力例 3

float_bits(0.0f)

出力例 3

0x00000000
Reference 
#include <stdint.h>
#include <string.h>

static_assert(sizeof(float) == sizeof(uint32_t));

uint32_t float_bits(float f) {
    uint32_t u;
    memcpy(&u, &f, sizeof u);
    return u;
}

参考実装は、memcpy で f のバイト列を u へそのまま写して返します。その前の static_assert は、float と uint32_t の大きさが違う環境ならコンパイルを止めます。C23 で static_assert はキーワードになり、メッセージも省けるようになりました。

return *(uint32_t *)&f; と書きたくなりますが、float のオブジェクトを uint32_t 型の左辺値で読むのは、厳密な別名規則に反する未定義動作です。コンパイラは uint32_t * が float を指すことはないと仮定して最適化してよいので、前後の書き込みと読み出しの順序が入れ替わることがあります。memcpy はバイト単位のコピーなのでこの規則に掛からず、GCC や Clang は最適化で1回のレジスタ間の移動に置き換えます。

掲載したのは参考実装で、唯一の正解ではありません。C では、union { float f; uint32_t u; } の f に書いて u から読む方法も規格で認められています1。

  1. 共用体で読み替える方法は C++ では未定義動作です。C++20 からは std::bit_cast<std::uint32_t>(f) が同じことをし、memcpy と違って定数式の中でも使えます。
