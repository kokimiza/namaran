compare_exchange.c

bool compare_exchange(int *obj, int *expected, int desired) {
}

*obj が *expected と等しければ *obj に desired を代入して true を返し、等しくなければ *obj の現在の値を *expected に代入して false を返す compare_exchange を書いてください。<stdatomic.h> の atomic_compare_exchange_strong と同じ約束を、普通の int で書くものです。desired が現在の値と同じでも、比較が一致すれば true を返します。

入力例 1

obj = 5; exp = 5; compare_exchange(&obj, &exp, 9)

出力例 1

true (obj = 9, exp = 5)

入力例 2

obj = 7; exp = 5; compare_exchange(&obj, &exp, 9)

出力例 2

false (obj = 7, exp = 7)

入力例 3

obj = 7; exp = 7; compare_exchange(&obj, &exp, 7)

出力例 3

true (obj = 7, exp = 7)
Reference 
bool compare_exchange(int *obj, int *expected, int desired) {
    if (*obj == *expected) {
        *obj = desired;
        return true;
    }
    *expected = *obj;
    return false;
}

比較の == は両辺を読むだけで何も書き換えず、代入の = は左辺を書き換えます。この関数では、比較の結果によって代入の向きが入れ替わります。一致すれば *obj に desired を書き、一致しなければ逆に *expected に *obj を書きます。

失敗したときに *expected を書き換えるのは、呼び出し側がそのまま再試行できるようにするためです。exp から次の値を計算して compare_exchange(&obj, &exp, next) を呼ぶループでは、失敗するたびに exp が obj の最新の値になり、次の試行はその値から計算し直せます1。

掲載したのは参考実装で、唯一の正解ではありません。比較の結果をいったん bool の変数に取り、return を1か所にまとめても同じ動きになります。

  1. 本物の atomic_compare_exchange_strong は、比較と代入を他のスレッドから割り込まれない1つの操作として行います。この参考実装は同じ約束を普通の int で書いただけなので、複数のスレッドから同時に呼ぶと、比較と代入の間に別のスレッドが値を書き換えることがあります。
