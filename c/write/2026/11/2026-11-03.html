palindrome_number.c

#include <stdbool.h>

bool is_palindrome_number(unsigned long n) {
}

n を10進数で書いたときの数字の並びが、前から読んでも後ろから読んでも同じなら true を、違えば false を返す is_palindrome_number を書いてください。n は 0 以上 10 億未満とし、0 や1桁の数は true です。文字列には変換せず、整数の演算だけで書いてください。

入力例 1

is_palindrome_number(12321)

出力例 1

true

入力例 2

is_palindrome_number(1230)

出力例 2

false

入力例 3

is_palindrome_number(0)

出力例 3

true
Reference 
bool is_palindrome_number(unsigned long n) {
    unsigned long rest = n;
    unsigned long reversed = 0;
    while (rest > 0) {
        reversed = reversed * 10 + rest % 10;
        rest /= 10;
    }
    return reversed == n;
}

rest % 10 で一の位を取り出して reversed の末尾に足し、rest /= 10 でその桁を捨てます。rest が 0 になったとき、reversed には数字を逆に並べた数が入っているので、それを元の n と比べます。

桁を削るのに n そのものを使うと、ループを抜けたときの n は 0 になっていて、比べる相手がもう残っていません。そこで、ループの中で減っていく値に rest、最後まで変わらない元の値に n と、役目ごとに別の名前を付けます。n は一度も書き換えないので、関数のどこで読んでも引数の値のままです。

1230 を逆に並べると 321 になり、末尾の 0 は先頭の 0 として消えるので false です。0 のときはループを1回も回らず、reversed も 0 のままなので true になります。n を 10 億未満としたのは、reversed を9桁に収め、どの処理系でも 4294967295 まで表せる unsigned long の範囲を超えないようにするためです。掲載したのは参考実装で、唯一の正解ではありません。
