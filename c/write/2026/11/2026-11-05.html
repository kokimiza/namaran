normalize_newlines.c

size_t normalize_newlines(char* s) {
}

文字列 s の改行をすべて '\n' の1文字にそろえる normalize_newlines を書いてください。"\r\n" の2文字と、後ろに '\n' が続かない単独の '\r' を、それぞれ '\n' 1文字に置き換えます。別の配列は使わずに s をその場で書き換え、書き換えたあとの長さを返します。空文字列なら何も変えずに 0 を返します。例では、入力例に呼ぶ前の s を、出力例に返り値と呼んだあとの s を、C の文字列リテラルで書きます。

入力例 1

s = "a\r\nb\rc\n"

出力例 1

6, s = "a\nb\nc\n"

入力例 2

s = "\r\r\n"

出力例 2

2, s = "\n\n"

入力例 3

s = ""

出力例 3

0, s = ""

size_t normalize_newlines(char* s) {
    size_t w = 0;
    size_t r = 0;
    while (s[r] != '\0') {
        char c = s[r++];
        if (c == '\r') {
            c = '\n';
            if (s[r] == '\n') {
                r++;
            }
        }
        s[w++] = c;
    }
    s[w] = '\0';
    return w;
}

読む位置 r と書く位置 w を別々に持ち、r で1文字読むたびに w へ高々1文字を書きます。w は r を追い越さないので、書き込む場所はいつも読み終えた範囲にあり、まだ読んでいない文字を上書きしません。別の配列を使わずにその場で書き換えられるのは、置き換えで文字列が長くならないからです。最後に s[w] へ '\0' を書いて文字列を終わらせ、w を長さとして返します。

'\r' を読んだら、その文字が "\r\n" の前半なのか単独の '\r' なのかを、次の文字 s[r] で決めます。'\n' なら r を1つ進めて読み飛ばし、どちらの場合も '\n' を1文字だけ書きます。入力例 2 の "\r\r\n" では、1文字目の '\r' の次は '\r' なので単独の改行として '\n' になり、2文字目と3文字目は "\r\n" として1つの '\n' になります。読んだ '\r' は終端より前にあるので、次の s[r] は遠くても終端の '\0' で、配列の外は読みません。

どれか1つの規則だけで書くと、入力例のどこかで外れます。'\r' と '\n' をそれぞれ '\n' に置き換えるだけなら、"\r\n" が改行2つになって入力例 1 は長さ 7 です。'\r' を消すだけなら、入力例 1 の b と c の間の改行がなくなります。終端の '\0' を書き忘れると、入力例 1 の s の後ろに元の文字列の最後の1文字 '\n' が残ります。掲載したのは参考実装で、唯一の正解ではありません。
