triangles.c

const int* triangles(void) {
}

0 から 9 までの n について、1 から n までの和を n 番目に並べた int の表を作り、その先頭を返す triangles を書いてください。表を作るのは最初に呼ばれたときの1回だけで、2回目以降は同じ表を返します。複数のスレッドが同時に呼んでも表は1回しか作らず、どのスレッドも作り終えた表を受け取るように、<threads.h> の call_once を使ってください。

入力例 1

triangles()[4]

出力例 1

10

入力例 2

triangles()[0]

出力例 2

0

入力例 3

triangles() == triangles()

出力例 3

1

#include <threads.h>

static once_flag once = ONCE_FLAG_INIT;
static int table[10];

static void fill(void) {
    for (int i = 1; i < 10; i++)
        table[i] = table[i - 1] + i;
}

const int* triangles(void) {
    call_once(&once, fill);
    return table;
}

call_once に渡せるのは void (*)(void) の関数だけです。引数を受け取れず値も返せないので、作った表をコールバックから呼び出し元へ渡す道は、両方から見える変数しかありません。参考実装は表 table と旗 once をファイルスコープの静的変数に置き、fill が table を埋め、triangles は call_once のあとで table の先頭を返します。静的変数はプログラムの終わりまで生きているので、そのポインタを返してもぶら下がりません。once は ONCE_FLAG_INIT で初期化しておく決まりです。掲載したのは参考実装で、唯一の正解ではありません。

fill は table[0] に何も書きませんが、静的変数は 0 で始まるので入力例 2 は 0 になり、table[i] はひとつ前の和に i を足して作るので、入力例 1 の table[4] は 0 + 1 + 2 + 3 + 4 = 10 です。2回目以降の呼び出しでは call_once が fill を呼ばずに戻り、毎回同じ table を返すので、入力例 3 は 1 になります。2つのスレッドが同時に初めて呼んだときは、片方が fill を実行し、もう片方は fill が戻るまで call_once の中で待ちます。そのため、埋まりかけの表を受け取るスレッドはありません。
