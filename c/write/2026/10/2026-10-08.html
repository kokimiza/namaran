same_contents.c

#include <stdio.h>

bool same_contents(FILE *a, FILE *b) {
}

読み込み用に開いた2つのストリーム a と b の中身が、最後のバイトまで同じかどうかを返す same_contents を書いてください。どちらもメモリに収まらないほど大きいことがあるので、中身全体を読み込まず、ファイルの大きさによらない一定のメモリで比べます。片方がもう片方の先頭部分と一致していても、長さが違えば false で、どちらも空なら true です。入力例は、a と b の中身をCの文字列リテラルで書いたものです。

入力例 1

"abc", "abc"

出力例 1

true

入力例 2

"abc", "abcd"

出力例 2

false

入力例 3

"", ""

出力例 3

true

#include <stdio.h>

bool same_contents(FILE *a, FILE *b) {
    int c;
    do {
        c = getc(a);
        if (c != getc(b)) return false;
    } while (c != EOF);
    return true;
}

参考実装は、a と b から1バイトずつ読んで比べます。手元に置くのは直前に読んだ1バイトだけなので、ファイルが何GBあっても使うメモリは変わりません。getc は1回ごとにファイルを読みに行くわけではなく、FILE が持つバッファから1バイトを取り出すだけなので、1バイトずつ呼んでも遅くはなりません。

長さの違いは EOF どうしの比較で見つかります。getc は読んだバイトを unsigned char の値として int で返し、ファイルの終わりではどのバイトとも違う負の値の EOF を返します。入力例2では、a が EOF を返したときに b はまだ 'd' を返すので、そこで false になります。両方が同時に EOF を返したときだけ、ループを抜けて true を返します。c を char にすると、char が符号付きの処理系では値 0xFF のバイトと EOF を区別できなくなるので、int で受けます。

掲載したのは参考実装で、唯一の正解ではありません。fread で両方から決まった大きさずつ読み、読めたバイト数と中身を memcmp で比べる書き方でも、メモリは一定に保てます。
