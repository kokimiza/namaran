claim_refresh.c

#include <stdatomic.h>

struct entry {
    atomic_long expires;
    atomic_bool refreshing;
};

bool claim_refresh(struct entry* e, long now) {
}

entry はキャッシュの1項目で、expires は値の有効期限の時刻、refreshing は誰かが値を再計算している最中かどうかです。時刻 now に呼ばれた claim_refresh は、期限が切れていて(now >= expires)まだ誰も再計算していないときだけ refreshing を true にして true を返し、呼んだ側がその再計算を引き受けます。それ以外のときは refreshing を変えずに false を返します。複数のスレッドが同時に呼んでも、true を受け取るのは1つだけでなければなりません。再計算を終えた側が expires を更新し、refreshing を false に戻すところまでは、この関数の仕事ではありません。

入力例 1

struct entry e = {10, false};
claim_refresh(&e, 12);

出力例 1

true
e.refreshing == true

入力例 2

struct entry e = {10, false};
claim_refresh(&e, 12);
claim_refresh(&e, 12);

出力例 2

true
false

入力例 3

struct entry e = {10, false};
claim_refresh(&e, 5);

出力例 3

false
e.refreshing == false
Reference 
bool claim_refresh(struct entry* e, long now) {
    return now >= atomic_load(&e->expires) && !atomic_exchange(&e->refreshing, true);
}

「refreshing が false なら true にする」を、読む操作と書く操作の2つに分けてはいけません。if (!e->refreshing) e->refreshing = true; と書くと、2つのスレッドが同時に false を読み、どちらも自分が引き受けたと思って再計算します。キャッシュの期限が切れた瞬間に大量の呼び出しが同じ値を作り直すのを防ぎたいのに、その入口で同じことが起きてしまいます。

atomic_exchange は新しい値を書き込み、書き込む前の値を返します。この読み書きは1つの不可分な操作なので、同時に呼ばれても、前の値として false を受け取るスレッドは1つしかありません。ほかのスレッドは true を受け取り、! で false を返します。すでに true のフラグに true を書いても値は変わらないので、引き受けられなかった側が状態を壊すこともありません。

期限の判定を && の左側に置いているのは、期限内のときにフラグへ触らないためです。順番を逆にすると、期限内でもフラグが true になり、それを戻す人がいなくなります。掲載したのは参考実装で、唯一の正解ではありません。atomic_compare_exchange_strong で「false なら true に置き換える」と書いても同じ動きになります。
