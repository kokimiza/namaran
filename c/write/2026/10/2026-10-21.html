nearly_equal.c

bool nearly_equal(double a, double b, double rel_tol) {
}

単体テストで浮動小数点数の計算結果を期待値と比べるための nearly_equal を書いてください。a と b の差の絶対値が、a と b の絶対値の大きいほうの rel_tol 倍以下なら true を、そうでなければ false を返します。a と b がどちらも0のときは true です。

入力例 1

nearly_equal(0.1 + 0.2, 0.3, 1e-9)

出力例 1

true

入力例 2

nearly_equal(1e-12, 2e-12, 1e-9)

出力例 2

false

入力例 3

nearly_equal(0.0, 0.0, 1e-9)

出力例 3

true
Reference 
bool nearly_equal(double a, double b, double rel_tol) {
    double larger = fabs(a) > fabs(b) ? fabs(a) : fabs(b);
    return fabs(a - b) <= rel_tol * larger;
}

0.1も0.2も0.3も、2進数の double では丸めた近い値でしか表せません。足し算の結果にも丸めが入るので、0.1 + 0.2 == 0.3 は偽になります。期待値を == で比べるテストは、計算が正しくても失敗します。そこで差の大きさを見ますが、許す幅を 1e-9 のような固定の値にすると、入力例 2 の 1e-12 と 2e-12 は差が 1e-12 しかないので等しいと判定されてしまいます。2倍も違う値です。

許す幅を値の大きさに比例させれば、この問題は起きません。差を値の大きさで割った比を相対誤差（relative error）といい、nearly_equal は相対誤差が rel_tol 以下かを、割り算をせずに掛け算の形で確かめています。割らないので、入力例 3 のように両方が0でも0で割ることにならず、0 <= 0 で true になります。比較を < にすると、この場合が false になります。

掲載したのは参考実装で、唯一の正解ではありません。大きいほうの絶対値は <math.h> の fmax(fabs(a), fabs(b)) でも求められます。相対誤差だけでは、期待値が0のとき（たとえば 0.1 + 0.2 - 0.3 の結果と0）は、計算結果がちょうど0でない限り等しいと判定できないので、実際のテストでは絶対誤差の下限を足した形もよく使われます1。

  1. Python の math.isclose(a, b, rel_tol=1e-09, abs_tol=0.0) は、差の絶対値が rel_tol 倍の幅と abs_tol の大きいほう以下かで判定します。abs_tol を0のままにすると、この問題の nearly_equal と同じ判定です。
