utf8_prefix.c

#include <stddef.h>

size_t utf8_prefix(const char *s, size_t n) {
}

s は UTF-8 で符号化された正しい文字列です。その先頭 n 文字(コードポイント)が占めるバイト数を返す utf8_prefix を書いてください。s の文字数が n に満たないときは s 全体のバイト数を返し、n が 0 なら 0 を返します。

入力例 1

utf8_prefix("naïve", 3)

出力例 1

4

入力例 2

utf8_prefix("東京", 1)

出力例 2

3

入力例 3

utf8_prefix("abc", 5)

出力例 3

3
Reference 
#include <stddef.h>

size_t utf8_prefix(const char *s, size_t n) {
    size_t i = 0;
    for (; s[i] != '\0'; i++) {
        bool lead = ((unsigned char)s[i] & 0xC0) != 0x80;
        if (lead && n-- == 0)
            break;
    }
    return i;
}

UTF-8 では、文字の先頭のバイトと2バイト目以降の継続バイトを上位2ビットで見分けられます。継続バイトはどれも 10xxxxxx の形なので、0xC0 でマスクした結果が 0x80 になるのが継続バイトで、それ以外が文字の先頭です。参考実装はバイトを前から順に見て、文字の先頭に出会うたびに残りの文字数 n を1つ減らします。

止まる位置は、n 文字目の先頭ではなく n + 1 文字目の先頭です。n 文字目の先頭で止めると、その文字の継続バイトが勘定に入りません。utf8_prefix("naïve", 3) なら3文字目 ï の先頭 0xC3 で止まって 3 を返し、2バイトある ï を途中で切ってしまいます。4文字目 v の先頭まで進めば、手前の ï の継続バイトは数え終わっており、4 が返ります。n + 1 文字目より先に終端の '\0' に着いたときは、ループを抜けた i がそのまま全体のバイト数です。

n-- == 0 は、減らす前の n を 0 と比べます。n が 0 のときに文字の先頭に着けばそこで抜けるので、n が 0 なら最初のバイトで止まって 0 を返します。このときにも減算は起きますが、size_t の減算は折り返すだけで未定義動作にはならず、減った値は使われません。

char が符号付きか符号なしかは処理系が決めます。符号付きの処理系では 0xC3 のようなバイトは負の値として読まれ、s[i] >= 0x80 のように大小で判定すると、先頭バイトも継続バイトもこの条件を満たしません。参考実装は unsigned char に変換してからマスクを掛けるので、どちらの処理系でも同じ値を見ます。

掲載したのは参考実装で、唯一の正解ではありません。数えた先頭バイトの数を別の変数に持ち、n と比べる書き方でもかまいません。
