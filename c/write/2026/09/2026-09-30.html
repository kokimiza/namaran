fail.c

[[noreturn]] void fail(const char *msg) {
}

標準出力に msg と改行を書いてから、終了状態 EXIT_FAILURE でただちにプログラムを終える fail を書いてください。atexit で登録した関数は呼びません。fail を呼ぶ前に標準出力へ書いた内容と msg は、出力先が端末でもファイルでも失われないようにします。例の bye は、標準出力に bye と1行書く関数です。

入力例 1

atexit(bye); printf("1 2 "); fail("stop");

出力例 1

1 2 stop

入力例 2

atexit(bye); fail("disk full");

出力例 2

disk full
Reference 
[[noreturn]] void fail(const char *msg) {
    puts(msg);
    fflush(stdout);
    _Exit(EXIT_FAILURE);
}

exit(EXIT_FAILURE) では条件を満たせません。exit は atexit で登録した関数を呼んでから終わるので、例1の出力に bye の行が加わります。登録した関数を呼ばずに終わるには _Exit を使います。

ただし _Exit は、ストリームのバッファを吐き出すかどうかを処理系に任せており、glibc は吐き出さずに終わります。標準出力が端末につながっていれば行バッファリングなので、puts が書く改行でそこまでの内容が送り出されます。ファイルやパイプにつながっていると完全バッファリングになり、1 2 も stop もバッファに残ったまま消えます。出力先によらず残すには、_Exit の前に fflush(stdout) で自分で吐き出します。

fflush を呼ぶ位置も決まっています。puts より先に呼ぶと、そのあとに書いた msg がまたバッファに残るので、書いてから吐き出し、それから終わります。fail は呼び出し元へ戻らないので [[noreturn]] を付けています。掲載したのは参考実装で、唯一の正解ではありません。標準出力のほかにも書き込み中のファイルがあるなら、fflush(NULL) で出力用のストリームをまとめて吐き出せます1。

  1. abort も後始末の関数を呼びませんが、バッファを吐き出すかどうかは処理系次第で、終了状態も EXIT_FAILURE ではなく異常終了を表す値になります。quick_exit は at_quick_exit で登録した関数だけを呼んでから _Exit と同じように終わるので、こちらもバッファは自分で吐き出す必要があります。
