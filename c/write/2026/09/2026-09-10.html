matrix_alloc.c

int **alloc_matrix(size_t rows, size_t cols) {
}

void free_matrix(int **m) {
}

rows行cols列のintの行列を確保し、m[i][j]で読み書きできるint **を返すalloc_matrixと、それを解放するfree_matrixを書いてください。全要素は1つの連続した領域に行の順で並べます。確保に失敗したら、途中まで確保したものを解放してNULLを返します。rowsとcolsは1以上とし、free_matrix(NULL)は何もしません。m = alloc_matrix(2, 3) → &m[1][0] - &m[0][0]が3、確保に失敗 → NULL、free_matrix(NULL) → 何もしない

Reference 
int **alloc_matrix(size_t rows, size_t cols) {
    int **m = malloc(rows * sizeof *m);
    if (m == NULL) {
        return NULL;
    }
    m[0] = malloc(rows * cols * sizeof **m);
    if (m[0] == NULL) {
        free(m);
        return NULL;
    }
    for (size_t i = 1; i < rows; i++) {
        m[i] = m[0] + i * cols;
    }
    return m;
}

void free_matrix(int **m) {
    if (m != NULL) {
        free(m[0]);
    }
    free(m);
}

確保は2回です。1回目は各行の先頭を指すポインタの表(int *がrows個)、2回目は全要素ぶんのint(rows * cols個)で、表のi番目には2回目の領域のi * cols番目のアドレスを入れます。m[i][j]は*(*(m + i) + j)なので、表からi行目のポインタを読み、そこからj個進んだintに届きます。

本物の2次元配列int a[2][3]なら、行の長さを型が知っているので、a[i][j]はアドレスを1回計算するだけで届きます。int **のm[i][j]は、表と要素の2か所を読みます。それでも要素を1つの領域に置いておけば、m[0]をint *としてrows * cols個まとめてmemcpyやqsortに渡せ、解放もfree2回で済みます。行ごとにmallocする書き方でも動きますが、確保と解放がrows + 1回に増え、途中で失敗したときの後始末も長くなります。

これは参考実装であり、唯一の正解ではありません。rows * colsの掛け算がsize_tで桁あふれしないかは、ここでは確かめていません1。

  1. 大きなrowsやcolsを受け付けるなら、掛ける前にcols > SIZE_MAX / rowsを確かめてNULLを返します。
