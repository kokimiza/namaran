straddle.c

#include <stdio.h>

struct pt { int x, y; };

#define CROSS(o, p, q) (p.x - o.x) * (q.y - o.y) - (p.y - o.y) * (q.x - o.x)

static bool straddles(struct pt a, struct pt b, struct pt c, struct pt d) {
    return CROSS(a, b, c) * CROSS(a, b, d) < 0;
}

int main(void) {
    struct pt a = {0, 0}, b = {2, 2}, c = {0, 1}, d = {2, 0};
    printf("%d %d\n", straddles(a, b, c, d), straddles(c, d, a, b));
}

これは何を出力するでしょうか?

Answer

1 0 です。

CROSS(o, p, q) が計算しようとしているのは、ベクトル o→p と o→q の外積(cross product)です。平面のベクトル (x1, y1) と (x2, y2) の外積は x1y2 − y1x2 で、o から p へ進むとき q が左側にあれば正、右側にあれば負、直線上なら0になります。straddles は、c と d が直線 ab の反対側にあるかを、2つの外積の積が負かどうかで判定するつもりの関数です。意図どおりなら、1つ目の呼び出しの外積は 2 と −4、2つ目は −2 と 4 で、どちらも積が負なので 1 1 になりそうに見えます。

ところが CROSS はマクロなので、呼び出しは字句のまま置き換えられます。置き換えた結果の全体を囲む括弧がないため、外積の引き算の左の項を P、右の項を Q と書くと、CROSS(a, b, c) * CROSS(a, b, d) < 0 は P1 − Q1 * P2 − Q2 < 0 になります。* は - より強く結びつくので、掛け合わされるのは1つ目の Q1 と2つ目の P2 だけで、外積どうしの積はどこにも現れません。

1つ目の呼び出しでは P1 = 2、Q1 = 0、P2 = 0、Q2 = 4 なので、2 − 0 − 4 = −2 となり、たまたま負になって 1 が出ます。2つ目の呼び出しでは P1 = −2、Q1 = 0、P2 = 2、Q2 = −2 なので、−2 − 0 + 2 = 0 です。0 は負ではないので、こちらは 0 になります。

置き換え結果の全体を括弧で囲めば、2つとも 1 になります。(p).x のように引数も括弧で囲むと、式を引数に渡したときに同じ問題が起きません。マクロをやめて static 関数にすれば、戻り値はいったん値になるので、優先順位の問題そのものが起きません。
