retry_jump.c

#include <setjmp.h>
#include <stdio.h>

int main(void) {
    jmp_buf env;
    volatile int n = 1;
    switch (setjmp(env)) {
        case 0:
            n += 10;
            longjmp(env, 0);
        case 1:
            n *= 2;
            longjmp(env, n);
        default:
            printf("%d\n", n);
    }
}

これは何を出力するでしょうか?

Answer

Output

22

longjmp が戻すのは実行の位置だけです。制御は setjmp から戻ってきたところへ移りますが、メモリにあるオブジェクトの値は巻き戻りません。n は volatile なので、setjmp を呼んだあとに書き換えても値は不定にならず、最後に書いた値のまま残ります。setjmp の戻り値は longjmp に渡した値ですが、0 を渡したときだけは 1 が返ります。0 は「初めて呼ばれた」ことを表す値なので、longjmp からは返せません。

初めて呼ばれた setjmp は 0 を返し、case 0 で n が 11 になります。longjmp(env, 0) で戻ると setjmp は 1 を返すので、次は case 1 に入ります。ここで n は 11 のままなので 22 になり、longjmp(env, 22) で戻ります。setjmp は 22 を返し、どの case にも当たらないので default で 22 を出力します。

longjmp に渡した 0 がそのまま返ると考えると、case 0 を何度も繰り返して終わらないと答えます。longjmp で n が setjmp を呼んだときの 1 に戻ると考えると、case 1 で 2 になり、出力は 1 か 2 になります。setjmp のあとで書き換えた局所変数は値が不定になると覚えていても、volatile が付いていればその規則は当てはまりません。
