two_checks.c

#include <stdio.h>

int main(void) {
    unsigned char msg[3][3] = {
        {0x41, 0x42, 0x43},
        {0xc1, 0xc2, 0x43},
        {0x40, 0x43, 0x43},
    };
    for (int i = 0; i < 3; i++) {
        unsigned char sum = 0, x = 0;
        for (int j = 0; j < 3; j++) {
            sum += msg[i][j];
            x ^= msg[i][j];
        }
        printf("%02x %02x\n", sum, x);
    }
}

これは何を出力するでしょうか?

Answer

Output

c6 40
c6 40
c6 40

1行目から計算します。sum += msg[i][j] は、sum と msg[i][j] を int に昇格してから足し、結果を unsigned char の sum に戻します。符号なしの型に入りきらない値を入れると、256 で割った余りになります。0x41 + 0x42 + 0x43 は 0xc6 で、まだ 256 未満です。x のほうは 0x41 ^ 0x42 が 0x03、それと 0x43 の XOR が 0x40 です。

2行目は、1行目の先頭2バイトの最上位ビット（0x80）を立てたものです。整数として足すと 0xc1 + 0xc2 + 0x43 = 0x1c6 で、1行目より 0x80 の2倍、つまり 256 だけ多くなります。sum に残るのは 256 で割った余りなので、1行目と同じ 0xc6 です。XOR は、各ビットの位置ごとに 1 の個数が奇数か偶数かを表します。同じ位置のビットが2バイトで反転すると、1 の個数は2つ増えるか2つ減るか1つずつ入れ替わるだけで、偶奇は変わりません。x も 0x40 のままです。

3行目は、0x41 の最下位ビットが 1 から 0 に、0x42 の最下位ビットが 0 から 1 に変わったものです。和は 1 減って 1 増えるので変わりません。XOR は、2行目と同じく同じ位置のビットが2回反転しただけなので変わりません。3行とも c6 40 になり、どちらの検査も2か所の破損を見逃します。

sum を整数のように読むと、2行目の和を 1c6 と答えます。unsigned char に戻す代入があるので、0x80 が2回加わった変化は消えます。XOR を「どこかのバイトが変われば値も変わる」と読むと、2行目と3行目の x に別の値を探すことになります。和は値の大きさしか見ず、XOR はビットごとの偶奇しか見ません。大きさが打ち消し合う破損や、同じ位置のビットが偶数回反転する破損は、どちらにも見えません。CRC は、どの位置のビットが変わったかによって余りへの効き方が変わるように作られています。同じ3行を8ビットの CRC で計算すると、3行とも違う値になります。
