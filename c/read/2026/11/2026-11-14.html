type_name.c

#include <stdio.h>

#define NAME(x) _Generic((x), char: "char", int: "int", char*: "char*", default: "other")

int main(void) {
    const char tag[] = "ab";
    char c = tag[0];
    printf("%s %s %s\n", NAME(tag), NAME(tag[1]), NAME(c = 'z'));
    printf("%c\n", c);
}

これは何を出力するでしょうか?

Answer

Output

other char char
a

_Generic は制御式の値ではなく型で関連付けを選びます。このときの型は、式を値として読み出したときの型です。配列は先頭要素へのポインタになり、オブジェクト自身に付いた const などの修飾子は外れます。1 そして制御式は型を決めるためだけに使われ、実行時には評価されません。

tag は const char の配列なので、値として読むと const char* になります。外れるのは tag 自身に付いた修飾子だけで、ポインタが指す先の const は型の一部として残ります。const char* は char* と別の型なので char* の関連付けには当たらず、default の "other" が選ばれます。

tag[1] は const char の要素そのものです。こちらは値として読み出すと要素自身の const が外れて char になり、"char" が選ばれます。同じ const でも、ポインタの指す先に付いていれば残り、読み出す値そのものに付いていれば外れます。

c = 'z' の型は、代入式の規則で左辺の型 char です。右辺の 'z' が int であることは代入式の型に関係しないので、3つ目も "char" です。制御式は評価されないので代入は起きず、c は tag[0] から入れた 'a' のまま2行目に出ます。

配列が char* になると考えると1つ目を char*、const が付いた要素はどこにも当たらないと考えると2つ目を other、'z' の型で選ばれると考えると3つ目を int と答えます。代入が実行されると考えると、2行目は z になります。

  1. 制御式の型をこれらの変換の後の型とする文言は、C11 に対する欠陥報告 DR 481 を受けて C17 で規格に入りました。それ以前は、const 付きの式をどの関連付けに当てるかが処理系によって分かれていました。
