fold_pair.c

#include <stdio.h>

int main(void) {
    int a = 2;
    int b = 7;
    for (int i = 0; i < 100; i++) {
        a = a + b;
        b = b - a;
    }
    printf("%d %d\n", a, b);
}

これは何を出力するでしょうか?

Answer

-9 2 です。

2行目の b = b - a; が読む a は、1行目で書き換えたあとの a です。更新前と更新後の値に別の名前を付けると、1回の繰り返しは next_a = a + b; と next_b = b - next_a; になります。next_b は b - (a + b)、つまり -a なので、1回の繰り返しで (a, b) は (a + b, -a) に移ります。2行の代入が同時に行われると読んで (a + b, b - a) とすると、値は回るたびに大きくなり、この答えには着きません。

100回を1回ずつ追う必要はありません。文字のまま3回続けると、(a, b) は (a + b, -a)、(b, -a - b)、(-a, -b) と移ります。3回で両方の符号が反転するので、6回で元の (2, 7) に戻ります。100 は 6 × 16 + 4 なので、結果は4回目と同じです。(2, 7) から (9, -2)、(7, -9)、(-2, -7)、(-9, 2) と進み、-9 2 が表示されます。値は −9 から 9 の間を回るだけなので、オーバーフローは起きません。

読みにくさの元は、a という1つの名前が、ループの本体の中で「更新前の値」と「更新後の値」の2つを指していることです。値ごとに名前を分けると、1回の繰り返しが何をするのかがはっきりし、周期にも気付きやすくなります。
