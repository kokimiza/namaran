lazy_base.c

#include <stdatomic.h>
#include <stdio.h>

static int get(void) {
    static atomic_bool started;
    static int base;
    if (!atomic_exchange(&started, true)) {
        printf("init %d\n", get());
        base = 10;
    }
    return base;
}

int main(void) {
    printf("%d\n", get());
}

これは何を出力するでしょうか?

Answer

Output

init 0
10

atomic_exchange は、新しい値を書き込み、書き込む前の値を返します。この2つは1つの操作として行われるので、複数のスレッドが同時に呼んでも false を受け取るのは1回だけです。get はこの性質を使って、初期化する役を1人に絞っています。ただし旗が立つのは初期化を始める時点で、終えた時点ではありません。

main からの1回目の呼び出しでは、started は静的変数なので最初は false です。atomic_exchange は false を返して旗を true にし、if の中へ進みます。printf が何かを書く前に、引数の get() が評価されます。この2回目の呼び出しでは atomic_exchange が true を返すので if を飛ばし、その時点の base を返します。base もまだ一度も代入されていない静的変数なので 0 です。こうして先に init 0 が出て、そのあと base が 10 になり、1回目の呼び出しが 10 を返して main が 10 を出します。

旗を「初期化が済んだ」印と読むと、2回目の呼び出しも if に入ると考え、再帰が止まらないと答えることになります。call_once のように、ほかの呼び出しは初期化が終わるまで待つと考えると init 10 と答えますが、この自前の仕組みには待つ処理がありません。2回目の呼び出しは、別のスレッドが初期化の途中に get を呼んだ場合と同じ立場にあり、そのスレッドも 0 を受け取ります。call_once は、ほかの呼び出しを初期化の完了まで待たせることで、これを防いでいます。
