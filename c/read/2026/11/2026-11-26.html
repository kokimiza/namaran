flags.c

#include <stdio.h>

void parse(int argc, char* argv[]) {
    int flags = 0;
    while (--argc > 0 && (*++argv)[0] == '-')
        while (*++argv[0])
            flags++;
    printf("%d %d\n", flags, argc);
}

int main(void) {
    char* v[] = {
        "prog", "-ab", "-c", "x", NULL};
    parse(4, v);
    parse(4, v);
}

これは何を出力するでしょうか?

Answer

Output

3 1
0 3

parse の中には、進め方の違う2種類のポインタがあります。仮引数の argv は main の配列 v の先頭を指すポインタの写しで、++argv が進めるのはこの写しだけです。一方 *++argv[0] は、[] が前置の ++ より強く結び付くので ++(argv[0]) と読みます。argv[0] は v の要素そのもので、これを進めると、v に入っている文字列へのポインタが書き換わります。この書き換えは parse から戻っても残ります。

1回目の呼び出しでは、argc が 3 になったところで argv が v[1] を指し、"-ab" の先頭は - なので内側のループに入ります。内側のループは v[1] を1文字ずつ進め、a と b で flags を2回増やし、終端の '\0' を指したところで止まります。v[2] の "-c" も同じで flags は 3 になり、v[2] も終端を指して残ります。argc が 1 になったところで v[3] の "x" を見て外側のループを抜けるので、3 1 を出力します。

2回目の呼び出しも argc を 3 に減らし、argv を v[1] へ進めます。ところが v[1] はもう "-ab" の先頭ではなく、1回目が残した終端の位置を指しており、そこから読める文字列は空です。先頭の文字は '\0' で - ではないので、外側のループは何も数えずに抜け、0 3 を出力します。

2回の呼び出しは引数がまったく同じなので、同じ処理を2度たどって 3 1 を2行と答えたくなります。argc と argv は呼ぶたびに新しく写されますが、v の要素は1つしかありません。1回目の呼び出しが何を書き換えたままにしたかを見れば、2回目は1行目を読むだけで答えが出ます。
