concat.c

#include <stdio.h>

static int scanned;

static char *cat(char *dst, const char *src) {
    while (*dst) {
        dst++;
        scanned++;
    }
    while ((*dst++ = *src++))
        ;
    return dst;
}

int main(void) {
    char buf[16] = "id:";
    char *end = cat(buf, "ab");
    cat(end, "cd");
    printf("%s %d\n", buf, scanned);
}

これは何を出力するでしょうか?

Answer

id:ab 3 です。

cat は dst から終端のヌル文字まで進みながら scanned を数え、そこへ src を写して、写し終えた位置を返します。返った位置を次の呼び出しの dst に渡せば、連結のたびに先頭から読み直さずに済むという設計です。1回目の cat(buf, "ab") は "id:" の3文字を走査して scanned を 3 にし、buf[3] から "ab" とヌル文字を写します。

ずれるのは、写すループの後置インクリメントです。*dst++ = *src++ はヌル文字を写した回にも dst を進めるので、ループを抜けたときの dst はヌル文字の1つ先の buf + 6 を指しています。end が置かれるのはヌル文字の上ではなく、その先です。

char buf[16] = "id:"; は、初期化子より後ろの要素をすべて0で埋めます。2回目の呼び出しでは buf[6] が最初からヌル文字なので走査は0文字で終わり、"cd" は buf[6] から写されます。scanned は 3 から増えません。

このとき buf には "id:ab"、ヌル文字、"cd" の順に並んでいます。%s は最初のヌル文字で止まるので、表示されるのは id:ab だけです。cat がヌル文字の位置を返していれば id:abcd 3 に、strcat のように dst をそのまま返していれば2回目が "id:ab" の5文字を走査し直して id:abcd 8 になるところでした。
