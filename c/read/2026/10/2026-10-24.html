round_trip.c

#include <stdio.h>

int main(void) {
    long long n = (1LL << 53) + 1;
    double d = (double)n;
    printf("%d %lld\n", n == d, (long long)d - n);
}

これは何を出力するでしょうか?

Answer

1 -1 です。

double を IEEE 754 の倍精度(binary64)とすると1、仮数部は53ビットなので、253 以上 254 未満の範囲で表せる値は2おきになります。n の 253+1 は、隣り合う2つの値 253 と 253+2 のちょうど中間にあります。既定の丸めは最も近い値を選び、中間なら仮数の最下位ビットが0になる方を選ぶ最近接偶数丸め(round half to even)なので、d は 253 になります。

n == d は long long と double の比較で、通常の算術型変換により n のほうが double に変換されてから比べられます。この変換も d を作ったときと同じ丸めを通るので、左辺も 253 になり、比較は真で 1 です。d は精度を失ったのだから n とは等しくないはずだ、と読むと 0 と答えることになります。

(long long)d - n では向きが逆になり、d が整数に戻ってから long long の引き算が行われます。253 は long long で正確に表せるので、結果は 253 - (253+1) の -1 です。比較の == は失われた1を見つけられませんが、整数の側で計算すればその1が差として現れます。

  1. C の規格は double の形式を決めておらず、表せない整数を浮動小数点数へ変換するときに上下どちらへ丸めるかも処理系定義です。付属書F(IEC 60559)に従う処理系は __STDC_IEC_559__ を定義し、変換を現在の丸めモードで行います。丸めモードの既定は最近接偶数丸めです。
