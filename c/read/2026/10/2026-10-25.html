single_flight.c

#include <stdatomic.h>
#include <stdio.h>

struct entry {
    int loaded_at;
    atomic_flag busy;
};

int get(struct entry* e, int now) {
    if (!atomic_flag_test_and_set(&e->busy) && now - e->loaded_at >= 2) {
        e->loaded_at = now;
        atomic_flag_clear(&e->busy);
    }
    return e->loaded_at;
}

int main(void) {
    struct entry e = {-2, ATOMIC_FLAG_INIT};
    for (int now = 0; now < 6; now++)
        printf("%d\n", get(&e, now));
}

これは何を出力するでしょうか?

Answer

0 が6行出ます。

atomic_flag_test_and_set は、フラグを立てたうえで、立てる前の値を返します。返り値が false なら自分が鍵を取ったことになり、true なら誰かがすでに持っています。どちらの場合も、呼んだあとのフラグは立っています。

now が 0 のときは、鍵を取り、0 - (-2) が 2 なので期限切れと判定されます。loaded_at を 0 にし、鍵を返します。now が 1 のときも、&& の左側が先に評価されて鍵を取ります。ところが右側の 1 - 0 >= 2 は偽なので、ブロックの中には入りません。鍵を返す atomic_flag_clear はブロックの中にしかないので、フラグは立ったまま残ります。

now が 2 以降では、test_and_set が true を返し、! で偽になります。&& は左側が偽なら右側を評価しないので、期限の確認まで進みません。再計算している人は誰もいないのに、鍵だけが残って全員が古い値を受け取り続けます。get は最後まで 0 を返します。

「期限が切れていたら鍵を取る」と読むと、2秒ごとに再計算されて 0 0 2 2 4 4 と答えることになります。そう動かすには now - e->loaded_at >= 2 を && の左側に置き、期限切れのときだけ鍵を取りにいく順にします。副作用のある式を && の左側に置くと、右側が偽だった場合にもその副作用だけが残ります。
