expect.c

#include <stdio.h>

static int failures = 0;
#define EXPECT(cond) failures += !cond

static int clamp(int x, int lo, int hi) {
    return x < lo ? hi : x > hi ? lo : x;
}

int main(void) {
    EXPECT(clamp(5, 0, 10) == 5);
    EXPECT(clamp(-5, 0, 10) == 0);
    EXPECT(clamp(15, 0, 10) == 10);
    printf("%d failed\n", failures);
}

これは何を出力するでしょうか?

Answer

1 failed です。

clamp は下限と上限を取り違えていて、x < lo のときに hi を、x > hi のときに lo を返します。テストが意図どおりに働けば2つ目と3つ目が失敗し、2 failed になるはずです。ところがマクロは引数を字句のまま置き換えるので、EXPECT(clamp(5, 0, 10) == 5) は failures += !clamp(5, 0, 10) == 5 に展開されます。単項の ! は == より強く結びつくため、否定されるのは比較の結果ではなく clamp の戻り値で、式は (!clamp(5, 0, 10)) == 5 と読まれます。

! の結果は0か1のどちらかです。1つ目は clamp が5を返し、!5 は0、0 == 5 は偽なので0を足します。2つ目は clamp が誤って10を返し、!10 は0になり、期待値がたまたま0なので 0 == 0 が真になって1を足します。3つ目は誤って0が返り、!0 は1ですが、1 == 10 は偽です。失敗として数えられるのは2つ目だけです。

この形のマクロは、期待値が0か1でない比較を一度も失敗にできません。2つ目が数えられたのも、期待値が0だったからにすぎません。#define EXPECT(cond) failures += !(cond) と引数を括弧で囲めば、否定は比較全体に掛かり、出力は 2 failed になります1。

  1. GCC は -Wall に含まれる -Wlogical-not-parentheses で、! が比較の左辺にしか掛かっていない式を警告します。展開後の式に対して出るので、マクロの中の書き忘れもここで見つかります。
