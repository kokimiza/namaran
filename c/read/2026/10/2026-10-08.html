longest.c

#include <stdio.h>
#include <string.h>

int main(void) {
    FILE *f = tmpfile();
    if (!f) return 1;
    fputs("abcdef\n\nghijklmn", f);
    rewind(f);

    char buf[4];
    size_t len = 0, longest = 0;
    int lines = 0;
    while (fgets(buf, sizeof buf, f)) {
        len += strlen(buf);
        if (buf[strlen(buf) - 1] != '\n') continue;
        lines++;
        if (len > longest) longest = len;
        len = 0;
    }
    printf("%d %zu\n", lines, longest);
}

これは何を出力するでしょうか?

Answer

2 7 です。

fgets(buf, sizeof buf, f) が1回に読むのは最大で sizeof buf - 1、つまり3文字で、改行を読んだらそこで止まります。読んだ改行は捨てずに buf に残します。1行目の abcdef\n は abc、def、\n の3回に分かれて届き、改行を含む3回目で len は7になります。strlen は改行も1文字に数えるので、longest に入るのは6ではなく7です。

2行目の空行は \n だけが1回で届き、len は1、lines は2になります。

最後の ghijklmn は8文字あり、ghi、jkl、mn に分かれて届きます。ファイルが改行で終わっていないので、どの塊も改行で終わらず、3回とも continue で次の fgets へ進みます。その次の fgets はファイルの終わりで NULL を返し、ループはそこで抜けます。len に溜まった8は longest と比べられないまま捨てられ、lines も増えません。最後の行も1行と数えて 3 8 と考えると間違えます。

このコードは塊ごとに長さを足し、改行が来た時点で1行と数えるので、どれほど長い行でも4バイトの buf だけで読めます。ただしこの数え方では改行で終わらない最後の行が数えられないので、ループの後で len が0でなければ、それも1行として扱う処理が要ります1。

  1. POSIX の getline は、行全体が入るまでバッファを広げながら読むので、どれほど長い行でも1回で受け取れます。そのかわり、使うメモリは一番長い行の長さに比例します。
