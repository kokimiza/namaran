writer_wait.c

#include <stdio.h>

static const int arrivals[] = {0, 2, 4, 6, 9};  // each reader reads for 3 ticks

static int readers_at(int t) {
    int n = 0;
    for (size_t i = 0; i < sizeof arrivals / sizeof arrivals[0]; i++)
        if (arrivals[i] <= t && t < arrivals[i] + 3) n++;
    return n;
}

int main(void) {
    int t = 1;                 // the writer starts waiting here
    while (readers_at(t) > 0)  // and may enter only when nobody is reading
        t++;
    printf("%d\n", t);
}

これは何を出力するでしょうか?

Answer

12 です。

readers_at(t) は、arrivals[i] <= t && t < arrivals[i] + 3 を満たす読み取り、つまりティック t に読んでいる最中の読み取りを数えます。到着 0 の読み取りが読んでいるのはティック0から2、到着 2 は2から4、到着 4 は4から6、到着 6 は6から8、到着 9 は9から11です。

書き込みはティック1から待ち始めますが、1から8まではどのティックにも誰かが読んでいます。ティック9では到着 6 の読み取りが抜けるものの(9 < 6 + 3 は偽)、同じティックに到着 9 の読み取りが入るので、readers_at(9) は1です。誰も読んでいないティックは12が最初で、書き込みはそこでようやく入れます。1回の読み取りは3ティックで終わるのに、書き込みは11ティック待たされます。

このコードの書き込みは、読んでいる人が1人もいない瞬間を待つだけで、読み取りの到着を止めません。書き込みが待っていても新しい読み取りが入れるこの方式を読み取り優先と呼びます。読み取りが重なりながら到着し続ける限りその瞬間は来ず、書き込みはいつまでも入れません。これが書き込み側の飢餓です。
