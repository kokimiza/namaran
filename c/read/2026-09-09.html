detect_n_plus_one.c

#include <stdio.h>
#include <string.h>

int main(void) {
    const char *queries[] = {
        "SELECT * FROM posts",
        "SELECT * FROM users WHERE id = ?",
        "SELECT * FROM users WHERE id = ?",
        "SELECT * FROM users WHERE id = ?",
        "SELECT * FROM tags WHERE post_id IN (?)",
    };
    size_t n = sizeof queries / sizeof queries[0];
    size_t run = 1;
    for (size_t i = 1; i <= n; i++) {
        if (i < n && strcmp(queries[i], queries[i - 1]) == 0) {
            run++;
            continue;
        }
        if (run >= 3) {
            printf("N+1? %zu x %s\n", run, queries[i - 1]);
        }
        run = 1;
    }
    return 0;
}

これは何を出力するでしょうか?

Answer

N+1? 3 x SELECT * FROM users WHERE id = ? の1行だけを出力します。

ループは直前と同じSQLが続くあいだ run を増やし、違うSQLに変わったところで、それまでの連続が3回以上なら報告します。strcmp は2つの文字列が等しいときに0を返すので、== 0 が「同じSQLが続いた」の条件です。users のSQLは3行続くので、i = 4 で tags のSQLに変わった時点で run は3になっており、ここで報告されます。posts と tags は1回ずつなので何も出ません。

上限が i < n ではなく i <= n なのは、ログの最後の連続を拾うためです。i == n の周回では i < n が偽になるので、queries[i] を読まずに報告の判定へ進みます。ログが users の連続で終わっていても、この周回で報告されます。

投稿の一覧を1本のSQLで取り、各投稿の著者を1件ずつ引くと、このログのように同じ形のSQLが投稿の数だけ並びます。これがN+1クエリで、見つけたら著者の取得を WHERE id IN (...) の1本にまとめます。
