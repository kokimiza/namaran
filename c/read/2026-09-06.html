stack_check.c

#include <assert.h>
#include <stdio.h>
#define NDEBUG

static int stack[] = {4, 7, 9};
static int top = 3;

static int pop(void) {
    return stack[--top];
}

int main(void) {
    assert(pop() == 9 || pop() == 7);
    assert(pop() == 7 && pop() == 4);
    printf("%d\n", top);
}

これは何を出力するでしょうか?

Answer

0 です。

assert が何に展開されるかは、<assert.h> を取り込んだ時点で NDEBUG が定義されているかどうかで決まります。このコードの #define NDEBUG は取り込みのあとにあるので、assert は式を評価して検査するマクロのまま残り、中の pop() は実行されます1。

1つ目の assert(pop() == 9 || pop() == 7) では、左の pop() が 9 を返して top が 2 になります。|| は左辺が真なら右辺を評価しないので、右の pop() は呼ばれません。2つ目の assert(pop() == 7 && pop() == 4) では、左の pop() が 7 を返して真になるため && の右辺も評価され、そこで 4 が取り出されます。pop() は合わせて3回呼ばれ、top は 0 で終わります。

NDEBUG で assert が消えると読むと、pop() は一度も呼ばれず 3 が出ると考えることになります。|| の右辺も評価されると読んだ場合は、1つ目で 9 と 7 が取り出され、2つ目の pop() == 7 が 4 == 7 で偽になるので、assert が失敗して何も出力せずに異常終了するように見えます。

#define NDEBUG を #include <assert.h> より前に移すか、コンパイラに -DNDEBUG を渡すと、2つの assert は中の式ごと消えて 3 が出力されます。条件の中で pop() を呼んでいるせいで、同じソースがビルドの設定によって 0 と 3 を出し分けます。

  1. <assert.h> は取り込むたびに、その時点の NDEBUG に合わせて assert を定義し直すと規格で決まっています。#define NDEBUG のあとでもう一度 <assert.h> を取り込めば、それより下の assert は消えます。
