#include <string>
#include <variant>

using Json = std::variant<std::nullptr_t, bool, int, std::string>;

std::string to_text(const Json& j) {
}

JSONの値を表す Json を受け取り、その値をJSONとして書いたときの字面を返す to_text を書いてください。nullptr は null、bool は true か false、int は10進の数、std::string は両端に " を付けた文字列にします。文字列の中のエスケープは考えなくてかまいません。

入力例 1

to_text(Json{true})

出力例 1

true

入力例 2

to_text(Json{std::string("hi")})

出力例 2

"hi"

入力例 3

to_text(Json{nullptr})

出力例 3

null

template <class... F> struct overloaded : F... { using F::operator()...; };

std::string to_text(const Json& j) {
    return std::visit(overloaded{
        [](std::nullptr_t) -> std::string { return "null"; },
        [](bool b) -> std::string { return b ? "true" : "false"; },
        [](int i) { return std::to_string(i); },
        [](const std::string& s) { return '"' + s + '"'; },
    }, j);
}

参考実装は、型ごとのラムダを overloaded で1つに束ねて std::visit に渡します。std::visit は j がいま持っている値をその型のまま渡すので、4つのラムダのうち引数の型が合うものが呼ばれます。

bool の変換は std::to_string に任せられません。bool は整数型の一つなので、std::to_string(true) では int 版が呼ばれて "1" が返ります。そのため bool 用のラムダを別に置いています。nullptr と bool のラムダに -> std::string と書いたのは、文字列リテラルをそのまま返すと戻り値の型が const char* と推論されるからです。std::visit は、どの型で呼んでも戻り値の型が同じであることを求めます。

掲載したのは参考実装で、唯一の正解ではありません。[](const auto& v) を1つだけ渡し、中で if constexpr と std::is_same_v を使って型を見分けてもかまいません。その場合は、std::remove_cvref_t で const と参照を外してから比べます。
