config_access.cpp

#include <string>

struct Config {
    std::string name = "default";
};

Config& config() {
}

configは、Configオブジェクトをただ1つだけ初回呼び出し時に生成し、以後は常にその同じオブジェクトへの参照を返す関数です(グローバル変数としてConfigを直接定義する代わりに、この関数を使えば他の静的初期化コードから呼ばれても初期化順序に依存しなくなります)。呼び出しの度に新しく作ってはいけません。config().name(初回) → "default"、&config() == &config() → true(常に同じオブジェクト)、config().name = "prod"; のあとの config().name → "prod"(変更が次回の呼び出しにも残る)

Reference 
Config& config() {
    static Config instance;
    return instance;
}

これは「Construct On First Use」と呼ばれるイディオムです。関数ローカルなstatic変数は、その関数が初めて呼ばれた時点で初めて初期化されることが規格で保証されています。グローバルスコープに直接Configオブジェクトを置いてしまうと、複数の翻訳単位にまたがる静的オブジェクト同士の初期化順序は規格上未規定になり、あるオブジェクトの初期化コードが、まだ初期化されていない別の静的オブジェクトを使ってしまう「static initialization order fiasco」を引き起こしかねません。関数呼び出しの形にしておけば、呼ばれた時点で確実に初期化が済んでいることが保証されるため、この問題を避けられます。これは参考実装であり、唯一の正解ではありません。
