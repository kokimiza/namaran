registry.cpp

#include <map>
#include <string>

std::map<std::string, int>& registry() {
}

名前から番号を引く表 std::map<std::string, int> を1つだけ持ち、その参照を返す registry を書いてください。表は最初に呼ばれたとき空の状態で用意し、以後はいつも同じ表を返します。別のファイルで定義された静的変数が、コンストラクタの中でもデストラクタの中でも registry() を呼ぶので、プログラムの開始前から終了処理の最後まで、どの時点で呼ばれても使える表を返してください。

入力例 1

registry().size()

出力例 1

0

入力例 2

registry()["x"] = 7; registry()["x"]

出力例 2

7

入力例 3

&registry() == &registry()

出力例 3

true
Reference 
#include <map>
#include <string>

std::map<std::string, int>& registry() {
    static auto* table = new std::map<std::string, int>;
    return *table;
}

参考実装は、関数内の static なポインタに new で作った表を1回だけ入れ、その表を最後まで解放しません。

表を大域変数 std::map<std::string, int> table; にすると、ほかのファイルの静的変数より先に構築される保証がありません。翻訳単位をまたぐ動的初期化の順序を規格は決めていないので、ほかのファイルのコンストラクタが、まだ構築されていない表に書き込むことがあります。関数内の static 変数は制御が初めて宣言を通ったときに構築されるので、誰が最初に呼んでも、返るのは構築済みの表です。

ただし static std::map<std::string, int> table; と値で持つと、今度は破棄の順序で壊れます。静的記憶域のオブジェクトは、構築が完了したのと逆の順に破棄されます。表より先に構築を終えたほかのファイルの変数が、あとから初めて registry() を呼んだ場合、表はその変数より後に構築されたことになり、先に破棄されます。その変数のデストラクタが registry() を呼ぶと、破棄済みの表を触ります。

new で作った表はデストラクタが呼ばれないので、終了処理のどの時点で呼ばれても生きています。メモリはプログラムが終わるときに OS が回収するので、解放しないことの実害はありません1。関数内 static の初期化はスレッドセーフなので、複数のスレッドが同時に最初の呼び出しをしても、作られる表は1つです。

掲載したのは参考実装で、唯一の正解ではありません。static auto& table = *new std::map<std::string, int>; と参照で持っても同じです。

  1. 静的変数から辿れるメモリは、LeakSanitizer もリークとして報告しません。
