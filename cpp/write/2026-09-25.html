checked_add.cpp

#include <limits>
#include <optional>

std::optional<int> checked_add(int a, int b) {
}

a + bがintで表せるならその和を、表せない(桁あふれする)ならstd::nulloptを返すchecked_addを書いてください。負の方向へのあふれもstd::nulloptです。checked_add(INT_MAX, 1) → std::nullopt、checked_add(-5, 3) → -2、checked_add(INT_MIN, -1) → std::nullopt

Reference 
std::optional<int> checked_add(int a, int b) {
    if (b > 0 && a > std::numeric_limits<int>::max() - b) {
        return std::nullopt;
    }
    if (b < 0 && a < std::numeric_limits<int>::min() - b) {
        return std::nullopt;
    }
    return a + b;
}

C++では符号つき整数のオーバーフローは未定義動作です(C++20で2の補数表現が必須になっても、ここは変わっていません)。だから「足してから、結果が小さくなっていないか調べる」(a + b < a)は書けません。あふれた時点でプログラム全体の意味が失われ、コンパイラはその比較を「常に偽」として消してよいからです。代わりに、あふれない計算だけで足す前に判定します。b > 0ならmax() - bは必ず表せるので、aがそれより大きければ上へあふれます。b < 0ならmin() - bが必ず表せるので、下へのあふれを同じ形で調べられます。これは参考実装であり、唯一の正解ではありません。GCC/Clangなら__builtin_add_overflow、C23なら<stdckdint.h>のckd_addが同じ判定をしてくれます。C++26のstd::add_sat(<numeric>)は、失敗を返す代わりにINT_MAXやINT_MINに張り付かせる飽和演算で、目的が違います。
