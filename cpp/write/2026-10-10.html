port_name.cpp

#include <string>

struct Device {
    virtual ~Device() = default;
    virtual std::string name() const { return "device"; }
};

struct Reader : virtual Device {
    std::string name() const override { return "reader"; }
};

struct Writer : virtual Device {
    std::string name() const override { return "writer"; }
};

struct Port : Reader, Writer {
    std::string name() const override {
    }
};

Port は読み取りと書き込みの両方の役目を持つ装置で、Reader と Writer が1つの Device を共有しています。Port の name() を書いてください。Reader の名前と Writer の名前を + でつないだ "reader+writer" を返し、Port を Device や Reader の参照を通して呼んだときも同じ文字列を返します。

入力例 1

Port p; p.name()

出力例 1

"reader+writer"

入力例 2

Port p; const Device& d = p; d.name()

出力例 2

"reader+writer"

入力例 3

Reader r; r.name()

出力例 3

"reader"
Reference 
std::string name() const override {
    return Reader::name() + "+" + Writer::name();
}

Reader::name() のように基底クラスの名前で修飾して呼ぶと、仮想関数でも動的な型による振り分けは起きず、Reader が定義した name がそのまま呼ばれます。修飾せずに name() と書けば Port::name 自身が呼ばれ、再帰が止まりません。

Port の name は省けません。Device は仮想基底クラスなので Port の中に1つしかなく、その name を Reader と Writer がそれぞれ上書きしています。Port が何も書かなければ、Device の参照から呼んだ name を Reader 版と Writer 版のどちらへ振り分けるかが決まらず、最終オーバーライダが一意でないとしてコンパイルエラーになります。Port::name を書くとそれが唯一の最終オーバーライダになり、入力例2のように Device の参照から呼んでも "reader+writer" が返ります。

掲載したのは参考実装で、唯一の正解ではありません。std::format("{}+{}", Reader::name(), Writer::name()) のように書いても同じ文字列を返せます。
