log.cpp

#include <string>

std::string* prefix;

struct LogInit {
    LogInit();
    ~LogInit();
};

LogInit::LogInit() {
}

LogInit::~LogInit() {
}

ヘッダ log.h には extern std::string* prefix; と上の LogInit の定義、それに static LogInit log_init; が書かれています。log.h は各翻訳単位の先頭でインクルードされるので、翻訳単位ごとに log_init が1つずつでき、その翻訳単位のほかの静的変数より先に構築されます。どの翻訳単位の静的変数も、コンストラクタとデストラクタの中で *prefix を使えるように、log.cpp に置く LogInit のコンストラクタとデストラクタを書いてください。*prefix の中身は "[app] " で、LogInit が1つでも生きている間は有効にし、すべて破棄されたら解放します。入出力例は、LogInit が1つもない状態から実行したときの標準出力です。

入力例 1

{ LogInit a, b; std::cout << *prefix << "start"; }

出力例 1

[app] start

入力例 2

{ LogInit a; { LogInit b; } std::cout << *prefix << "still"; }

出力例 2

[app] still

入力例 3

{ LogInit a; } LogInit b; std::cout << *prefix << "again";

出力例 3

[app] again
Reference 
#include <string>

std::string* prefix;
static int users;

struct LogInit {
    LogInit();
    ~LogInit();
};

LogInit::LogInit() {
    if (users++ == 0) prefix = new std::string("[app] ");
}

LogInit::~LogInit() {
    if (--users == 0) delete prefix;
}

参考実装は、生きている LogInit の数を users で数えます。数が0から1になるコンストラクタで *prefix を作り、1から0になるデストラクタで解放するので、入力例2のように内側の b が先に消えても、a が生きている限り *prefix は残ります。

users と prefix に初期化子を付けていないのは、どの log_init のコンストラクタより先に値が決まっている必要があるからです。初期化子のない静的変数はゼロ初期化され、これはどの翻訳単位の動的初期化よりも前に済みます。どの翻訳単位の log_init が最初に構築されても、そのコンストラクタは users == 0 を見て *prefix を作ります。std::string prefix = "[app] "; のように文字列そのものを大域変数にすると、その動的初期化と、ほかの翻訳単位の静的変数の初期化のどちらが先になるかは決まりません。

破棄の側は、静的変数が構築と逆の順に破棄されることを使います。各翻訳単位では log_init がほかの静的変数より先に構築されるので、破棄はそれらより後になります。*prefix を解放するのは、すべての log_init のうち最後に破棄されるものなので、その時点では *prefix を使う静的変数はどの翻訳単位にも残っていません。デストラクタのたびに解放すると、最初に破棄された log_init が、ほかの翻訳単位がまだ使う *prefix を消してしまいます。

掲載したのは参考実装で、唯一の正解ではありません。new の代わりに、適切に整列した静的な領域へ placement new で構築する書き方もあり、std::cout はこの仕組みで使えるようになっています1。

  1. この手法は Nifty Counter や Schwarz Counter と呼ばれます。<iostream> をインクルードすると、標準ライブラリによっては翻訳単位ごとに std::ios_base::Init のオブジェクトができ、その数を数えて std::cout などを構築・後始末します。C++11 からは、<iostream> をインクルードした翻訳単位の静的変数が std::cout を使えることを規格が保証しています。
