transfer.cpp

struct Account {
    std::mutex m;
    long balance;
};

bool transfer(Account& from, Account& to, long amount) {
}

口座 from の残高が amount 以上なら、from から to へ amount を移して true を返し、足りなければ何も変えずに false を返す transfer を書いてください。transfer は複数のスレッドから同時に、どの口座からどの口座へも呼ばれます。どの呼び出しも途中で止まったまま戻らない、ということがあってはいけません。from と to が同じ口座のこともあり、そのときは残高を変えずに、残高が amount 以上かどうかを返します。例では、口座を 名前{残高} と書き、呼び出す前と後の残高を示します。

入力例 1

a{100}, b{0}: transfer(a, b, 30)

出力例 1

true; a{70}, b{30}

入力例 2

a{70}, b{30}: transfer(b, a, 50)

出力例 2

false; a{70}, b{30}

入力例 3

a{70}: transfer(a, a, 70)

出力例 3

true; a{70}

bool transfer(Account& from, Account& to, long amount) {
    if (&from == &to) {
        std::lock_guard lock(from.m);
        return from.balance >= amount;
    }
    std::scoped_lock lock(from.m, to.m);
    if (from.balance < amount) {
        return false;
    }
    from.balance -= amount;
    to.balance += amount;
    return true;
}

残高を調べてから書き換えるまでの間に、別のスレッドが同じ口座を書き換えてはいけないので、from と to の両方の m をロックしてから調べます。2つを順に std::lock_guard で取ると、transfer(a, b, 1) を呼ぶスレッドが a を取り、同時に transfer(b, a, 1) を呼ぶスレッドが b を取ったところで、両方が相手の持つ mutex を待ち続けて止まります。std::scoped_lock に2つの mutex を渡すと、引数の順に関係なく、互いに待ち合って止まることのない手順で両方をロックします。

from と to が同じ口座だと、std::scoped_lock に同じ std::mutex を2回渡すことになります。同じスレッドがすでに持っている std::mutex をもう一度ロックするのは未定義動作なので、先にアドレスを比べ、同じ口座なら std::lock_guard で1回だけロックして残高を調べます。

どちらのロックも、return で関数を抜けるときにデストラクタが外します。残高が足りずに途中で戻る場合も、外し忘れることはありません。

掲載したのは参考実装で、唯一の正解ではありません。std::scoped_lock の代わりに、std::less で比べてアドレスの小さい口座から先にロックする、と順番を決めても、互いに待ち合って止まることはなくなります。
