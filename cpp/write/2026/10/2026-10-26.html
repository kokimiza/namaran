tagged_slot.cpp

struct Tagged {
    int value;
    unsigned version;
};

bool try_set(std::atomic<Tagged>& slot, Tagged seen, int desired) {
}

slot には値 value と、書き換えのたびに1増える版番号 version が入っています。seen は以前 slot から読んだ中身です。slot が seen を読んだときのままなら、値を desired にし、版番号を1つ進めて true を返す try_set を書いてください。読んだあとに一度でも書き換えがあったときは、値が元に戻っていても何もせずに false を返します。

入力例 1

std::atomic<Tagged> slot{Tagged{1, 0}};
try_set(slot, {1, 0}, 5)

出力例 1

true

入力例 2

std::atomic<Tagged> slot{Tagged{1, 2}};
try_set(slot, {1, 0}, 5)

出力例 2

false

入力例 3

std::atomic<Tagged> slot{Tagged{1, 0}};
try_set(slot, {1, 0}, 5);
try_set(slot, {1, 0}, 9)

出力例 3

false
Reference 
bool try_set(std::atomic<Tagged>& slot, Tagged seen, int desired) {
    return slot.compare_exchange_strong(seen, Tagged{desired, seen.version + 1});
}

compare_exchange_strong は、slot の中身を seen と丸ごと比べ、等しいときだけ新しい中身を書き込みます。比べる中身に版番号が入っているので、値が 1 から別の値を経て 1 に戻っていても、そのあいだの書き換えで版番号が進んでいれば比較は失敗します。書き込む版番号を seen.version + 1 にしておくと、この関数による書き換えも、あとで読む側から検出できます。

版番号で書き換えを検出できるのは、slot を書き換えるすべての経路が版番号を進めている場合だけです。値だけを書き戻す処理が一か所でもあれば、そこで同じ見逃しが起きます。

掲載したのは参考実装で、唯一の正解ではありません。compare_exchange_weak を使う場合は、中身が等しくても失敗することがあるので、呼び出し側で読み直してやり直す前提になります。
