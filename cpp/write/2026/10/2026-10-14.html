create.cpp

#include <iostream>
#include <memory>
#include <string>
#include <utility>

struct Widget {
    virtual ~Widget() = default;
    virtual void init() = 0;
};

struct Label : Widget {
    std::string text;
    explicit Label(std::string t) : text(std::move(t)) {}
    void init() override { std::cout << "[" << text << "]\n"; }
};

template <class T, class... Args>
std::unique_ptr<T> create(Args&&... args) {
}

Widget の派生クラスは、構築が終わったあとで init() を1回呼び、準備を済ませる約束になっています。T を args から構築し、init() を呼んでから std::unique_ptr<T> で返す create を書いてください。出力例は、呼び出したときに標準出力に出る文字列です。

入力例 1

create<Label>("OK")

出力例 1

[OK]

入力例 2

create<Label>("")

出力例 2

[]

template <class T, class... Args>
std::unique_ptr<T> create(Args&&... args) {
    auto p = std::make_unique<T>(std::forward<Args>(args)...);
    p->init();
    return p;
}

std::make_unique でオブジェクトを作り終えてから、init() を呼びます。make_unique から戻った時点で T までの構築が済んでいるので、p->init() は T の版、ここでは Label::init に届きます。引数は std::forward で、左辺値か右辺値かという区別を保ったまま T のコンストラクタへ渡します。

Widget のコンストラクタの中で init() を呼べば、create は要らなくなりそうに見えます。しかし Widget() の本体が動いている間、オブジェクトはまだ Widget で、仮想関数の呼び出しは Widget の版で解決されます。Widget::init は純粋仮想関数なので、この呼び出しは未定義動作です1。構築が終わってから呼ぶ、という順序を守らせるために、構築と init() を1つの関数にまとめています。

掲載したのは参考実装で、唯一の正解ではありません。std::unique_ptr<T> p(new T(std::forward<Args>(args)...)); と書いても同じように動きます。

  1. GCC 14 では、コンストラクタから純粋仮想関数を直接呼ぶと警告が出て、定義のない Widget::init を探すリンクにも失敗します。別のメンバ関数を間に挟んで呼ぶとビルドは通り、実行すると pure virtual method called と表示して異常終了します。
