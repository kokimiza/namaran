curry.cpp

auto curry(auto f) {
}

関数オブジェクト f を受け取り、その引数を1つずつ受け取る関数を返す curry を書いてください。f が3引数なら、curry(f)(a)(b)(c) は f(a, b, c) と同じ値になります。f の引数の個数は決まっておらず、ジェネリックラムダのように型も決まっていないことがあります。受け取った引数で f を呼べるようになった時点で呼び、その値を返します。引数なしで呼べる f なら、curry(f) がその場で f() の値を返します。

入力例 1

curry([](int a, int b, int c) { return a * 100 + b * 10 + c; })(1)(2)(3)

出力例 1

123

入力例 2

curry(std::plus<>{})(2)(3)

出力例 2

5

入力例 3

curry([] { return 7; })

出力例 3

7
Reference 
auto curry(auto f) {
    if constexpr (std::invocable<decltype(f)>)
        return f();
    else
        return [f](auto x) {
            return curry([f, x](auto... rest) -> decltype(f(x, rest...)) { return f(x, rest...); });
        };
}

引数の個数が分からないので、curry は毎回「いまの f を引数なしで呼べるか」だけを調べます。呼べるなら f() を返し、呼べなければ引数を1つ受け取るラムダ式を返します。そのラムダ式は、受け取った x を先頭に固定した新しい関数を作り、それをまた curry に渡します。入力例 1 では、(1) で「残りを受け取って f(1, ...) を呼ぶ関数」が、(2) で「f(1, 2, ...) を呼ぶ関数」ができ、(3) のあとの関数は引数なしで f(1, 2, 3) を呼べるので、ここで123が返ります。if constexpr の選ばなかった側は実体化されないので、2つの return の型が違ってもかまいません。

判定の要は、内側のラムダ式の -> decltype(f(x, rest...)) です。これを書かずに戻り値の型を推論に任せると、std::invocable は戻り値の型を知るために本体を実体化し、f(1) のような引数の足りない呼び出しがその場でコンパイルエラーになります。戻り値の型を宣言に書いておけば、呼べないことは宣言の置き換えの段階で分かり、エラーではなく「呼べない」という判定になります。入力例 2 の std::plus<> も、引数が1つのときは呼べないと判定されます。

捕捉はどちらもコピーにします。返したラムダ式は curry の呼び出しが終わったあとで呼ばれるので、[&f] のように参照で捕捉すると、とっくに消えた引数を指すことになります。

掲載したのは参考実装で、唯一の正解ではありません。受け取った引数を std::tuple に溜めていき、std::apply で f に渡せるかを requires 式で確かめる書き方もあります。どちらの書き方でも、既定引数を持つ関数は、既定引数を使える個数がそろった時点で呼ばれます。
