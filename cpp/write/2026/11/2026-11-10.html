port.cpp

struct Port {
    int value;

    consteval Port(int n) : value(n) {
    }
};

TCPのポート番号を持つ型 Port のコンストラクタの本体を書いてください。n が1以上65535以下なら、その値を value に持つ Port ができます。範囲外の n で Port を作ろうとする行は、実行時ではなくコンパイル時にエラーにします。

入力例 1

Port{8080}.value

出力例 1

8080

入力例 2

Port{65535}.value

出力例 2

65535

入力例 3

Port{0}.value

出力例 3

コンパイルエラー

Reference

struct Port {
    int value;

    consteval Port(int n) : value(n) {
        if (n < 1 || n > 65535) {
            throw "port out of range";
        }
    }
};

範囲外のときに throw へ進むだけで、コンパイル時のエラーになります。コンストラクタは consteval なので、Port{0} のような呼び出しはその場で定数として評価されなければなりません。定数として評価している途中で throw に達すると、その呼び出しは定数式になれず、GCC は throw の行を指して「定数式ではない」と報告します。範囲内の n では throw に達しないので、評価は最後まで進んで value に n が入ります。これは参考実装で、唯一の正解ではありません。投げる値は文字列でなくてもよく、その文字列はエラーメッセージに出るので、何が悪いかを書いておくと読む人の助けになります。

真っ先に思いつく static_assert(n >= 1 && n <= 65535); は、範囲内の値でもコンパイルできません。consteval 関数の中でも、引数の n は定数式の中で使えない値として扱われるからです。関数の本体は呼び出しごとではなく一度だけ型検査され、そのときの n は値の分からない変数です。値ごとの検査は、呼び出しごとの評価の中で throw のような定数式にできない処理に達するかどうか、で書くことになります。

consteval を constexpr に変えると、検査の効き方が変わります。constexpr Port p{0}; のように定数を求める場所ではエラーになりますが、普通の変数 Port p{0}; は実行時の呼び出しに回され、実行時に例外が投げられます。入力例3の Port{0}.value がどこに書かれてもコンパイルエラーになるのは、consteval が呼び出しを必ずコンパイル時に評価させるからです。
