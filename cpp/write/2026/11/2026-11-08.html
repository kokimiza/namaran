quine.cpp

#include <print>

int main() {
}

実行すると、このプログラム自身のソースコードと1文字も違わない文字列を標準出力に出すように、main を書いてください。最後の改行も含めて一致させます。ソースファイルを開いて読んではいけません。

入力例 1

./quine > out.cpp && cmp out.cpp quine.cpp && echo same

出力例 1

same

入力例 2

g++ -std=c++26 out.cpp -o q2 && ./q2 | cmp - quine.cpp && echo same

出力例 2

same

#include <print>

int main() {
    constexpr auto s = R"(#include <print>

int main() {{
    constexpr auto s = R{0}({1}){0};
    std::print(s, '{0}', s);
}}
)";
    std::print(s, '"', s);
}

ソースを出力するには、ソースを文字列として持つしかありません。ところがその文字列リテラルもソースの一部なので、文字列の中に文字列リテラル自身を書くことになり、その中にまたリテラルを書く、と終わりません。参考実装は、文字列 s を2つの役に使ってこの繰り返しを断ち切ります。s にはプログラム全体を書きますが、s 自身の中身が入る場所だけは {1} という穴にしておきます。std::print(s, '"', s) は s を書式文字列として出力しながら、その穴に s そのものを差し込みます。外側の文章は書式文字列としての s から、リテラルの中身は値としての s から出てくるので、中身を2回書く必要がありません。これは参考実装で、唯一の正解ではありません。

2つの役では、同じ文字の出方が違います。書式文字列として読まれると {{ は { になるので、int main() {{ は int main() { と出力されます。値として差し込まれた s は書いたとおりに出るので、リテラルの中では {{ のまま出力され、ソースのリテラルと一致します。二重引用符は s の中に1つも書かず、{0} の穴に引数の '"' を差し込んで出します。s が " を含まないので、生文字列の終わりの印 )" がリテラルの途中に現れることもありません。s を constexpr にしているのは、std::print が書式文字列をコンパイル時に検査し、定数式しか受け取らないためです。最後の行の }} のあとの改行も s に入っているので、出力の末尾はソースの最後の改行と一致し、入力例1の cmp は差を見つけません。出力はソースと同じなので、入力例2のようにそれをコンパイルして実行しても、また同じソースが出てきます。
