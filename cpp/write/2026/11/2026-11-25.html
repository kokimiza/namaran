int_buf.cpp

#include <cstddef>

class IntBuf {
    std::size_t n;
    int* p;

public:
    explicit IntBuf(std::size_t n)
        : n(n), p(new int[n]{}) {}
    IntBuf(IntBuf&& o) noexcept;
    ~IntBuf() {
        delete[] p;
    }
    std::size_t size() const {
        return n;
    }
};

IntBuf::IntBuf(IntBuf&& o) noexcept {
}

IntBuf は、要素数 n の int の配列を new[] で確保して持つクラスです。このクラスのムーブコンストラクタを書いてください。o が持っていた配列を、新しい配列を確保せずに新しいオブジェクトへ移し、o は要素数 0 のオブジェクトとして残します。要素数 0 の IntBuf をムーブしたときも同じです。例では、入力のコードを実行したあとの a.size() と b.size() をこの順に書きます。

入力例 1

IntBuf a(3); IntBuf b(std::move(a));

出力例 1

0 3

入力例 2

IntBuf a(0); IntBuf b(std::move(a));

出力例 2

0 0

#include <cstddef>
#include <utility>

class IntBuf {
    std::size_t n;
    int* p;

public:
    explicit IntBuf(std::size_t n)
        : n(n), p(new int[n]{}) {}
    IntBuf(IntBuf&& o) noexcept;
    ~IntBuf() {
        delete[] p;
    }
    std::size_t size() const {
        return n;
    }
};

IntBuf::IntBuf(IntBuf&& o) noexcept {
    n = std::exchange(o.n, 0);
    p = std::exchange(o.p, nullptr);
}

std::exchange(o.p, nullptr) は、o.p に nullptr を入れ、入れる前の値を返します。返ってきた元のポインタを p に受け取れば、配列の持ち主は新しいオブジェクトに移り、o はもう配列を指しません。要素数も同じように o.n から受け取り、o.n は 0 にします。掲載したのは参考実装で、唯一の正解ではありません。メンバ初期化子で : n(o.n), p(o.p) と受け取り、本体で o.n = 0; o.p = nullptr; と書いても同じです。

ポインタを写すだけで o.p を残すと、入力例1は 3 3 を出したあとで壊れます。ムーブされた a も、スコープを抜けるときにはデストラクタが呼ばれるからです。a と b の両方が同じ配列を delete[] して、二重解放になります。o.p を nullptr にしておけば、a のデストラクタの delete[] nullptr は何もしません。入力例2の要素数 0 でも、new int[0]{} が返すのは null でない有効なポインタで、delete[] で解放する必要があります。そのため要素数 0 のときも、ポインタを移して o.p を nullptr にする手順は変わりません。
