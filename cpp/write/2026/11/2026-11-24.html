std::size_t longest_line(std::istream& in) {
}

in から読める行のうち、いちばん長い行の文字数を返す longest_line を書いてください。行末の改行は文字数に数えません。最後の行に改行が付いていなくても1行として扱い、1行も無いときは 0 を返します。入力は何GBにもなるファイルのことがあるので、全体をメモリに読み込まず、使うメモリは最も長い1行の分までに抑えます。例では、in から読める中身を C++ の文字列リテラルで書きます。

入力例 1

"ab\ncdef\ng\n"

出力例 1

4

入力例 2

"xy\nlast"

出力例 2

4

入力例 3

""

出力例 3

0

std::size_t longest_line(std::istream& in) {
    std::string line;
    std::size_t best = 0;
    while (std::getline(in, line)) {
        best = std::max(best, line.size());
    }
    return best;
}

std::getline(in, line) は、次の改行の手前までを line に読み、改行そのものは読み捨てます。返すのはストリーム自身で、条件の中では「1文字以上読めたか、改行を読んだなら真」になるので、そのまま while の条件に書けます。line はループの外で1つだけ作って使い回すので、メモリはそれまでに読んだ最も長い行の分しか使いません。行を読むたびに長さを best と比べ、大きいほうを残します。掲載したのは参考実装で、唯一の正解ではありません。

入力例1では ab、cdef、g の3行を読み、最大の 4 を返します。最後の改行のあとには文字が無いので、4回目の getline は何も読めずに偽になり、空の4行目は生まれません。入力例2の last は改行で終わっていませんが、getline は1文字以上読めた時点で成功を返すので、ループの本体は実行されます。ストリームの終わりに着いたことは次の呼び出しで偽になって初めて分かります。入力例3は1回目の getline が偽になり、best は 0 のままです。
