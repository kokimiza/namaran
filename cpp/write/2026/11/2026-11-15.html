chosen_type.cpp

#include <type_traits>
#include <utility>

template <class U, class... Ts> struct chosen {
};

型の並び Ts の各型 T について、T を値で受け取る関数が1つずつあり、すべて同じ名前で多重定義されているとします。そこへ U 型の値を1つ渡して呼んだとき、選ばれる関数の引数の型を chosen<U, Ts...>::type にしてください。Ts は互いに異なる1個以上の型で、選ばれる関数はいつもただ1つに決まるものとします。

入力例 1

chosen<float, int, double>::type

出力例 1

double

入力例 2

chosen<const char*, std::string, bool>::type

出力例 2

bool

入力例 3

chosen<int, int>::type

出力例 3

int

#include <type_traits>
#include <utility>

template <class T> struct candidate {
    static std::type_identity<T> pick(T);
};

template <class... Ts> struct candidates : candidate<Ts>... {
    using candidate<Ts>::pick...;
};

template <class U, class... Ts> struct chosen {
    using type = decltype(candidates<Ts...>::pick(std::declval<U>()))::type;
};

どの関数が選ばれるかを決める規則を、型の計算として書き直す必要はありません。問題文にある多重定義を実際に宣言し、そこへ U の値を渡す呼び出し式を書けば、コンパイラ自身が選びます。選ばれた関数が分かるように、candidate<T>::pick は std::type_identity<T> を返すと宣言しておき、呼び出し式の型を decltype で取り出して、その ::type を答えにします。掲載したのは参考実装で、唯一の正解ではありません。

pick には本体がありません。decltype の中の式は型を調べるためだけにあり、評価されないので、呼ぶ関数は宣言されていれば足り、定義は要りません。U の値も同じで、std::declval<U>() は宣言だけの関数で、U を作れる型かどうかに関係なく「U の値」を表す式になります。Ts の型ごとに pick を1つずつ並べるには、candidate<Ts> をすべて基底クラスにし、using candidate<Ts>::pick...; でそれぞれの pick を1つの多重定義にまとめます。この using がないと、基底ごとの同じ名前がぶつかって呼び出しが曖昧になります。

入力例 1 では、float から double への変換は浮動小数点数の昇格として扱われ、int への変換より優先されます。入力例 2 では、const char* から bool への変換は組み込みの変換で、std::string のコンストラクタを通す変換より優先されるので、bool が選ばれます。こうした順位を自分で表にすると、例 2 のような思いがけない結果を取りこぼしますが、コンパイラに選ばせれば本物の呼び出しと同じ答えになります。入力例 3 のように候補が1つなら、その型がそのまま答えです。
