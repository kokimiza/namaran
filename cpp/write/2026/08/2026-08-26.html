#include <string>
#include <variant>

template <class... F> struct match : F... {
    using F::operator()...;
};

using Value = std::variant<std::monostate,
                           int,
                           std::string>;

std::string show(const Value& v) {
}

Value は、値が無い状態を表す std::monostate、整数、文字列のどれか1つを持ちます。v が値を持たなければ null、整数ならその10進表記、文字列なら前後を " で囲んだものを返す show を書いてください。match は、渡したラムダの operator() を1つのオーバーロードの集まりにまとめる型で、使っても使わなくてもかまいません。

入力例 1

show(Value{})

出力例 1

null

入力例 2

show(42)

出力例 2

42

入力例 3

show(std::string("hi"))

出力例 3

"hi"

#include <string>
#include <variant>

template <class... F> struct match : F... {
    using F::operator()...;
};

using Value = std::variant<std::monostate,
                           int,
                           std::string>;

std::string show(const Value& v) {
    return std::visit(
        match{
            [](std::monostate)
                -> std::string {
                return "null";
            },
            [](int n) {
                return std::to_string(n);
            },
            [](const std::string& s) {
                return '"' + s + '"';
            },
        },
        v);
}

std::visit は、v がいま持っている型に合わせて、match にまとめたラムダのどれかを呼びます。ラムダは Value の3つの型に1つずつ用意し、std::monostate のときに null を返すラムダも欠かせません。Value{} は最初の型の std::monostate を持つので、入力例 1 はこのラムダを通ります。掲載したのは参考実装で、唯一の正解ではありません。

1つ目のラムダにだけ -> std::string を書いているのは、std::visit が、どの型の場合も呼び出しの結果が同じ型であることを求めるからです。return "null"; だけでは、このラムダの戻り値型は const char* と推論されます。ほかの2つは std::string を返すので、型がそろわずコンパイルできません。2つ目は std::to_string が、3つ目は std::string に文字を足した '"' + s + '"' が std::string になるので、書かなくても戻り値型がそろいます。

v.index() で番号を調べて std::get で取り出す書き方もできます。ただしその書き方では、Value に型を足して分岐を書き忘れても、コンパイラは教えてくれません。std::visit なら、受け取れない型が残った時点でコンパイルが止まります。
