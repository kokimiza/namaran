make_argv.cpp

#include <string>
#include <vector>

std::vector<char *> make_argv(std::vector<std::string> &args) {
}

文字列のベクタ args から、execvp や posix_spawnp に渡す argv を作る make_argv を書いてください。戻り値は、args の各文字列の先頭を指す char * を順に並べ、最後に nullptr を1つ足したものです。args が空なら nullptr だけが入ります。args が {"ls", "-l"} → {args[0].data(), args[1].data(), nullptr}、args が {} → {nullptr}

Reference 
std::vector<char *> make_argv(std::vector<std::string> &args) {
    std::vector<char *> argv;
    argv.reserve(args.size() + 1);
    for (auto &a : args) {
        argv.push_back(a.data());
    }
    argv.push_back(nullptr);
    return argv;
}

exec 系と posix_spawn 系の関数は、argv を「char * の配列で、終わりが nullptr」として受け取ります。要素数を渡す引数はないので、最後の nullptr を忘れると、子プロセスの側で配列の外まで読み進めてしまいます。

要素の型が const char * ではなく char * なのは、これらの関数の引数が char *const argv[] と宣言されているからです。c_str() は const char * しか返しませんが、C++17 からは data() が const でない文字列に対して char * を返します。args を非 const の参照で受け取っているので、const_cast は要りません。

argv の要素は args の文字列バッファを指しているだけで、文字列をコピーしてはいません。子プロセスを起動し終えるまでは args を生かしておき、途中で文字列を伸ばしたり要素を足したりしないようにします。バッファが移動すると、argv のポインタは解放済みの領域を指します。掲載したのは参考実装で、唯一の正解ではありません。std::ranges::transform で詰めてから nullptr を足す書き方もあります。
