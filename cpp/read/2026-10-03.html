brace_sizes.cpp

#include <iostream>
#include <vector>

int main() {
    auto x = {3};
    auto y{3};
    std::vector<int> a(x);
    std::vector<int> b(y);
    std::vector<int> c{y};
    std::cout << a.size() << b.size() << c.size() << '\n';
}

これは何を出力するでしょうか?

Answer

131 です。

auto x = {3}; のように = と波括弧で初期化すると、auto は std::initializer_list<int> と推論されます。= の無い auto y{3}; は、要素が1つなら int です1。見た目のよく似た2行が、別の型の変数を作っています。

a(x) は丸括弧の初期化ですが、渡している x がすでに std::initializer_list<int> のオブジェクトです。オーバーロード解決でこの実引数に最もよく合うのは vector(std::initializer_list<int>) なので、a は要素 3 を1つだけ持ち、サイズは 1 です。丸括弧なら initializer_list のコンストラクタは選ばれない、と覚えていると、ここを 3 と読み違えます。

b(y) には int の 3 を丸括弧で渡すので、要素数を受け取る vector(size_type) が選ばれ、0 が3つ並びます。サイズは 3 です。

c{y} の中身は b と同じ int ですが、こちらは波括弧のリスト初期化です。リスト初期化では、initializer_list を受け取るコンストラクタが使えるならそれが最優先されます。{y} は std::initializer_list<int> になれるので、c も要素 3 を1つ持ち、サイズは 1 です。y が int だと見抜いた人ほど、b と同じ 3 を予想しやすいところです。

3つのサイズを区切らずに続けて出力するので、131 になります。

  1. C++11 と C++14 の規格では、auto y{3}; も std::initializer_list<int> でした。C++17 で、要素1つの直接リスト初期化は要素の型になるよう改められ(N3922)、GCC や Clang はこの変更を C++11/14 のモードにも遡って適用しています。auto y{3, 4}; のように要素が2つ以上あるとコンパイルエラーです。
