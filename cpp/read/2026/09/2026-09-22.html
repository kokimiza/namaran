static_order.cpp

#include <iostream>

struct Tracer {
    const char* name;
    Tracer(const char* n) : name(n) { std::cout << "+" << name << '\n'; }
    ~Tracer() { std::cout << "-" << name << '\n'; }
};

Tracer a("a");
Tracer b("b");

int main() {
    Tracer c("c");
    std::cout << "main\n";
}

このプログラムを実行すると、標準出力はどうなるでしょうか?

Answer

+a・+b・+c・main・-c・-b・-aの7行です。同じ翻訳単位内にあるファイルスコープの静的記憶域オブジェクト(a・b)は、その動的初期化が宣言順に行われることが規格で保証されており、しかもmainの最初の文より前に終わっています。だから+a・+bがまず出て、それからmainに入り、ローカル変数cが構築されて+c、続けてmainが出力されます。mainを抜けるとき、まずローカル変数cが(スコープを抜ける通常の規則で)破棄されて-c。そのあと、動的初期化を行った静的記憶域オブジェクトは構築順とは逆順に破棄されるので、b・aの順で-b・-aが出ます。ただし、この「宣言順」の保証が効くのはあくまで同じ翻訳単位の中だけです。a・bを別々の.cppファイルに分けてしまうと、複数の翻訳単位をまたいだ初期化順序は規格上未規定になり、これが俗に「static initialization order fiasco」と呼ばれる問題につながります。
