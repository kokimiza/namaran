#include <iostream>
#include <sstream>

int main() {
    std::istringstream in("abcdefghij");
    char buf[4];
    while (in.read(buf, 4)) {
        std::cout.write(buf, in.gcount());
        std::cout << '|';
    }
    std::cout.write(buf, in.gcount());
    std::cout << '\n';
}

これは何を出力するでしょうか?

Answer

Output

abcd|efgh|ij

in.read(buf, 4) は、4文字を読めたときだけ成功します。途中でストリームの終わりに着くと、読めた分だけ buf の先頭に入れたうえで failbit と eofbit を立てます。read が返すのはストリーム自身で、while の条件では failbit が立っていれば偽になります。読めた文字数は、成功か失敗かに関係なく in.gcount() が返します。

10文字の入力では、1回目と2回目の read が abcd と efgh を読んで成功し、ループの中でそれぞれ4文字と | を出力します。3回目は ij の2文字しか読めないので失敗し、ループの本体は実行されません。それでも buf の先頭2文字は ij に書き換わっており、gcount() は 2 なので、ループのあとの write が ij を出力し、最後に改行が続きます。

規則を1つずつしか使わないと、別の答えに着きます。2文字でも読めれば成功すると考えると、3回目もループの中に入って ij| を出力し、4回目の失敗のあとで gcount() が 0 になるので、出力は abcd|efgh|ij| です。失敗した read は buf も gcount() も変えないと考えると、ループのあとの write は前の efgh をもう一度書くことになります。実際の出力は、失敗が「4文字に足りなかった」ことだけを表し、読めた分は buf と gcount() に残る、という2つを合わせたものです。大きなファイルを固定長で読むループで、ループのあとにこの1行を忘れると、最後の半端なブロックだけが黙って処理されずに残ります。
