ctor_dispatch.cpp

#include <iostream>

struct A {
    virtual ~A() = default;
    virtual char id() const { return 'A'; }
};

struct B : A {
    B() { std::cout << id(); }
    char id() const override { return 'B'; }
};

struct C : B {
    C() { std::cout << id() << '\n'; }
    char id() const override { return 'C'; }
};

int main() {
    C c;
}

これは何を出力するでしょうか?

Answer

BC です。

C c; は、基底の A、B、C の順にコンストラクタを実行します。B() の本体が動いている間、C の部分はまだ作られていないので、オブジェクトは B としてふるまいます。仮想関数の呼び出しもこのとき実行中のコンストラクタのクラスで解決され、id() は B::id を呼んで B を出力します。

C() の本体に入るころには C までの構築が終わっており、同じ id() が今度は C::id に届いて C を出力します。最後にできあがるのは C のオブジェクトですが、それを理由に CC にはならず、いつも基底の版が呼ばれるわけでもないので AC にもなりません1。

  1. Java や C# では、基底クラスのコンストラクタから呼んだ仮想メソッドも派生クラスの版に届きます。そのため派生クラスのフィールドが初期化される前の値を読むことがあり、C++ とは別の形の罠になります。
