fast_io.cpp

#include <cstdio>
#include <iostream>

bool fast_io() {
    static const bool enabled = std::ios::sync_with_stdio(false);
    return enabled;
}

int main() {
    bool a = fast_io();
    bool b = std::ios::sync_with_stdio(false);
    bool c = fast_io();
    std::printf("%d %d %d\n", a, b, c);
    std::fflush(stdout);
    std::cout << "done\n";
}

これは何を出力するでしょうか?

Answer

1 0 1 と done の2行です。

std::ios::sync_with_stdio(false) が返すのは、切り替えに成功したかどうかでも、呼んだあとの状態でもなく、呼ぶ前に標準ストリームが C の標準入出力と同期していたかどうかです。プログラムの開始時は同期しているので、true を返すのは最初の呼び出しだけで、2回目以降は false を返します。

最初の呼び出しは a = fast_io() の中で起きます。enabled は関数内の static 変数で、制御が初めて宣言を通ったときに1回だけ初期化されるので、ここで sync_with_stdio(false) が呼ばれ、true が入ります。続く b の行は2回目の呼び出しなので false です。c = fast_io() の時点では初期化が済んでいるため sync_with_stdio は呼ばれず、enabled に残っている true がそのまま返ります。

enabled という名前からは「この呼び出しで速くなった」と読めますが、入っているのは「呼ぶ前は同期していた」という値です。成功したかどうかを返すと読むと 1 1 1、呼んだあとの状態を返すと読むと 0 0 0 になり、static 変数の初期化が呼び出しのたびに起きると読むと c を 0 と答えることになります。

同期を切ったあとの printf と std::cout は別々のバッファに書くので、そのまま混ぜると、出てくる順は保証されません。このコードは std::fflush(stdout) で C 側のバッファを出し切ってから std::cout に書くので、1 0 1 の行が done より先に出ます。
