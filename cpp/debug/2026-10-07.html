audit.cpp

#include <iostream>

struct Audit {
    int events = 0;
    ~Audit() { std::cout << "events: " << events << '\n'; }
};

Audit& audit() {
    static Audit a;
    return a;
}

struct Session {
    ~Session() { ++audit().events; }
};

Session session;

int main() {
    ++audit().events;
}

audit は、記録した件数をプログラムの終了時に出力する監査ログ Audit を返す関数です。main がログインを1件、大域変数 session のデストラクタがログアウトを1件記録するつもりです。引数も標準入力も使いません。いまは events: 1 が出ます。本来は events: 2 が出るはずです。

Answer

Wrong

Audit& audit() {
    static Audit a;
    return a;
}

struct Session {
    ~Session() { ++audit().events; }
};

session は main より前に構築されますが、関数内 static の a が構築されるのは、main が初めて audit() を呼んだときです。静的記憶域期間のオブジェクトは構築を終えたのと逆の順に破棄されるので、後から構築された a が先に破棄されます。

a のデストラクタが events: 1 を出力した時点では、ログアウトはまだ記録されていません。そのあと session のデストラクタが audit() を呼びますが、返ってくるのは寿命の尽きた a への参照です。その events を増やすのは未定義動作で、増やした件数が出力されることもありません。

Right

struct Session {
    Session() { audit(); }
    ~Session() { ++audit().events; }
};

session のコンストラクタで audit() を呼ぶと、a の構築は session の構築の途中で終わります。構築を先に終えた a は session より後に破棄されるので、ログアウトが記録されてから events: 2 が出力されます。

関数内 static は、使う前に必ず構築されるので初期化順序の問題は避けられますが、破棄の順序は構築の順序で決まります。デストラクタから使うオブジェクトは、自分のコンストラクタで一度触って先に構築させておきます1。

  1. 直す前の Session はコンストラクタが自明なので、session は静的に初期化されます。規格は、静的に初期化されたオブジェクトも、動的に初期化された場合と同じ順序で破棄すると定めています。
