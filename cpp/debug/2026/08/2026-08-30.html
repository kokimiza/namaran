transfer.cpp

#include <algorithm>
#include <iostream>

void transfer(int& from, int& to, const int& amount) {
    if (amount <= from) {
        from -= amount;
        to += amount;
    }
}

int main() {
    int alice = 30;
    int bob = 0;
    const int cap = 50;
    transfer(alice, bob, std::min(alice, cap));
    std::cout << alice << ' ' << bob << '\n';
}

from から to へ amount を移す transfer で、main は alice の残高から最大 cap までを bob へ移します。alice が 30、cap が 50 なので、本来は 30 が移って 0 30 が出るはずが、いまは 0 0 が出て、30 がどこにも残りません。alice が cap 以上のとき（たとえば 80 なら 30 50）は正しく動きます。直すのは transfer の中だけにしてください。

Answer

Wrong

void transfer(int& from, int& to, const int& amount) {
    if (amount <= from) {
        from -= amount;
        to += amount;
    }
}

transfer だけを見ると、amount を確かめてから from を減らし、同じ amount を to に足すので、減った額と増えた額は等しく見えます。この読み方は、amount が from とは別の値であることを前提にしています。ところが const int& は値を受け取るのではなく、呼び出し側のどこかの変数を指す別名で、const は「この名前を通しては書き換えない」という意味しか持ちません。別名の先がほかの名前を通して書き換われば、amount を読んだ結果も変わります。

main が渡した std::min(alice, cap) も、そうした別名の1つです。std::min は値のコピーを返さず、2つの引数のうち小さいほうへの const 参照を返します。30 と 50 では alice への参照が返るので、amount は alice の別名で、from と同じ変数を指します。amount <= from の確認は 30 で通りますが、from -= amount で alice が 0 になった時点で amount を読んでも 0 です。続く to += amount は 0 を足すので、0 0 になります。alice が 80 のときは cap への参照が返り、cap は書き換わらないので、正しく動きます。

Right

void transfer(int& from, int& to, int amount) {
    if (amount <= from) {
        from -= amount;
        to += amount;
    }
}

amount を値で受け取ると、呼び出した時点の 30 が transfer の中のコピーに入ります。このコピーは alice とは別の変数なので、from -= amount で alice が 0 になっても amount は 30 のままで、確かめた額、引いた額、足した額の3つが同じになります。amount に from や to そのものを渡されても、同じ理由で正しく動きます。int のように小さい型は、コピーの手間を省くために参照で受け取る理由がありません。1

  1. 同じ心配は標準ライブラリの側にもあります。v.push_back(v[0]) の引数は v 自身の要素への参照で、push_back が領域を取り直すと古い要素は消えます。標準はこの呼び出しも正しく動くことを求めているので、標準ライブラリの実装は古い要素を消す前に新しい要素を作ります。
