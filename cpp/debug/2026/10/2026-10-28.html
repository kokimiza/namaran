style_flags.cpp

#include <cstdint>
#include <print>

constexpr std::uint16_t kBold = 1u << 0;
constexpr std::uint16_t kStrike = 1u << 8;

std::uint8_t has_style(std::uint16_t style, std::uint16_t flag) {
    return style & flag;
}

int main() {
    std::uint16_t style = kBold | kStrike;
    std::println("{} {}", has_style(style, kBold) != 0, has_style(style, kStrike) != 0);
}

文字の装飾をフラグの組 style で持ち、has_style で、指定したフラグが立っているかを0か0以外で返すつもりのコードです。main は太字と取り消し線の両方を立てた style を調べます。本来は true true と出力されるはずが、いまは true false と出力され、取り消し線が立っていないことになります。

Answer

Wrong

std::uint8_t has_style(std::uint16_t style, std::uint16_t flag) {
    return style & flag;
}

style & flag の値は1か0ではなく、flag のビットがその位置に残った値です。kStrike は 1u << 8、つまり下から9番目のビットなので、取り消し線を調べたときの値は256になります。

return はこの256を戻り値の型 std::uint8_t へ暗黙に変換します。符号なし整数型への変換は、値を2の8乗で割った余りにするので、256は0になり、立っていたビットは消えます。kBold の値1は8ビットに収まるので、太字だけは正しく答えます。下位8個のフラグでは正しく動き、9個目のフラグから黙って false になります。

Right

bool has_style(std::uint16_t style, std::uint16_t flag) {
    return style & flag;
}

戻り値の型を bool にします。整数から bool への変換は、ビットを切り取るのではなく、0なら false、それ以外なら true にするので、256も true になります。uint8_t のままにするなら return (style & flag) != 0; と、変換の前に比較で真偽に直します。return {style & flag}; と波括弧で返せば、値が収まらないかもしれない変換をコンパイラが指摘します1。

  1. 波括弧による初期化(リスト初期化)では、規格が縮小変換を誤りとしています。Clang はこれをエラーにし、GCC は既定では警告(-Wnarrowing)にします。return や代入の = による変換は誤りではなく、-Wall -Wextra でも警告されません。警告させるには -Wconversion が要ります。
