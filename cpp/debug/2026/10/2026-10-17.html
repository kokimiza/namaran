build_report.cpp

#include <cstdio>
#include <iostream>

static void row(const char *step, double sec) {
    std::printf("%-6s %6.2f\n", step, sec);
}

int main() {
    std::ios::sync_with_stdio(false);
    std::cout << "step      sec" << std::endl;
    row("parse", 0.5);
    row("link", 1.25);
    std::cout << "total    1.75" << std::endl;
}

main は、ビルドの段階ごとにかかった秒数を、見出しの行、parse と link の行、total の行の順に表にして出すつもりのコードです。入力はありません。端末で実行すると正しく並びますが、標準出力をファイルにリダイレクトすると、いまは見出し、total、parse、link の順に4行が並びます。本来の出力は、見出し、parse、link、total の順です。

Answer

Wrong

int main() {
    std::ios::sync_with_stdio(false);
    std::cout << "step      sec" << std::endl;

同期を切ると、std::cout は C の stdout とは別のバッファに書くようになります。std::endl が書き出すのは std::cout のバッファだけで、printf の行がたまっている stdout のバッファには触れません。

stdout がファイルを指すとき、C の標準出力は全バッファリング（fully buffered）になり、バッファが一杯になるかプログラムが終わるまで書き出しません1。見出しと total の行は std::endl のたびにファイルへ書かれ、row の2行はプログラムの終了時にやっと書かれるので、最後に回ります。端末では stdout が改行ごとに書き出されるため、同じプログラムでも正しく並んで見えます。

Right

int main() {
    std::cout << "step      sec" << std::endl;

同期を切る行を消すと、std::cout は stdout と同期したまま動き、std::cout への出力と printf の出力は書いた順に同じ stdout へ入ります。リダイレクト先がファイルでも端末でも、表は見出しから total まで順に並びます。速さのために同期を切りたいなら、row も std::cout で書いて、C の出力関数を混ぜないようにします。

  1. C の規格は、標準入力と標準出力が対話的な装置を指していないと判断できる場合に限り、全バッファリングで開くと定めています。端末を指す stdout は、多くの処理系で行バッファリング（line buffered）になります。
