until_end.cpp

#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::istringstream in("apple\r\nEND\r\nbanana\r\n");
    int count = 0;
    for (std::string line; std::getline(in, line);) {
        if (line == "END") break;
        ++count;
    }
    std::cout << count << '\n';
}

このプログラムは、END だけの行が来るまでに何行あるかを数えるつもりのものです。main は、Windows で保存したファイルの中身を std::istringstream に入れて読むので、引数も標準入力も使いません。いまは 3 が出ますが、本来は 1 が出るはずです。

Answer

Wrong

for (std::string line; std::getline(in, line);) {
    if (line == "END") break;

std::getline が読み捨てるのは \n だけです。Windows で保存したファイルの行は \r\n で終わるので、2回目の getline で line に入るのは END\r の4文字で、"END" と等しくなりません。break しないまま3行すべてを数え、3 を出力します。

Right

for (std::string line; std::getline(in, line);) {
    if (line.ends_with('\r')) line.pop_back();
    if (line == "END") break;

比べる前に、行末に残った \r を1文字だけ取り除きます。2回目の line は END になって break し、数えるのは apple の1行だけです。\n だけで終わる行には \r がないので何も起きず、どちらの改行のファイルも同じように読めます1。

  1. Windows でファイルをテキストモードで開くと、読むときに \r\n が \n に変換されるので、この欠陥は表に出ません。同じファイルを Linux や macOS で読んだときや、ネットワークや文字列から読んだときに \r が残ります。
