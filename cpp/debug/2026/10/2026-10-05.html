endpoint.cpp

#include <iostream>
#include <string>

std::string endpoint(const std::string& path);

const std::string health_url = endpoint("health");
const std::string base_url = "https://example.com/api/";

std::string endpoint(const std::string& path) {
    return base_url + path;
}

int main() {
    std::cout << health_url << '\n';
}

endpoint は、API の URL の前半 base_url にパスをつなげて返す関数で、health_url はそれで作った大域定数です。引数も標準入力も使いません。g++ 14 でビルドして動かすと、いまは health とだけ出ます。環境によっては別の結果になったり落ちたりすることもあります。本来は https://example.com/api/health が出るはずです。

Answer

Wrong

const std::string health_url = endpoint("health");
const std::string base_url = "https://example.com/api/";

名前空間スコープの変数は、同じ翻訳単位の中では定義の順に初期化されます。health_url の初期化子が endpoint を呼んだ時点で、base_url はまだ初期化されていません。24文字の文字列で std::string を作るにはメモリの確保が要るので、この初期化は定数式にならず、実行時の動的初期化として順番を待つからです。

生存期間が始まっていないオブジェクトを読むのは未定義動作です。g++ 14 で health だけが出るのは、動的初期化の前に静的記憶域が0で埋められていて、全ビットが0の std::string がたまたま空文字列として読めたからです。その後で base_url は正しく初期化されますが、health_url はもう作り終わっています1。

Right

constexpr const char* base_url = "https://example.com/api/";

constexpr の変数は定数初期化され、どの動的初期化よりも前に値が入っています。health_url の初期化中に endpoint が読んでも、base_url はもう文字列リテラルを指しています。base_url + path は const char* と std::string をつなぐ operator+ になり、結果は同じ文字列です。

2行を入れ替えても、このファイルの中では直ります。ただ、定義の順に頼る直し方は、2つの変数が別のファイルに分かれた時点で効かなくなります。翻訳単位をまたぐ動的初期化の順序は決まっていないので、そもそも動的初期化をしない形にしておくほうが確実です。

  1. 短い文字列なら事情が変わります。libstdc++ の std::string は15文字までをオブジェクトの中に持つので、"Hello, " のような初期化はメモリを確保せず定数式になり、定数初期化されます。変数に constinit を付けると、定数初期化できない初期化はコンパイルエラーになるので、どちらになるかをコンパイラに確かめさせられます。
