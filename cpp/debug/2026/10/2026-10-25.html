order_pair.cpp

#include <algorithm>
#include <iostream>

void order(int& a, int& b) {
    auto [lo, hi] = std::minmax(a, b);
    a = lo;
    b = hi;
}

int main() {
    int a = 5, b = 2;
    order(a, b);
    std::cout << a << ' ' << b << '\n';
}

order は、2つの変数 a と b を、a が小さいほうになるよう並べ替えるつもりの関数です。main は a = 5、b = 2 を渡し、並べ替えたあとの2つを出力します。いまの出力は 2 2 です。本来の出力は 2 5 です。

Answer

Wrong

auto [lo, hi] = std::minmax(a, b);
a = lo;
b = hi;

2つの引数を取る std::minmax は、値ではなく引数への参照の組 std::pair<const int&, const int&> を返します。auto で構造化束縛すると、この組は写しになりますが、写しの要素も参照のままです。a = 5、b = 2 では lo が b を、hi が a を指します。

a = lo で a は 2 になります。続く b = hi の hi は a を指しているので、読み出されるのは書き換えたばかりの 2 です。元の 5 はどこにも残っておらず、出力は 2 2 になります。auto だから値がコピーされた、と読むとこの上書きを見落とします。

Right

auto [lo, hi] = std::minmax({a, b});

波括弧で囲むと、std::initializer_list を受け取る版の std::minmax が選ばれます。この版は値の組 std::pair<int, int> を返すので、lo と hi は a と b から切り離された 2 と 5 を持ちます。そのあとで a を書き換えても hi は変わらず、b に 5 が入ります。if (a > b) std::swap(a, b); と書いても同じように直ります。1

  1. std::tie(a, b) = std::minmax(a, b); も同じ理由で壊れます。std::tie への代入は要素を先頭から順に代入するので、b へ代入するときには、参照先の a がもう書き換わっています。
