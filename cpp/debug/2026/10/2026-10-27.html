length_prefix.cpp

#include <cstdint>
#include <cstring>
#include <print>

// 2-byte length field, big-endian
void put_length(std::uint8_t* out, std::uint16_t len) {
    std::memcpy(out, &len, sizeof len);
}

int main() {
    std::uint8_t header[2];
    put_length(header, 0x0102);
    std::println("{:02x} {:02x}", header[0], header[1]);
}

メッセージの先頭に付ける2バイトの長さを、ビッグエンディアン(上位のバイトが先)で書き込むつもりの put_length です。長さ 0x0102 を書き込むと、本来は 01 02 と出力されるはずが、x86-64 の機械で動かすと 02 01 と出力されます。

Answer

Wrong

void put_length(std::uint8_t* out, std::uint16_t len) {
    std::memcpy(out, &len, sizeof len);
}

std::memcpy は、len がメモリ上に置かれているバイトを、その並びのまま out へ写します。整数をメモリにどの順で置くかは機械が決めることで、x86-64 は下位のバイトを先に置くリトルエンディアンです。0x0102 はメモリ上で 02 01 と並んでいるので、そのまま写した header も 02 01 になります。

ビッグエンディアンの機械で動かすと 01 02 と出るので、欠陥は動かす機械によって現れたり隠れたりします。この長さを受け取った相手は 0x0201 で513バイトのメッセージだと読み、そこから先の区切りをすべて読み違えます。

Right

void put_length(std::uint8_t* out, std::uint16_t len) {
    out[0] = len >> 8;
    out[1] = len & 0xff;
}

メモリ上の並びを写すのをやめ、シフトで上位のバイトと下位のバイトを取り出して、決めた順に書きます。len >> 8 は値としての上位8ビットで、メモリにどう置かれているかには関係しません。これで、どの機械で動かしても 01 02 が書かれます。1

  1. C++23 には、値のバイト順を入れ替える std::byteswap と、動かしている機械のバイト順を表す std::endian::native があります。これらを使って「リトルエンディアンの機械なら入れ替えてから写す」と書くこともできますが、シフトで書けば機械のバイト順を調べる必要がありません。
