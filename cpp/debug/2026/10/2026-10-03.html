2026-10-03

ports.cpp

#include <initializer_list>
#include <iostream>

auto ports_from(int base) {
    auto ports = {base, base + 1, base + 2};
    return ports;
}

int main() {
    for (int p : ports_from(8080))
        std::cout << p << '\n';
}

ports_from は、base から始まる連続した3つのポート番号を返す関数です。引数も標準入力も使わず、ports_from(8080) の結果を1行に1つずつ出力します。いまは 32764 や -468173408 のような、実行環境によって変わるでたらめな数が出ます。本来は 8080、8081、8082 の3行が出力されるはずです。

Answer

Wrong

auto ports = {base, base + 1, base + 2};
return ports;

= と波括弧で初期化した auto は std::initializer_list<int> と推論されます。initializer_list は要素を自分では持たず、コンパイラが用意した配列(背後の配列)を指すだけの軽いビューで、コピーしても配列は複製されません。この配列の寿命は ports と同じなので、ports_from から戻った時点で尽きます。

戻り値の型も auto から std::initializer_list<int> に推論されるので、main が受け取るのは、もう存在しないスタック上の配列を指すビューです。range-for がそこを読むのは未定義動作で、手元では別の関数呼び出しに上書きされたスタックの値が出力されました。GCC はこの return に -Winit-list-lifetime の警告を出しますが、コンパイルは通ります。

Right

#include <array>

std::array ports{base, base + 1, base + 2};
return ports;

<array> を読み込み、std::array に要素を持たせます。std::array は要素を自分の中に持つ集成体なので、return で値ごと呼び出し側へ渡り、関数を出たあとも要素が残ります。型はクラステンプレートの実引数推論で std::array<int, 3> になり、main の range-for はそのまま使えます。

auto ports{base, base + 1, base + 2}; と = を外すだけでは直りません。= の無い波括弧で auto を推論できるのは要素が1つのときだけで、3つではコンパイルエラーになります1。

  1. C++26 では、要素がすべて定数式の initializer_list なら、背後の配列を静的記憶域に置いてもよいことになりました(P2752)。{80, 443} のような定数だけのリストは、関数を出たあとも読めてしまうことがあります。この問題では base が実行時の値なので、そうはなりません。
