note.cpp

#include <print>
#include <string>

void note(const std::string& msg) {
    std::println(std::runtime_format(msg));
}

int main() {
    note("set x = {1, 2}");
}

note は、受け取った文字列 msg をそのまま1行に出力するつもりの関数です。main は、波括弧を含むメッセージを1つ渡します。

いまの出力

（何も出力せずに異常終了する）

本来の出力

set x = {1, 2}
Answer

Wrong

std::println(std::runtime_format(msg));

std::println の最初の引数は、出力する文字列ではなく書式文字列です。std::runtime_format で包むと、実行時の文字列 msg がそのまま書式として解釈されます。書式の中の { は置換フィールドの始まりで、その直後には引数の番号、:、} のどれかが続くはずです。{1, 2} では番号 1 のあとに , が来るので書式として正しくなく、std::println は std::format_error を投げます。どこでも捕まえていないので std::terminate が呼ばれ、何も出力せずに異常終了します。

Right 時間計算量 𝒪(n) 空間計算量 𝒪(1) n は msg の文字数 

std::println("{}", msg);

書式文字列を "{}" という定数にして、msg は引数として渡します。引数の中身は書式として読まれないので、{ や } を含んでいても文字のまま出力されます。書式文字列が定数になったことで、置換フィールドと引数の対応もコンパイル時に検査されるようになります1。

  1. std::println(msg) と書くとコンパイルエラーになります。書式文字列はコンパイル時に検査するために定数でなければならず、それを外すのが std::runtime_format(C++26)です。コンパイルエラーを消そうとして std::runtime_format で包むと、この欠陥ができあがります。C の printf(msg) も同じ形の欠陥で、こちらは例外ではなく未定義動作になります。
