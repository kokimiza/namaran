hex_byte.cpp

#include <iostream>
#include <string>

std::string hex_byte(unsigned char b) {
    std::string s;
    s += '0' + (b >> 4);
    s += '0' + (b & 0xf);
    return s;
}

int main() {
    std::cout << hex_byte(0x3c) << '\n';
}

1バイトの値を、小文字の2桁の16進数の文字列にするつもりの hex_byte です。hex_byte(0x3c) を表示すると、本来は 3c となるはずが、いまは 3< と表示されます。

Answer

Wrong

s += '0' + (b >> 4);
s += '0' + (b & 0xf);

0x3c の上の4ビットは3、下の4ビットは12です。'0' + 3 は '3' になりますが、'0' + 12 は 'c' になりません。'0' + n で数字の文字が得られるのは、'0' から '9' の文字コードが連続して並んでいるからで、その保証は '9' までです。'9' の先に続くのは英字ではなく、ASCII では : ; < = > ? の6つの記号です。12は '0' から数えて '<' に当たるので、3< が表示されます。

0〜9の桁だけでできたバイト、たとえば 0x42 は正しく 42 になります。10以上の桁を含むバイトだけが記号に化けるので、数字だけの値で試していると見落とします。

Right

s += "0123456789abcdef"[b >> 4];
s += "0123456789abcdef"[b & 0xf];

16個の桁の文字を順に並べた文字列リテラルを、桁の値で添字アクセスします。b >> 4 も b & 0xf も0〜15なので、必ず範囲内の1文字が選ばれ、12なら13文字目の 'c' です。数字と英字の文字コードがどう並んでいるかに頼らないので、どの文字コードでも同じ結果になります。
