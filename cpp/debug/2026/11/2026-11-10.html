trace.cpp

#include <iostream>
#include <source_location>
#include <string_view>

void trace(std::string_view msg) {
    std::cout << std::source_location::current().line() << ": " << msg << '\n';
}

int main() {
    trace("start");
    trace("stop");
}

trace は、自分を呼び出した行の番号を付けてメッセージを出すつもりの関数です。このプログラムは本来、10: start と 11: stop の2行を出力するはずが、いまは 6: start と 6: stop を出力します。

Answer

Wrong

void trace(std::string_view msg) {
    std::cout << std::source_location::current().line() << ": " << msg << '\n';

std::source_location::current() は consteval 関数で、書かれたその場所でコンパイル時に評価され、その式があるファイル名と行番号を値として埋め込みます。この呼び出しは trace の本体の6行目にあるので、出力される行番号はいつも6です。trace がどこから何回呼ばれても、本体のこの式が評価し直されて呼び出し元を調べることはありません。

Right

void trace(std::string_view msg, std::source_location loc = std::source_location::current()) {
    std::cout << loc.line() << ": " << msg << '\n';

current() を既定引数に移します。既定引数の式は、関数の宣言の場所ではなく、引数を省いた呼び出しのたびにその呼び出し側で評価されます。current() もその呼び出しの位置で評価されるので、10行目の trace("start") では10が、11行目の trace("stop") では11が loc に入ります。std::source_location::current() を既定引数に書くこの形は、規格がこの関数の使い方として想定しているものです1。

  1. 規格の std::source_location の節には、current() を既定引数に書いて呼び出し側の位置を受け取る例が載っています。C++20 で導入される前は、同じ目的に __LINE__ を使うマクロが使われていました。
