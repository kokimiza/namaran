repeat_sum.cpp

#include <print>

double repeat_sum(double x, int n) {
    double sum = 0.0;
    auto c = 0;
    for (int i = 0; i < n; ++i) {
        double y = x - c;
        double t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}

int main() {
    std::println("{}", repeat_sum(0.1, 10));
}

repeat_sum(x, n) は、x を n 回足した総和を求める関数です。足すたびに丸めで失った分を c に記録し、次に足す値から差し引くことで、単純に足すより誤差を小さくするつもりです。repeat_sum(0.1, 10) を出力すると、本来は 1 が出るはずが、いまは単純に足したときと同じ 0.9999999999999999 が出ます。

Answer

Wrong

    double sum = 0.0;
    auto c = 0;

auto c = 0; の c は、初期化子の 0 が int のリテラルなので int になります。ループの中の c = (t - sum) - y; は double の値を int に代入し、小数部を捨てて0の方向へ切り捨てます。0.1 を足すときに失われる分は10のマイナス17乗程度で、絶対値が1未満なので、c には毎回 0 が入ります。

c が常に 0 なら、y = x - c は x のままで、sum は sum + x を順に足すだけです。補正の式は書かれていても効いておらず、結果は単純な足し算と同じ 0.9999999999999999 になります。コンパイラはこの代入を、警告を厳しくしない限り黙って通します。1

Right

    double sum = 0.0;
    double c = 0.0;

c を double にすれば、(t - sum) - y で求めた小さな誤差が切り捨てられずに残ります。次の回では y = x - c がその誤差を足し戻し、10回の加算で失った分が sum に返って、結果は 1 になります。auto を使うなら、auto c = 0.0; のように初期化子の側で型を決めます。

  1. GCC と Clang では、-Wconversion や -Wfloat-conversion を付けると、double から int への暗黙の変換に警告が出ます。どちらも -Wall -Wextra には含まれていません。
