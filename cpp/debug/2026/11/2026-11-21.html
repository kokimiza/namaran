count_entries.cpp

#include <filesystem>
#include <iostream>
namespace fs = std::filesystem;

int count(const fs::path& dir) {
    int n = 0;
    for (auto& e :
         fs::directory_iterator(dir)) {
        n += 1;
        if (e.is_directory())
            n += count(e.path());
    }
    return n;
}

ディレクトリの下にある項目（ファイル、ディレクトリ、シンボリックリンク）を、下の階層まで含めて数える count です。カレントディレクトリにディレクトリ a があり、a の中にディレクトリ b と、.. を指すシンボリックリンク up があるとき、count(".") を呼びます。いまは値を返さず、std::filesystem::filesystem_error が投げられて異常終了します（Linux でのメッセージは Too many levels of symbolic links）。本来は 3 を返すはずです。

Answer

Wrong

        n += 1;
        if (e.is_directory())
            n += count(e.path());

directory_entry::is_directory() は、項目がシンボリックリンクならリンクの先を調べます。a/up は ..、つまりカレントディレクトリを指すので、is_directory() は真になり、count("./a/up") が呼ばれます。その中にはまた a があり、./a/up/a/up、./a/up/a/up/a/up と同じ木を際限なくたどり直します。

OS は、1つのパスを解決するあいだにたどるシンボリックリンクの数に上限を設けています（Linux では40）。パスに up が積み重なってこの上限を超えると、項目の状態を調べる呼び出しが失敗し、filesystem_error が投げられます。誰も捕まえないので、プログラムはそこで終了します。

Right

        n += 1;
        if (e.is_directory() &&
            !e.is_symlink())
            n += count(e.path());

is_symlink() は、リンクの先ではなく項目そのものを調べます。ディレクトリでもリンクなら中へ降りないようにすると、a/up は1つの項目として数えられるだけになります。数えるのは a、a/b、a/up の3つで、count(".") は 3 を返します。リンクを経由しないかぎり、ディレクトリの木は親へ戻れないので、この再帰は必ず止まります。
