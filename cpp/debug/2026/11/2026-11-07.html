spawn_point.cpp

#include <iostream>
#include <random>
#include <utility>

int main() {
    std::minstd_rand0 g(2026);
    auto [x, y] = std::make_pair(g() % 100, g() % 100);
    std::cout << x << ' ' << y << '\n';
}

シード2026の乱数エンジンから先に引いた値で x を、次に引いた値で y を決め、どの環境でも同じ点を作るつもりのプログラムです。エンジンが出す最初の2つの値は34050982と1064204372なので、本来の出力は 82 72 です。いまは GCC 14 でビルドすると 72 82 が表示されます。

Answer

Wrong

auto [x, y] = std::make_pair(g() % 100, g() % 100);

C++ では、関数の引数をどの順に評価するかが決まっていません。std::make_pair の2つの引数の g() % 100 は、どちらが先に呼ばれてもよく、x86-64 の GCC は後ろの引数から評価します。そのため2つ目の引数が最初の値34050982を受け取って y が82になり、1つ目の引数が1064204372を受け取って x が72になります。エンジン自体は同じシードから同じ列を出しているのに、どの値がどちらに入るかがコンパイラ次第なので、別のコンパイラでは 82 72 になることもあります。

Right

auto x = g() % 100;
auto y = g() % 100;

別々の文にすれば、前の文が終わってから次の文が始まるので、x が必ず先に引いた値になります。乱数エンジンのように呼ぶたびに状態が変わる関数を、1つの式の中で2回以上呼ぶと、同じ問題が起きます。シードで結果を再現したい処理では、引く順番をこのように文の順番で決めておきます1。

  1. 波括弧の初期化子リストの中だけは、左から順に評価すると規格が決めています。std::pair{g() % 100, g() % 100} と書けば、コンストラクタを呼ぶ場合でも左の要素が先に評価されます。C++17 で順序が決まった << の左右の評価とは別の規則です。
