range_sum.cpp

#include <iostream>

int sum(int lo, int hi) {
    if (lo == hi) {
        return lo;
    }
    int mid = (lo + hi) / 2;
    return sum(lo, mid) + sum(mid + 1, hi);
}

int main() {
    std::cout << sum(1, 8) << '\n';
    std::cout << sum(-8, 8) << '\n';
}

lo 以上 hi 以下の整数の和を、区間を2つに分けて再帰で求める sum です。main は sum(1, 8) と sum(-8, 8) を順に出力します。本来は 36 と 0 を1行ずつ出して終わるはずが、いまは sum(-8, 8) の計算中にスタックを使い果たし、0 を出さずに異常終了します。

Answer

Wrong

    int mid = (lo + hi) / 2;
    return sum(lo, mid) + sum(mid + 1, hi);

再帰が止まるのは、どの呼び出しも基底ケースの lo == hi に近づくときだけです。2つ以上の整数を持つ区間は、lo <= mid < hi なら両側とも元より短くなります。最初に崩れうるのは整数が2つだけの区間で、mid が lo にならなければいけません。ところが C++ の整数除算は 0 の方向へ切り捨てるので、lo + hi が負の奇数のときは、(lo + hi) / 2 が切り上げた値になります。[-8, -7] では -15 / 2 が -7 で mid == hi になり、左側の sum(lo, mid) は sum(-8, -7) を呼び直します。

sum(-8, 8) は、中点 0 で分けた [-8, 0] から [-8, -4]、[-8, -6]、[-8, -7] と左へ降りていき、そこで同じ呼び出しを繰り返します。呼び出しは戻らないまま積み重なり、スタックを使い果たして落ちます。sum(1, 8) では lo + hi がいつも正なので、切り捨ては切り下げと同じになり、この区間は現れません。

Right

    int mid = lo + (hi - lo) / 2;
    return sum(lo, mid) + sum(mid + 1, hi);

hi - lo は区間の中ではいつも 0 以上なので、(hi - lo) / 2 の切り捨ては切り下げと同じです。mid = lo + (hi - lo) / 2 は lo の符号に関係なく lo 以上 hi 未満に収まり、両側の区間はどちらも元より短くなります。[-8, -7] なら mid は -8 で、sum(-8, -8) と sum(-7, -7) がどちらも基底ケースに着きます。lo + hi を作らないので、lo と hi が大きいときに和が int の範囲を越える心配もなくなります1。

  1. C++20 から <numeric> にある std::midpoint(lo, hi) も、オーバーフローせずに中点を求め、割り切れないときは lo の側へ丸めます。ここで使っても同じように直ります。
