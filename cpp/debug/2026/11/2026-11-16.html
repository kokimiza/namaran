swap_ends.cpp

#include <iostream>
#include <vector>

template <class T> void swap_ends(std::vector<T>& v) {
    auto tmp = v.front();
    v.front() = v.back();
    v.back() = tmp;
}

int main() {
    std::vector<bool> v{true, false, false};
    swap_ends(v);
    std::cout << v[0] << v[1] << v[2] << '\n';
}

swap_ends は、どんな要素型の std::vector でも先頭と末尾の要素を入れ替えるつもりの関数テンプレートです。{true, false, false} を渡すと 001 が出力されるはずですが、いまは 000 が出力されます。std::vector<int> の {1, 0, 0} なら、正しく 0, 0, 1 に入れ替わります。

Answer

Wrong

auto tmp = v.front();
v.front() = v.back();
v.back() = tmp;

std::vector<bool> の front() は bool& ではなく、先頭のビットを指す代理オブジェクト std::vector<bool>::reference を値で返します。auto はこの型をそのまま推論するので、tmp は先頭の値の写しではなく、先頭のビットを指したままのオブジェクトになります。

次の行で先頭に末尾の false が入ると、tmp を通して見える値も false に変わります。最後の v.back() = tmp; は書き換わった先頭を末尾へ写すので、退避したはずの true はどこにも残らず、000 になります。std::vector<int> では front() が int& を返し、auto は参照を外して int の写しを作るので、この欠陥は表に出ません。

Right

T tmp = v.front();
v.front() = v.back();
v.back() = tmp;

tmp の型を要素型 T と書けば、T が bool のときは代理オブジェクトから bool への変換が起き、その時点の先頭の値 true が tmp に写されます。そのあと先頭を書き換えても tmp は変わらないので、末尾に true が入って 001 になります。T が int のときは、auto と書いたときと同じ写しになります。
