flags.cpp

#include <algorithm>
#include <print>
#include <thread>
#include <vector>

int main() {
    std::vector<bool> done(8);
    std::jthread t([&] {
        for (int i = 0; i < 8; i += 2)
            done[i] = true;
    });
    for (int i = 1; i < 8; i += 2)
        done[i] = true;
    t.join();
    auto n = std::ranges::count(done, true);
    std::println("{}", n);
}

8個の作業の完了フラグ done のうち、偶数番目をワーカースレッドが、奇数番目を main のスレッドが立て、最後に立ったフラグの数を出すプログラムです。2つのスレッドは別々の要素にしか書き込まないので、いつでも 8 と出るつもりでした。ところが -fsanitize=thread を付けてビルドして実行すると、ThreadSanitizer が WARNING: ThreadSanitizer: data race を報告します。

Answer

Wrong

    std::vector<bool> done(8);

標準ライブラリのコンテナは、別々のスレッドが別々の要素を書き換えてもデータ競合にならないことを保証しています。ただし、この保証には std::vector<bool> だけが含まれていません。1 std::vector<bool> は要素を1ビットずつ語に詰めて持つので、done の8要素は同じ1つの語に入っています。

ビットだけを書くことはできないので、done[i] = true は、語全体を読み、そのビットを1にした値を語全体に書き戻します。2つのスレッドが同じ語をこうして読み書きするのは、同じメモリ位置へのデータ競合で、未定義動作です。実際に起こりうるのは、片方のスレッドが古い語を読んでいるあいだに相手がビットを立て、その語を書き戻して相手のビットを消してしまうことで、そのときは 8 より小さい数が出ます。

Right

    std::vector<char> done(8);

std::vector<char> の要素は1つずつが別のオブジェクトで、別々のメモリ位置を占めます。それぞれのスレッドは自分が書く要素のバイトだけを書き換えるので、相手のフラグを読み書きすることがなくなります。std::ranges::count(done, true) は、char の要素を true を整数にした 1 と比べるので、この行は直さずに済みます。

  1. 規格はコンテナの要件の中で、vector<bool> を除いて、同じコンテナの異なる要素の内容を同時に書き換えてよいと定めています。
