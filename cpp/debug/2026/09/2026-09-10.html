hit_counters.cpp

#include <functional>
#include <iostream>
#include <string>
#include <vector>

struct Counter {
    std::string name;
    int hits = 0;

    std::function<void()> hook() {
        return [this] { ++hits; };
    }
};

int main() {
    std::vector<Counter> counters;
    std::vector<std::function<void()>> hooks;
    for (const char* name : {"a", "b", "c"}) {
        counters.push_back({name});
        hooks.push_back(counters.back().hook());
    }
    for (auto& h : hooks) {
        h();
    }
    for (const auto& c : counters) {
        std::cout << c.name << "=" << c.hits << " ";
    }
    std::cout << "\n";
    return 0;
}

Counterは、配ったコールバックが呼ばれるたびに自分のhitsを1増やすつもりの型です。入力は、a、b、cの3つを作ってそれぞれのコールバックを1回ずつ呼ぶmainで、本来の出力はa=1 b=1 c=1です。手元でビルドして実行するとa=0 b=0 c=1が出ましたが、このプログラムは未定義動作を含むので、この出力も保証されません。どこを直せばよいでしょうか?

Answer

[this]がキャプチャするのはCounterのオブジェクトではなく、thisというポインタの値です。コールバックの本体の++hitsは++this->hitsの意味なので、呼ばれたときには、キャプチャした時点のアドレスにあるhitsを書き換えます。

そのアドレスはpush_backで変わります。std::vectorは容量が足りなくなると新しい領域を確保し、要素をそこへムーブして古い領域を解放するからです。容量の増え方は実装が決めますが、手元の実装ではbとcを足したときに再配置が起き、aとbのコールバックは解放された領域を指したままになりました。解放済みの領域への書き込みは未定義動作です。aとbが0と表示されたのは、書き込みが古い領域に入り、いまのcountersの要素に届かなかったからです。

countersをstd::deque<Counter>に変えると直ります(#include <deque>も足します)。std::dequeのpush_backは反復子を無効にしますが、既存の要素への参照とポインタは無効にしないので、キャプチャしたthisは最後まで同じ要素を指します。ループの前にcounters.reserve(3)を置いても再配置は起きなくなりますが、名前を増やしたときにreserveの数を直し忘れると、同じバグに戻ります。

[=]に書き換えても直りません。[=]でメンバを使ったときにコピーされるのもthisで、hitsではないからです1。[*this]() mutableでオブジェクトごとコピーすると、今度はクロージャの中のコピーだけが増え、countersの要素は0のままです。コールバックから要素そのものを書き換えるには、要素のアドレスが変わらない入れ物が要ります。

  1. [=]でthisを暗黙にキャプチャする書き方は、C++20で非推奨になりました。
