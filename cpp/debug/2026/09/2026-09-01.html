hits.cpp

#include <atomic>
#include <print>
#include <thread>

int main() {
    std::atomic<int> hits{0};
    {
        auto work = [&] {
            for (int i = 0; i < 100000; i++) {
                hits = hits + 1;
            }
        };
        std::jthread a(work), b(work);
    }
    std::println("{}", hits.load());
}

2つのスレッドがそれぞれ100000回ずつ hits を1増やし、合計を表示するつもりのコードです。入力はありません。いまの出力は実行のたびに変わり、手元では 164436、128407、150223 のように200000より小さい値が出ました。本来の出力は 200000 です。

Answer

Wrong

hits = hits + 1;

右辺の hits は load、代入は store で、この1行は「読む」と「書く」の2つの操作に分かれています。スレッドAが100を読み、101を書く前にスレッドBも100を読むと、AもBも101を書くので、2回足したのに1しか増えません。この取りこぼしが実行中に何万回も起き、起きる回数は2つのスレッドの進み方で毎回変わります1。

Right

hits += 1;

std::atomic<int> の += は hits.fetch_add(1) と同じで、読む、足す、書くを1つの不可分な操作として行います。その間にほかのスレッドの書き込みは入れないので、200000回の加算がすべて残ります。hits++ と書いても同じです。

  1. hits が std::atomic なので、1回ずつの読み書きは不可分で、データ競合（同期のない読み書きの衝突。C++では未定義動作）にはなっていません。int のままなら未定義動作でした。ここで起きているのは、正しく定義された操作の組み合わせで結果が足りなくなる競合状態（race condition）です。
