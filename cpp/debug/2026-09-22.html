boot_registrar.cpp

#include <iostream>

int next_id() {
    static int next = 100;
    return next++;
}

struct Counter {
    int value;
    Counter() : value(next_id()) {}
    void increment() { ++value; }
};

extern Counter counter;

struct Registrar {
    Registrar() { counter.increment(); }
};

Registrar registrar;
Counter counter;

int main() {
    std::cout << counter.value << '\n';
}

起動時にRegistrarが自分自身をCounterへ登録する(incrementを呼ぶ)つもりのコードです。動作は未定義で保証されませんが、実際に動かすとたとえば100が出力されることが多く(加算した分が消えてしまいます)、101にはなりません。何が問題で、どう直せばよいでしょうか?

Answer

registrarはcounterより先に宣言されているため、同じ翻訳単位内での動的初期化順序の規則(宣言順)によりregistrarが先に構築されます。その時点でcounterはまだ自分のコンストラクタが走っておらず、生存期間が始まっていません。そこへRegistrarのコンストラクタがcounter.increment()を呼んでしまうのは、生存期間の始まっていないオブジェクトを操作する未定義動作です。しかもこの後counter自身のコンストラクタが実行されると、valueはnext_id()の値でまるごと上書きされるため、実行してみるとincrement()による加算は跡形もなく消え、たとえば100が出ます(101にはなりません)。これは複数の翻訳単位にオブジェクトを分けた場合に初期化順序を制御できなくなる「static initialization order fiasco」の、1つの翻訳単位内での縮図です。実務での対策も同じで、グローバルオブジェクトの代わりに関数ローカルstaticを返すアクセサ関数(Construct On First Use)に置き換え、初回アクセス時に必ず構築を終えた状態にします: 

Counter& counter() {
    static Counter instance;
    return instance;
}

struct Registrar {
    Registrar() { counter().increment(); }
};

Registrar registrar;
