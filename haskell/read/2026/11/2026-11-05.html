Describe.hs

describe :: Maybe Int -> String
describe ~(Just _) = "some"
describe Nothing = "none"

main :: IO ()
main = mapM_ (putStrLn . describe) [Just 3, Nothing]

これは何を出力するでしょうか?

Answer

Output

some
some

関数の等式は上から順に試され、引数がパターンに合った最初の等式が使われます。普通の Just _ なら、Nothing は合わずに2つ目の等式へ進みます。ところが ~ を付けた ~(Just _) は、その場では照合をしません。中の変数が初めて使われたときに照合する約束だけをして、どんな値にも合ったことにします。

そのため describe Nothing も1つ目の等式で受け止められ、"some" になります。_ は値を使わないので、あとで照合が行われる機会も無く、失敗も起きません。2つ目の等式 describe Nothing = "none" には、どの引数も届きません。

見慣れた Just と Nothing の場合分けとして読むと、2行目は none になります。~ が付いたパターンは失敗しないので、それより後ろに書いた等式は使われません。1

  1. GHC の -Wall は、届かない2つ目の等式を redundant（冗長）と警告します。1つ目の等式を ~(Just n) = "some " ++ show n にすると、Nothing のときは n を使った時点で照合が行われて失敗し、例外になります。
