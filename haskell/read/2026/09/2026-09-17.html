Partial.hs

import Control.Exception
import Data.IORef

step :: IORef [Int] -> Int -> IO ()
step ref n
  | n == 3 = throwIO (userError "cancelled at 3")
  | otherwise = modifyIORef ref (n :)

main :: IO ()
main = do
  ref <- newIORef []
  r <- try (mapM_ (step ref) [1 .. 5]) :: IO (Either IOException ())
  readIORef ref >>= print . reverse
  print r

これは何を出力するでしょうか?

Answer

1行目に [1,2]、2行目に Left user error (cancelled at 3) と出力されます。

mapM_ (step ref) [1 .. 5] は、step ref 1、step ref 2 と順に IO アクションを実行します。1 と 2 では modifyIORef がリストの先頭に値を足し、3 で throwIO が例外を投げた時点で、残りの 4 と 5 は実行されません。try はこの例外を Left として受け取りますが、それまでに IORef へ書いた内容を元に戻すことはしません。IORef への書き込みはただの副作用で、トランザクションではないからです1。途中でキャンセルされた処理は、キャンセルされるまでの変更をそのまま残します。

リストには先頭へ足しているので中身は [2,1] で、reverse して [1,2] と表示されます。userError で作った IOException を show すると、user error (…) の形になります。

  1. 巻き戻したいなら、書き込む前の値を覚えておき、例外が起きたら書き戻す処理を自分で書きます。STM の TVar なら、atomically の中から例外が抜けるとそのトランザクションの書き込みは捨てられます。ただし STM は Haskell 2010 の範囲外で、stm パッケージが提供します。
