Rename.hs

data Account
  = Personal { owner :: String, balance :: Int }
  | Joint { owner :: String, coOwner :: String, balance :: Int }
  deriving Show

rename :: String -> String -> Account -> Account

口座 Account には、名義人が1人の Personal と、名義人が2人の Joint があります。名義人の名前のうち old と等しいものをすべて new に置き換え、それ以外のフィールドはそのままにした口座を返す rename old new a を書いてください。old と等しい名義人がいなければ、a と同じ口座を返します。

入力例 1

rename "ann" "amy" (Personal "ann" 10)

出力例 1

Personal {owner = "amy", balance = 10}

入力例 2

rename "bob" "ben" (Joint "ann" "bob" 5)

出力例 2

Joint {owner = "ann", coOwner = "ben", balance = 5}

入力例 3

rename "zed" "z" (Personal "ann" 10)

出力例 3

Personal {owner = "ann", balance = 10}
Reference 
rename :: String -> String -> Account -> Account
rename old new a = case renamed of
  Joint {} -> renamed { coOwner = swap (coOwner renamed) }
  _ -> renamed
  where
    swap name = if name == old then new else name
    renamed = a { owner = swap (owner a) }

owner は両方の構成子にあるフィールドなので、a { owner = swap (owner a) } はどちらの口座にも使えます。coOwner は Joint にしか無く、Personal の値に対して coOwner を読んだり { coOwner = ... } で書き換えたりすると、型検査は通ったまま実行時に例外になります。a { owner = swap (owner a), coOwner = swap (coOwner a) } と1つの更新にまとめると、入力例 2 は通っても、入力例 1 で例外になります1。

そこで、coOwner に触る前に case で構成子を確かめます。Joint {} はフィールドの中身を問わずに Joint の値に一致するパターンで、この枝の中なら coOwner を読んでも書き換えても失敗しません。owner だけを先に置き換えた renamed を作っておくと、Personal の枝はそれを返すだけで済みます。

掲載したのは参考実装で、唯一の正解ではありません。rename old new (Personal o b) と rename old new (Joint o c b) の2つの節に分け、構成子ごとに値を作り直しても同じ結果になります。

  1. このページの検証に使った GHC 9.14 では、-Wall に含まれる -Wincomplete-record-updates と -Wincomplete-record-selectors が、この書き方を警告します。Haskell 2010 の言語仕様は警告を定めていないので、どこまで知らせてくれるかは処理系とその版によります。
