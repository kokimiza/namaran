Reserve.hs

import Data.IORef

reserve :: IORef Int -> Int -> IO Bool

在庫 ref から n 個を取り置く reserve を書いてください。在庫が n 個以上あれば n を引いて True を返し、足りなければ在庫を変えずに False を返します。複数のスレッドが同じ ref に対して同時に呼んでも、在庫より多くを取り置かないようにしてください。

入力例 1

newIORef 5 >>= \r -> mapM (reserve r) [3, 3, 2]

出力例 1

[True,False,True]

入力例 2

newIORef 0 >>= \r -> mapM (reserve r) [1, 0]

出力例 2

[False,True]
Reference 
reserve :: IORef Int -> Int -> IO Bool
reserve ref n = atomicModifyIORef' ref grab
  where
    grab s
      | s >= n = (s - n, True)
      | otherwise = (s, False)

atomicModifyIORef' は、今の値を受け取って (新しい値, 返す結果) の組を返す純粋な関数を、不可分な1回の操作として適用します。在庫が足りるかどうかの判定は、この関数 grab の中に置きます。grab が見る s は書き込まれる直前の値そのものなので、確認してから使うまでの間に別のスレッドが割り込む隙がありません。

readIORef で読んで比べ、足りれば writeIORef で書く形でも、1スレッドなら例と同じ結果になります。しかし在庫が 3 のときに2つのスレッドが同時に reserve r 3 を呼ぶと、両方が 3 を読んで成功と判断し、それぞれ 0 を書きます。在庫は3個しかなかったのに、合わせて6個を渡したことになります。読むことと書くことが別の操作なので、その間に他のスレッドの更新が挟まり、確認の結果が古くなるからです。

名前の末尾の ' は、新しい値を正格に評価する版であることを示します。' のない atomicModifyIORef では、s - n が評価されないままサンクとして積み重なることがあります。掲載したのは参考実装で、唯一の正解ではありません。MVar と modifyMVar を使っても同じことができます。
