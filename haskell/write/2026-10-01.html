Bump.hs

bumpOnce :: [IORef Int] -> IO ()

IORef Int のリストを受け取り、リストに現れる参照の中身をそれぞれちょうど 1 だけ増やす bumpOnce を書いてください。同じ参照が何度現れても、増やすのは1回だけです。中身が同じ値でも、別々に作った参照はそれぞれ増やします。空のリストでは何もしません。

入力例 1

do { a <- newIORef 1; b <- newIORef 1; bumpOnce [a, b, a]; mapM readIORef [a, b] }

出力例 1

[2,2]

入力例 2

do { a <- newIORef 5; bumpOnce [a, a, a]; readIORef a }

出力例 2

6

入力例 3

bumpOnce []

出力例 3

()

import Data.IORef
import Data.List (nub)

bumpOnce :: [IORef Int] -> IO ()
bumpOnce = mapM_ (\r -> modifyIORef r (+ 1)) . nub

IORef の == は中身ではなく、同じ参照かどうかを比べます。nub は == で重複を除くので、同じ参照の2回目以降だけを取り除き、中身が等しい別の参照は残します。残った参照を modifyIORef で1回ずつ増やせば、条件どおりになります。

重複を除かずに mapM_ で増やすと、例1の a は2回増えて 3 になります。一方、中身を読んでから値で重複を除くのも誤りです。例1の a と b はどちらも中身が 1 なので、値で比べると片方しか残らず、もう片方が増えません。除くべきなのは同じ値ではなく同じ参照で、その比べ方をしてくれるのが IORef の == です。

nub の比較回数はリストの長さの2乗に比例します。IORef には Ord のインスタンスがないので、Data.Set に入れて速く重複を除くことはできません。

掲載したのは参考実装で、唯一の正解ではありません。すでに増やした参照のリストを持ちながら先頭から進み、elem で調べてから増やす書き方もあります。
