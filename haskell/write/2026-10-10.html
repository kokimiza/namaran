RetryBudgets.hs

retryBudgets :: Int -> Int -> [Int]

失敗した通信を再試行するときに、各試行へ渡すタイムアウトをミリ秒で順に並べたリストを返す retryBudgets を書いてください。1回の試行には最大で perTry ミリ秒を与えますが、合計は処理全体の期限 deadline ミリ秒を超えてはいけません。どの試行も与えられた時間を使い切って失敗するものとし、残り時間が perTry に満たなくなったら、最後の試行には残り時間だけを与えます。deadline が0以下なら空リストを返します。perTry は正の数とします。

入力例 1

retryBudgets 300 1000

出力例 1

[300,300,300,100]

入力例 2

retryBudgets 500 1000

出力例 2

[500,500]

入力例 3

retryBudgets 300 0

出力例 3

[]
Reference 
retryBudgets :: Int -> Int -> [Int]
retryBudgets perTry deadline
  | deadline <= 0 = []
  | otherwise = t : retryBudgets perTry (deadline - t)
  where
    t = min perTry deadline

参考実装は、残り時間 deadline から1回分の時間 t を引いて再帰します。t は perTry と残り時間の小さいほうなので、残りが perTry に満たない最後の1回は残り時間だけを受け取ります。そこで残りがちょうど0になり、再帰が止まります。

毎回 perTry をそのまま渡すと、入力例1では4回目も300ミリ秒を受け取り、全体で1200ミリ秒かかります。試行ごとのタイムアウトが止めるのは1回の通信の長引きだけなので、処理全体の期限は、残り時間として試行から試行へ持ち回る必要があります。

掲載したのは参考実装で、唯一の正解ではありません。Data.List の unfoldr を使い、残り時間を状態にして書くこともできます。
