Version.hs

compareVersion :: String -> String -> Ordering

バージョンを表す2つの文字列を比べ、1つ目が古ければ LT、同じなら EQ、新しければ GT を返す compareVersion を書いてください。バージョンは . で区切った3つの0以上の整数で、その後ろに - と英小文字のラベルが付くことがあります(2.0.0-rc)。比べ方は次のとおりです。まず3つの整数を左から数として比べます。整数がすべて等しければ、ラベルの付いたもの(正式版の前の版)はラベルのないもの(正式版)より古く、ラベルどうしは文字列として辞書順に比べます。入力はこの形のものだけです。

入力例 1

compareVersion "1.10.0" "1.9.0"

出力例 1

GT

入力例 2

compareVersion "2.0.0-rc" "2.0.0"

出力例 2

LT

入力例 3

compareVersion "2.0.0-alpha" "2.0.0-beta"

出力例 3

LT

data Stage = Pre String | Final
  deriving (Eq, Ord)

compareVersion :: String -> String -> Ordering
compareVersion a b = compare (key a) (key b)

key :: String -> ([Int], Stage)
key s = (map read (splitDots core), stage)
 where
  (core, rest) = break (== '-') s
  stage = if null rest then Final else Pre (drop 1 rest)

splitDots :: String -> [String]
splitDots s = case break (== '.') s of
  (w, []) -> [w]
  (w, _ : rest) -> w : splitDots rest

比べ方を自分で書く代わりに、比べ方がそのまま導出された Ord になる値(キー)に文字列を変換し、compare に任せます。ただし、すぐに思いつくキーの形には、順序を誤るものがいくつかあります。文字列のまま比べると、"1.10.0" と "1.9.0" は3文字目の '1' と '9' で決まり、LT になります。そこで数字の部分を [Int] にします。リストの Ord は先頭から1要素ずつ比べる辞書式なので、[1,10,0] と [1,9,0] は2番目の要素で GT に決まります。

次はラベルです。ラベルがあるかないかは Maybe String で表したくなりますが、導出された Ord では Nothing が Just のどの値よりも小さいので、正式版のほうが古いことになり、入力例 2 が GT になります。Maybe の Ord も、data Maybe a = Nothing | Just a と宣言された構築子の順で決まっているからです。そこで、同じ規則を逆向きに使う型を作ります。Stage は Pre を先に宣言したので、どの Pre も Final より小さくなります。Pre どうしは、導出された Ord が中の String を比べるので、"alpha" < "beta" の辞書順がそのまま使われます。data Stage = Final | Pre String と書くと、入力例 2 がまた逆になります。

最後に、2つをタプル ([Int], Stage) にまとめます。タプルの Ord も左の要素から比べるので、整数が等しいときに限ってラベルが比べられ、問題の比べ方の順と一致します。掲載したのは参考実装で、唯一の正解ではありません。Ord を自分で書くインスタンスにしても同じ順序は作れますが、構築子とフィールドの並べ方で順序を決めておけば、比べる処理を1行も書かずに済みます。
