SaveDurably.hs

saveDurably :: FilePath -> String -> IO ()

ファイル path の中身を文字列 s に置き換え、その内容が記憶装置に書き込まれるまで待ってから戻る saveDurably を書いてください。戻ったあとに電源が落ちても、s が残っているようにします。s が空なら空のファイルにします。Haskell 2010 の標準ライブラリの範囲外ですが、GHC に同梱の unix パッケージから、System.Posix.Unistd の fileSynchronise :: Fd -> IO ()(OSが抱えている書き込みが記憶装置に届くまで待つ)と、System.Posix.IO の handleToFd :: Handle -> IO Fd(Handle を閉じ、その下のファイル記述子を返す)、closeFd :: Fd -> IO () を使ってかまいません。

入力例 1

saveDurably "port.conf" "8080\n" >> readFile "port.conf"

出力例 1

"8080\n"

入力例 2

saveDurably "empty.conf" "" >> readFile "empty.conf"

出力例 2

""

入力例 3

saveDurably "port.conf" "9090\n" >> readFile "port.conf"

出力例 3

"9090\n"

import System.IO
import System.Posix.IO (closeFd, handleToFd)
import System.Posix.Unistd (fileSynchronise)

saveDurably :: FilePath -> String -> IO ()
saveDurably path s = do
  h <- openFile path WriteMode
  hPutStr h s
  fd <- handleToFd h
  fileSynchronise fd
  closeFd fd

hPutStr で書いた文字は、まず Handle のバッファに入ります。handleToFd は Handle を閉じる前にこのバッファを空にするので、ここで文字がOSへ渡ります。ただしOSは受け取った書き込みをメモリ上のページキャッシュに置き、記憶装置へは後でまとめて書きます。バッファを空にしただけで戻ると、そのあいだに電源が落ちたときに中身が失われます。

fileSynchronise は fsync(2) を呼び、そのファイルについてOSが抱えている書き込みが記憶装置に届くまで待ちます。同期はバッファを空にしたあとでなければ意味がありません。まだバッファにある文字はOSに渡っていないので、同期しても記憶装置には届かないからです。handleToFd で記述子を取り出した時点でバッファは空なので、そのあとの fileSynchronise は s の全体を対象にします。

掲載したのは参考実装で、唯一の正解ではありません。例外が起きても記述子を閉じるなら、bracket で包みます。書き換えの途中で電源が落ちたときに古い中身まで失いたくないなら、一時ファイルに書いて同期してから renameFile で置き換え、さらにディレクトリも同期します。
