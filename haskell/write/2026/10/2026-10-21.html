LengthPrefix.hs

frames :: [Int] -> [[Int]]

TCP で受け取ったバイト列（0から255の Int のリスト）を、メッセージの本体のリストに区切る frames を書いてください。バイト列にはメッセージが隙間なく並んでいて、各メッセージは先頭の1バイトが本体の長さを表し、そのあとにその長さの本体が続きます。最後のメッセージが途中で切れていて、本体が長さに足りなければ、そのメッセージは結果に含めません。長さが0のメッセージは空のリストになります。バイト列が空なら空のリストを返します。

入力例 1

frames [2, 7, 8, 0, 1, 5]

出力例 1

[[7,8],[],[5]]

入力例 2

frames [1, 9, 4, 1, 2]

出力例 2

[[9]]

入力例 3

frames [3, 1, 2]

出力例 3

[]
Reference 
frames :: [Int] -> [[Int]]
frames (n : rest)
  | length body == n = body : frames more
 where
  (body, more) = splitAt n rest
frames _ = []

先頭の1バイト n を取り、残りを splitAt n で本体と後続に分け、後続にまた frames を適用します。splitAt はリストが n 個に足りなくてもエラーにせず、あるだけを返します。入力例 2 の2つ目のメッセージは長さ4なのに本体が [1, 2] の2個しかなく、splitAt はそのまま [1, 2] を返します。本体の長さが n と等しいかをガードで確かめるのはこのためで、確かめないと途中で切れた [1,2] がメッセージとして出てしまいます。

ガードが偽になると、照合は frames の次の定義式に進み、frames _ = [] がそこで打ち切ります。空のリストもこの式に来ます。where の body と more はガードからも本体からも使えるので、切り出しは1回で済みます。

掲載したのは参考実装で、唯一の正解ではありません。実際の受信処理では、切れた最後のメッセージを捨てずに次に届くバイト列の前へつなぐ必要があるので、メッセージのリストと一緒に残りのバイト列も返す形にします。
