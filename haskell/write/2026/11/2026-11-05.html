PeakFrom.hs

peakFrom :: (Int -> Int) -> Int -> Int

関数 f は lo 以上の整数で定義されていて、ある位置 p までは引数が1増えるごとに値が大きくなり、p から先では引数が1増えるごとに値が小さくなります。p が lo のときは、はじめから小さくなる一方です。この p を返す peakFrom f lo を書いてください。p の上限は与えられません。f を呼ぶ回数は、p - lo の桁数に比例する程度に抑えます。途中の計算で Int があふれることはないものとします。

入力例 1

peakFrom (\x -> x * (200 - x)) 0

出力例 1

100

入力例 2

peakFrom negate 5

出力例 2

5

入力例 3

peakFrom (\x -> negate (abs (x - 37))) 0

出力例 3

37

peakFrom :: (Int -> Int) -> Int -> Int
peakFrom f lo = search lo (lo + 2 * d)
 where
  d = until (\s -> f (lo + s) >= f (lo + 2 * s)) (* 2) 1
  search l h
    | h - l < 3 = snd (maximum [(f x, x) | x <- [l .. h]])
    | f m1 < f m2 = search (m1 + 1) h
    | otherwise = search l (m2 - 1)
   where
    m1 = l + (h - l) `div` 3
    m2 = h - (h - l) `div` 3

区間を縮める探し方は、両端が決まっていないと始められません。そこでまず、p を必ず含む区間を作ります。until は条件を満たすまで関数を適用し続けるので、d は 1、2、4、8 と倍になり、f (lo + d) >= f (lo + 2 * d) を初めて満たした値で止まります。右の点 lo + 2 * d の値が左の点 lo + d より大きくないなら、lo + 2 * d はもう p を越えているか、ちょうど2点の間に p があります。どちらでも p は lo から lo + 2 * d の間にあり、ここまでに f を呼ぶ回数は p - lo の桁数に比例します。入力例 1 では d = 128 で f 128 が 9216、f 256 が -14336 になって止まり、(0, 256) から探し始めます。入力例 2 は f 6 が f 7 より大きいので d = 1 のまま止まり、(5, 7) です。

search は、区間を三等分する2点 m1 と m2 で f を比べます。f m1 < f m2 なら p は m1 より右にあり、そうでなければ m2 より左にあるので、どちらかの側を捨てて区間を約3分の2にします。ただし幅が 3 未満になると (h - l) `div` 3 は 0 で、m1 と m2 が両端に重なります。この比べ方を続けると、幅0の区間からさらに (l, l - 1) のような空の区間へ進み、再帰が終わりません。幅が 3 未満になったら残りの高々3点の値を直接比べ、maximum が値の最も大きい組を選んで、その位置を snd で取り出します。

区間を作る段を省いて上限を決め打ちにすると、それより先に p がある関数で間違えます。倍にする段を、1ずつ右へ進めて値が下がるところを探す形にすると、答えは合っても f を呼ぶ回数が p - lo に比例してしまいます。掲載したのは参考実装で、唯一の正解ではありません。区間ができたあとは、隣り合う2点 f m と f (m + 1) を比べて半分ずつ捨てる二分探索でも探せます。
