Transfer.hs

import Data.IORef
import qualified Data.Map as M

transfer :: IORef (M.Map String Int) -> String -> String -> Int -> IO Bool

ref には、口座の名前から残高への Map が入っています。口座 from から口座 to へ amount を移す transfer を書いてください。両方の口座があり、from の残高が amount 以上なら、from から amount を引いて to に足し、True を返します。どちらかの口座が無いか、残高が足りなければ、何も変えずに False を返します。from と to が同じ口座のときは、残高が足りれば True を返し、残高は変わりません。複数のスレッドが同じ ref に同時に transfer を呼んでも、残高が負になったり、口座の合計が変わったりしないようにしてください。amount は 0 以上とします。例では、ref の中身を M.toList の結果で書きます。

入力例 1

[("alice",100),("bob",20)]
transfer ref "alice" "bob" 30

出力例 1

True
[("alice",70),("bob",50)]

入力例 2

[("alice",70),("bob",50)]
transfer ref "alice" "alice" 50

出力例 2

True
[("alice",70),("bob",50)]

入力例 3

[("alice",70),("bob",50)]
transfer ref "alice" "carol" 10

出力例 3

False
[("alice",70),("bob",50)]

transfer :: IORef (M.Map String Int) -> String -> String -> Int -> IO Bool
transfer ref from to amount = atomicModifyIORef' ref move
 where
  move accounts = case (M.lookup from accounts, M.member to accounts) of
    (Just balance, True)
      | balance >= amount ->
          (M.adjust (+ amount) to (M.adjust (subtract amount) from accounts), True)
    _ -> (accounts, False)

atomicModifyIORef' に渡す move は、いまの Map を受け取り、新しい Map と transfer の結果の組を返す純粋な関数です。atomicModifyIORef' は、move が読んだ Map と書き戻す Map の間にほかのスレッドの更新を挟ませません。残高の確認と、from と to の2つの更新をすべて move の中で行うので、確かめた残高がそのまま引く残高になります。

確認か更新のどれかを外に出すと、それぞれ別の誤りになります。先に readIORef で残高を確かめてから atomicModifyIORef' で引くと、その間にほかのスレッドが同じ口座から引いた分を見落とし、残高が負になりえます。引く側と足す側を別々の atomicModifyIORef' にすると、2回の間に別のスレッドが読む Map では、引いた分がどちらの口座にも無く、合計が減って見えます。to の口座が無いと分かったのが引いたあとなら、引いた分を戻す処理も要ります。

from と to が同じ口座のときは、M.adjust を順に2回適用しているので、引いてから同じ額を足して元に戻ります。2つの新しい残高を元の Map から計算して M.insert で書くと、この場合は to への書き込みが from への書き込みを上書きし、残高が amount だけ増えてしまいます。掲載したのは参考実装で、唯一の正解ではありません。Map ごと MVar に入れて modifyMVar で更新しても、同じことができます。
