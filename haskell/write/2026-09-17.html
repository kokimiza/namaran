Rollback.hs

withRollback :: IORef a -> IO b -> IO b

ref の値を覚えてから act を実行し、act が例外で止まったら ref を実行前の値に書き戻して、同じ例外を投げ直す withRollback を書いてください。act が成功したときは ref に触れず、act の結果を返します。ref が [1] のとき、withRollback ref (modifyIORef ref (2 :) >> throwIO e) は e を投げ、そのあとの ref は [1]。withRollback ref (modifyIORef ref (2 :)) のあとは [2,1]。

Reference 
import Control.Exception
import Data.IORef

withRollback :: IORef a -> IO b -> IO b
withRollback ref act = do
  saved <- readIORef ref
  act `onException` writeIORef ref saved

Control.Exception の onException は、第1引数のアクションが例外で終わったときだけ第2引数を実行し、そのあと同じ例外を投げ直します。成功したときは第2引数を実行せず、結果をそのまま返します。書き戻しと投げ直しをどちらもこの関数に任せられるので、本体は「値を覚える」と「失敗したら戻す」の2行で済みます。別スレッドから killThread で止められたときも、非同期例外として同じ経路を通り、値は書き戻されます。

catch で書くなら、ハンドラの中で writeIORef ref saved のあとに throwIO で投げ直すのを忘れないようにします。忘れると例外がそこで消え、呼び出し側は失敗に気づけません。すべての例外を受けるには、ハンドラの引数の型を SomeException と書いておく必要もあります。

これは参考実装で、唯一の正解ではありません。書き戻せるのは ref だけで、act がほかの IORef やファイルに書いた変更は残ることにも注意してください。
