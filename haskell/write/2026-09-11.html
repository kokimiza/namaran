RunWithCleanup.hs

runWithCleanup :: IO a -> IO () -> IO a

runWithCleanup action cleanupを実装してください。actionを実行し、それが正常終了しても例外を投げても、終了後には必ずcleanupを実行すること。actionの結果やそこで投げられた例外は、そのまま呼び出し元に伝わるようにすること(runWithCleanupが握りつぶしてはいけません)。runWithCleanup (putStrLn "work" >> return (42 :: Int)) (putStrLn "cleanup") → work・cleanupの順に出力し42を返す、runWithCleanup (throwIO Boom) (putStrLn "cleanup") → cleanupを出力したあと例外Boomがそのまま外へ伝わる

Reference 
runWithCleanup :: IO a -> IO () -> IO a
runWithCleanup action cleanup = action `finally` cleanup

Control.Exceptionのfinallyは、まさに「1つ目のアクションを実行し、正常終了でも例外でも必ず2つ目のアクションを実行してから、1つ目の結果(または例外)をそのまま伝える」という動作をする関数です。Haskellにはスコープを抜けるときに自動で呼ばれるデストラクタやDropが無いので、この種の「後始末を忘れない」仕組みは自分で(あるいはfinallyやbracketのようなライブラリ関数を介して)明示的に組み立てる必要があります。runWithCleanupは、この考え方を一番小さい形で切り出したものです。これは参考実装であり、唯一の正解ではありません。
