Transfer.hs

import Data.IORef

transfer :: IORef Int -> IORef Int -> Int -> IO ()
transfer from to n = do
  a <- readIORef from
  b <- readIORef to
  writeIORef from (a - n)
  writeIORef to (b + n)

main :: IO ()
main = do
  acct <- newIORef 100
  transfer acct acct 30
  readIORef acct >>= print

transfer from to n は、口座 from から口座 to へ n を移すつもりです。引数も標準入力も使わず、残高 100 の口座から同じ口座へ 30 を移して、残高を出力します。自分への振替なので本来は 100 と出力されるはずが、いまは 130 と出力されます。

Answer

Wrong

a <- readIORef from
b <- readIORef to
writeIORef from (a - n)
writeIORef to (b + n)

from と to に同じ acct を渡したので、2つの引数は同じ参照です。a と b はどちらも同じ場所から読んだ 100 で、1回目の書き込みで残高は 70 になります。

ところが2回目の書き込みは、70 になる前に読んだ b を使って 100 + 30 を書きます。70 は上書きされ、130 が残ります。

Right

modifyIORef from (subtract n)
modifyIORef to (+ n)

modifyIORef は書き込む直前に中身を読みます。2回目の modifyIORef が読むのは1回目が書いた 70 なので、同じ参照でも 70 + 30 で 100 に戻ります。from と to が別の参照なら、これまでどおり片方が減り、もう片方が増えます1。

  1. from == to のときは何もせずに返す、という直し方もあります。IORef の == は中身ではなく同じ参照かどうかを比べるので、この判定で自分への振替を見分けられます。
