Shipping.hs

shipping :: Int -> Int -> Int
shipping weight distance = case weight of
  0 -> 0
  1 -> base
  _ -> base + extra
    where
      base = distance * 10
      extra = (weight - 1) * 5

main :: IO ()
main = print (map (`shipping` 3) [0, 1, 2])

shippingは、重さweightと距離distanceから送料を計算するつもりの関数です。入力はmap (`shipping` 3) [0, 1, 2]で、本来は[0,30,35]を表示するはずですが、いまはコンパイルが通りません。どこを直せばよいでしょうか?

Answer

whereから始まる3行を2文字ずつ左へずらし、whereを選択肢と同じ列に置きます。いまのwhereは関数全体ではなく、最後の選択肢_ -> base + extraに付いています。

caseの選択肢は、関数の定義と同じように自分のwhereを持てます。ofのあとで開いた暗黙のブロックでは、選択肢の始まる列より右から始まる行は直前の選択肢の続きとして読まれます。whereはその列より右にあるので最後の選択肢の一部になり、baseとextraはその選択肢の中でしか見えません。1 -> baseのbaseがスコープにないというエラーは、ここから来ています。

whereを選択肢と同じ列に置くと、レイアウト規則はまず新しい選択肢が始まったと見なして;を補います。ところがwhereで始まる選択肢はないので、構文エラーになる字句の手前で暗黙のブロックを閉じる規則が働き、caseのブロックはそこで閉じます1。その結果whereはshippingの定義全体に付き、3つの選択肢のどれからもbaseとextraが見えます。

「同じ列なら閉じる」と「深ければ続き」は見た目では区別しにくいので、選択肢を4文字下げ、whereを2文字下げにする書き方もよく使われます。whereが選択肢より左にあれば、字下げだけでcaseのブロックが閉じ、この規則に頼らずに済みます。

  1. Haskell 2010 Language Reportの10.3節でparse-error(t)と書かれている規則です。let x = 1 in xを1行で書けるのも、inの手前でこの規則がletのブロックを閉じるからです。
