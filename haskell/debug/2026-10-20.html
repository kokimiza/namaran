2026-10-20

Settings.hs

import Data.Dynamic
import Data.Maybe (fromMaybe)

number :: String -> Integer
number = read

settings :: [(String, Dynamic)]
settings = [("host", toDyn "localhost"), ("retries", toDyn (number "3"))]

retries :: Int
retries = fromMaybe 1 (lookup "retries" settings >>= fromDynamic)

main :: IO ()
main = print retries

settings は、型の違う設定値を Dynamic に包んで名前と組にした一覧で、retries はそこから再試行の回数を Int として取り出し、見つからなければ1を使うつもりの定義です。設定には number "3" の値が入っているので本来の出力は 3 ですが、いまの出力は 1 です。

Answer

Wrong

number :: String -> Integer
settings = [("host", toDyn "localhost"), ("retries", toDyn (number "3"))]
retries = fromMaybe 1 (lookup "retries" settings >>= fromDynamic)

toDyn は値と一緒にその型の情報を Dynamic に入れ、fromDynamic は、入っている型が求める型と一致したときだけ Just を返します。number "3" の型は Integer なので、"retries" に入っているのは Integer の3です。retries は Int を求めるので型が一致せず、fromDynamic は Nothing を返し、fromMaybe が代わりの1を返します。Int と Integer はどちらも整数を表しますが別の型で、fromDynamic は型の変換をしません。

Right

number :: String -> Int

number が Int を返すようにすると、Dynamic に入れる型と取り出す型がそろい、fromDynamic は Just 3 を返します。Dynamic に包んだあとの型の食い違いはコンパイラには見えず、実行時に Nothing になるだけなので、入れる側と取り出す側で同じ型を使うことは書く側が守るしかありません1。

  1. Data.Dynamic は base に含まれるモジュールで、使う側のコードに拡張機能は要りません。値の型の情報は Typeable クラスが持っていて、GHC はすべての型に Typeable のインスタンスを自動で用意します。
