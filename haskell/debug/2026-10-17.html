Validate.hs

import Control.Exception (SomeException, handle)
import System.Exit (ExitCode (..), exitWith)
import System.IO (hPutStrLn, stderr)

report :: SomeException -> IO ()
report e = hPutStrLn stderr ("unexpected: " ++ show e)

main :: IO ()
main = handle report $ do
  let xs = [3, -1, 4] :: [Int]
  if any (< 0) xs
    then do
      putStrLn "invalid input"
      exitWith (ExitFailure 2)
    else print (sum xs)

main は、整数の列に負の数があれば invalid input と出して終了コード 2 で終わり、なければ合計を出すつもりのプログラムです。handle report は、予期しない例外を標準エラー出力に記録するために付けてあります。入力は xs の [3, -1, 4] です。いまは標準出力に invalid input が出たあと、標準エラー出力に unexpected: ExitFailure 2 が出て、終了コード 0 で終わります。本来は invalid input だけを出して、終了コード 2 で終わります。

Answer

Wrong

import Control.Exception (SomeException, handle)

report :: SomeException -> IO ()

exitWith (ExitFailure 2) は、その場でプロセスを終わらせずに、ExitFailure 2 という ExitCode 型の値を例外として投げます。終了コードになるのは、この例外が main の外まで伝わったときです。

handle report が捕まえるのは report の引数の型の例外で、SomeException はすべての例外を表す型なので、ExitCode の例外もここで捕まります。report は unexpected: ExitFailure 2 を書いて普通に戻るため、main は正常に終わったことになり、終了コードは 0 になります。呼び出したシェルスクリプトや CI からは、不正な入力が成功に見えます。

Right

import Control.Exception (IOException, handle)

report :: IOException -> IO ()

report の引数の型を IOException にすると、handle が捕まえるのは入出力の失敗だけになります。ExitCode の例外は handle を素通りして main の外まで伝わり、ランタイムが終了コード 2 でプログラムを終えます。すべての例外を記録したいなら、SomeException のまま fromException で ExitCode かどうかを調べ、そうであれば throwIO で投げ直す方法もあります1。

  1. Control.Exception は GHC の base ライブラリのモジュールで、Haskell 2010 の言語報告には含まれていません。言語報告のライブラリで例外を捕まえる関数は、System.IO.Error の catchIOError のように入出力のエラーだけを扱うもので、こちらは ExitCode を捕まえません。
