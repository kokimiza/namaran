Profile.hs

data Profile = Profile { name :: String, city :: String }
  deriving Show

data Event = Rename String | Move String

apply :: Event -> Profile -> Profile
apply (Rename n) p = p { name = n }
apply (Move c) p = p { city = c }

current :: Profile -> [Event] -> Profile
current = foldr apply

main :: IO ()
main = print (current (Profile "" "") [Rename "Ann", Move "Oslo", Rename "Anna"])

currentは、初期のプロフィールにイベント列を古い順に適用して、いまのプロフィールを再構築するつもりの関数です。入力はcurrent (Profile "" "") [Rename "Ann", Move "Oslo", Rename "Anna"]。いまの出力はProfile {name = "Ann", city = "Oslo"}ですが、本来の出力はProfile {name = "Anna", city = "Oslo"}です。どこを直せばよいでしょうか?

Answer

foldr apply z [e1, e2, e3]はapply e1 (apply e2 (apply e3 z))で、いちばん内側、つまり最後のイベントRename "Anna"が最初に適用され、最初のイベントRename "Ann"が最後に上書きします。applyを「イベントを状態に適用する」自然な引数順Event -> Profile -> Profileで書くと、foldlが要求するb -> a -> bには合わず、foldrのa -> b -> bにはぴったり合います。型が通る方を選ぶと、順序が逆になるわけです。古い順に適用するにはfoldlを使い、引数の順をflipで合わせます:

current = foldl (flip apply)

MoveとRenameのように別のフィールドを触るイベントどうしは順序に関係ないので、同じフィールドを2回変えるイベントがあって初めてこのバグは見えます。長い履歴を再生するなら、サンクをためないData.Listのfoldl'がより安全です。
