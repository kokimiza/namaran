Replay.hs

import Data.List (foldl')

newtype Value = Value Int

step :: Value -> String -> Value
step (Value n) "inc" = Value (n + 1)
step _ s = Value (read s)

run :: [String] -> Int
run cmds = case foldl' step (Value 0) cmds of
  Value n -> n

main :: IO ()
main = print (run ["oops", "5", "inc"])

数を表す文字列と "inc" からなる命令の列を先頭から実行し、最後の値を返すつもりの run です。数の命令は値をその数で置き換え、"inc" は値を1増やします。状態は foldl' で1手ずつ進めますが、あとの命令で置き換えられた数は使われないので、読み取れない文字列が混ざっていても答えには関係しないはずです。run ["oops", "5", "inc"] を表示すると、いまは何も出力されずに Prelude.read: no parse という例外で終了します。本来の出力は 6 です。

Answer

Wrong

newtype Value = Value Int

foldl' は、次の要素へ進む前に、途中の状態を外側のコンストラクタが分かる形（弱頭部正規形、WHNF）まで評価します。1手目の状態 step (Value 0) "oops" は Value (read "oops") です。Value が newtype だと、コンストラクタは実行時には消えていて、この値の弱頭部正規形は中の read "oops" を評価した結果そのものになります。そのため1手目で read "oops" が評価され、"5" で置き換わる前に例外が起きます。

Right

data Value = Value Int

data のコンストラクタは実行時にも残るので、foldl' の評価は外側の Value が見えたところで止まり、中の read "oops" は評価されないまま残ります。2手目の "5" がその状態を Value (read "5") に置き換えるので、"oops" を読み取る式は一度も評価されずに捨てられます。最後の "inc" で5に1が足され、6 が表示されます1。

  1. HLint は直したあとの data Value = Value Int に「newtype にせよ」という提案を出し、注記に「decreases laziness」（遅延性が下がる）と添えます。この問題のコードは、その注記が指す違いで壊れていました。
