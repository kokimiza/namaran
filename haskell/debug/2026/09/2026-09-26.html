Counter.hs

module Main (main) where

main :: IO ()
main = do
  writeFile "count.txt" "41"
  s <- readFile "count.txt"
  let n = read s :: Int
  writeFile "count.txt" (show (n + 1))
  readFile "count.txt" >>= putStrLn

count.txt に書かれた数を1増やして同じファイルへ書き戻し、書き戻した内容を表示するつもりのプログラムです。入力は、最初に書き込む "41" です。いまは何も表示されず、2回目の writeFile が、ファイルが使用中だという例外を出して止まります。本来の出力は 42 です。どこを直せばよいでしょうか?

Answer

readFile はファイルを開き、中身を読まないまま文字列を返します。この文字列は、使われた分だけあとから読まれる遅延リストで、最後まで読まれたところでファイルが閉じられます。let n = read s も n を束縛するだけで read は動かないので、2回目の writeFile の時点で count.txt はまだ1文字も読まれておらず、読み込み用に開いたままです。writeFile は中身の show (n + 1) を評価するより先にファイルを書き込み用に開こうとしますが、同じプロセスが読み込み用に開いているファイルなので、GHC の実行時システムはファイルがロックされているという例外を投げます1。

直すには、書き込みの前に文字列を最後まで読ませます。最小の修正は、let を readIO に替えることです: 

  n <- readIO s :: IO Int

readIO は read と同じく文字列を解析する IO アクションで、do の中のこの行で実行されます。解析した値の後ろに余計な文字が無いことを確かめるために文字列の終わりまで読むので、ここで count.txt が閉じられ、次の writeFile が通ります。解析に失敗したときも、read のように値を使った先で error になるのではなく、この行で IO の例外になります。

  1. Haskell 2010 の報告書は、少なくとも同じプロセスの中では、1つのファイルに「複数の読み手か、1つだけの書き手」というロックを掛けるよう実装に求めています。GHC はこれに従っています。
