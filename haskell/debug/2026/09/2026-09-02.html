Jobs.hs

import Data.IORef
import System.IO.Error (catchIOError)

runJob :: IORef Bool -> Int -> IO ()
runJob busy n = do
  running <- readIORef busy
  if running
    then putStrLn ("busy " ++ show n)
    else do
      writeIORef busy True
      if n == 2 then ioError (userError "boom") else putStrLn ("done " ++ show n)
      writeIORef busy False

main :: IO ()
main = do
  busy <- newIORef False
  mapM_ (\n -> runJob busy n `catchIOError` \_ -> putStrLn ("failed " ++ show n)) [1, 2, 3]

runJob は、ジョブを同時に1つしか動かさないように、実行中の印として busy を True にしてからジョブを実行し、終わったら False に戻すつもりの関数です。main はジョブ1、2、3を順に実行し、失敗したジョブには failed と表示します。ジョブ2は失敗するので、本来は done 1、failed 2、done 3 の3行が表示されるはずですが、いまは3行目が busy 3 になり、ジョブ3が実行されません。

Answer

Wrong

writeIORef busy True
if n == 2 then ioError (userError "boom") else putStrLn ("done " ++ show n)
writeIORef busy False

ジョブ2では ioError が例外を投げ、do ブロックの残りは実行されません。writeIORef busy False も飛ばされるので、busy は True のまま残ります。

例外は main の catchIOError が受け止めて failed 2 を表示しますが、このハンドラは busy を戻しません。ジョブ3は前のジョブがまだ動いていると判断して busy 3 を表示し、これ以降のジョブも、どれも実行されなくなります。

Right

import Control.Exception (finally)

      writeIORef busy True
      work `finally` writeIORef busy False
  where
    work = if n == 2 then ioError (userError "boom") else putStrLn ("done " ++ show n)

finally は、左の動作が正常に終わっても例外で止まっても右の動作を実行し、例外はそのまま投げ直します1。busy を戻す処理が例外の経路でも必ず走るので、ジョブ2の失敗は failed 2 として報告され、busy は False に戻ってジョブ3が実行されます。

  1. finally は Haskell 2010 の言語報告書が定めるライブラリにはなく、GHC に付属する base パッケージの Control.Exception にあります。言語拡張は使っていません。印を立てる処理と戻す処理を組にするなら、同じモジュールの bracket_ も使えます。
