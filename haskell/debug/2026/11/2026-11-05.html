2026-11-05

ConfigKeys.hs

parse :: String -> (String, String)
parse s = (k, v)
 where
  (k, _ : v) = break (== '=') s

main :: IO ()
main = mapM_ (putStrLn . fst . parse) ["a=1", "flag", "b=2"]

設定の行を最初の = の前と後ろに分けて組で返すつもりの parse です。= の無い行は、行全体をキーとし、値を空文字列とする約束です。main は3行のキーだけを順に表示します。本来は a、flag、b の3行を表示するはずが、いまは a だけを表示したあと、Non-exhaustive patterns in (k, _ : v) という例外で止まります。

Answer

Wrong

(k, _ : v) = break (== '=') s

where や let でパターンを使って束縛すると、そのパターンには暗黙に ~ が付き、定義した時点では照合されません。そのため parse "flag" そのものは失敗せず、組 (k, v) を返します。fst が取り出すのも k だけで、v は使われません。

ところが、遅延したパターンは、変数のどれか1つが使われた時点で全体がまとめて照合されます。putStrLn が k を求めると、break (== '=') "flag" の結果 ("flag", "") が (k, _ : v) 全体と照合され、2つ目の成分の空文字列が _ : v に合わずに失敗します。k が使うのは1つ目の成分だけですが、k だけを先に取り出す途中の段階はありません。"a=1" では ("a", "=1") が合うので、a は表示されます。

Right

parse s = (k, drop 1 rest)
 where
  (k, rest) = break (== '=') s

パターンを、どんな組にも合う (k, rest) にし、先頭の = を外す処理は drop 1 に任せます。drop 1 は空文字列に対しても空文字列を返すので、= の無い行でも失敗せず、約束どおり値が空文字列になります。k を使ったときの照合も必ず成功するので、flag と b も表示されます。1

  1. GHC 9.2 以降は、合わない値がありうるパターン束縛を -Wall に含まれる -Wincomplete-uni-patterns で警告します。~ を明示したパターンも同じく警告の対象です。
