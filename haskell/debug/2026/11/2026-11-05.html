ArgMin.hs

argMin :: (Double -> Double) -> Double -> Double -> Double
argMin f lo hi
  | hi - lo < 1e-9 = lo
  | f m1 < f m2 = argMin f lo m2
  | otherwise = argMin f m1 hi
 where
  m1 = lo + (hi - lo) / 3
  m2 = hi - (hi - lo) / 3

main :: IO ()
main = do
  print (argMin (\x -> (x - 2) * (x - 2)) 0 10)
  print (argMin (\x -> (x - 2e8) * (x - 2e8)) 0 1e9)

[lo, hi] で、ある位置までは減り続けてそこから増え続ける関数 f について、最小になる位置を、幅が 1e-9 未満になるまで区間を縮めて求める argMin です。1つ目の呼び出しは 1.999999999475721 を返しますが、2つ目の呼び出しがいつまでも終わらず、プログラムが止まりません。本来は2行目に 2.0e8 の近くの値が表示されて終わるはずです。

Answer

Wrong

argMin f lo hi
  | hi - lo < 1e-9 = lo
  | f m1 < f m2 = argMin f lo m2
  | otherwise = argMin f m1 hi
 where
  m1 = lo + (hi - lo) / 3
  m2 = hi - (hi - lo) / 3

Double が表せる数は飛び飛びで、隣り合う2つの数の間隔は、値の大きさにほぼ比例して広がります。有効数字が2進数で53桁しかないので、間隔は値のおよそ 2-52 倍です。2 の近くでは 4e-16 ほどですが、2.0e8 の近くでは約 3e-8 あり、1e-9 よりずっと広くなります。2つ目の呼び出しの区間は 2.0e8 の近くまで縮みますが、そこで lo と hi が別の数である限り、hi - lo は少なくとも間隔1つ分の約 3e-8 で、1つ目の枝の hi - lo < 1e-9 は決して真になりません。

区間の幅が間隔1つ分まで縮んだところで、(hi - lo) / 3 は間隔の3分の1になります。lo にそれを足した結果は、最も近い Double に丸められて lo に戻り、m2 も同じように hi に戻ります。すると次の再帰は、どちらの枝に進んでも argMin f lo hi と同じ引数になり、同じ計算を永遠に繰り返します。1つ目の呼び出しが終わったのは、2 の近くの間隔が 1e-9 より狭く、幅が 1e-9 を下回るまで縮められたからです。

Right

argMin f lo hi
  | hi - lo < 1e-9 || m1 <= lo || m2 >= hi = lo
  | f m1 < f m2 = argMin f lo m2
  | otherwise = argMin f m1 hi
 where
  m1 = lo + (hi - lo) / 3
  m2 = hi - (hi - lo) / 3

三等分点が区間の内側に入らなくなったら、それ以上は区間を縮められないので、そこで止めます。m1 <= lo か m2 >= hi になるのは、幅が値の大きさに対する Double の間隔の数個分まで縮んだときだけで、そのときの lo は Double で表せる範囲で、最小の位置のすぐそばにあります。2つ目の呼び出しは 2.0e8 を返し、間隔が 1e-9 より狭い1つ目の呼び出しでは、これまでどおり幅の条件で止まります。

幅の条件を値の大きさに比例させる(1e-9 * max 1 (abs lo) など)か、再帰の回数を決めておく直し方でも止まります。どちらも、浮動小数点数の間隔より細かい幅を終わりの条件にしない、という点は同じです。
