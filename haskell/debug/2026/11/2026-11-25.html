Solutions.hs

solutions
  :: (Int, Int) -> (Int, Int) -> [Int]
solutions (a, m) (b, n) =
  [x | x <- [a, m ..], x `mod` n == b]

main :: IO ()
main = print (take 3 xs)
 where
  xs = solutions (2, 3) (3, 5)

solutions (a, m) (b, n) は、m で割った余りが a で、n で割った余りが b である a 以上の整数を、小さい順に並べるつもりの関数です。3 で割ると 2 余り、5 で割ると 3 余る数の最初の3つを表示すると、本来は [8,23,38] を出力するはずが、いまは [3,8,13] を出力します。

Answer

Wrong

  [x | x <- [a, m ..], x `mod` n == b]

[a, m ..] は、a から始まり、最初の2項の差 m - a ずつ増える並びです。(2, 3) では [2, 3 ..] になり、公差は 1 なので、2 以上のすべての整数が候補になります。3 で割った余りが 2 という条件はこの時点で消え、残るのは 5 で割った余りの条件だけなので、3、8、13 が出てきます。3 は3で割り切れ、13 は3で割ると1余るので、どちらも1つ目の条件を満たしません。

Right

  [x | x <- [a, a + m ..], x `mod` n == b]

2項目を a + m にすると、公差は (a + m) - a = m になり、候補は 2、5、8、11、…… と、3 で割った余りが 2 の数だけになります。その中から 5 で割った余りが 3 のものを残すので、8、23、38 が出力されます。a が 0 のときだけは [a, m ..] と [a, a + m ..] が同じ並びになるので、余りが 0 の条件で試すとこの欠陥は見つかりません。
