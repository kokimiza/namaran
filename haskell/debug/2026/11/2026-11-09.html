2026-11-09

CountLines.hs

import System.IO

countLines :: FilePath -> IO Int
countLines path = withFile path ReadMode $ \h -> do
  s <- hGetContents h
  return (length (lines s))

main :: IO ()
main = do
  writeFile "access.log" "GET /\nGET /a\nPOST /b\n"
  countLines "access.log" >>= print

ファイルを一定のメモリで読みながら行数を数え、表示するつもりのプログラムです。3行の access.log を書いてから countLines を呼ぶと、本来は 3 が表示されるはずが、いまは何も表示されず、access.log: hGetContents: illegal operation (delayed read on closed handle) という例外で終わります。

Answer

Wrong

countLines path = withFile path ReadMode $ \h -> do
  s <- hGetContents h
  return (length (lines s))

hGetContents はファイルの中身をその場では読まず、文字列が評価されたときに、そこまでをハンドルから読み出します。return (length (lines s)) も行数を数えずに、「s の行数」という未評価の式を返します。withFile は渡した関数が値を返すとハンドルを閉じるので、この式は1文字も読まれないまま withFile の外へ出ます。main の print が行数を表示しようとして初めて式が評価され、hGetContents は閉じたハンドルから続きを読もうとして例外を投げます。

Right

countLines path = withFile path ReadMode $ \h -> do
  s <- hGetContents h
  return $! length (lines s)

return $! x は x を評価してから return します。Int を評価すると数そのものまで計算されるので、length は withFile の中で、ハンドルが開いている間にファイルを最後まで読み、3を数え終えます。withFile の外へ出るのは評価済みの3です。length が数え終えた行はもう誰からも参照されないので、すぐに捨てられ、ファイルが大きくなっても使うメモリは増えません。ファイル全体を一度に読む hGetContents' に替えても例外は消えますが、中身をすべてメモリに置くので、一定のメモリで数えるという目的からは外れます1。

  1. hGetContents' は base 4.15(GHC 9.0)で System.IO に加わりました。Haskell 2010 の報告書の System.IO には無い関数です。
