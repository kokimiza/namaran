Continuation.hs

escape :: String -> String
escape ('\\' : s@(c : _))
  | c `elem` "\\n" = '\\' : '\\' : escape s
escape ('\n' : s) = '\\' : 'n' : escape s
escape (c : s) = c : escape s
escape [] = []

unescape :: String -> String
unescape ('\\' : 'n' : s) = '\n' : unescape s
unescape ('\\' : '\\' : s) =
  '\\' : unescape s
unescape (c : s) = c : unescape s
unescape [] = []

main :: IO ()
main = print (unescape (escape "ls \\\n-l"))

改行を \n の2文字にするエスケープ escape と、それを元に戻す unescape です。出力を短く保つため、escape はバックスラッシュを、そのままでは読み違えられるときだけ \\ の2文字にします。unescape (escape s) はどの s でも s に戻るはずです。行末のバックスラッシュで次の行へ続けるシェルのコマンド "ls \\\n-l"(Haskell の文字列リテラルで書いています)では、"ls \\\n-l" と出るはずが、いまは "ls \\n-l" と出て、改行が n に変わっています。

Answer

Wrong

escape ('\\' : s@(c : _))
  | c `elem` "\\n" = '\\' : '\\' : escape s

unescape がバックスラッシュの意味を決めるときに見るのは、escape が書き出したあとの次の文字です。ところが escape は、バックスラッシュを二重にするかどうかを、エスケープする前の次の文字 c で決めています。2つが食い違うのは、c が改行のときです。改行はバックスラッシュと n の2文字になるので、バックスラッシュが二重にならないまま改行の前に残ると、出力はバックスラッシュ2つと n になります。これはエスケープしたバックスラッシュ1つと、ふつうの文字 n を並べたものと同じ並びです。

例の "ls \\\n-l" では、バックスラッシュの次が改行なので、c `elem` "\\n"(バックスラッシュか n か)は偽になり、バックスラッシュは1つのまま出ます。続く改行が \n になり、escape の結果は ls 、バックスラッシュ2つ、n-l です。unescape は先頭の2つのバックスラッシュを組にして1つに戻し、残った n をそのまま残すので、改行の代わりに n が入った "ls \\n-l" が返ります。

Right

escape ('\\' : s@(c : _))
  | c `elem` "\\n\n" = '\\' : '\\' : escape s

バックスラッシュを二重にしなければならないのは、出力でその直後に来る文字がバックスラッシュか n のときです。出力の次の文字は、元の次の文字がバックスラッシュか改行ならバックスラッシュ、n なら n なので、調べる文字の集まりに改行を加えて、バックスラッシュ、n、改行の3つにします。それ以外の文字が続くバックスラッシュと、文字列の最後のバックスラッシュは、出力でも後ろにバックスラッシュも n も来ないので、unescape の最初の2つの節に当たらず、1文字のまま戻ります。1

  1. バックスラッシュを無条件に \\ にしても往復は保たれますが、出力は長くなります。問題の escape は短さを選んでいるので、その方針のまま直しました。
