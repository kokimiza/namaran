Units.hs

import Data.Int (Int32)

kib = 1024

packetBytes :: Int32 -> Int32
packetBytes n = n * kib

main :: IO ()
main = do
  print (packetBytes 3)
  print (kib * kib * kib * 4)

kib は 1 KiB のバイト数 1024 を表す定数で、main は 3 KiB のバイト数と、4 GiB（1024 × 1024 × 1024 × 4）のバイト数を表示するつもりです。本来は 3072 と 4294967296 の2行が出るはずが、いまは 3072 と 0 が出ます。

Answer

Wrong

kib = 1024

packetBytes :: Int32 -> Int32
packetBytes n = n * kib

main の kib * kib * kib * 4 には型が書かれていません。1024 のような整数リテラルは Num のどの型にもなれるので、kib も使う場所ごとに Int32 にも Integer にもなる、と読みたくなります。ところが、引数を取らない kib = 1024 のような束縛に型シグネチャが無く、型が Num a のような型クラスの制約を持つときは、Haskell は a を多相にしません。kib はある1つの型の定数になり、その型はモジュールの中のすべての使い方から1つに決められます。

このモジュールで kib の型を決めているのは packetBytes です。packetBytes の型は Int32 -> Int32 なので、n * kib の kib は Int32 に決まり、main の kib も同じ Int32 の定数を指します。Int32 の演算は 2 の 32 乗で割った余りで行われる（範囲の外は、表せる範囲へ巻き戻る）ので、1024 × 1024 × 1024 × 4 = 2 の 32 乗は 0 になります。packetBytes 3 の 3072 は Int32 に収まるので正しく、こちらだけを見ても欠陥に気付けません。1

Right

kib :: (Num a) => a
kib = 1024

packetBytes :: Int32 -> Int32
packetBytes n = n * kib

型シグネチャ kib :: (Num a) => a を付けると、kib は本当に多相な定数になります。Num の制約は、使う場所ごとに呼び出し側の型の Num のインスタンスとして渡されるので、packetBytes の中では Int32 の 1024、main の中では別の型の 1024 になります。main の式は型が書かれていないので既定の型の Integer で計算され、桁あふれせずに 4294967296 が出ます。packetBytes 3 は前と同じ 3072 です。2

  1. この規則は単相性制限（monomorphism restriction）と呼ばれ、Haskell 2010 Language Report の 4.5.5 節にあります。型クラスの制約を持つ定数を多相にすると、使うたびに値が計算し直されるおそれがあるので、型シグネチャが無いときは1つの型に固定します。GHCi では既定でこの制限が外されているので、同じ定義を GHCi に打ち込むと 4294967296 が出ることがあります。
  2. GHC に -Wall を付けると、main の式が既定の型 Integer に決まったことを -Wtype-defaults の警告で知らせます。直したコードの検証では、この警告だけを止めています。
