Accounts.hs

import qualified Data.Map as Map
import Data.Char (toLower)

register :: String -> Int -> Map.Map String Int -> Map.Map String Int
register email uid db
  | Map.member (map toLower email) db = db
  | otherwise = Map.insert email uid db

main :: IO ()
main = print (Map.toList (register "ann@x.jp" 2 (register "Ann@x.jp" 1 Map.empty)))

register は、メールアドレスを大文字と小文字の違いを無視して比べ、同じアドレスがすでに登録されていれば db をそのまま返すつもりの関数です。main は Ann@x.jp を登録したあとで ann@x.jp を登録します。引数も標準入力も使いません。いまは [("Ann@x.jp",1),("ann@x.jp",2)] が出ます。本来は [("ann@x.jp",1)] が出るはずです。

Answer

Wrong

register email uid db
  | Map.member (map toLower email) db = db
  | otherwise = Map.insert email uid db

登録済みかを確かめるときは小文字にしたキーを探しますが、登録するときは受け取った email をそのままキーにしています。1件目の Ann@x.jp は、db が空なのでそのまま "Ann@x.jp" というキーで登録されます。

2件目の ann@x.jp を確かめるときに探すのは "ann@x.jp" です。Map のキーは文字列として完全に一致するものしか見つからないので、"Ann@x.jp" とは一致せず、2件目も登録されます。大文字を含むアドレスで登録した利用者は、確かめる側からは一度も見つからないことになります。

Right

register email uid db
  | Map.member key db = db
  | otherwise = Map.insert key uid db
  where key = map toLower email

小文字にしたキーを where で一度だけ作り、確かめるときにも登録するときにも同じ key を使います。1件目は "ann@x.jp" として登録されるので、2件目を確かめたときに見つかり、db はそのまま返ります1。

  1. データベースで同じことをするなら、小文字にした列に一意インデックスを張るか、大文字と小文字を区別しない照合順序の列に一意制約を付けます。アプリケーションで確かめてから挿入するだけでは、同時に届いた2件の申し込みを防げません。
