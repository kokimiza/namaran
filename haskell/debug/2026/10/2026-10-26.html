Heartbeat.hs

import Control.Monad (forM_)
import System.Directory (getFileSize)
import System.IO

beat :: Handle -> Int -> IO ()
beat h n = do
  hPutStrLn h ("beat " ++ show n)

main :: IO ()
main = do
  h <- openFile "worker.log" WriteMode
  forM_ [1 .. 3] $ \n -> do
    beat h n
    getFileSize "worker.log" >>= print
  hClose h

beat は、処理の進み具合を外のプロセスが worker.log で見られるように、1行ずつ心拍を書くつもりの関数です。main は心拍を3回書き、そのたびにOSから見た worker.log の大きさを getFileSize で表示します。本来の出力は 7、14、21 ですが、いまは 0、0、0 が出て、ログを見張るプロセスには心拍が1つも見えません。

Answer

Wrong

beat :: Handle -> Int -> IO ()
beat h n = do
  hPutStrLn h ("beat " ++ show n)

openFile で開いたファイルの Handle は、既定でブロック単位のバッファリングになります。端末につながった標準出力と違って改行ではバッファを空にせず、バッファが一杯になるか Handle を閉じるまで文字を溜め続けます。"beat 1\n" などの7バイトは3回ともバッファに残り、OSから見たファイルは空のままです。

外のプロセスが読めるのはOSに渡った分だけなので、hClose するまで心拍は1つも見えません。監視する側は止まっていると判断し、途中でプロセスが強制終了されれば、溜まっていた行はファイルに残らずに失われます。

Right

beat :: Handle -> Int -> IO ()
beat h n = do
  hPutStrLn h ("beat " ++ show n)
  hFlush h

書いた直後に hFlush でバッファを空にすると、心拍の行はその場でOSに渡り、ほかのプロセスから読めるようになります。開いたあとで hSetBuffering h LineBuffering にしても、改行のたびに同じことが起きます。hFlush が保証するのはOSに渡すところまでで、記憶装置への書き込みは待ちません。1

  1. 電源が落ちても残すには、OSに同期を求める fsync(2) が要ります。Haskell 2010 の System.IO にはこれに当たる関数がなく、GHC では unix パッケージの fileSynchronise を使います。
