Largest.hs

import Data.List (sortBy)
import Data.Ord (Down (..), comparing)

files :: [(String, String)]
files = [("a.log", "900"), ("b.log", "1200"), ("c.log", "80")]

largestFirst :: [(String, String)] -> [String]
largestFirst = map fst . sortBy (comparing (Down . snd))

main :: IO ()
main = print (largestFirst files)

files はファイル一覧から読んだファイル名とバイト数の組で、largestFirst はファイル名を大きいファイルから順に並べるつもりの関数です。入力は files の3件で、大きさは 900、1200、80 バイトです。いまの出力は ["a.log","c.log","b.log"] です。本来の出力は ["b.log","a.log","c.log"] です。

Answer

Wrong

largestFirst = map fst . sortBy (comparing (Down . snd))

snd はバイト数を文字列のまま取り出すので、comparing が比べるのは String どうしです。String は Char のリストで、リストの compare は先頭から順に要素を比べ、最初に違った要素の大小で結果を決めます。この順序を辞書式順序（lexicographic order）といいます。"900"、"1200"、"80" は先頭の '9'、'1'、'8' で決着し、文字列としては "900" が最も大きく、"1200" が最も小さくなります。Down で大きい順にした結果が a.log、c.log、b.log です。

Right

largestFirst = map fst . sortBy (comparing (Down . bytes))
  where
    bytes :: (String, String) -> Integer
    bytes = read . snd

read で Integer に直してから比べれば、compare は数としての大小を返し、桁数の多い 1200 が最も大きくなります。文字列の比較で数の大小が合うのは、桁数がそろっているときだけです1。

  1. sortBy は比べるたびに bytes を呼ぶので、同じ文字列を何度も read します。Data.List の sortOn (Down . bytes) は各要素のキーを一度だけ計算してから並べ替えるので、キーの計算が重いときはこちらが向いています。
