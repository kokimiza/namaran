2026-10-18

Hot.hs

import Data.Maybe (listToMaybe)

data Reading
  = Reading { sensor :: String, celsius :: Double }
  | Offline { sensor :: String }

firstHot :: [Reading] -> Maybe String
firstHot rs = listToMaybe [sensor r | r <- rs, celsius r > 30]

main :: IO ()
main = print (firstHot [Reading "a" 25, Offline "b", Reading "c" 35])

firstHot は、温度計の読み取り結果の列から、30度を超えた最初の温度計の名前を返すつもりの関数です。読み取りに失敗した温度計は Offline になっています。入力は main の [Reading "a" 25, Offline "b", Reading "c" 35] です。いまは何も出力されずに、例外 No match in record selector celsius で止まります。本来の出力は Just "c" です。

Answer

Wrong

firstHot rs = listToMaybe [sensor r | r <- rs, celsius r > 30]

sensor は両方の構成子にあるフィールドですが、celsius は Reading にしか無いので、セレクタ celsius は Offline の値に使うと例外を投げます。内包表記は rs を先頭から順に調べて、条件 celsius r > 30 を要素ごとに評価します。1つ目の Reading "a" 25 では条件が偽になり、2つ目の Offline "b" で celsius が呼ばれて例外になります1。

listToMaybe はリストの最初の1要素しか求めないので、30度を超える読み取りが Offline より前にあれば、評価はそこで止まって例外は起きません。[Reading "c" 35, Offline "b"] なら Just "c" が返り、並び順によってだけ落ちる関数になっています。

Right

firstHot rs = listToMaybe [s | Reading s c <- rs, c > 30]

内包表記の生成器の左辺にパターンを書くと、パターンに一致しない要素は例外にならずに読み飛ばされます2。Reading s c <- rs は Offline の要素を捨て、Reading の値からだけ名前と温度を取り出すので、Offline の値に celsius を使う箇所がなくなります。

  1. このページの検証に使った GHC 9.14 では、-Wall に含まれる -Wincomplete-record-selectors が、この celsius r を警告します。Haskell 2010 の言語仕様は警告を定めていないので、知らせてくれるかどうかは処理系とその版によります。
  2. Haskell 2010 の報告書は、内包表記を concatMap と局所関数に置き換える変換規則で意味を定めています。生成器のパターンに一致しない要素に対しては、その局所関数が空リストを返すので、要素は結果に何も残しません。
