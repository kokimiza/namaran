2026-10-24

Tick.hs

import Data.IORef

counter :: IO (IORef Int)
counter = newIORef 0

tick :: IO Int
tick = do
  r <- counter
  modifyIORef r (+ 1)
  readIORef r

main :: IO ()
main = do
  a <- tick
  b <- tick
  print (a, b)

tick は、プログラム全体で1つのカウンタを1増やし、増やしたあとの値を返すつもりの関数です。main は tick を2回呼びます。いまの出力は (1,1) です。本来の出力は (1,2) です。

Answer

Wrong

counter :: IO (IORef Int)
counter = newIORef 0

tick :: IO Int
tick = do
  r <- counter
  modifyIORef r (+ 1)
  readIORef r

counter の型は IO (IORef Int) で、IORef そのものではなく「実行すると新しい IORef を作って返す」アクションです。tick の中の r <- counter はこのアクションを実行するので、tick を呼ぶたびに中身が 0 の箱が新しく作られます。1回目も2回目も新しい箱を1増やして読むので、どちらも 1 になります。

トップレベルの counter は一度しか評価されないので箱も1つだけだ、と読むのはもっともらしい誤りです。一度だけ評価されて共有されるのはアクションという不変な値で、そのアクションを実行した結果は実行のたびに別になります。

Right

tick :: IORef Int -> IO Int
tick r = do
  modifyIORef r (+ 1)
  readIORef r

main :: IO ()
main = do
  r <- newIORef 0
  a <- tick r
  b <- tick r
  print (a, b)

箱は main で一度だけ作り、tick に引数で渡します。2回の tick は同じ r を書き換えるので、2回目は1回目が残した 1 に足して 2 を返します。どの箱を共有するかが型と引数に現れるので、tick がどの状態を書き換えるかも呼び出し側から読めます1。

  1. トップレベルに1つだけの IORef を置く書き方として、unsafePerformIO (newIORef 0) に {-# NOINLINE #-} を付ける慣用句が知られています。unsafePerformIO は IO の実行を純粋な値に見せかける関数で、NOINLINE を忘れて定義がインライン化されると箱が複数できます。引数で渡す形なら、こうした注意は要りません。
